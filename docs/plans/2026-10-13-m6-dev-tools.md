# M6 개발 도구 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `test "…": … ;;`와 `assert`, `fung test`, `fung check`, 경고(W0101·W0102·W0103), REPL(줄 편집 직접 구현), `dbg`를 만들고, M4·M5에서 미룬 작은 결함을 정리한다. 끝나면 알파 기준(M0~M6)에 닿는다.

**Architecture:** 토큰과 식 노드가 **바이트 구간**을 갖게 되어 `assert`·`dbg`가 식의 소스 텍스트를 보여 줄 수 있다. `test` 블록은 desugar가 **인자 없는 함수**로 바꾸고, 컴파일러는 `Tests` 옵션이 켜졌을 때만 `CLOSURE` + `TEST k`로 Runtime의 테스트 표에 등록한다(`fung run`은 아무 코드도 내지 않는다). `assert`는 `ASSERT k` 한 명령이고 k는 Proto의 `Asserts` 표(식·좌·우 텍스트, 비교 연산자)를 가리킨다. 경고는 resolve가 모으고(`Result.Warnings`) 로더가 합쳐 `check`·`test`만 출력한다. REPL은 줄마다 "지금까지의 전역 이름"을 들고 resolve·컴파일하며(`Options.Globals`, `Redefine`), 전역 표는 고정 용량으로 미리 잡아 이전 클로저가 재정의를 보게 한다. 줄 편집기는 유닉스에서만 raw 모드(`syscall` termios), 그 외·파이프는 보통 줄 읽기.

**Tech Stack:** Go 1.27, 표준 라이브러리만 (`syscall`, `unsafe`는 터미널 raw 모드에 한함).

**Spec:** `08-tooling-and-errors.md` (경고, `fung` 명령, REPL, `dbg`, 테스트), `01-syntax.md` (`test_block`, `assert`), `04-modules.md` (테스트 블록은 `fung test`에서만), `06-go-interop-and-stdlib.md` (`dbg`는 prelude), `03-functions-and-patterns.md` (모델 C: 테스트 본문은 만들어질 때 보이는 변수를 복사).

## 계획 수준의 결정

1. **구간 정보.** `lexer.Token`에 `Off`·`End`(바이트 오프셋), `tree.Node`에 `Off`·`End`를 더한다. 파서의 `expr()`이 식마다 채우고, 문장 노드도 채운다. 소스 자르기는 프런트엔드가 `compiler.Options.Source`로 넘긴 원문에서 한다. `-e`도 원문이 있으므로 같다.
2. **`test` 블록.** 파서 `(test body)`(Lit = 이름), desugar가 `(test name (fn () body))`로 바꾼다(`FnInfo.Name = "test: 이름"`, 호출 경로에 그렇게 보인다). resolve는 보통 람다처럼 다룬다(그 자리에서 보이는 변수를 복사). 컴파일러는 `Options.Tests`가 참이면 `CLOSURE n; TEST k`(k = 이름 상수), 거짓이면 아무 코드도 내지 않는다. 라이브러리 최상위에서도 허용(04). 중첩(함수 안의 `test`)은 E0221? — 아니다, 새 번호 **E0114 `test must be at the top level`**(파서가 잡는다: 문장 시작에서 `test`를 보면 최상위인지 확인; 블록 깊이로 판단).
3. **`assert`.** 파서 `(assert e)`. 컴파일러: `e`가 `(op CMP a b)`(CMP ∈ `== != < > <= >=`)이면 `a; b; ASSERT k`, 아니면 `e; ASSERT k`. `Proto.Asserts[k] = {Text, Left, Right, Op}`. VM: 두 피연산자형은 `Compare`/`Equal`로 판정하고 실패 시 E0807 메시지에 `텍스트`, 그리고 리터럴이 아닌 쪽의 `좌 = 값`/`우 = 값` 줄을 덧붙인다(리터럴 판정은 컴파일러가 하고 `Left`/`Right`를 빈 문자열로 둔다). 단항형은 bool이어야 하고(E0505) 거짓이면 E0807 + `value = false` 없음(값이 false인 것은 자명). 피연산자는 **한 번만** 평가된다.
4. **E0807 메시지와 힌트.** `assertion failed: %s`. 추가 줄은 `Error.Help`가 아니라 새 필드 `Error.Notes []string`으로 들어가 발췌 뒤에 한 줄씩 `  left = …` 형식으로 찍힌다 (08의 예시 모양).
5. **경고.** resolve가 `Result.Warnings []*diag.Error`(코드 W01xx)를 돌려준다. W0101 `unused import `%s``(모듈 이름·별칭·목록 이름이 한 번도 읽히지 않음), W0102 `unused variable `%s``(블록 지역 변수와 패턴 이름 중 `_`로 시작하지 않고 한 번도 읽히지 않은 것; 매개변수와 파일 전역은 제외), W0103 `` `%s` shadows a prelude function ``(최상위 `fn`·변수, 매개변수, 패턴 이름이 prelude 이름과 같음). `diag.Error.Error()`는 W로 시작하면 `warning[…]`. 로더가 모듈별 경고를 `Program.Warnings`로 합친다(의존 순서). `check`와 `test`만 출력하고 종료 코드에 영향 없음.
6. **`fung check [file | -e code]`.** `Loader{Tests: true}`로 적재만. 에러 → 2, 경고 출력 → 0, 성공 무출력.
7. **`fung test [path]`.** 경로가 없으면 `.`, 파일이면 그 파일, 디렉터리면 재귀로 `.fung`(이름이 `_`로 시작하는 디렉터리는 건너뜀 — 골든 fixture와 같은 규칙). 파일마다: 새 Runtime, prelude 부트, `Loader{Tests: true}`, 모듈 등록, 진입 실행, `rt.Tests()`를 순서대로 `rt.CallTest`로 실행. 테스트가 0개인 파일은 출력 없이 건너뜀. 출력 형식은 08. 컴파일 실패 파일은 에러를 찍고 그 파일을 `FAIL`로 세며 다른 파일은 계속; 종료 코드는 컴파일 실패가 하나라도 있으면 2, 아니면 실패가 있으면 1.
8. **REPL 전역 표.** `Runtime.Run`이 REPL용으로 `rt.globals`를 **용량 65536으로 한 번 할당**한다(`Runtime.PrepareREPL()`); 넘으면 E0806 `too many globals (limit 65536)`. 이전 클로저의 슬라이스 헤더가 같은 배열을 가리키므로 재정의가 보인다. 모듈 전역에는 영향 없다.
9. **REPL resolve.** `resolve.Options{Globals []string, Redefine bool}`: 파일 스코프를 기존 전역으로 미리 채우고(모두 재대입 가능한 보통 변수로; `Redefine`이면 상수 제약 해제), 새 전역은 그 뒤 번호를 받는다. 컴파일러의 `GlobalNames`는 전체. import는 REPL에서도 되지만 같은 모듈을 다시 import하면 E0309 대신 **조용히 기존 바인딩을 재사용**한다(REPL 편의; `Redefine`일 때만).
10. **REPL 입력 규칙.** 줄을 받아 파싱; 에러가 EOF 토큰 위치면 "더 받는다"(블록 열림, 줄 끝 연산자). 그 외 에러는 보고하고 줄을 버린다. 식 문장의 값은 `Format`으로 출력(`nil`도 출력), 문장(`assign` `fn` `import` `typealias` `test` `assert`)으로 끝나면 출력 없음. 런타임 에러는 보고하고 세션 계속(at_exit는 `:quit`/Ctrl-D 때). `:help` `:quit` `:load file`만.
11. **줄 편집기.** `internal/repl/line_unix.go`(`//go:build darwin || linux`)와 `line_other.go`. 키: 글자 입력, ←/→, Home/End(Ctrl-A/Ctrl-E 포함), Backspace, Delete(Ctrl-D는 빈 줄에서만 종료), ↑/↓ 기록, Ctrl-C(줄 취소), Ctrl-L(화면 지움), Enter. 유니코드는 룬 단위로 다루고 폭은 1로 가정한다(한글 폭 2는 알파 이후). 터미널 판정은 `os.Stdin.Stat()`의 `ModeCharDevice`.
12. **`dbg`.** prelude `dbg(x, text = nil, where = nil)`: stderr에 `[where] text = Format(x)` 또는 `dbg = Format(x)`, `x` 반환. 컴파일러는 callee가 `(prelude dbg)`이고 위치 인자 하나·이름 인자 없음이면 텍스트·`file:line` 상수를 덧붙인다.
13. **정리 작업(Task 8)에서 고치는 것:** `int`/`float`의 `_` 위치 검사(01 규칙: 숫자 사이에만), `sym(s)`는 이름 규칙에 맞을 때만, 쓰기 전용 핸들의 `read_line`은 `'invalid`, `pad_*`의 빈 pad는 E0403, `repeat`·`pad_*`의 결과 길이 상한 1e8 룬(초과 E0806 `too many characters (limit …)`), 순환 메시지는 표시 경로(`lib/a.fung → lib/b.fung → lib/a.fung`), E0309는 "name `%s` is already bound to a module".

## Review Focus

1. `assert f() == g()`에서 `f`·`g`가 각각 **한 번만** 평가된다 (Task 4 테스트: 부수효과 횟수).
2. 테스트 하나가 `assert` 실패·런타임 에러·`exit`를 해도 다음 테스트가 돈다; `exit`는 그 파일의 남은 테스트를 멈추고 종료 코드를 따른다 (Task 5).
3. W0102가 매개변수·`_x`·파일 전역·패턴의 `_`에는 나지 않고, 블록 안에서만 쓰인 변수에는 난다; `fung run`은 경고를 절대 내지 않는다 (Task 3·5).
4. REPL에서 `fn f() = g()` 뒤에 `fn g()`를 재정의하면 `f()`가 새 `g`를 본다 (Task 6).
5. `x |> dbg`의 텍스트가 `x`의 소스 전체이고 stdout에는 아무것도 없다; 멀티바이트(한글) 식의 구간이 정확하다 (Task 1·4).

// internal/lexer/lexer_test.go (추가)
func TestTokensCarryByteSpans(t *testing.T) {
	toks, _, err := Lex("t.fung", "참치 = \"a b\" + 1")
	if err != nil {
		t.Fatal(err)
	}
	src := "참치 = \"a b\" + 1"
	want := []string{"참치", "=", "\"a b\"", "+", "1"}
	for i, w := range want {
		if got := src[toks[i].Off:toks[i].End]; got != w {
			t.Errorf("token %d span = %q, want %q", i, got, w)
		}
	}
	eof := toks[len(toks)-1]
	if eof.Off != len(src) || eof.End != len(src) {
		t.Errorf("EOF span = %d..%d", eof.Off, eof.End)
	}
}
```

	w := Errorf("W0101", Pos{File: "t.fung", Line: 1, Col: 1}, "fs")

func TestAssertAndTestOpcodes(t *testing.T) {

		if !op.HasArg() {
			t.Errorf("%s needs an argument", op)

func TestTestAndAssertStatements(t *testing.T) {

// assertStmt compiles (assert e). A top-level comparison is split so the
// failure report can show each side's value (08); a literal side is not
// reported (its value is its text).
func (c *compiler) assertStmt(n *tree.Node) *diag.Error {
	e := n.Kids[0]
	a := bytecode.Assert{Text: e.Text(c.opts.Source)}
	if e.Head == "op" && isComparison(e.Lit.(string)) && len(e.Kids) == 2 {
		a.Op = e.Lit.(string)
		for i, side := range e.Kids {
			if err := c.expr(side, false); err != nil {
				return err
			}
			if !isLiteral(side) {
				if i == 0 { a.Left = side.Text(c.opts.Source) } else { a.Right = side.Text(c.opts.Source) }
			}
		}
	} else if err := c.expr(e, false); err != nil {
		return err
	}
	c.proto.Asserts = append(c.proto.Asserts, a)
	c.proto.Emit(bytecode.OpAssert, len(c.proto.Asserts)-1, n.Pos)
	return nil
}

	r, l := t.pop(), t.pop()

		if a.Left != "" { e.Notes = append(e.Notes, a.Left+" = "+value.Format(l)) }
		if a.Right != "" { e.Notes = append(e.Notes, a.Right+" = "+value.Format(r)) }
		return nil, e
	}
case bytecode.OpTest:
	fn := t.pop()
	t.rt.tests = append(t.rt.tests, Test{Name: string(f.proto.Consts[in.Arg()].(value.Str)), Fn: fn})
```
