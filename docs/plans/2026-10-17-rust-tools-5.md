# Rust 이식 5단계: 도구(check·test·fmt·REPL) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rust CLI가 Go CLI의 명령 전체(`check`·`test`·`fmt`·REPL·`version`·`help`)를 같은 출력·종료 코드로 제공하고, 경고 W0101~W0104를 낸다. 먼저 Go 포매터 버그를 고친다.

**Architecture:** 경고·`test` 블록 컴파일·포매터는 `crates/fung-front`(의존성 0개), 명령·테스트 실행기·REPL은 `crates/fung-cli`, raw 모드는 `fung-vm`이 이미 쓰는 `libc`를 통해(필요하면 `fung-vm`에 작은 터미널 도우미를 둔다 — `fung-cli`는 작업 공간 크레이트만 의존할 수 있다).

**Tech Stack:** Rust 1.94, std(+ `fung-vm`의 `libc`), Go(정답지·포매터 수정).

**Spec:** `docs/superpowers/specs/2026-10-17-rust-tools-5-design.md`

## Global Constraints

- 크레이트는 `deny.toml` 허용 목록만. `fung-front` 0개, `fung-cli`는 작업 공간 크레이트만(`tests/deps.rs`). 새 크레이트 없음.
- Go 구현은 Task 0(포매터 버그 수정) 말고는 수정하지 않는다.
- 커밋 전: `gofmt -l .`(빈 출력), `go vet ./...`, `go test ./...`, Go `fung fmt --check extras examples tests/lang`, `cargo fmt --check`,
  `cargo clippy --all-targets --locked -- -D warnings`(디버그와 `--release`), `FUNG_REQUIRE_PARITY=1 cargo test --locked`(디버그와 `--release`).
- 코드·주석·에러 문구·커밋 메시지는 영어, 학습 노트·설계 문서는 한국어. Conventional Commits, 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. 다른 이메일 금지.
- 커밋은 자기 경로만 명시적으로 `git add`(`-A`·`-a` 금지).
- **실행권 규칙**, `unsafe`는 `// SAFETY:`, 동시성 테스트는 상태로 순서.
- Go와 같음은 바이트 단위(출력·종료 코드). Go를 흉내 내려고만 붙이는 것은 보고서에 적는다.

## Review Focus

1. 포매터가 입력의 의미를 바꾸지 않는다: 출력 토큰 열 보존 안전장치가 Go와 같게 동작하고, 주석·빈 줄·문자열 보간·여러 줄 문자열·`;;` 블록이 보존된다 → Task 3.
2. `fung test`에서 한 파일의 에이전트·배경 태스크·`at_exit`·`exit`·교착이 다음 파일로 새지 않고, 종료 코드 집계가 Go와 같다 → Task 2.
3. 경고가 거짓 양성을 내지 않는다(`_` 접두사, 패턴 안의 이름, 클로저가 쓰는 이름, 재대입, `test` 블록 안 사용) → Task 1.
4. REPL: 파이프 입력에서 여러 줄 입력·에러 뒤 계속·재정의·`exit`가 Go와 같고, 터미널이 아닐 때 raw 모드를 켜지 않으며, 비정상 종료에도 터미널 상태를 되돌린다 → Task 4.
5. 경로 순회: 심볼릭 링크, `_`로 시작하는 이름, 숨김 파일, 존재하지 않는 경로, 파일과 디렉터리 섞인 인자에서 `check`·`test`·`fmt`가 Go와 같은 파일을 같은 순서로 처리한다 → Task 1, 2, 3.
