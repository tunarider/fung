# Rust 이식 4a단계: `fs`·`path` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Go의 `_native.fs`(17개)·`_native.path`(6개)를 Rust로 옮겨 `fs`·`path` 모듈과 prelude 파일 함수가 Go와 같은 출력으로 돌게 하고, `fs_and_path` 골든 테스트를 비교에 넣으며, 3b의 취소 노드 누수를 고친다.

**Architecture:** `crates/fung-vm/src/native/{fs,path}.rs`가 Go `internal/native/{fs,path}.go`를 함수 단위로 옮긴다. 파일 입출력은 실행권 밖(`outside`), 파일 핸들은 `Value`의 새 종류(핸들마다 잠금, 마지막 사본에서 닫힘). Go `filepath` 규칙·`glob`·운영체제 에러 문구는 Go와 같게 직접 구현하고 과도기 잔가지로 기록한다.

**Tech Stack:** Rust 1.94 표준 라이브러리만(`std::fs`, `std::path`, `std::io`).

**Spec:** `docs/superpowers/specs/2026-10-15-rust-fs-4a-design.md`

## Global Constraints

- Rust 크레이트 의존성 0개. Go 구현(`cmd/`, `internal/`, `extras/`)은 수정하지 않는다.
- 커밋 전: `gofmt -l .`(빈 출력), `go vet ./...`, `go test ./...`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`(디버그와 `--release`),
  `FUNG_REQUIRE_PARITY=1 cargo test`, `FUNG_REQUIRE_PARITY=1 cargo test --release`.
- 코드·주석·에러 문구·커밋 메시지는 영어, 학습 노트는 한국어. Conventional Commits. 커밋 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- git 작성자는 저장소 설정 그대로. 다른 이메일 금지.
- **실행권 규칙**: fung 값(`Rc`를 품은 모든 것)은 실행권을 쥔 스레드만 만지고 해제한다. `outside`의 클로저에는 fung 값을 넣지 않는다(바이트·문자열·경로만).
- 표시 없는 `tests/lang` 파일은 Go 대조에서 Go와 바이트 단위로 같다. 새 에러 번호를 만들지 않는다.
- 동시성 테스트는 고정 `sleep`이 아니라 상태로 순서를 맞춘다(`crates/fung-vm/src/testutil.rs`의 탐침).
- Go를 흉내 내려고만 붙이는 코드는 `docs/design/open-questions.md` "Go 동등을 위한 과도기 잔가지"에 한 줄씩 더한다.

## Review Focus

1. 운영체제 에러의 `message`가 Go와 글자까지 같다(`cannot read \`x\`: no such file or directory` — Rust `io::Error`의 `Display`(`No such file or directory (os error 2)`)가 새어 나오면 안 됨) → Task 2.
2. 한 파일 핸들에 여러 태스크가 동시에 `write_line`해도 줄이 섞이지 않고, 실행권 밖 입출력 중에도 다른 태스크가 돈다 → Task 4.
3. 핸들을 닫지 않고 버려도 파일 디스크립터가 새지 않는다(수천 번 열고 버리기) → Task 4.
4. `glob`·`walk`·`list`의 결과 순서가 Go와 같다(사전순, 중첩 디렉터리, 숨김 파일) → Task 3.
5. 경로 함수가 이상한 입력(`""`, `"/"`, `"a//b/../c/"`, `".hidden"`, `"a.b.c"`)에서 Go `filepath`와 같다 → Task 1.

### Task 2: `_native.fs` — 파일·디렉터리 함수와 운영체제 에러

**Files:** Create `crates/fung-vm/src/native/fs.rs`(+ `fs_tests.rs`), `crates/fung-vm/src/native/oserr.rs`(운영체제 에러 → Go 문구), Modify `native.rs`, `boot.rs`
- Go 참조: `internal/native/fs.go`(`fsErr`, `read` `write` `append` `exists` `stat` `mkdir` `remove` `remove_all` `move` `copy` `temp_dir`), `internal/nat`(`ErrValue`, `Reason`)

**Interfaces:**
- Produces: `_native.fs`의 위 11개. 실패는 Go처럼 `Err({kind, message})`: `kind`는 `'not_found`·`'exists`·`'permission`·`'io`, `message`는 `cannot <verb> \`<path>\`: <reason>`. `<reason>`은 Go `nat.Reason`이 내는 문자열(유닉스 errno의 Go 문구: `no such file or directory`, `permission denied`, `file exists`, `is a directory`, `not a directory`, `directory not empty` 등). `pub(crate) fn reason(e: &std::io::Error) -> String`(Task 3·4가 씀).
- 입출력은 `outside`로(실행권 밖에서 바이트·문자열만 다루고, 값은 실행권을 다시 쥔 뒤 만든다).

- [ ] **Step 1: 실패하는 테스트** — `fs_test.go`의 해당 케이스를 옮기고, 임시 디렉터리에서 Go 바이너리와 같은 출력을 단언하는 케이스를 더한다: 없는 파일 읽기, 디렉터리 읽기, 권한 없는 파일 쓰기(권한을 빼고 만든 파일; root에서 돌면 건너뜀), 있는 디렉터리 `mkdir`, 비지 않은 디렉터리 `remove`, `copy`·`move`의 대상이 없음/있음, `stat`의 결과 맵(Go와 같은 키·순서).
  `reason`은 errno별 표로 단위 테스트(Go 바이너리로 각 errno 문구 확인).
- [ ] **Step 2: 실패 확인** — Run: `cargo test -p fung-vm fs` / Expected: FAIL.
- [ ] **Step 3: 구현** — errno → Go 문구 표는 Go `syscall`의 유닉스 문구(macOS·Linux 공통 부분)를 옮긴다. 표에 없는 errno는 Go와 같은 방식(Go `Errno.Error`)으로.
- [ ] **Step 4: 통과 확인** — Run: 커밋 전 검사 전체 / Expected: PASS.
- [ ] **Step 5: 커밋** — `feat(rust): add file and directory functions to the fs module`

### Task 3: `list`·`glob`·`walk`

**Files:** Modify `crates/fung-vm/src/native/fs.rs`, Create `crates/fung-vm/src/native/glob.rs`(+ 테스트)
- Go 참조: `internal/native/fs.go`(`fsListFn`, `fsGlobFn`, `fsWalkFn`), Go 표준 `path/filepath.Glob`·`Match`·`WalkDir`

**Interfaces:**
- Consumes: Task 1 `clean`, Task 2 `reason`.
- Produces: `list(dir, full=?)`(M8 미결 정리의 `full`), `glob(pattern)`, `walk(dir)` — 결과 리스트의 모양·순서·에러는 Go와 같다. `glob`의 패턴 문법 에러(Go `filepath.ErrBadPattern`)도 Go와 같은 값.

- [ ] **Step 1: 실패하는 테스트** — Go `filepath.Match`의 표(대괄호, 범위, `^`/`!` 부정, `\\` 이스케이프, 잘못된 패턴)를 옮기고, 임시 디렉터리 트리(중첩, 숨김 파일, 대소문자, 빈 디렉터리)에서 `list`·`glob`·`walk` 결과가 Go 바이너리와 같은지(같은 디렉터리를 두 구현에 주거나 경로를 치환해) 단언.
- [ ] **Step 2: 실패 확인** — Run: `cargo test -p fung-vm glob fs` / Expected: FAIL.
- [ ] **Step 3: 구현** — Go `filepath.Match`·`Glob`·`WalkDir`(사전순) 알고리즘을 옮긴다. 디렉터리 순회는 `outside`에서 이름 목록만 모으고 값은 실행권 안에서.
- [ ] **Step 4: 통과 확인** — Run: 커밋 전 검사 전체 / Expected: PASS.
- [ ] **Step 5: 커밋** — `feat(rust): add list, glob and walk to the fs module`
