`docs/plans/2026-11-11-full-review.md`(이하 "점검 문서")의 115개 항목을 고치는 계획이다.

## 2. 결정 없이 고치는 항목

버그·성능·정리·문서로 분류된 항목은 점검 문서의 "고치는 법"대로 한다.

- **버그**: FE40, FE41, FE42, FE46(D38로 사라지지 않으면), FE49, FE50, FE52~FE57, FE60, VA28, VA36, VA40, CC14, CC16, CC18, LB41, TL11, TL14.

## 3. 고칠 때의 규칙

- **브랜치**: 지금 작업 브랜치(`claude/language-bytecode-vm-review-4cf7c7`) 위에서 한다. main 스쿼시는 사용자가 요청할 때.
- **커밋**: 4절의 묶음마다 하나(크면 둘 이상). Conventional Commits, 영어, 동작이 바뀌면 `feat!`/`fix!`. 작성자 `tunarider <tunarider@tunaground.net>`.
- **TDD**: 항목마다 시험을 먼저 쓰고 실패를 확인한다. 재현은 점검 문서의 것을 그대로 시험으로 옮긴다. 언어 동작은 `tests/lang/*.fung`, 내부는 해당 `*_tests.rs`.
- **검사**: 묶음 커밋마다 CLAUDE.md의 전체 검사(`cargo fmt --check`, clippy 두 번, `cargo test` 두 번, `cargo deny`·`cargo audit`). 실패하면 다음 묶음으로 넘어가지 않는다.
- **에러 번호**: 새 번호는 `crates/fung-front/src/diag/catalog.rs`에서 붙이고 `FUNG_UPDATE_SPEC=1 cargo test spec_file`. 은퇴 번호는 표에 은퇴로 남기고 다시 쓰지 않는다.
- **저장소의 `.fung`**: 언어 규칙이 바뀌는 묶음은 `extras/`·`examples/`·`tests/lang/`·`bench/`·매뉴얼 펜스를 `grep`으로 먼저 찾아 같은 커밋에서 고친다.
- **기대 출력·매뉴얼**: `FUNG_EXPECTED=bless …`·`FUNG_UPDATE_MANUAL=1 …`로 다시 쓰고 diff를 검토한다.
- **CHANGELOG**: 사용자에게 보이는 변화는 묶음마다 `[Unreleased]`에(호환 깨짐은 "호환 깨짐" 아래).
- **점검 문서**: 항목을 고칠 때마다 해당 절에 `처리:` 줄(커밋, 바꾼 문서, 결정 번호).
- **성능 항목**: 고치기 전에 기준을 재고(같은 바이너리를 번갈아 여러 번, CPU 시간 중앙값), 고친 뒤 같은 측정을 `docs/notes/bench-languages.md`에 기록한다.
