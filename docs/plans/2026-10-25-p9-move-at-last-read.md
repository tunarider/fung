# P9: 마지막 읽기에서 넘겨주기 (맵·리스트 누적의 제자리 수정) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `fold(0..n, {}, (m, i) => put(m, k, i))`처럼 쌓는 동안 아무도 중간 결과를 보지 않는 맵·리스트가 제자리에서 바뀐다.
목표(open-questions P9): 비교의 `map`이 Python의 2배 안(지금 3.4배).

**원인 (2026-10-25 측정):** 제자리 수정 장치는 이미 있다. `put`·`+`는 값이 홀로 쥐어져 있으면(`Rc` 참조 수 1) 복사하지 않는다(`Rc::make_mut`).
그런데 람다의 `put(m, …)`에서 `put`이 받는 맵은 참조 수가 언제나 2다. 지역 변수 `m`이 하나, `LOADLOCAL`이 복사해 넘긴 인자가 하나.
03의 규칙이 "지역 변수는 마지막으로 읽는 **문장이 끝난 뒤** 놓는다"라서다. 그래서 `put`마다 HAMT 경로와 항목 벡터의 경로를 복사하고 옛 판을 해제한다.
꼬리 호출 직전에 지역 변수를 비우는 실험에서 `map`이 0.376 → 0.19초.

**결정 (사용자, 2026-10-25): B.** 지역 변수의 **마지막 읽기는 값을 넘겨준다**(복사하지 않고 칸을 비움). Rust의 move, Koka·Lean의 "functional but in-place"와 같은 생각.
- 03 "값의 수명"의 규칙: "그 변수를 마지막으로 읽는 문장이 끝난 뒤 놓인다" → "**마지막으로 읽는 곳에서 넘어간다**(읽은 쪽이 쥐고, 그쪽이 놓으면 놓인다)".
- 한 번도 읽지 않는 변수는 함수가 돌아올 때까지 산다(`_guard` 관용구, 그대로).
- 관찰되는 차이는 L7 때와 같은 종류다: 값이 그 문장이 끝나기 전에 놓일 수 있다(채널 끝이 더 일찍 닫힘, 메모리가 더 일찍 풀림).
- 기각: A(꼬리 호출에서만 놓기). 재귀 누적 `go(put(acc, k, v), rest)`에서는 `put`이 꼬리 호출의 인자 안에서 먼저 돌아 효과가 없고, 규칙에 예외를 더한다.

**Architecture:**
- 새 명령 `MOVELOCAL`(53): 칸의 값을 꺼내 스택에 올리고 칸을 비운다. 나머지는 `LOADLOCAL`과 같다.
- 컴파일러(`compiler/moves.rs`): 함수 본문마다 평가 순서의 **뒤에서 앞으로** 걸으며 "뒤에서 읽히는 칸" 집합을 들고 다닌다(생존 분석).
  `(local i)`를 만났을 때 그 칸이 집합에 없으면 그 읽기가 마지막이다(노드 주소로 표시). 그다음 집합에 넣는다. 쓰기(대입·패턴)는 다루지 않는다(집합이 커질 뿐이라 안전 쪽).
  - `if`(·`and`·`or`): 두 가지를 같은 "뒤" 집합에서 따로 걷고, 조건은 두 결과의 합집합에서 걷는다.
  - `??`: 오른쪽을 "뒤"에서 걷고, 왼쪽은 "뒤 ∪ 오른쪽의 읽기"에서 걷는다.
  - `match`: 주제는 갈래마다 다시 읽히므로 넘기지 않는다. 가드도 넘기지 않는다. 갈래 본문은 "뒤"에서 따로 걷는다. 앞쪽은 "뒤 ∪ 모든 읽기".
  - `return`: 뒤가 없다(빈 집합).
  - 함수 값(`fn`): 붙잡는 칸은 읽기다(복사, 넘기지 않음). 안쪽 함수의 본문은 자기 분석을 따로 한다.
  - `?`의 이른 반환은 뒤가 없으니 따로 다루지 않는다.
  - 대입 문장은 값만 걷는다. 기본값 식(프롤로그)은 분석 밖이라 늘 `LOADLOCAL`.
- 최상위(`<main>`)는 그대로(전역 위주, 분석하지 않음).
- `CLEARLOCAL`은 그대로 둔다(넘겨준 칸에 다시 써도 해가 없다).
