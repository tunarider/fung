# L14. 스케줄링의 한계: 시작 순서, 늦은 시작, 공정성, REPL Ctrl-C, `fung test`의 런타임, 가려지는 교착

상태: 열림 (2026-10-26). 0.5.0 전에 고친다. 목록: [README](README.md).

## 문제

open-questions "알려진 한계" → "태스크"의 여섯 항목이다. 모두 M:1 스케줄러(`crates/fung-vm/src/vm/sched.rs`, 설명 `docs/notes/R7-scheduler.md`)의 성질이다. 하나씩 닫을 수 있게 번호를 붙인다.

1. **형제 태스크의 시작 순서**는 보장되지 않는다(05 "범위"도 되감기 순서를 같은 말로 적음). 실제로는 한 차례에 띄운 형제가 띄운 순서로 돈다. `for i in 1..5: spawn(s, () => print(i)) ;;`는 `1 2 3 4`다(확인함). 언어가 약속하지 않는 순서에 프로그램과 `test` 블록이 기대도 아무것도 알려 주지 않는다.
2. **띄운 태스크는 띄운 쪽이 차례를 넘기거나(호출 1,000번, `YIELD_EVERY`) 주차하기 전에는 돌지 않는다.** `scope(fn(s): spawn(s, () => print("child")); print("parent") ;;)`는 `parent`, `child` 순이다(확인함). 적힌 한계 "곧바로 끝나는 태스크가 띄운 자식은 한 번도 돌지 못하고 부모와 함께 취소된다"는 자유 `spawn` 시절(`docs/notes/R3a-runtime.md`)의 문장이다. 구조적 동시성(L1)에서는 다시 만들지 못했다: 자식은 범위의 노드 아래 달리고 범위는 자식을 기다린다(`spawn(s, …)`로 바깥 범위에 띄운 손자도 돈다, 확인함). 남은 경우는 첫 차례 전에 범위가 취소된 것이다: `scope(fn(s): spawn(s, () => print("child")); cancel(s) ;;)`는 `child`를 찍지 않고 `Err({kind: 'cancelled, …})`다.
3. **공정성.** (가) 오래된 깨움이 태스크에 차례를 한 번 더 준다. (나) 연결의 차례 줄(`Turnstile`)은 놓을 때 기다리는 쪽을 모두 깨워 다시 다투게 한다. 노트는 "굶기지는 않는다"고 적었지만, 놓은 태스크가 같은 차례에 다시 잡으면 깨어난 쪽은 또 줄에 선다. 굶김이 없는지는 확인하지 못했다.
4. **REPL**: 한 묶음에 Ctrl-C 둘이 오면 `release`가 시작하기도 전에 태스크를 버린다(알림은 "정리가 끝나지 않음"). 버릴 때 태스크를 먼저 버리고 이벤트 루프 등록을 뒤에 해제한다(닫힌 fd 번호에 해제를 부름; 해는 없음). 터미널 재현은 하지 않았다.
5. **`fung test`**: 파일 N의 런타임(과 스레드 풀)은 파일 N+1이 신호 정책을 바꿀 때 사라진다. 쌓이지는 않지만 끝난 파일의 풀 스레드가 다음 파일의 적재 동안 산다.
6. **끝없이 도는 태스크가 다른 태스크 사이의 교착을 가린다.**

```
$ cat a.fung
fn spin(n) = spin(n + 1)
(tx, rx) = channel()
scope(fn(s):
  spawn(s, () => spin(0))
  spawn(s, () => recv(rx))
  nil
;;)
$ fung run a.fung                      # 끝나지 않는다(3초 뒤 SIGALRM으로 끊음)
```

`spin`을 빼면 곧바로 `error[E0702]: deadlock: all tasks are waiting`와 `recv at b.fung:3:22 (<lambda>, holds its own sending end)`다. 05 "종료"는 "모든 태스크가 서로 기다려 멈추면" 교착이라 했으니 명세대로지만, 원칙 1(조용히 넘어가는 동작은 에러)에는 못 미친다.

## 지금 동작과 원인

- 시작: `Task::start`(`vm/task.rs`)가 새 `Fiber`를 `world.new_fibers`에 넣고, `Sched::adopt`가 차례가 끝난 뒤 실행 대기열 끝에 넣는다. `Sched::run`은 한 바퀴마다 `adopt` → `timers_due` → `ready.take_ids`(다른 스레드·채널이 깨운 것) 순으로 줄을 채운다. 그래서 한 차례에 띄운 형제는 띄운 순서다.
- 오래된 깨움: `Ready::push`는 중복을 거르지 않는다(`has_others`의 주석: "a task's own id may be queued twice"). `Sched::turn`은 주차하지 않은 태스크의 번호가 와도 차례를 준다. 차례를 넘겨(`Turn::Yielded`) 줄에 선 태스크가 그사이 깨워지면 한 바퀴에 차례를 두 번 받는다. README S9의 "주차 직전에 세운 `turn_due`가 깨어난 뒤에도 남음"은 이웃한 결함이다(S9에서 고친다).
- 차례 줄: `crates/fung-vm/src/native/net.rs`의 `Turnstile::release`가 `busy`를 풀고 `WaitList::wake_all`(`vm/block.rs`).
- REPL: `vm/stop.rs`의 `apply`가 `Event::Interrupt`에서 `w.interrupted && w.in_run`이면 `w.abandon = true`. `Sched::events`가 한 바퀴에 게시된 사건을 한꺼번에 처리하므로 둘이 같은 묶음이면 첫 것의 취소가 돌 틈 없이 둘째가 버리기를 켠다. `Sched::abandon`은 `slots`를 먼저 버리고 `take_all_io`의 해제를 뒤에 한다.
- `fung test`: `crates/fung-cli/src/test.rs`의 `test_file`이 `fung_vm::signals::set(Some(stop_requests(rt.stop_handle(), …)))`. 정책(`crates/fung-vm/src/signals.rs`의 `POLICY`)이 `StopHandle`(`Arc<Shared>`)을 쥐어 다음 `set`까지 런타임의 공유 부분이 산다.
- 교착 판정: `Sched::run`이 대기열이 비고 모두 주차했을 때만 `Task::judge`(`vm/deadlock.rs`)를 부른다. 도는 태스크가 하나라도 있으면 판정하지 않는다. 보내는 끝을 스스로 쥔 경우의 판정(`own_sender`)은 스택·붙잡은 값·전역의 맨 위 값만 본다. 값 깊이 훑기는 E0705의 `channel::contains`에 있다.

## 고려할 점

- 순서를 약속하면 여러 코어(M:N, 0.5.0 뒤)로 갈 때 되돌릴 수 없다. 약속하지 않으면 지금의 우연한 순서에 기대는 코드가 조용히 생긴다. 드러내려면 순서를 일부러 흔들어야 한다. Trio는 같은 바퀴의 태스크 순서를 무작위로 뒤집어 순서 의존을 드러낸다(설정으로 끌 수 있다). Go는 고루틴 순서를 약속하지 않고 경쟁 검출기를 따로 둔다.
- 늦은 시작은 흔한 선택이다(Trio `start_soon`, asyncio `create_task`, Kotlin `launch`의 기본 디스패치). 첫 차례 전에 취소된 자식이 한 줄도 돌지 않는 것은 Trio와도 같다(첫 확인 지점에서 끊김). fung은 함수 호출마다 확인하므로 사실상 첫 호출에서 끊긴다. 문제는 동작이 아니라 낡은 설명이다.
- 공정성은 정확성 문제가 아니지만, 차례 줄의 굶김이 있으면 "한 연결에 읽는 태스크 둘"이 끝나지 않을 수 있다. 줄을 넘겨주는 방식(먼저 온 쪽에 바로 넘김, `parking_lot`의 공정한 풀기)은 깨어난 쪽이 취소됐을 때 다음으로 넘기는 처리가 필요하다.
- 부분 교착 판정은 "그 태스크를 깨울 수 있는 것을 쥔 태스크가 모두 막혔는가"를 봐야 한다. 오탐(깨울 수 있는데 교착이라 함)은 프로그램을 죽이므로 절대 없어야 하고, 놓침은 지금과 같다. 판정은 값 전체를 훑어 비싸므로 드물게 돌려야 한다. Go 런타임은 전체 교착만 보고하고, 최근 판에는 GC의 도달 가능성으로 새는 고루틴을 찾는 실험 기능이 있다(판과 이름은 확인하지 못했다).

## 선택지

1(시작 순서): (가) 약속하지 않고 그대로. (나) "같은 차례에 띄운 형제는 띄운 순서로 시작"을 약속. (다) 약속하지 않고, `fung test`에서 한 바퀴의 새 태스크·깨운 태스크 순서를 씨앗으로 흔들고 실패하면 씨앗을 보인다(`FUNG_SCHED_SEED`로 다시 돌림). 추천: (다). 경쟁 상태를 시험 때 드러내고, `fung run`과 매뉴얼 펜스의 결정적 출력은 그대로다.
2(늦은 시작): (가) 동작은 그대로 두고 05·open-questions의 낡은 문장을 지금 동작(첫 차례 전에 범위가 취소되면 돌지 않음)으로 고친다. (나) 띄우자마자 첫 차례를 준다. 추천: (가). (나)는 띄우는 쪽의 차례를 빼앗아 `spawn`마다 문맥 전환이 생긴다.
3(공정성): (가) 오래된 깨움은 `Slot`에 "줄에 있음" 표시를 두어 겹친 번호를 버린다. (나) 차례 줄은 놓을 때 맨 앞 하나에 넘긴다(`busy`를 그 태스크 몫으로 남김, 그 기다림이 끝나지 않고 버려지면 다음으로). 추천: 둘 다. 먼저 굶김을 재현하는 시험을 쓴다.
4(REPL): (가) 둘째 Ctrl-C는 첫 취소 뒤 스케줄러가 적어도 한 바퀴를 돈 뒤에만 버리기로 센다(`interrupted`에 바퀴 번호). 버릴 때는 루프 등록을 먼저 해제하고 태스크를 버린다. 추천: (가).
5(`fung test`): (가) `test_file`이 끝날 때 런타임을 쥐지 않는 "파일 사이" 정책(첫 신호만 `first`에 적음)으로 바꾼다. 추천: (가).
6(가려지는 교착): (가) 그대로 두고 05에 Go와 같은 한계로 적는다. (나) 부분 교착 판정: 시간 제한 없이 주차한 태스크가 있고 그 집합이 일정 시간(예: 1초) 바뀌지 않으면, 막히지 않은 태스크·전역·시간 제한이 있는 태스크가 깨울 끝(보내는 끝, 받는 끝, 태스크 핸들, 범위)을 쥐는지 값 깊이로 훑어 고정점을 구하고, 남은 것이 있으면 E0702로 보고한다. 추천: (나)를 시험 먼저 설계해 보고, 오탐 없는 규칙과 비용 측정이 나오면 넣는다. 나오지 않으면 (가)로 닫고 이유를 남긴다.
