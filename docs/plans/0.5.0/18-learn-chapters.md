# L18. 배우기 8~14장의 장 끝, 4장의 이른 람다·재귀

상태: 열림 (2026-10-26). 0.5.0 전에 고친다. 목록: [README](README.md). 작은 문제 S15에서 옮겼다: 글을 새로 쓰는 일이라 한 세션의 잔손질이 아니다.

## 문제

**장 끝의 구성이 둘로 갈린다.** 배우기 1~7장은 모두 `짚고 넘어가기 {#notes}` → `해 보기 {#exercises}` → `정리 {#summary}`로 끝난다.
8~14장은 본문 절 뒤에 바로 `정리`가 온다. 짚고 넘어가기(`:::box learn`·`:::box mistake`·`:::box other`)는 본문 사이에 흩어져 있거나 없고, 연습 문제는 없다.

```
$ for f in manual/learn/*.md; do grep '^## ' $f | tail -3 | tr '\n' '|'; echo; done
01~07: … | ## 짚고 넘어가기 {#notes} | ## 해 보기 {#exercises} | ## 정리 {#summary}
08:    ## 구조 분해 대입 | ## 태그: 나만의 값 종류 | ## 정리
…
14:    ## fung fmt: 모양 맞추기 | ## fung check: 실행하기 전에 검사 | ## 정리
```

독자는 앞의 일곱 장에서 "장 끝에서 손으로 해 본다"를 배웠는데, 정작 패턴·에러·모듈·파일·동시성·HTTP·테스트처럼 손에 익혀야 할 장에서 그 단계가 빠진다.
설계(`docs/superpowers/specs/2026-10-20-manual-structure-design.md`)와 작성 지침(`docs/plans/2026-10-20-manual-2-content.md`)은 장마다 같은 끝 구성을 요구한다.

**4장의 이른 람다·재귀.** 4장(`manual/learn/04-conditions-and-loops.md`)은 `map`·`filter`·`fold`에서 람다(`x => x * 2`)를 쓰고, `while`이 없는 대신 꼬리 재귀를 소개한다.
함수 정의(`fn`)와 람다는 5장에서 배운다. 그래서 4장의 독자는 아직 배우지 않은 문법 두 가지(람다, 자기를 부르는 함수)를 따라 써야 한다.

## 지금 동작과 원인

글의 문제다. 1~7장은 매뉴얼 2단계(배우기)의 앞 절반으로 먼저 쓰였고, 8~14장은 나중에 쓰며 끝 구성을 맞추지 않았다(open-questions "매뉴얼 후속", 2026-10-20 최종 검토).
4장은 "반복"을 한 장에 모으려다 람다와 재귀를 앞당겼다.

## 고려할 점

- 연습 문제는 매뉴얼 생성기가 검사한다: `fung run` 펜스는 두 번 돌려 출력이 같아야 하고, 실패하는 예는 `exit=`·`error=`를 적는다. 답을 보여 주는 방식은 1~7장의 "해 보기"를 그대로 따른다.
- 네트워크(13장)와 동시성(12장)의 연습은 생성할 때 돌 수 있어야 한다: 외부 호스트 대신 같은 프로그램 안의 `http.serve`, `sleep` 대신 상태로 순서를 정하는 예.
- 4장을 고치는 길은 둘이다. 람다를 쓰는 부분을 5장 뒤로 미루면 4장에서 `map`·`filter`가 빠지고, 람다를 4장에서 "짧은 함수 표기"로 한 단락 먼저 소개하면 5장과 겹친다.

## 선택지

장 끝: (가) 8~14장에 `짚고 넘어가기`·`해 보기`를 1~7장과 같은 모양으로 더한다. 흩어진 박스는 `짚고 넘어가기`로 모은다. (나) 1~7장의 끝을 줄여 8~14장에 맞춘다.
추천: (가). 손으로 해 보는 단계가 빠진 쪽이 문제이고, 뒤 장일수록 연습이 더 필요하다.

4장: (가) 람다를 4장의 `map` 앞에서 "이름 없는 작은 함수"로 한 단락 소개하고(자세한 것은 5장), 꼬리 재귀는 5장의 함수 뒤로 옮긴다. (나) 람다를 쓰는 절 전체를 5장 뒤로 옮긴다.
추천: (가). `map`·`filter`는 `for` 바로 다음에 보여 줄 가치가 크고, 람다는 `x => …` 모양 하나만 알면 된다. 재귀는 함수를 알아야 하므로 5장이 맞다.

## 정할 것

1. 8~14장의 연습 문제 수: 1~7장처럼 장마다 3~4개(추천).
2. 꼬리 재귀를 5장으로 옮길 때 4장의 "`while`이 없다" 설명을 남길지: 남기고 "5장에서 대신 쓰는 법을 본다"로 넘긴다(추천).

## 할 일

1. 1~7장의 `짚고 넘어가기`·`해 보기` 모양(박스 종류, 연습 문제와 답의 형식)을 정리해 작성 지침(`docs/plans/2026-10-20-manual-2-content.md`)에 적는다.
2. 8~14장마다: 흩어진 박스를 `짚고 넘어가기`로 모으고, 연습 문제 3~4개를 쓴다. 생성기의 검사를 통과하게(`FUNG_UPDATE_MANUAL=1 cargo test -p fung-cli --test manual_build`).
3. 4장: 람다 소개 한 단락, 꼬리 재귀 절을 5장으로. 장 사이 링크와 각 장의 "이 장에서 배우는 것" 목록을 고친다.
4. 바뀐 예제 수만큼 `FMT_STDIN_CASES`(`tools_expected.rs`)를 고친다.

## 끝의 기준

- 배우기 14장 모두 `## 짚고 넘어가기 {#notes}` → `## 해 보기 {#exercises}` → `## 정리 {#summary}`로 끝난다(위 `grep`으로 확인).
- 4장은 5장에서 처음 나오는 문법(`fn` 정의, 재귀)을 쓰지 않고, 람다는 소개한 뒤에 쓴다.
- 매뉴얼 생성과 검사가 통과한다.
