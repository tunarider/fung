# Rust 이식 2단계: 값과 VM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** fung의 값·영속 컬렉션·VM·내장 함수를 Rust로 옮겨, 동시성과 네이티브 모듈을 쓰지 않는 프로그램의 `fung run` 결과(표준 출력·표준 에러·종료 코드)가 Go 구현과 바이트 단위로 같게 한다.

**Architecture:** 새 크레이트 `crates/fung-vm`(값, 영속 컬렉션, VM, 내장 함수)이 `fung-front`의 `Proto`를 받아 실행한다. `fung-cli`에 `run`/파일/`-e`를 더하고, Rust 테스트가 Go 바이너리와 실행 결과를 직접 비교한다. 명령 체계·에러 번호·출력은 Go와 같고 각 모듈 안은 Rust 관용으로 쓴다.

**Tech Stack:** Rust 1.94 (edition 2024, 크레이트 0개), Go 1.27 (정답지).

**Spec:** `docs/superpowers/specs/2026-10-15-rust-vm-design.md`

## Global Constraints

- Rust 크레이트 의존성 0개(`fung-vm`·`fung-cli`의 `[dependencies]`는 워크스페이스 경로 의존만).
- `rust-toolchain.toml`의 Rust 1.94, 모든 크레이트 `edition = "2024"`.
- 커밋 전: `gofmt -l .`(빈 출력), `go vet ./...`, `go test ./...`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`. Task 11 이후에는 `cargo test --release`도.
- 코드·주석·에러 문구·커밋 메시지는 영어, 학습 노트는 한국어. Conventional Commits. 커밋 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- git 작성자는 저장소 설정 그대로. 다른 이메일 금지.
- 비교 대상 출력은 Go와 바이트 단위로 같다. 에러 번호와 문구는 `spec/errors.txt`(Go가 생성)에서 온다. 새 번호를 만들지 않는다.
- 동시성 내장 함수(`spawn` `await` `cancel` `channel` `send` `recv` `close` `sleep` `atom` `swap` `deref`, `_native.conc.spawn_awaited`)는 부르면 `E0805 not supported yet: <name>`.
- 사용자 프로그램이 Rust 패닉을 일으키면 안 된다. 실수로 생긴 패닉은 스레드 경계에서 E0801로 보고한다.
- Go 구현(`cmd/`, `internal/`, `extras/`)은 수정하지 않는다.

## 이식 규칙 (모든 작업에 적용)

- Go 소스가 참조 구현이다. 각 작업은 대응하는 Go 파일을 함수 단위로 읽고 같은 동작을 Rust로 쓴다(줄 단위 번역 금지).
- 출력 순서가 드러나는 곳에서 `HashMap` 순회 금지.
- 작업에 이름으로 나열한 Go 테스트는 **모두** Rust로 옮긴다(케이스 표까지). Go 테스트가 Go 전용(고루틴, 메모리 할당 수, HTTP, 파일 핸들, 시각)이면 옮기지 않고 보고서에 이유를 적는다.
- 깊은 입력을 다루는 테스트는 `std::thread::Builder::new().stack_size(4 << 30)` 스레드에서 돈다.
- 정확한 기대 출력은 Go 바이너리로 만든다: `go build -o /tmp/fung-go ./cmd/fung` 후 `/tmp/fung-go -e '<code>'`.
- 2단계 범위 밖(동시성 실행, `fs`·`json`·`time`·`regex`·`path`·`http`·`cli` 모듈, `Time`·파일 핸들 값, REPL·`check`·`test`·`fmt`)은 만들지 않는다.

## Review Focus

1. 백만 개짜리 리스트·맵과 깊은 영속 벡터의 마지막 참조가 사라질 때 재귀 해제로 스택이 넘치지 않아야 한다 → Task 3, Task 4.
2. 공유된 컬렉션에 덧붙이거나 `put`해도 원본이 바뀌지 않아야 한다(`make_mut`가 공유 값을 고치면 안 됨) → Task 3, Task 4.
3. 람다를 부르는 내장 함수 안의 런타임 에러가 Go와 같은 호출 경로로 보고되어야 한다 → Task 5, Task 8.
4. `at_exit` 핸들러 안의 에러·`exit`·패닉이 Go와 같은 순서와 종료 코드로 처리되어야 한다 → Task 5, Task 10.
5. 동시성 내장 함수를 부르면 패닉이 아니라 E0805가 위치와 함께 나와야 한다 → Task 9.
