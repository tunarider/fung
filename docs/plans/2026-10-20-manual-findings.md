# 매뉴얼을 쓰며 찾은 언어·도구의 문제

2026-10-20부터. 매뉴얼 2~5단계(`docs/plans/2026-10-20-manual-2-content.md`)를 쓰면서 작성자들이 실제 동작을 돌려 보다가 찾은 것을 모은다.
매뉴얼에는 **지금의 실제 동작**을 적었다. 여기 있는 것을 고치면 매뉴얼의 해당 항목도 같이 고친다(생성기가 예제 출력의 변화를 잡아 준다).

항목마다: 재현, 지금 동작, 문제, 고치는 길(결정이 필요하면 선택지와 추천). 상태는 `[ ]` 열림, `[x]` 닫힘.

## 1. 고칠 것 (버그)

- [x] **F-1. `get`에 맵이 아닌 값을 주면 prelude 내부 위치가 드러난다** (에러 카탈로그 작성 중)
  - 닫음(2026-10-24): `get`을 Rust 내장 함수로 옮겼다(`put`·`remove`와 같은 자리, 구현 언어 지침). 맵이 아니면 E0506 `cannot get from list`, 호출 경로에 prelude가 보이지 않는다. 번호는 E0403이 아니라 E0506: E0506이 "내장 함수가 그 타입으로는 할 수 없는 일"의 문서화된 번호이고(`put`·`keys`·`first("abc")`), E0403은 매개변수에 적은 타입 표기의 번호다.
  - 재현: `print(get([1], 0))`
  - 지금: `error[E0803]: get expects a map, got 'list`, 호출 경로가 `extras/prelude.fung:105 get`을 가리킨다.
  - 문제: 인자 타입이 틀린 것은 코드 오류이고, 내장 함수의 다른 타입 오류는 E0403(부른 자리)이다. `get`은 fung으로 쓴 함수라 `fail`(E0803)로 끝나고, 사용자가 볼 일이 없는 `extras/prelude.fung`의 줄이 나온다. 기조 "구현을 밖으로 드러내지 않는다"와 어긋난다.
  - 고치는 길: fung으로 쓴 prelude 함수의 인자 검사를 E0403과 같은 모양(부른 자리를 가리킴)으로 낸다. `get` 말고도 `extras/prelude.fung`의 `fail`을 쓰는 검사를 같이 훑는다.

- [x] **F-3. 슬라이스 끝이 길이를 넘으면 "index … out of range"(E0507)다** (에러 카탈로그 작성 중)
  - 닫음(2026-10-24): 번호는 E0507 그대로, 문구가 `slice end 5 is out of range (length 2)`처럼 시작·끝을 말한다.

- [x] **F-4. `take`·`drop`에 문자열을 주면 "cannot map over str"(E0506)이다** (배우기 1~7장 작성 중)
  - 닫음(2026-10-24): (나). `take`·`drop`이 문자열을 글자 단위로 자른다. 다른 타입(`take(1, 2)`)의 에러는 아직 `cannot map over int`로 내부 `map`이 보인다(남은 일).
  - 재현: `print(take("abc", 2))` → `error[E0506]: cannot map over str`
  - 문제: 사용자는 `map`을 부르지 않았는데 `map`이 나온다(fung으로 쓴 `take`의 내부가 드러남, F-1과 같은 종류). 또 슬라이스 절은 "있는 만큼만 원하면 `take`·`drop`"이라고 리스트와 문자열을 함께 말했다(매뉴얼은 리스트로 고쳤다).
  - 결정: (가) `take`·`drop`은 리스트 전용으로 두고 문자열이면 E0403(`expected list, got str`)을 낸다. (나) 문자열도 받아 글자 단위로 자른다. 추천: (나) 슬라이스가 문자열에도 되는 것과 맞고, "있는 만큼만 자르기"는 문자열에서도 흔하다. 어느 쪽이든 내부 `map` 이름이 나오지 않게 한다.

- [x] **F-10. `timeout`의 `Err`에는 `message`가 없다** (예제 모음 작성 중)
  - 닫음(2026-10-24): 시간 초과·취소·닫힌 채널의 `Err`에 `message`(`timed out after 2s`·`cancelled`·`channel closed`). `==`로 견주던 코드는 깨진다(CHANGELOG 호환 깨짐).
  - 지금: prelude `timeout`은 `Err({kind: 'timeout})`, `http.get`의 시간 초과는 `message`가 있다. 실패를 `e.message`로 찍는 흔한 코드(승인한 시안의 ssh 예도)가 시간 초과에서 E0508로 멈춘다.
  - 고치는 길: 모든 `Err` 맵이 `kind`와 `message`를 갖도록 맞춘다(`timeout`은 `message: "timed out after 2s"` 꼴). 다른 `Err({kind})`만 돌려주는 곳(취소 `{kind: 'cancelled}` 등)도 함께 훑는다.

- [ ] **F-12. `fs.stat`에 수정 시각이 없다** (예제 모음 작성 중)

## 2. 결정이 필요한 것

- [x] **D-1. E0508 도움말이 `??`를 권하지만, 필드 접근에는 통하지 않는다** (에러 카탈로그 작성 중)
  - 닫음(2026-10-24): (가). 도움말은 `use get(m, key, default) for a default`.
  - 재현: `cfg = {host: "db"}` / `print(cfg.port ?? 5432)` → 그대로 `error[E0508]: key 'port' not found`(도움말 `use get(m, key, default) or ?? for a default`).
  - 지금: `??`는 왼쪽이 `nil`이거나 `Err`일 때 오른쪽을 준다. `cfg.port`는 값을 내기 전에 런타임 에러로 멈추므로 `??`까지 가지 않는다. 통하는 것은 `get(cfg, "port") ?? 5432`, `get(cfg, "port", 5432)`.
  - 선택지: (가) 도움말을 `use get(m, key, default)`로 고친다(`??` 언급 삭제). (나) `m.k ?? d`를 특별히 "없으면 d"로 만든다(없는 키 읽기가 에러라는 엄격함 규칙에 예외가 생긴다).
  - 추천: (가). 기조 "예외 조항을 줄인다"와 "없는 키를 nil로 읽기는 에러"를 지킨다.
- [ ] **D-2. 실제 도움말과 카탈로그(`spec/errors.txt`)의 도움말이 자주 다르다** (에러 카탈로그 작성 중)
  - 예: E0204는 "비슷한 이름"이나 최상위 변수 안내를 붙이고, E0206은 실제 이름을 넣고, E0308은 카탈로그에 없는 도움말(`import it under another name`)을 내고, E0702는 상황마다 다르거나 없다.
  - 문제: 카탈로그는 "번호마다 무엇을 보여 주는가"의 기준인데, 실제와 달라 매뉴얼의 자동 도움말 줄이 실제 출력과 어긋난다.
  - 선택지: (가) 카탈로그의 help 칸을 "기본 도움말"로 보고 상황별 도움말은 따로 둔다(지금 상태를 문서화). (나) 상황별 도움말도 카탈로그에 템플릿으로 올린다.
  - 추천: (가)에 더해, 카탈로그에 help가 비어 있는데 실제로는 늘 같은 도움말을 내는 것(E0308 등)은 카탈로그에 올린다.
- [x] **D-4. 뒤에 붙는 `?`·`!`가 `|>`보다 세게 묶인다** (prelude 레퍼런스 작성 중)
  - 닫음(2026-10-24): (가). E0229 `` `?` on the right of `|>` applies to the call, not to the pipe ``, 도움말은 괄호로 감싸기.
  - 재현: `xs |> try_map(f)?`는 `xs |> (try_map(f)?)`로 읽혀 `try_map`이 인자 하나로 불리고 E0407이 난다. 고쳐 쓴 꼴: `(xs |> try_map(f))?`.
  - 문제: 파이프의 끝에서 결과값을 꺼내는 것은 아주 흔한 모양인데, 에러가 원인(우선순위)을 말하지 않는다.
  - 선택지: (가) 우선순위는 그대로, 파이프 오른쪽이 `f(…)?`·`f(…)!` 꼴이면 컴파일 에러로 "괄호로 묶으라"고 알린다(E0227처럼 파이프 전용 진단). (나) 파이프 오른쪽 끝의 `?`·`!`는 파이프 전체에 걸리게 문법을 바꾼다.
  - 추천: (가). 우선순위 규칙에 예외를 만들지 않고, 흔한 실수를 정확한 진단으로 잡는다.
- [ ] **D-3. E08xx(한도와 환경) 중 일부는 컴파일 단계에서 나서 종료 코드가 2다** (에러 카탈로그 작성 중)
  - E0802(괄호 중첩 한도), 인자·매개변수 개수 한도(E0806, 4095)는 실행 전에 나므로 2로 끝난다. 매뉴얼은 "E04xx 이후는 실행 중"이라는 큰 나눔을 쓰는데 정확하지 않다.
  - 선택지: (가) 지금대로, 매뉴얼에 예외를 적는다(적었다). (나) 컴파일 단계 한도를 E01xx·E04xx 쪽 번호로 옮긴다(번호는 한 번 붙이면 바꾸지 않는다는 규칙과 충돌).
  - 추천: (가).

## 3. 기록만 (매뉴얼에 반영, 고칠 필요 없음)

- (2026-10-24 처리: 09의 명령 인코딩·되돌리기·노드 모양 검사, 06의 `fs.close`와 `Err` 모양, 05의 형제 되감기 순서를 코드에 맞췄다. M2 노트는 기록이라 두었다.) 설계 문서·노트가 지금 코드와 다른 곳(VM 1~8장 작성 중, 매뉴얼은 코드대로 씀): `09-implementation-plan.md`의 "피연산자가 둘이면 다음 단어"(실제로는 24비트에 둘을 나눠 담고 두 단어 명령은 없다, 명령 53가지), "되돌리기 세 곳"(실제로는 `try_destructure`·`arm_head` 둘, 람다는 `lambda_params_ahead`로 앞질러 봄; 매뉴얼 부록도 고쳤다), "노드 모양 검사는 desugar"(실제로는 모르는 머리 단어의 E0801뿐), "문법 에러 뒤 다시 맞춰 읽기"(지금은 첫 에러에서 멈춤), M2 노트의 "Levenshtein 2 이하"(실제로는 길이별 0·1·2, OSA 거리). 부록의 "이름은 첫 글자로 예약어까지 가른다"도 고쳤다. 설계 문서를 코드에 맞출지, 계획으로 남길지 정리가 필요하다.
- 모듈 레퍼런스 작성 중 확인한 세부 동작(매뉴얼에 반영): `fs.mkdir`의 중간이 파일이면 `'io`, 읽기 핸들에 쓰면 `'invalid`, `fs.close` 두 번째는 `Err('closed)`(06 설계 문서는 `Ok(nil)`만 적음 → 문서 갱신 필요), `fs.glob`의 `*`는 숨은 파일에도 맞고 `**`는 `*`와 같다, `json.stringify(indent: 0)`은 한 줄, `time.parse`는 빠진 날짜 필드를 0000-01-01로, `time.unix`는 초 밑을 내림, `exit(300)`은 44, `exit(-1)`은 255.
- prelude 레퍼런스 작성 중 고친 옛 서술(매뉴얼 반영, 설계 문서도 확인 필요): `parse_float`·`parse_dur`의 실패는 `Err('parse)`가 아니라 `Err({kind: 'parse, message})`, 취소는 `Err('cancelled)`가 아니라 `Err({kind: 'cancelled})`, 1억 원소 범위 한도(E0806)는 전체 결과를 만드는 함수(`map`·`sort`·`reverse`·`unique` 등)에만 걸린다.
- 예제 모음 작성 중 확인한 세부 동작(매뉴얼 반영): `fs.glob("./*.x")`·`fs.walk(".")`의 결과에는 앞의 `./`가 없다, `time.format`은 UTC에서 `Z`, `parse_float("NaN")`은 `Err`, `regex.replace`의 바꿀 문자열에서 `$5`는 그룹 참조라 값에 `$`가 있으면 비어 나올 수 있다(이스케이프 방법 확인 필요), `cli.parse`는 같은 옵션을 여러 번 주면 마지막 값만 남긴다, 아래쪽 `head`가 파이프를 닫으면 141로 조용히 끝난다.
- VM 9~17장 작성 중 고친 것: 부록 `internals.md`의 세 서술(반환 타입이 있는 함수의 자기 꼬리 호출은 `TAILCALL`로 남는다, `Runtime::hold`는 없다(테스트 블록·REPL 입력마다 따로 실행), REPL 전역 표는 비어 시작한다)과 낡은 코드 주석 넷(`vm/task.rs`의 "운영체제 스레드", `vm/offload.rs`의 "세 가지 일", `vm/sched.rs`의 "조건 변수에서 잔다", `repl/mod.rs`·`m6_tests.rs`의 `Runtime::hold`). `docs/notes/R5-tools.md`(기록)에도 `Runtime::hold`가 남아 있다. 취소된 형제 태스크가 되감기는 순서는 정해져 있지 않다(취소 노드의 자식이 `HashMap`) — 의도라면 05 설계 문서에 적고, 아니면 생성 순서로.
- `fung test`는 파일의 최상위 코드를 먼저 실행한다(08 설계 문서에 있음, 매뉴얼 배우기 14장에 반영).

- 언어 명세의 잘못된 예 둘을 고쳤다(배우기 1~7장 작성 중): 모르는 이스케이프의 예 `"C:\new"`는 `\n`이 줄바꿈이라 에러가 아니다(→ `"C:\data"`, E0103). 슬라이스 절의 `take`·`drop` 안내는 리스트에만 맞다(F-4).
- 원고 문법: `**…**` 안에 코드나 링크가 들어가면 굵게가 적용되지 않던 것을 생성기에서 고쳤다.

- E0307(진입 파일을 import)은 다른 모듈이 진입 파일을 가져올 때만 난다. 파일이 자기 자신을 가져오면 순환(E0302)이 먼저 잡힌다.
- 예상과 다른 번호(규칙대로이고 문제 아님): `30sec`는 E0102(숫자 모양), `1.2.3`은 E0112(`1.2` 뒤의 필드 접근), `len(5)`는 E0506, `not 1`은 E0505, 모듈 이름에 대입은 E0308.
- `args`는 함수가 아니라 값이다(`args()`는 E0401).
- E0703·E0704·W0104는 쓰지 않는 번호, E0805는 지금 아무것도 내지 않는다(번호는 재사용하지 않는다).
