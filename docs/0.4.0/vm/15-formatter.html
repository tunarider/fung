포맷터

fung fmt는 트리에서 코드를 새로 찍지 않는다. 렉서의 토큰과 주석을 줄마다 다시 배치하고, 결과를 다시 렉싱해 토큰이 입력과 같을 때만 쓴다.

  1. 소스
  2. 토큰
  3. 트리
  4. 코어
  5. 바이트코드
  6. 실행
이 장에서 배울 것
  • 포맷터가 하는 일과 "옵션 없는 단일 스타일"의 뜻
  • 포맷터를 만드는 두 길: 토큰 재배치와 트리 다시 찍기, 그리고 주석이라는 난제
  • 줄 시작마다 "무엇이 열려 있나"를 보는 들여쓰기 상태 기계
  • 토큰 쌍마다 공백을 정하는 표, 그리고 match와 주석의 정렬
  • 포맷터 버그가 코드를 바꾸지 못하게 하는 안전장치

5부는 언어 둘레의 도구다. 첫 도구는 포맷터다. 포맷터는 컴파일러의 앞단(2부)을 다시 쓰는 도구라서, 단계 띠의 "토큰"에 서 있다.

포맷터는 무엇을 하나

포맷터(formatter)는 코드의 뜻은 그대로 두고 모양만 한 가지 스타일로 고친다. 들여쓰기 폭, 연산자 둘레의 공백, 빈 줄, 정렬 같은 것이다. 모양을 기계가 정하면 사람은 모양을 두고 다투지 않아도 되고, 차이(diff)에는 뜻이 바뀐 줄만 남는다.

fung fmt는 설정이 없는 단일 스타일이다(설계 08). 바로잡는 것은 넷이다.

  • 공백: 이항 연산자·=>·= 양옆 한 칸, ,·: 뒤 한 칸, 괄호 안쪽과 호출 괄호 앞은 붙인다.
  • 들여쓰기: 2칸. 깊이는 열린 블록(: … ;;)과 열린 괄호의 수로 정한다.
  • 빈 줄: 연속은 하나로, 블록 시작 직후와 ;; 직전과 파일 끝의 빈 줄은 지운다.
  • 정렬: 연속한 match 절의 =>와 꼬리 주석의 열을 맞춘다.

그리고 하나를 하지 않는다. 줄바꿈은 사용자가 쓴 대로 둔다. 한 줄로 쓴 match는 한 줄로 남는다.

fn status(code)=match code:
 200=>"ok" # fine
 404 =>"missing"   # not there
     _=>"error"
;;
servers=[ "web1","web2" ]
each(servers,fn(h):
print( h,status(200) )
;;)

fung fmt를 지나면 이렇게 된다. 결과는 fung 코드이므로 그대로 실행된다.

fn status(code) = match code:
  200 => "ok"       # fine
  404 => "missing"  # not there
  _   => "error"
;;
servers = ["web1", "web2"]
each(servers, fn(h):
  print(h, status(200))
;;)
web1 ok
web2 ok

두 길

포맷터를 만드는 길은 크게 둘이다.

  • 트리 다시 찍기. 코드를 파싱해 트리(4장)를 만들고, 트리에서 코드를 새로 찍는다. 줄 너비(예: 80칸)를 넘으면 어디서 줄을 바꿀지 알고리즘이 고른다. 원래 줄바꿈은 대부분 무시된다.
  • 토큰 재배치. 렉서의 토큰 열(3장)을 받아 토큰 사이의 공백과 줄 앞의 들여쓰기만 다시 쓴다. 줄바꿈은 원래대로 둔다.

트리 다시 찍기의 가장 큰 난제는 주석이다. 주석은 실행에 필요 없으므로 보통 트리에 들어가지 않는다. fung의 겉 트리도 그렇다. 위 예의 겉 트리를 보면 # fine 같은 주석이 흔적도 없다.

fn status(code)=match code:
 200=>"ok" # fine
 404 =>"missing"   # not there
     _=>"error"
;;
servers=[ "web1","web2" ]
each(servers,fn(h):
print( h,status(200) )
;;)
$ fung dump ast example.fung
(program (fn status(code) (block (match code (arm (plit 200) (nil) (block "ok")) (arm (plit 404) (nil) (block "missing")) (arm (pwild) (nil) (block "error"))))) (assign servers (list "web1" "web2")) (call each servers (fn (h) (block (call print h (call status 200))))))

트리에서 다시 찍으려면 주석을 어느 노드에 붙일지("이 주석은 앞의 식에 속하나, 뒤의 문장에 속하나") 규칙을 정해야 하는데, 그 규칙은 어떤 언어에서도 깔끔하지 않다.

다른 언어는
  • Prettier(JavaScript 등)는 트리를 다시 찍는 대표다. 줄 너비에 맞춰 접는 알고리즘은 Philip Wadler의 "A prettier printer"(2003)에서 왔다.
  • Black(Python)도 트리를 다시 찍는다. 그리고 포맷한 결과를 다시 파싱해 트리가 원래와 같은지 확인한 뒤에야 쓴다. fung의 안전장치와 같은 생각이다.
  • rustfmt도 트리 기반이고 줄 너비로 접는다. clang-format은 토큰 열을 바탕으로 줄을 다시 나누는 쪽에 가깝다.
fung의 선택: 토큰 재배치

이유는 셋이다(노트 M9).

  • 주석. 렉서는 처음부터 주석을 토큰 흐름에서 빼되 위치와 함께 별도 목록(trivia)에 보관한다(3장, 설계 08). 그래서 주석은 줄 번호만으로 원래 줄에 붙일 수 있다.
  • 검증. 출력을 다시 렉싱해 토큰 열(줄바꿈 제외)이 입력과 같은지 기계적으로 확인할 수 있다. 다르면 쓰지 않는다. 그래서 "포맷터가 코드를 망가뜨리는" 종류의 버그는 원천적으로 사용자에게 닿지 않는다.
  • 의도 존중. 한 줄로 쓴 match는 그렇게 두고 싶은 것이다. fung은 들여쓰기에 의미가 없는 문법이라(블록은 : … ;;), 들여쓰기만 바로잡아도 효과의 대부분을 얻는다.

줄로 나누기

포맷터(crates/fung-front/src/format.rs의 format_bytes)는 이 순서로 일한다.

  1. 렉싱. 렉서로 토큰과 주석을 얻는다. 포맷터는 토큰마다 종류, 줄 번호, 원문에서의 바이트 위치만 본다(Tok). 문자열·숫자·기간은 토큰의 원문 바이트를 그대로 쓴다. 그래서 리터럴은 절대 바뀌지 않는다.
  2. 파싱. 파서를 한 번 돌려 문법이 맞는지만 본다. 구문 에러가 있으면 아무것도 고치지 않고 에러를 낸다(종료 코드 2).
  3. 줄 나누기(format/lines.rs의 split_lines). 토큰을 원래 줄마다 묶는다. 줄 하나(Line)는 토큰들, 꼬리 주석, 그리고 뒤에서 정할 들여쓰기와 정렬할 =>의 자리를 갖는다.
  4. 들여쓰기(format/layout.rs의 layout), 빈 줄 정리(tidy_blank), 공백과 정렬을 적용해 출력(format/spacing.rs의 gap, format/align.rs의 align).
  5. 검증(same). 아래 "안전장치" 절.

들여쓰기 상태 기계

줄 시작마다 "지금 무엇이 열려 있나"를 보고 들여쓰기를 정한다. 핵심 자료구조는 열린 것들의 스택이다. 항목은 블록(fn·if·else·match·for·test 뒤의 : … ;;)이거나 괄호((·[·{)이고, 각 항목은 그것을 연 줄의 들여쓰기(base)를 기억한다(Opener).

  • 보통 줄: 가장 안쪽 항목의 base + 1.
  • 닫는 토큰(;;·)·]·})으로 시작하는 줄: 그 항목의 base.

이 두 규칙만으로 each(servers, fn(h): … ;;)가 맞는다. fn(h): 블록과 each( 괄호가 같은 줄에서 열렸으므로 둘의 base가 같다. 본문은 그 base + 1이고, ;;)는 그 base로 돌아간다. 깊이를 "열린 개수"로 세면 본문이 두 칸 더 들어가 버린다. 괄호와 블록을 같은 스택에 두되 "연 줄의 들여쓰기"를 기억하는 것이 이 문제의 열쇠였다(노트 M9).

몇 가지 까다로운 판단이 더 있다. 모두 파서가 하는 판단을 토큰 수준에서 흉내 낸 것이다.

  • 블록은 어디서 열리나. :은 맵 키, 이름 인자, 타입 표기에도 쓰인다. 그래서 :을 볼 때마다 블록을 열지 않는다. 블록 키워드를 보면 "같은 괄호 깊이의 다음 :을 기다린다"고 적어 둔다(Pending). fn f(x: int) -> int:에서 x: int의 :은 괄호 안이라 걸리지 않고, -> 뒤의 :이 블록을 연다.
  • else의 두 뜻. if 사슬의 else인가, c then a else b의 일부인가. 짝이 없는 then을 괄호마다 세어 두고(thens), 짝이 있으면 식이 이어지는 것, 없으면 if 사슬로 본다.
  • match 절. 괄호 밖에 =>가 있으면 절이다. xs |> map(x => x)의 =>는 괄호 안이라 절이 아니다.
  • 이어지는 줄. 다음 줄이 |>·.·??·and·or·then·else로 시작하거나, 앞 줄이 식을 끝낼 수 없는 토큰(이항 연산자, =, =>)으로 끝났으면 그 문장보다 한 단계 더 들인다. 언어의 줄 이어짐 규칙과 같다.

공백 표

토큰 사이의 공백은 인접한 토큰 쌍마다 0칸인지 1칸인지 정하는 함수 하나(gap)가 정한다. 까다로운 것은 같은 토큰이 자리에 따라 다르게 쓰이는 경우다.

  • 접두 -. a - b와 -x는 토큰이 같다. 앞 토큰이 연산자, 여는 괄호, ,, =>, =, 예약어이거나 줄 처음이면 부호다(prefix_context).
  • 호출 괄호. f (x)는 f(x)로 붙인다. 앞 토큰이 이름·태그·)·]일 때만이다(is_callee). 문자열은 부를 수 없으므로 import "./x" (a)의 공백은 지킨다. 저장소 전체를 포맷해 보다가 잡은 버그다.
  • ;;). ;; 뒤에 닫는 괄호가 오면 붙인다.

빈 줄과 정렬

빈 줄은 연속을 하나로 줄이고, 블록을 여는 줄 바로 뒤, ;; 바로 앞, 파일의 처음과 끝에서 지운다(tidy_blank). 파일 끝은 줄바꿈 하나다.

정렬은 두 가지를 같은 장치 하나로 한다(align). 연속한 줄 묶음에서 최대 너비를 재고 거기에 맞춰 채운다. match 절의 =>는 패턴의 최대 너비 + 1칸에, 꼬리 주석은 코드의 최대 너비 + 2칸에 맞춘다. 빈 줄, 주석만 있는 줄, 들여쓰기가 다른 줄이 묶음을 끊는다. 다만 절 본문이 다음 줄로 넘어가 더 깊이 들어간 줄은 => 묶음을 끊지 않는다. =>를 먼저, 주석을 나중에 맞춘다. 반대로 하면 =>를 채운 뒤 주석 열이 틀어진다.

너비는 글자 수가 아니라 화면의 칸 수다(유니코드 UAX #11). 한글·한자 같은 넓은 글자는 2칸, 결합 문자는 0칸이다(표는 spec/unicode.txt). 그래서 한글이 섞인 줄도 열이 맞는다.

fn label(code) = match code:
  200 => "정상"     # 한글은 두 칸
  503 => "점검 중"  # 화면 칸으로 맞춘다
  _   => "알 수 없음"
;;
fn double(x) = x * 2
total = double(21)

print(label(200), total)

안전장치

포맷터가 만든 출력은 쓰기 전에 다시 렉싱된다(same). 그리고 두 가지를 비교한다.

  • 줄바꿈을 뺀 토큰 열의 원문이 입력과 같은가.
  • 주석의 수와 내용(끝 공백 제외)이 같은가.

하나라도 다르면 출력을 쓰지 않고 E0801 내부 오류(formatter changed the code of …)를 낸다. 포맷터가 바꾸는 것은 공백뿐이므로, 토큰과 주석이 같으면 코드의 뜻은 같다. 트리를 비교하는 Black보다 단순한 확인이다. 그리고 같은 입력을 두 번 포맷해도 결과가 같다(멱등).

포맷터는 바이트 단위로 일한다. 렉서는 잘못된 UTF-8 바이트를 U+FFFD로 읽지만, 포맷터는 토큰과 주석의 원래 바이트를 써 내므로 그런 바이트도 바뀌지 않는다. 파일 맨 앞의 BOM은 렉서처럼 건너뛰고 쓰지 않는다.

명령

  • fung fmt 경로…: 파일을 제자리에서 고치고 바뀐 파일 이름을 찍는다. 디렉터리는 그 아래 .fung 전부(_나 .으로 시작하는 디렉터리는 건너뛴다).
  • fung fmt --check 경로…: 고칠 파일 이름만 찍고, 있으면 종료 코드 1. CI용이다.
  • fung fmt -: 표준 입력을 받아 표준 출력에 쓴다. 편집기 연동에 쓴다.

저장소의 시험(crates/fung-cli/tests/fmt_repo.rs)이 저장소의 모든 .fung 파일이 --check를 통과하는지 지킨다. 이 매뉴얼의 실행 예제도 모두 fmt --check를 통과해야 페이지가 만들어진다.

  • crates/fung-front/src/format/lines.rs: 줄 Line, split_lines.

fn report(xs):
  each(sizes(xs), fn(n):
    print("size", n)  # one line per item
  ;;)
;;
report(["a", "bb"])
size 1
size 2

map(x => 줄은 =>로 끝나 식을 끝낼 수 없으므로 다음 줄이 한 단계 들어간다. report의 블록을 연 줄 바로 뒤의 빈 줄 둘과 ;; 바로 앞의 빈 줄은 지워진다. each(…, fn(n):는 괄호와 블록을 같은 줄에서 열었으므로 본문은 그 줄보다 한 단계, ;;)는 그 줄과 같은 깊이다. 꼬리 주석은 코드 끝에서 두 칸 뒤에 붙는다.

정리

  • fung fmt는 공백·들여쓰기·빈 줄·정렬만 바로잡고 줄바꿈은 그대로 두는, 옵션 없는 단일 스타일이다.
  • 트리를 다시 찍지 않고 렉서의 토큰과 주석을 줄 단위로 다시 배치한다. 주석을 노드에 붙이는 난제가 없고, 출력을 검증할 수 있고, 사용자의 줄바꿈을 존중한다.
  • 들여쓰기는 "열린 블록·괄호의 스택과 그것을 연 줄의 들여쓰기"로 정한다. 공백은 토큰 쌍의 표, 정렬은 연속 줄 묶음의 최대 너비(화면 칸 수)로 정한다.
  • 출력을 다시 렉싱해 토큰과 주석이 입력과 같을 때만 쓴다. 다르면 E0801로 거부한다.
