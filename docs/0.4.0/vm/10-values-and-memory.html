값과 메모리

fung의 값은 16바이트짜리 Rust 열거형 하나다. 큰 값은 참조 계수로 공유하고, 리스트와 맵은 사본이 원본과 구조를 나눠 쓰는 영속 자료구조라서 불변이어도 누적이 선형이다.

이 장에서 배울 것
  • 동적 타입 언어가 값의 종류와 내용을 함께 담는 방법(상자, 태그 붙은 공용체, NaN 박싱)
  • 메모리를 돌려받는 두 길, 가비지 컬렉터와 참조 계수의 장단점
  • fung이 참조 계수를 고를 수 있었던 이유: 불변 값에는 순환이 없다
  • 깊이 겹친 값을 재귀 없이 지우는 방법
  • 불변 리스트·맵을 통째로 복사하지 않고 "바꾸는" 영속 자료구조
  • 지역 변수의 값이 언제 놓이는가(CLEARLOCAL)

9장까지 "값을 스택에 올린다", "값을 복사한다"고 쉽게 말했다. 이 장은 그 값이 메모리에서 어떤 모양이고, 다 쓰면 누가 치우는지를 본다.

값을 담는 법

fung은 동적 타입 언어다. 변수 x에 정수가 들었는지 문자열이 들었는지는 실행해 봐야 안다. 그래서 값마다 "나는 무엇인가"(종류)와 "내 내용"(값)을 함께 들고 다녀야 한다. ADD는 두 값의 종류를 보고 정수 덧셈, 실수 덧셈, 문자열 잇기, 리스트 잇기 중 하나를 고르고, 맞지 않으면 E0501을 낸다(1 + "a").

종류와 내용을 담는 방법은 크게 셋이다.

  • 모든 값을 상자에. 값마다 힙에 작은 객체를 만들고, 그 머리에 종류를 적는다. 변수는 그 객체를 가리키는 포인터 하나다. 단순하지만 1 + 2에도 객체가 생긴다.
  • 태그 붙은 공용체(tagged union). 고정 크기의 칸 하나에 "종류 번호 + 내용"을 담는다. 작은 값(정수, 실수, 불)은 칸에 바로 들어가고, 큰 값(문자열, 리스트)만 힙의 객체를 가리킨다.
  • NaN 박싱(NaN boxing). 64비트 실수 중 "숫자가 아님"(NaN)을 나타내는 비트 패턴은 거의 쓰이지 않는다. 그 빈자리에 포인터나 작은 정수를 숨겨 넣어 값 하나를 8바이트에 담는다.
다른 언어는
  • CPython은 모든 값이 상자다. 정수 1도 참조 계수와 타입 포인터를 머리에 단 PyObject다. 그래서 -5부터 256까지의 작은 정수는 미리 만들어 두고 다시 쓴다.
  • LuaJIT와 Firefox의 SpiderMonkey는 NaN 박싱을 쓴다. Chrome의 V8은 포인터의 맨 아래 비트로 "작은 정수"(Smi)와 포인터를 가르는 포인터 태깅을 쓴다.
  • Lua 5.x(표준 구현)는 태그 붙은 공용체다. 값 하나가 내용 칸과 종류 태그로 된 16바이트 남짓이다.

fung의 값은 Rust 열거형(enum) 하나, 곧 태그 붙은 공용체다(crates/fung-vm/src/value.rs의 Value).

enum Value {
    Int(i64), Float(f64), Bool(bool), Nil, Dur(i64),   ← 칸에 바로 들어감
    Sym(Sym),                                          ← 전역 인턴 표의 번호
    Str(Rc<String>), List(Rc<List>), Map(Rc<Map>),     ← 힙의 객체를 가리킴
    Tuple(..), Tag(..), Range(..), Closure(..), Module(..), Time(..),
    Native(&'static Native),                           ← 내장 함수: 계수 없는 참조
    Task(..), Scope(..), Sender(..), Receiver(..), Atom(..),
    File(Arc<File>), Conn(Arc<Conn>), Listener(Arc<Listener>),
}
  • 크기는 16바이트다. 종류 표시 8바이트와 내용 칸 8바이트. 시험이 이 크기를 고정한다(value/tests.rs).
  • 정수·실수·불·기간은 상자 없이 칸에 바로 들어간다. x * 2는 힙을 건드리지 않는다.
  • 심볼 'ok는 프로세스 전체의 인턴 표에 한 번 등록된 이름의 번호다(value/sym.rs). 그래서 심볼 비교는 정수 비교다.
  • 내장 함수는 프로그램 내내 살아 있으므로 &'static 참조로 가리킨다. 세어야 할 것이 없다.
  • 그 밖의 큰 값은 Rc(아래)로 가리킨다. Value를 복제해도 큰 리스트는 복사되지 않는다.

9장에서 본 스택 칸은 Option<Value>였다. None이 "아직 빈 칸", Some(Value::Nil)이 fung의 nil이다. 이것도 16바이트다. Rust가 Value의 종류 표시에서 쓰지 않는 값 하나를 None으로 써서 크기를 늘리지 않기 때문이다(niche 최적화).

다 쓴 값은 누가 치우나

리스트를 만들면 힙에 메모리를 잡는다. 아무도 그 리스트를 쓰지 않게 되면 메모리를 돌려줘야 한다. 이 일을 누가, 언제 하느냐가 언어 런타임의 큰 갈림길이다.

  • 손으로. C의 malloc/free. 빠르지만 잊으면 누수, 두 번 하면 메모리 손상이다. 스크립트 언어의 사용자에게 맡길 일이 아니다.
  • 추적형 가비지 컬렉터(tracing GC). 가끔 멈추고, 전역과 스택에서 출발해 닿는 객체를 모두 표시한 뒤, 닿지 않은 것을 치운다. 객체끼리 서로 가리키는 고리(순환)도 문제없이 치운다. 대신 언제 치울지 런타임이 정하고, 치우는 동안의 멈춤이나 그것을 줄이기 위한 복잡한 장치(세대별 수집, 동시 수집)가 따른다.
  • 참조 계수(reference counting). 객체마다 "나를 가리키는 손잡이 수"를 센다. 손잡이를 복사하면 하나 올리고, 버리면 하나 내린다. 0이 되는 순간 그 자리에서 해제한다. 멈춤이 없고 해제 시점이 정확하다. 약점은 둘이다. 순환은 계수가 0이 되지 않아 치우지 못하고, 여러 스레드가 같은 계수를 고치려면 원자적 연산이 필요해 느려진다.
다른 언어는
  • JVM과 JavaScript 엔진, Lua는 추적형 GC다. JVM과 V8은 세대별 GC, Lua 5.4는 점진적·세대별 모드를 고를 수 있다.
  • CPython은 참조 계수가 기본이고, 순환을 잡으려고 추적형 순환 수집기를 하나 더 둔다. 여러 스레드가 계수를 고쳐도 안전하게 하려고 GIL(13장)을 썼다.
  • Swift는 컴파일러가 계수를 올리고 내리는 코드를 넣는 ARC다. 순환은 사용자가 weak로 끊어야 한다.
  • Erlang은 프로세스(경량 태스크)마다 작은 힙을 따로 두고 따로 수집한다. 프로세스 사이로 보내는 메시지는 복사한다.
fung의 선택: 원자적이지 않은 참조 계수 Rc
  • Rust에는 가비지 컬렉터가 없다. 직접 만들지 않는다면 남는 길은 참조 계수다(노트 R2).
  • fung의 값은 불변이다. 값을 만들 때 그 값이 가리킬 수 있는 것은 이미 있는 값뿐이다. 그래서 값끼리는 고리를 만들 수 없고, 참조 계수만으로 회수가 완전하다(부록 내부 구조). "순환을 회수하는 GC"는 동시성 v2 설계에서 일부러 목표 밖에 두었다.
  • 계수는 원자적이지 않은 Rc다. fung 값은 실행 스레드 하나에서만 만지므로 원자적 연산이 필요 없다(13장). 이것은 타입이 지킨다.
  • 덤으로 "손잡이가 하나뿐이면 몰래 고쳐도 아무도 모른다"는 성질을 쓸 수 있다(아래 영속 자료구조).

순환이 생길 수 있는 자리

불변 값만으로는 고리가 생기지 않는다. 그런데 fung에도 바뀌는 것이 몇 있다. 채널(버퍼에 값이 쌓인다), atom(가리키는 값이 바뀐다), 모듈 전역 표가 그렇다. 이것들은 나중에 자기를 가리키게 될 수 있다. 그래서 고리가 생길 자리를 규칙으로 막았다.

  • 채널에 그 채널의 끝을 보내면 E0705다. 버퍼가 자기 보내는 끝을 쥐면 채널은 영원히 닫히지 않는다. send가 보내는 값을 훑어 막는다.
(tx, rx) = channel(1)
print(send(tx, [tx]))
error[E0705]: channel sent into itself
  --> example.fung:2:11
  |
2 | print(send(tx, [tx]))
  |           ^
  |
 call path (innermost first):
   example.fung:2 <entry>
  • atom에는 바뀌는 것을 품은 값(atom, 채널의 끝, 태스크, 범위, 파일, 소켓)을 넣지 못한다(E0708).
cache = atom({})
(tx, rx) = channel()
reset(cache, {inbox: tx})
error[E0708]: an atom cannot hold an atom, a channel end, a task, a scope, a file or a socket
  --> example.fung:3:6
  |
3 | reset(cache, {inbox: tx})
  |      ^
  |
 call path (innermost first):
   example.fung:3 <entry>
  • 모듈 전역 표는 그 모듈의 함수를 담고, 함수는 자기 모듈의 전역 표를 든다(11장). 이것은 고리다. 그래서 런타임이 끝날 때 전역 표를 비워 고리를 끊는다(World::release_values).

두 검사가 값 전체를 훑으면 큰 맵을 reset할 때마다 비용이 크기에 비례한다. 그래서 영속 벡터의 노드마다 "바뀌는 것을 품었는가"를 기억해 두고, 바뀐 경로만 다시 본다. 막지 못하는 고리(서로의 끝을 버퍼에 담은 채 버려진 두 채널 등)는 open-questions의 "알려진 한계"에 적혀 있다.

깊은 값 지우기

참조 계수에는 덜 알려진 함정이 하나 더 있다. Rust는 값을 버릴 때 그 필드를 차례로 버린다. 리스트 안의 리스트 안의 리스트가 백만 겹이면, 마지막 손잡이가 사라질 때 버리기가 백만 단 재귀한다. 운영체제 스레드의 스택이 넘쳐 프로세스가 죽는다. 추적형 GC는 반복문으로 훑으므로 이런 문제가 없다.

fung은 값을 담는 모든 그릇(리스트, 맵, 튜플, 태그, 클로저, 모듈, 채널의 끝, 태스크 핸들, atom)이 자기 Drop에서 자식을 꺼내 명시적 스택에 옮기고, 그 스택을 반복문으로 비운다(crates/fung-vm/src/value/release.rs). 계수가 1인, 곧 정말 지워질 그릇만 스택에 넣는다. 계수가 2 이상이면 계수만 내려가고 깊어질 일이 없기 때문이다.

fn nest(n, acc) = n == 0 then acc else nest(n - 1, [acc])

deep = nest(1000000, [])
print(len(deep))
1

백만 겹 리스트가 만들어지고, 프로그램이 끝날 때 재귀 없이 지워진다.

바꾸지 않는 값을 싸게 바꾸기

fung의 리스트와 맵은 불변이다. put(m, k, v)는 m을 고치지 않고 새 맵을 돌려준다. xs + [4]도 xs는 그대로 둔다.

xs = [1, 2, 3]
ys = xs + [4]
m = {host: "web1", port: 80}
m2 = put(m, "port", 8080)

print(xs, ys)
print(m, m2)
[1, 2, 3] [1, 2, 3, 4]
{host: "web1", port: 80} {host: "web1", port: 8080}

가장 쉬운 구현은 새 값을 만들 때 원본을 통째로 복사하는 것이다. 그러면 fold로 키 n개를 put해 쌓을 때 복사량이 1 + 2 + … + n, 곧 n²/2가 된다. 2만 개면 2억 번의 복사다. fung의 첫 구현(M10 전)이 그랬고, 2만 개 put 누적이 7.5초 걸렸다.

고칠 길은 셋이었다(노트 M10).

  1. 영속 자료구조(persistent data structure). 새 버전이 옛 버전과 구조의 대부분을 공유한다. Clojure·Scala·Haskell의 길이다.
  2. 혼자 쥐었으면 제자리 수정. 참조가 하나뿐이면 몰래 고친다. Swift의 copy-on-write, Koka·Lean의 참조 계수 최적화가 이 길이다.
  3. 빠른 일괄 함수를 따로(from_pairs 등). 사용자가 느린 방법과 빠른 방법을 외워야 한다.
fung의 선택: 영속 자료구조, 그리고 Rc::make_mut

1번을 골랐다. 사용자가 코드를 하나도 바꾸지 않아도 빨라지고, 여러 태스크가 잠금 없이 같은 값에서 각자 새 값을 만들 수 있다는 성질도 그대로다. 3번은 "같은 일을 하는 방법은 하나로"(원칙 6)와 예외 조항을 줄이는 원칙 7에 어긋난다(노트 M10). 그리고 Rust의 Rc로 옮기면서 2번이 덤으로 따라왔다(아래).

구조 공유와 길 복사

값을 평평한 배열 대신 가지가 32개인 얕은 트리에 담는다. 하나를 바꾸면 루트에서 그 값까지 내려가는 길에 있는 노드만 새로 만들고, 나머지 가지는 원본의 노드를 그대로 가리킨다.

원본                      바꾼 뒤
   [루트]                    [루트']          ← 새 노드
  /  |  \                   /  |  \
 A   B   C                 A   B'  C          ← A·C는 원본과 공유
     |                         |
    [잎]                      [잎']           ← 새 노드

깊이는 log₃₂ n이다. 100만 개여도 4단계라 바꿀 때마다 노드 4개만 새로 만든다. 32 = 2⁵라서 인덱스나 해시를 5비트씩 잘라 "몇 번째 가지"를 비트 연산으로 바로 구한다. 노드 하나가 포인터 32개라 캐시에도 잘 맞는다. Clojure가 실험으로 정한 값을 여러 언어가 그대로 쓴다.

Rust에서는 길의 노드마다 Rc::make_mut를 부른다(value/pvec.rs). 그 노드의 계수가 1이면, 곧 아무도 옛 버전을 쥐고 있지 않으면 제자리에서 고친다. 누가 쥐고 있으면 그 노드만 복사한다. 같은 코드가 "혼자 쓰는 누적값"과 "옛 버전이 살아 있는 값"을 둘 다 처리한다. 2번 길이 공짜로 붙은 셈이다.

  • 리스트는 Clojure의 PersistentVector다. 마지막 32개 이하는 트리 밖의 tail 배열에 따로 두어서, 끝에 붙이기가 대부분 tail만 고치는 일이다. 큰 리스트는 {벡터, 시작, 끝} 보기이기도 해서, xs[1..]이나 [x, ...rest]는 같은 벡터를 가리키며 범위만 다른 보기를 상수 시간에 만든다. 잘라 낸 조각이 바탕의 1/4보다 작으면 복사해서 떼어 낸다. 작은 조각이 큰 원본을 메모리에 붙잡아 두지 않게 하려는 것이다(value/list.rs).
  • 맵은 키의 해시를 5비트씩 끊어 내려가는 HAMT(Hash Array Mapped Trie, value/hamt.rs)다. 그런데 HAMT는 해시 순서라 넣은 순서를 모르고, fung 맵은 넣은 순서대로 순회·출력해야 한다. 그래서 "넣은 순서의 항목 벡터 + 키에서 위치로 가는 HAMT 색인" 두 구조를 짝지었다(value/omap.rs). Python 3.7 이후의 dict가 순서 배열과 해시 색인으로 넣은 순서를 지키는 것과 같은 생각을 영속 구조로 옮긴 것이다.
  • 작은 것은 평평하게. 스크립트의 컬렉션은 대부분 작다. 리스트는 32개, 맵은 16개 이하면 평범한 배열로 두고 넘을 때만 트리로 바꾼다(SMALL_MAX, SMALL_MAP_MAX). 경계값은 fung 스크립트로 재서 정했다. 읽기는 경계 16·32·64 어디서도 차이가 없었고(명령 하나를 해석하는 비용이 몇 ns 차이를 덮는다), 맵은 16으로 낮추니 48개짜리 맵 만들기가 빨라졌다.
n = 20000
counts = fold(0..n, {}, (acc, i) => put(acc, "k${i % 5000}", get(acc, "k${i % 5000}", 0) + 1))
items = fold(0..n, [], (acc, i) => acc + [i])

print(len(counts), counts["k42"])
print(len(items), items[19999])
5000 4
20000 19999

이 정도는 디버그 빌드에서도 순식간이다. 릴리스 빌드의 성능 시험(crates/fung-cli/tests/perf.rs)이 이런 모양 다섯을 2만 개로 돌려 0.3초를 넘으면 실패하므로, 구현이 n²로 돌아가면 바로 드러난다.

남은 n². 문자열은 Rc<String>이라 acc + s가 매번 새 문자열을 만든다. 긴 문자열을 쌓을 때는 리스트에 모아 join한다. 리스트 앞에 붙이기([x] + acc)도 매번 전체를 복사하므로, 뒤에 붙인 뒤 reverse한다.

지역 변수의 수명

참조 계수는 해제 시점이 정확하다. 그러면 "언제 마지막 손잡이가 사라지는가"가 곧 의미가 된다. 특히 채널은 보내는 끝의 마지막 사본이 사라질 때 닫힌다(14장). 그런데 지역 변수가 함수가 끝날 때까지 값을 쥐고 있으면, 그 함수 안에서 그 채널을 끝까지 읽는 코드는 영원히 기다린다.

그래서 컴파일러는 함수 본문의 문장마다 "이 지역 변수가 뒤에서 다시 읽히는가"를 보고, 아니면 그 문장 뒤에 칸을 비우는 명령 CLEARLOCAL을 넣는다(설계 03 "값의 수명", 2026-10-20 검토 L7). 반복문이 없는 언어(반복은 재귀)라서 분석이 문장 단위로 끝난다. 클로저가 붙잡는 것도 읽기다.

fn total(path):
  lines = ["a", "bb", "ccc"]
  sizes = map(lines, len)
  print(path)
  sum(sizes)
;;

print(total("x.log"))

total의 0007번이 lines(슬롯 1)를, 0012번이 path(슬롯 0)를 비운다. 그 뒤로는 두 값이 이 프레임 때문에 살아 있지 않다. 채널 쪽에서 보면 이렇다.

fn numbers(n) = scope(fn(s):
  (tx, rx) = channel()
  spawn(s, () => each(0..n, i => send(tx, i)!))
  fold(rx, 0, (acc, x) => acc + x)
;;)

print(numbers(5))
10

spawn 문장 뒤에 tx의 칸이 비워지므로, 보내는 끝을 쥔 것은 생산 태스크의 클로저뿐이다. 그 태스크가 끝나면 마지막 사본이 사라지고 채널이 닫혀 fold가 끝난다.

규칙의 나머지 둘도 알아 두자. 한 번도 읽지 않는 변수는 함수가 돌아올 때까지 산다. _watch = stop_signal()처럼 쥐고 있는 것 자체가 뜻인 값을 위해서다(Rust의 let _guard와 같은 관용구). 최상위 변수는 프로그램 끝까지 산다. 최상위 fn이 언제든 읽을 수 있기 때문이다(9장).

로그 수준 세기

수준이 INFO·WARN·ERROR인 로그 3만 줄을 흉내 낸 리스트를 만들고, fold와 put으로 수준별 개수를 세 보자. 그리고 0부터 29999까지를 "최근 것이 먼저" 순서로 담은 리스트를 만들되 앞에 붙이기([i] + acc)를 쓰지 않고 만들어 보자. 왜 그 편이 빠른가?

풀이 보기 
levels = ["INFO", "WARN", "INFO", "ERROR", "INFO"]
entries = map(0..30000, i => levels[i % 5])

counts = fold(entries, {}, (acc, lv) => put(acc, lv, get(acc, lv, 0) + 1))
newest_first = reverse(fold(0..30000, [], (acc, i) => acc + [i]))

print(counts)
print(take(newest_first, 3))
{INFO: 18000, WARN: 6000, ERROR: 6000}
[29999, 29998, 29997]

put의 누적값은 fold가 혼자 쥐고 있으므로 길의 노드가 대부분 제자리에서 고쳐지고, 맵이 커져도 바꿀 때마다 노드 몇 개만 손댄다. 뒤에 붙이기는 tail만 고치는 일이 대부분이다. 앞에 붙이기는 매번 리스트 전체를 새로 만들어 n²이 되므로, 뒤에 붙인 뒤 reverse 한 번(선형)으로 순서를 뒤집는다.

정리

  • fung의 값은 16바이트 Rust 열거형 Value다. 정수·실수·불·기간은 칸에 바로 들어가고, 큰 값은 Rc로 힙의 객체를 가리킨다. 빈 칸은 None이라 nil과 다르다.
  • 메모리는 가비지 컬렉터가 아니라 참조 계수로 돌려받는다. 불변 값끼리는 고리가 없어서 회수가 완전하고, 바뀌는 것(채널, atom)이 고리를 만들 자리는 E0705·E0708이 막는다.
  • 깊은 값은 그릇마다의 Drop이 자식을 명시적 스택으로 옮겨 재귀 없이 지운다.
  • 리스트는 영속 벡터와 보기, 맵은 항목 벡터와 HAMT 색인이다. 바꿀 때 길의 노드만 새로 만들고, 혼자 쥔 노드는 Rc::make_mut로 제자리에서 고친다. 작은 컬렉션은 평평한 배열이다.
  • 지역 변수는 마지막으로 읽힌 문장 뒤에 CLEARLOCAL로 놓인다. 그래서 채널의 끝이 제때 닫힌다.

레퍼런스: 값과 타입, 컬렉션 함수. 부록의 컬렉션의 내부에 연산 비용 표가 있다. 다음 장은 값 중에서도 특별한 값, 모듈이 어떻게 찾아지고 실행되는지를 본다.
