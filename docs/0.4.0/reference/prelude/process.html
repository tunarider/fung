프로세스와 환경

외부 명령을 실행하고 환경 변수를 읽는다. 명령은 쉘을 거치지 않는 exec가 기본이다. 종료 코드가 0이 아니면 Err이므로 exec(…)!가 쉘의 set -e와 같다.

프로세스와 환경이란

실행 중인 프로그램 하나를 프로세스(process)라고 한다. fung 스크립트도 프로세스이고, 스크립트가 git이나 ssh, kubectl을 실행하면 그것은 자식 프로세스(child process)가 된다. 자식 프로세스는 세 가지를 남긴다: 표준 출력에 쓴 글(out), 표준 에러에 쓴 글(err), 종료 코드(code, 0이면 성공). exec는 명령이 끝날 때까지 기다렸다가 이 셋을 맵으로 돌려준다. 출력은 터미널에 흘러나오지 않고 값으로 모인다.

명령은 문자열의 리스트로 준다: ["git", "commit", "-m", msg]. 첫 원소가 실행할 프로그램이고 나머지가 인자다. 쉘을 거치지 않으므로 msg에 공백, 따옴표, $, ;가 들어 있어도 한 인자로 그대로 간다. 쉘의 따옴표 규칙을 신경 쓸 필요가 없고, 바깥에서 온 값이 명령을 바꿔 버리는 명령 주입(command injection)도 일어나지 않는다. 파이프(|)나 글로브(*.log) 같은 쉘 기능이 꼭 필요할 때만 sh를 쓴다.

환경 변수(environment variable)는 프로세스가 부모에게서 물려받는 이름=값 목록이다. HOME, PATH, 그리고 DB_HOST처럼 설정을 넘기는 데 쓰는 것들이 있다. env로 읽고, 자식 프로세스에 더 넘길 것은 exec의 env 인자로 준다. fung에는 자기 환경을 바꾸는 함수가 없다.

이 페이지의 세 함수는 fung으로 쓴 prelude가 네이티브 함수를 그대로 이름 붙인 것이다.

함수

exec

명령을 쉘 없이 실행하고 끝나기를 기다려 Ok({out, err, code})를 돌려준다. 0이 아닌 종료는 Err.

exec(cmd, cwd = nil, env = nil, stdin = nil)

설명

cmd의 첫 원소를 PATH에서 찾아 나머지를 인자로 실행한다(/가 든 이름이면 그 경로를 쓴다). 명령이 끝나면 표준 출력과 표준 에러를 문자열로 모아 돌려준다. 출력 끝의 줄바꿈도 그대로 들어 있으므로 값 하나를 얻을 때는 trim하고, 여러 줄이면 lines로 나눈다.

  • 성공(종료 코드 0): Ok({out, err, code: 0}).
  • 0이 아닌 종료: Err({kind: 'exit, code, out, err, message}). 출력도 들어 있으므로 실패 이유를 e.err로 보여 줄 수 있다. exec(…)!로 쓰면 실패할 때 멈추므로 쉘의 set -e와 같고, 문장으로만 쓴 exec(…)도 Err를 버리면 E0606으로 멈춘다.
  • 실행할 수 없음: 실행 파일이 없거나, 실행 권한이 없거나, cwd가 없으면 Err({kind: 'not_found, message}). 이유는 command not found in PATH, permission denied 등이다. 실행 권한이 없는 스크립트는 ["sh", "script.sh"]로 돌린다.

cwd를 주면 그 디렉터리에서 실행한다. env는 지금 환경에 덧붙일 맵이다(같은 이름은 덮어쓴다). stdin을 주면 그 문자열을 명령의 표준 입력으로 넣고 닫는다. stdin이 nil이면 명령은 빈 입력을 받는다. fung이 받은 표준 입력을 명령에 넘기지 않는다. 이름 붙인 인자로 쓰면 읽기 좋다: exec(["make"], cwd: "/src", env: {CC: "clang"}).

취소: 부른 태스크가 취소되면(timeout, exit, 범위의 취소) 명령에 SIGTERM을 보내고, 2초 뒤에도 남아 있으면 SIGKILL을 보낸 뒤 취소로 되감긴다. 그래서 timeout(30s, () => exec(cmd))는 걸린 명령을 남겨 두지 않는다.

터미널: fung이 터미널의 전경에서 돌면(사람이 터미널에서 실행했으면) 명령도 fung과 같은 프로세스 그룹이라 비밀번호 프롬프트처럼 터미널을 직접 쓸 수 있고, Ctrl-C도 셸에서처럼 명령에 간다. 이때 취소는 명령 하나에만 간다. 터미널이 없으면(서비스, 컨테이너, CI, cron) 명령은 자기 프로세스 그룹에서 돌고, 취소는 그룹 전체에 가서 셸이 띄운 손자 프로세스까지 끝난다.

여러 명령을 동시에 돌리려면 태스크로 나눈다(scope, conc.pmap). 명령을 기다리는 동안에도 다른 태스크는 계속 돈다.

매개변수

  • cmd: 비지 않은 문자열 리스트. [프로그램, 인자…].
  • cwd: 실행할 디렉터리, 또는 nil(지금 디렉터리).
  • env: 덧붙일 환경 변수(값이 문자열인 맵), 또는 nil.
  • stdin: 표준 입력으로 넣을 문자열, 또는 nil.

돌려주는 값

Ok({out: 문자열, err: 문자열, code: 0}), 또는 Err({kind: 'exit, code, out, err, message}), 또는 Err({kind: 'not_found, message}).

에러

인자의 타입이 틀리면 런타임 에러 E0403: cmd가 문자열이거나(exec("ls -l")은 안 된다), 비었거나, 문자열이 아닌 원소가 있을 때, env의 값이 문자열이 아닐 때 등.

예제

출력 얻기

r = exec(["echo", "hi"])!
print(r)
print(trim(r.out))
{out: "hi\n", err: "", code: 0}
hi

실패를 가르기

fn run(cmd) = match exec(cmd):
  Ok(r)                    => "ok: ${trim(r.out)}"
  Err({kind: 'exit, code}) => "exited with ${code}"
  Err({kind: 'not_found})  => "no such command"
;;

print(run(["echo", "fine"]))
print(run(["sh", "-c", "exit 3"]))
print(run(["no-such-command-xyz"]))
ok: fine
exited with 3
no such command

셸의 set -e처럼 멈추기

exec(["sh", "-c", "echo building; exit 2"])!
print("not reached")
error[E0603]: unhandled Err: `sh` exited with code 2
  --> example.fung:1:44
  |
1 | exec(["sh", "-c", "echo building; exit 2"])!
  |                                            ^
  |
 call path (innermost first):
   example.fung:1 <entry>

인자에 공백과 특수 문자가 있어도 그대로

msg = "fix: it's \"done\"; rm -rf /"
print(exec(["printf", "%s\n", msg])!.out |> trim)
fix: it's "done"; rm -rf /

msg는 쉘을 거치지 않으므로 ; 뒤가 명령으로 실행되지 않는다.

기한을 두고 실행하기

print(timeout(100ms, () => exec(["sleep", "5"])))
Err({kind: 'timeout})

sleep은 기한이 지나자 SIGTERM으로 끝났다.

sh

문자열 cmd를 /bin/sh -c cmd로 실행한다. 파이프나 글로브 같은 쉘 기능이 필요할 때만 쓴다.

sh(cmd, cwd = nil, env = nil, stdin = nil)

설명

exec(["/bin/sh", "-c", cmd], …)와 같다. 돌려주는 값, cwd·env·stdin, 취소의 규칙이 모두 exec와 같다. 종료 코드는 쉘의 것, 곧 파이프라인의 마지막 명령의 것이다.

바깥에서 온 값을 sh 문자열에 끼워 넣지 않는다

sh("grep ${pattern} app.log")에서 pattern이 사용자 입력이면, x; rm -rf ~ 같은 값이 명령이 되어 실행된다(명령 주입). 값이 들어가는 명령은 exec(["grep", pattern, "app.log"])처럼 리스트로 쓴다. 쉘 기능이 꼭 필요하면 값을 env로 넘기고 쉘 안에서 "$PATTERN"으로 따옴표를 쳐서 읽는다.

매개변수

  • cmd: 쉘 명령 문자열.
  • cwd, env, stdin: exec와 같다.

돌려주는 값

exec와 같다.

에러

exec와 같다.

예제

파이프와 글로브

준비물: a.log, b.log

a.log

ok
ERROR one

b.log

ERROR two
ERROR three
print(sh("cat *.log | grep -c ERROR")!.out |> trim)
3

값은 env로 넘기기

pattern = "two; echo injected"
r = sh("echo \"$P\"", env: {P: pattern})!
print(trim(r.out))
two; echo injected

실패도 Err

print(sh("exit 2"))
Err({kind: 'exit, code: 2, out: "", err: "", message: "`/bin/sh` exited with code 2"})

env

환경 변수 name의 값(문자열)을, 없으면 nil을 돌려준다. 인자가 없으면 전체를 맵으로.

env(name = nil)

설명

값은 언제나 문자열이다. 수가 필요하면 parse_int로 바꾼다. 없는 변수는 에러가 아니라 nil이므로 ??로 기본값을 붙이기 좋다: env("PORT") ?? "8080". 꼭 있어야 하는 변수면 env("DB_HOST") ?? fail("DB_HOST is required").

인자 없이 부르면 모든 환경 변수를 {이름: 값} 맵으로 돌려준다.

매개변수

  • name: 변수 이름(문자열), 또는 nil(전체).

돌려주는 값

문자열 또는 nil. 인자가 없으면 맵.

에러

name이 문자열도 nil도 아니면 런타임 에러 E0403.

예제

기본값과 함께

port = env("PORT") ?? "8080"
print(port)
8080

값이 있을 때

실행 방법 
DEPLOY_ENV=staging RETRIES=3 fung example.fung
print(env("DEPLOY_ENV"), parse_int(env("RETRIES") ?? "1")!)
print(env("NOT_SET_ANYWHERE"))
staging 3
nil

전체를 맵으로

실행 방법 
APP_DEBUG=1 APP_NAME=api fung example.fung
app = pairs(env()) |> filter(((k, _)) => starts_with(k, "APP_")) |> sort_by(((k, _)) => k)
print(app)
[("APP_DEBUG", "1"), ("APP_NAME", "api")]
