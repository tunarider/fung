fung 0.1.0 · 설계 문서는 docs/design

Go처럼 쓰고 Lisp처럼 도는 작은 함수형 스크립트 언어. 파일 이름 바꾸기, 로그 요약, 작은 웹서버 같은 일상의 스크립트를 위해 만들었다.

파이프 |>는 평범한 호출로, !는 unwrap으로, 이름은 전부 슬롯 번호(local·global·prelude)로 풀렸다. 이것이 "겉은 Go, 속은 Lisp"의 실체다.

무엇을 위한 언어인가

fung은 개인 학습과 일상의 소소한 사용을 위한 언어다. 범용 언어를 목표로 하지 않는다.

  • 쓰는 곳: 쉘 스크립트로 짜던 작은 작업(파일 일괄 정리, 로그 집계, 설정 검사), 여러 URL을 병렬로 확인하는 도구, 간단한 JSON API 서버.
  • 안 쓰는 곳: 본격적인 쉘 작업(그건 계속 쉘로), 성능이 중요한 처리, GUI.
  • 우선순위: 성능보다 쓰기 편함. 다만 조용히 틀리는 동작은 편함보다 위험하다고 보고 막는다.

Go로 구현한 바이트코드 VM이고, 실행 파일 fung 하나로 배포된다. 확장자는 .fung. 이름은 한국어 "펑"(빠르게 만들고 치고 빠진다)과 function, Go에서 왔다.

기조

설계 중 새 결정이 필요할 때마다 아래 일곱 가지로 판단했다. 문법과 라이브러리의 모양은 대부분 여기서 따라 나온다.

엄격함이 우선이다

조용히 넘어가는 동작은 에러다. 암묵적 형변환("5" + 3), 참·거짓 흉내(if []:), 정수 오버플로의 감김, 없는 키를 nil로 읽기, NaN·Inf는 모두 런타임 에러다. PHP의 "문법 에러만 아니면 일단 돈다"는 편안함은 부작용 때문에 버렸다.

짧은 축약 문법을 좋아한다

자주 쓰는 일에는 짧은 표기가 있다: 에러 처리 ! ? ??, 한 줄 조건 c then a else b, 짧은 함수 fn f(x) = …, 람다 x => …, 파이프 |>, 맵 축약 {name, port}.

들여쓰기를 강제하지 않는다

블록은 :로 열고 ;;로 닫는다. 들여쓰기는 의미가 없어서 무엇이든 한 줄로도 쓸 수 있다: if ok: a() else: b() ;;. 모양은 포맷터 fung fmt가 맞춘다.

Go는 안에서 쓰고 밖으로 드러내지 않는다

GC, 고루틴, 표준 라이브러리는 Go에 기댄다. 하지만 문법·용어·함수 이름은 fung 고유의 것이고, Go의 동작(맵 순회 순서, 정수 감김, 패닉과 스택 추적)은 새어 나오지 않는다. 사용자는 Go 도구 없이 fung 하나만 있으면 된다.

핵심은 작게, 나머지는 fung으로

언어 핵심은 최소한의 값 연산과 원시 연산만 가진다. take·sum·pmap·retry·cli.parse 같은 것은 fung으로 작성해 실행 파일에 넣었다. Go로 쓰는 것은 바깥세상과의 다리(파일·네트워크·프로세스)와 성능이 필요한 안쪽 루프(JSON 파싱, 정규식)뿐이다.

같은 일을 하는 방법은 하나다

주석은 #만, 문자열은 보간이 되는 "…"와 원시 `…`로 역할이 나뉘고, 맵 키는 항상 문자열이다. 반복은 map·filter·fold와 꼬리 재귀뿐이고 while은 없다.

예외 조항을 줄인다

"이때는 이렇고 저때는 저렇다"는 규칙이 적어야 한다. 편의를 위한 특례를 더하기보다 규칙 하나에서 결과가 따라 나오게 한다. 예를 들어 클로저 규칙은 "함수는 만들어질 때 보이는 변수의 값을 복사한다" 하나뿐이고, 최상위 함수든 람다든 같다.

핵심 개념

값은 불변이다
리스트·맵을 바꾸는 연산은 없다. put(m, "k", v), xs + [x]처럼 새 값을 만든다. 그래서 태스크 사이에 값을 그냥 넘겨도 안전하다. 바뀌는 상자는 동시성용 atom 하나뿐이다.
값을 만드는 구문은 모두 식이다
if, match, for, 블록이 값을 돌려준다. 문장은 대입과 선언(fn, import, type, test)뿐이다.
실패는 값이거나 중단이다
외부 요인으로 실패할 수 있는 일(파일, 네트워크, 파싱)은 Ok(v)/Err(e)를 돌려준다. 코드가 틀린 것(타입 오류, 범위 밖 인덱스)은 런타임 에러로 그 자리에서 멈춘다. 에러를 잡는 try는 없다.
반복은 파이프와 꼬리 재귀다
목록 처리는 xs |> filter(f) |> map(g). 상태가 있는 반복(재시도, 폴링, 누적)은 꼬리 재귀로 쓰고, VM이 프레임을 재사용하므로 백만 번 돌아도 스택이 넘치지 않는다.
동적 타입, 선택적 표기
fn area(r: num) -> float처럼 타입을 적으면 호출과 반환 때 검사한다. 적지 않으면 검사하지 않는다.
동시성은 원시 연산 몇 개
spawn/await/cancel, 채널, atom, sleep. async/await 문법은 없고, 막히는 호출은 그냥 막히며 그동안 다른 태스크가 돈다.

빠른 시작

설치

Linux와 macOS(amd64, arm64)는 설치 스크립트로 받는다. GitHub 릴리스에서 내 플랫폼의 바이너리를 받아 SHA256SUMS와 대조한 뒤 ~/.local/bin에 둔다. sudo는 필요 없다.

curl -fsSL https://raw.githubusercontent.com/tunarider/fung/main/install.sh | sh
fung version

버전과 위치는 환경 변수로 고른다: FUNG_VERSION=0.1.0, FUNG_INSTALL_DIR=/usr/local/bin. 다시 실행하면 업데이트, 지우려면 그 파일을 지우면 된다. 바이너리 하나에 표준 모듈이 다 들어 있어 따로 설치할 것이 없다.

Go 1.27이 있다면 go install도 된다. 저장소에서 직접 빌드할 수도 있다.

go install github.com/tunarider/fung/cmd/fung@latest
go build -o ~/.local/bin/fung ./cmd/fung

받은 파일이 이 저장소의 GitHub Actions에서 빌드된 것인지는 gh attestation verify <파일> --repo tunarider/fung로 확인할 수 있다.

첫 스크립트

디렉터리의 파일을 크기순으로 보여 주는 스크립트다. 파일 첫 줄에 shebang을 두면 직접 실행할 수 있다.

#!/usr/bin/env fung
# usage: fung biggest.fung <dir> [n]
import fs
import path

dir = first(args) ?? fail("usage: biggest.fung <dir> [n]")
n = int(get_arg(1, "5"))

fn get_arg(i, default) = i < len(args) then args[i] else default

sizes = fs.list(dir)!
  |> map(f => (f, fs.stat(path.join(dir, f))!.size))
  |> sort_by(((_, size)) => -size)
  |> take(n)

for (name, size) in sizes:
  print(pad_left(str(size), 10), name)
;;

최상위 fn은 프로그램 시작 전에 만들어지므로 정의보다 앞에서 불러도 된다. 대신 최상위 변수는 볼 수 없어서 값은 인자로 넘긴다(스코프).

테스트를 같은 파일에

fn slug(s) = lower(s) |> split(" ") |> filter(w => w != "") |> join("-")

test "slug joins words with dashes":
  assert slug("Hello  World") == "hello-world"
  assert slug("") == ""
;;

fung run은 test 블록을 무시하고, fung test가 그것만 돌린다. 실패하면 양쪽 값이 함께 찍힌다.

명령

명령하는 일
fung script.fung [args…]스크립트 실행. fung run script.fung과 같다. 뒤의 인자는 args(문자열 리스트)로 들어간다.
fung -e 'code'코드 한 줄 실행.
fungREPL. 줄 편집, 기록(~/.fung_history), 정의 유지, :help :load :quit.
fung check script.fung실행하지 않고 문법·이름·import를 검사하고 경고를 보여 준다.
fung test [path]test 블록 실행. 경로가 디렉터리면 그 아래 .fung 전부(_로 시작하는 디렉터리 제외).
fung fmt [--check] path…공백·들여쓰기·정렬을 단일 스타일로 고친다. 줄바꿈은 그대로 둔다. --check는 고칠 파일만 알려 주고, -는 표준 입력을 받는다.
fung dump ast|core|bytecode file컴파일의 중간 단계를 보여 준다(내부 구조).

에러와 종료 코드

에러는 번호, 메시지, 소스 발췌, 런타임 에러면 호출 경로를 보여 준다. Go의 패닉이나 스택 추적은 나오지 않는다.

error[E0507]: index 5 is out of range (length 2)
  --> report.fung:2:8
  |
2 | print(x[5])
  |        ^
  |
 call path (innermost first):
   report.fung:2 <entry>
번호분류
E01xx문법(렉서·파서)
E02xx이름과 스코프
E03xx모듈과 import
E04xx호출과 타입 표기
E05xx런타임 연산(타입 불일치, 0 나누기, 오버플로, 범위 밖 인덱스, 없는 키)
E06xx패턴과 결과값(맞는 패턴 없음, !가 Err를 만남)
E07xx동시성(교착, atom 재진입)
E08xx한도와 환경(스택 깊이, fail, assert, 내부 오류)
W01xx경고(check·test에서만): 안 쓰는 import·변수, prelude 이름 가리기, 값 자리 블록이 대입으로 끝남
