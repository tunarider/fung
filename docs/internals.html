내부 구조

Rust로 쓴 바이트코드 VM이다. 트리를 직접 도는 인터프리터가 더 단순하다는 것을 알고 고른 선택으로, 컴파일러와 VM의 원리를 배우는 것이 목적이었고 꼬리 호출 최적화도 VM 쪽이 자연스럽다.

아래 세 줄짜리 프로그램이 각 단계에서 어떤 모양인지 fung dump로 볼 수 있다. 이 쪽의 출력은 모두 실제 명령의 결과다.

fn sq(x) = x * x
xs = [1, 2, 3] |> map(sq)
print(sum(xs))

겉 트리 (fung dump ast)

파서가 만든 트리. 문법의 모양을 그대로 담는다: 파이프는 pipe, 블록은 block, 이름은 아직 이름이다.

(program
  (fn sq(x) (block (binary * x x)))
  (assign xs (pipe (list 1 2 3) (call map sq)))
  (call print (call sum xs)))

코어 트리 (fung dump core)

desugar와 resolve를 거친 트리. 파이프가 평범한 호출이 되었고, 모든 이름이 자리 번호로 바뀌었다: 함수의 지역 슬롯 (local n), 모듈 전역 칸 (global n), prelude 값 (prelude name).

(do
  (let (global 0) (fn sq(x) (do (op * (local 0) (local 0)))))
  (let (global 1) (call (prelude map) (list 1 2 3) (global 0)))
  (call (prelude print) (call (prelude sum) (global 1))))

바이트코드 (fung dump bytecode)

컴파일러가 함수마다 하나씩 만든 명령열. 왼쪽 열은 명령 번호와 그 명령의 소스 위치(줄:칸)다. prelude 함수는 상수로 직접 들어가고, 지역 변수는 슬롯 번호로 읽는다.

0001  1:1   STOREGLOBAL  0    ; sq
0002  2:19  CONST        0    ; <fn map>
0003  2:7   CONST        1    ; 1
0004  2:10  CONST        2    ; 2

0000  1:12  LOADLOCAL    0

VM은 <main>을 실행한다. 스택 기계라서 CONST와 LOAD*가 값을 쌓고, MUL·LIST·CALL이 쌓인 값을 꺼내 결과를 올린다.

렉서

소스 문자열을 토큰 열로 바꾼다. 토큰은 {종류, 글자, 위치(파일·줄·칸), 바이트 구간, 값}이다.

  • 글자 수준 규칙은 전부 여기서 끝난다: 숫자 형태와 범위, 기간의 단위 순서, 문자열 이스케이프, 보간 ${…} 조각, 원시 문자열, 심볼. 잘못된 것은 E01xx로 바로 멈춘다.
  • 줄바꿈은 NEWLINE 토큰으로 그대로 내보낸다. 줄 이어짐이나 :의 역할은 렉서가 판단하지 않고 파서가 문맥으로 정한다.
  • 주석은 토큰 흐름에서 빼되 위치와 함께 별도 목록(trivia)에 보관한다. 실행에는 필요 없지만 포맷터가 원래 자리에 돌려놓는 데 쓴다.
  • ;;는 항상 가장 길게 자른다. 이름은 첫 글자만 보고 이름·태그·예약어를 가른다.

파서와 균일 트리

문장은 재귀 하강으로, 식은 Pratt 파서로 읽는다. Pratt 파서는 연산자마다 "왼쪽 결합력"을 숫자로 두고, 그 숫자 비교 하나로 모든 이항·단항·후위 연산의 우선순위와 결합 방향을 처리한다. 우선순위 표를 숫자로 옮긴 것이 곧 파서다.

세 곳에서 되돌리기를 쓴다. 앞을 조금 읽어 보고 아니면 원래 자리로 돌아가는 방식이다.

  • 문장 시작의 패턴 =(구조 분해 대입인가, 식인가)
  • (a, b) =>(람다인가, 튜플인가)
  • match 절의 패턴 [when 조건] =>(새 절인가, 앞 절 본문의 문장인가)

패턴 문법이 작아서 되돌리기 비용이 적다.

균일 트리

트리 노드의 모양은 하나뿐이다: {머리, 위치, 자식들, 리터럴 값, 소스 구간}. f(a, b)는 (call f a b), if c: a else: b ;;는 (if c (do a) (do b)). 노드 종류마다 Rust 타입을 따로 만들지 않는다. "속은 Lisp"의 실체이며, dump, desugar, 이름 해석이 모두 같은 모양 위에서 일하고, 나중에 매크로를 넣을 자리도 이것이다.

대가로 Rust 컴파일러가 "이 노드에는 자식이 셋"을 검사해 주지 않는다. 그 검사는 desugar가 한다.

desugar와 코어 언어

겉 문법을 작은 코어 언어로 풀어낸다. 컴파일러는 코어 언어만 안다. 겉 문법을 늘려도 컴파일러와 VM은 그대로다.

코어 형태여기로 풀리는 겉 문법
(do e…)블록 본문. 값은 마지막 식.
(let 패턴 e)x = e, 구조 분해 대입
(if c a b)if/else if 사슬, then … else, and/or(단락 평가)
(fn 이름 인자표 본문)fn 정의, 람다, 익명 함수, _ 부분 적용, for의 본문
(call f 인자… (named 이름 e)…)호출, x |> f(a) → (call f x a), for → (call map xs (fn …))
(op 연산자 a b)산술·비교·in·... 연산자는 값이 아니다(fold(xs, 0, +)는 없다).
(field x "name") (index x i) (slice x a b)x.name, x[i], x[a..b]
(tag Ok e…)Ok(e)
(match e (arm 패턴 guard 본문)…)match

이름 해석

코어 트리를 한 번 훑어 모든 이름을 다섯 가지 중 하나로 분류하고 번호를 매긴다. 컴파일러와 VM은 이름을 다시 찾지 않는다. 실행 중에는 문자열 이름 조회가 없다.

지역 슬롯 (local n)
함수의 인자와 지역 변수. 블록이 끝나면 그 슬롯을 다른 변수가 재사용한다.
붙잡은 값 (captured n)
클로저가 만들어질 때 복사해 둔 바깥 변수.
자기 자신 (self)
블록 안에서 이름 붙인 fn이 자기를 부를 때.
모듈 전역 (global n)
파일 최상위의 변수와 fn.
prelude (prelude name)
내장 함수. 상수로 직접 들어간다.

스코프 규칙 위반(정의 전 읽기 E0204, 바깥 변수 재대입 E0205, 블록 밖 이름 E0206, for 안의 return, 최상위 return, 모듈 이름 가리기, 대안 패턴의 이름 불일치)은 첫 번째에서 멈추지 않고 전부 모아 보고한다. 경고(W0101~W0104)도 여기서 만든다.

바이트코드

명령 인코딩

명령 하나는 고정 폭 32비트다: 상위 8비트가 명령, 하위 24비트가 피연산자. 디코딩과 점프 계산이 단순하고 역어셈블러가 쉽다. 24비트면 상수 번호, 슬롯 번호, 점프 위치에 충분하다. 가변 길이 바이트 열은 매 명령의 길이를 따져야 해서 택하지 않았다.

CALL은 피연산자 하나에 두 수를 담는다: 하위 12비트가 위치 인자 수, 그 위 12비트가 이름 인자 수.

함수 원형(Proto)

함수마다 하나. 명령열, 상수 풀, 인자 표(이름·기본값 여부·...rest·타입 표기), 지역 슬롯 수, 붙잡을 값 목록, 안쪽 함수 원형들, 패턴 트리들, 그리고 명령마다 소스 위치 하나(명령열과 나란한 배열)를 가진다. 런타임 에러가 정확한 줄과 칸을 가리킬 수 있는 이유다.

VM

값의 표현

Rust 열거형 Value 하나다: Int(i64), Float, Bool, Nil, Sym(전역 인턴 표의 번호라 비교가 정수 비교), Dur, Time, Str(Rc<String>), List·Map(컬렉션의 내부), Tuple, Tag, Range, Closure, Native(Rust 함수, &'static 참조), Module, File, 소켓, 그리고 태스크·범위·채널의 두 끝·atom. 크기는 16바이트(종류 표시 + 칸 하나)이고, 정수·실수·불·기간은 상자 없이 칸에 바로 들어간다.

큰 값은 참조 계수 Rc로 가리킨다. 가비지 컬렉터가 없고, 값을 가리키는 손잡이가 0이 되는 순간 바로 해제된다. 값을 복제해도 큰 리스트가 복사되지 않고 계수만 오른다. 불변 값만으로는 순환을 만들 수 없으므로(값을 만들 때 그 값은 아직 없다) 참조 계수만으로 회수가 완전하다. 바뀌는 칸인 atom에는 바뀌는 것을 담지 못하게 하고(E0708), 채널에 그 채널의 끝을 보내는 것은 E0705로 막는다. 깊게 겹친 값(백만 겹 리스트)도 재귀 없이 명시적 스택으로 해제한다.

모든 연산이 새 값을 만든다. 리스트와 맵은 사본이 원본과 구조를 공유하는 영속 자료구조라, 누적과 꼬리 재귀도 선형이다(컬렉션의 내부). 값 층 밖의 코드는 Len·At·All·Slice·Put 같은 메서드와 빌더로만 리스트·맵을 다룬다.

스택 칸은 Option<Value>다. None은 "슬롯이 아직 비어 있음"이고, fung의 nil은 별도 값 Value::Nil이다. 이 구분이 기본값 처리를 공짜로 만든다(아래).

태스크, 스택, 프레임

실행 단위는 태스크다. 태스크마다 피연산자 스택 하나를 갖고, 호출마다 프레임 {Proto, ip, 슬롯 시작 위치, 클로저, 전역 표}을 쌓는다. 지역 변수는 그 프레임의 슬롯 시작 위치 + 번호로 스택에서 바로 읽는다. 전역 상태는 없다: 여러 태스크가 서로 다른 운영체제 스레드에서 같은 바이트코드를 번갈아 실행한다(동시성 런타임).

프레임 깊이가 100,000을 넘으면 E0804 "stack overflow"와 "꼬리 재귀나 fold를 쓰세요"라는 힌트가 나온다. 프레임이 작은 구조체라 그 깊이도 수십 MB 수준이다.

호출 규약

스택에는 [함수, 위치 인자…, (이름 심볼, 값)…]이 놓인다. VM이 원형의 인자 표를 보고 새 프레임 슬롯에 묶는다: 위치 인자는 차례로, 이름 인자는 표에서 찾아, 남는 위치 인자는 ...rest 리스트로. 맞지 않으면 E04xx. 내장 함수도 같은 인자 표를 선언하므로 같은 검사를 같은 곳에서 받는다. 그래서 exec(cmd, cwd: d)가 된다.

빠른 길: fung 함수를 위치 인자만으로, 매개변수 개수만큼 정확히 부르는 가장 흔한 경우는 묶는 일을 건너뛴다. 인자가 그대로 새 프레임의 첫 슬롯이 되고, 나머지 슬롯은 비워 둔 채 스택에 이어 붙는다. 힙 할당이 하나도 없다. 인자를 잠시 담는 배열도 태스크마다 하나를 재사용한다. 호출된 쪽이 인자를 곧바로 프레임이나 내장 함수의 새 배열로 옮겨 두기 때문에, 다음 호출이 그 배열을 덮어써도 안전하다. fold·map·each·filter는 원소마다의 인자를 태스크 스택에 바로 쌓으므로 원소마다 배열을 만들지 않고, 범위(0..n)는 리스트로 펼치지 않고 수를 하나씩 만들어 돈다. 이 둘로 함수 호출과 반복이 약 2.5배 빨라졌다.

이어 가기 프레임: 람다를 부르는 내장 함수(map·fold·with·timeout·scope·swap 등)는 함수를 직접 부르지 않는다. "이 함수를 이 인자로 불러 달라, 끝나면 이 상태로 이어 달라"를 돌려주고(Lua 5.2의 lua_callk와 같은 생각), VM이 그 상태 상자를 프레임 옆의 이어 가기 줄에 두고 같은 실행 루프에서 부른다. 부른 함수가 돌아오면 상자가 결과를 받고, 에러·취소·exit가 지나가면 상자가 되감기를 본다(with가 release를 부르는 자리). 그래서 태스크 하나에는 실행 루프가 하나뿐이고, 태스크의 모든 상태(프레임, 값, 상자)가 힙에 있다. 그린 스레드 스케줄러가 태스크를 주차하려면 이것이 필요하다. 처음 가져오는 모듈의 본문도 같은 방식으로 돈다. 콜백이 보통 내장 함수면(map(xs, str)) 되부를 일이 없으므로 그 자리에서 바로 부른다.

기본값은 함수 서두(prologue)에 컴파일된다: "슬롯이 비었으면 기본값 식을 실행해 채운다". 호출할 때마다 평가되고 앞 인자를 참조할 수 있는 이유다.

fn greet(name, greeting = "hello") = "${greeting}, ${name}"

== greet ==

0001  1:1   JUMPIFSET    4          ; 슬롯 1이 차 있으면 기본값 건너뛰기
0002  1:27  CONST        0    ; "hello"
0003  1:1   STORELOCAL   1
0004  1:41  LOADLOCAL    1
0005  1:38  CONST        1    ; ", "
0006  1:54  LOADLOCAL    0
0007  1:38  CONCAT       3          ; 보간 조각 셋을 잇는다
0008  1:36  RETURN

타입 표기는 서두의 CHECKTYPE, 반환 타입은 RETURN 직전의 CHECKRETURN이 검사한다.

클로저: 복사, 상자 없음

CLOSURE n은 원형 n의 "붙잡을 값 목록"(현재 프레임의 슬롯 또는 현재 클로저가 붙잡은 값)을 복사해 새 클로저를 만든다. 대부분의 언어는 바깥 변수가 나중에 바뀌는 것을 보여 주려고 변수를 상자(upvalue)에 담아 공유하지만, fung은 "함수는 만들어질 때 보이는 변수의 값을 복사한다"는 규칙 하나로 정했기 때문에 상자가 필요 없다.

fn adder(n) = x => x + n

모듈 전역과 끌어올리기

모듈마다 전역 표(Vec<Option<Value>>)가 있고 이름→번호는 컴파일 때 정해진다. 최상위 fn 칸은 모듈 본문을 실행하기 전에 채운다(끌어올리기). 그래서 순서와 상관없이 서로 부른다. 변수 칸은 본문이 진행되며 채워진다. 함수는 전역 변수를 실행 중에 조회하지 않고 만들어질 때 복사하는데, 최상위 fn은 변수가 생기기 전에 만들어지므로 최상위 변수를 볼 수 없다. 이것이 스코프 규칙의 구현상 이유다.

꼬리 호출

컴파일러가 꼬리 위치의 호출을 TAILCALL로 낸다. VM은 새 프레임을 쌓지 않고 인자를 현재 프레임 슬롯에 다시 묶은 뒤 ip를 0으로 돌린다. 그래서 꼬리 재귀는 스택을 쓰지 않는다.

패턴 매칭

패턴은 명령열로 펼치지 않고 원형의 패턴 트리로 둔다. MATCH n 한 명령이 실행 중에 트리를 해석해 맞으면 이름들을 슬롯에 묶고 true를 올린다. 패턴의 의미가 Rust 함수 하나(vm/matcher.rs)에 모여 있어 이해하고 고치기 쉽다. guard는 그 뒤의 평범한 비교와 JUMPIFFALSE이고, 아무 절도 맞지 않으면 NOMATCH가 E0601을 낸다. 구조 분해 대입은 MATCHORFAIL이다.

결과값 축약

  • UNWRAPABORT(!): Ok(v)면 v, Err면 E0603으로 중단.
  • UNWRAPTEST(?): Ok(v)면 v, Err면 그것을 남긴 채 함수의 반환으로 점프.
  • COALESCE L(??): nil이나 Err면 꺼내고 L로 점프해 오른쪽을 평가, Ok(v)면 v를 올리고 L을 건너뛴다.

에러

VM 에러는 {번호, 인자, 위치, 호출 경로}다. 위치는 실패한 명령의 소스 위치 표에서, 호출 경로는 프레임들을 거슬러 올라가며 만든다(꼬리 호출로 재사용된 프레임은 횟수로 표시). 런타임 에러는 태스크 전체를 되감는다. 잡는 구문은 없다.

Rust 코드의 패닉(내장 함수나 VM의 버그)은 Rust에서 fung 코드로 들어가는 입구마다 catch_unwind로 잡아 E0801 내부 오류로 바꾼다. Rust 백트레이스는 사용자에게 가지 않는다.

컬렉션의 내부

리스트와 맵은 불변이다. 그래서 "바뀐 사본"을 만들 때마다 원본은 그대로 두어야 한다. M10 전까지 fung은 사본을 통째로 만들었고, 그 때문에 누적과 꼬리 재귀가 n²이었다. 지금은 사본이 원본과 대부분을 공유하는 영속 자료구조를 쓴다. 언어의 의미(값, 순서, 비교, 출력)는 하나도 바뀌지 않았다.

왜 통째 복사는 n²인가

put(acc, k, v)가 맵 전체를 복사하면, n개를 쌓을 때 복사량이 1 + 2 + … + n, 곧 n²/2다. 리스트의 acc + [x], 꼬리를 떼는 [_, ...rest]와 ys[1..]도 같은 모양이었다. 2만 개 기준으로 0.1에서 잰 값이다(같은 기계, fung 스크립트).

패턴M10 전M10 후
fold로 put 누적(새 키)7.5s61ms
fold로 put(기존 키 갱신 섞임)3.1s31ms
fold로 acc + [i]0.80s13ms
[_, ...rest] 재귀0.76s14ms
ys[1..] 재귀0.75s14ms

crates/fung-cli/tests/perf.rs(릴리스 빌드)가 이 다섯을 0.3초 기준으로 지키므로 n²로 돌아가면 테스트가 실패한다.

구조 공유와 길 복사

값을 평평한 배열 대신 가지가 32개인 얕은 트리에 담는다. 하나를 바꾸면 그 값까지 내려가는 길의 노드만 새로 만들고, 나머지 가지는 원본의 노드를 그대로 가리킨다. 원본은 하나도 바뀌지 않는다.

원본                      바꾼 뒤
   [루트]                    [루트']          ← 새 노드
  /  |  \                   /  |  \
 A   B   C                 A   B'  C          ← A·C는 원본과 공유
     |                         |
    [잎]                      [잎']           ← 새 노드

깊이는 log₃₂ n이다. 100만 개여도 4단계라 바꿀 때마다 노드 4개(포인터 약 128개)만 복사한다. 32 = 2⁵라서 인덱스나 해시를 5비트씩 잘라 "몇 번째 가지"를 비트 연산으로 바로 구한다.

Rust에서는 길의 노드마다 Rc::make_mut를 부른다. 그 노드를 아무도 공유하지 않으면(혼자 쓰는 누적값, 빌더) 제자리에서 고치고, 누가 옛 버전을 들고 있으면 위처럼 길만 복사한다. 같은 코드가 두 경우를 다 처리한다.

리스트: 영속 벡터와 보기

  • 영속 벡터(Clojure의 PersistentVector): 인덱스 i를 5비트씩 끊어 트리를 내려간다. 마지막 32개는 따로 둔 tail 배열에 있어서, 끝에 붙이기는 tail만 복사한다. tail이 차면 트리에 잎으로 끼우며 그 길만 복사한다.
  • 보기: 큰 리스트는 {벡터, 시작, 끝}이다. xs[a..b], drop, ...rest는 같은 벡터를 가리키며 위치만 다른 보기를 만든다(상수 시간). 끝이 벡터의 끝인 보기에 덧붙이면 벡터를 이어서 키우고, 앞쪽 조각에 덧붙이면 그 조각을 새 벡터로 떼어 낸 뒤 붙인다. 원본은 어느 쪽이든 그대로다.
  • 메모리 규칙: 잘라 낸 결과가 바탕 벡터의 1/4보다 작으면 복사해서 떼어 낸다. 작은 조각이 큰 원본을 붙잡아 메모리에 남기지 않게 하려는 것이다.

맵: HAMT와 넣은 순서

HAMT(Hash Array Mapped Trie)는 키를 32비트로 해시하고 5비트씩 끊어 내려가는 트리다. 노드는 "어느 칸이 차 있는가"를 나타내는 32비트 비트맵과 찬 칸만 담은 배열이다. 칸의 위치는 "내 앞에 찬 칸의 수"로, CPU의 비트 세기 명령 한 번(u32::count_ones)으로 구한다. 해시 32비트를 다 써도 같은 키들은 마지막에 작은 충돌 목록에 둔다.

그런데 HAMT는 해시 순서라 넣은 순서를 모른다. fung 맵은 넣은 순서대로 순회·출력해야 한다(02). 그래서 두 구조를 짝짓는다.

항목들(영속 벡터, 넣은 순서): [("a", 1), ("b", 2), ("c", 3)]
색인(HAMT):                   "a" → 0, "b" → 1, "c" → 2
  • 새 키: 항목 벡터 끝에 붙이고 색인에 위치를 넣는다.
  • 기존 키: 색인으로 위치를 찾아 그 칸만 바꾼다. 순서가 유지된다.
  • remove: 그 칸을 "빈 자리"로 표시하고 색인에서 뺀다. 순회는 빈 자리를 건너뛰고, 빈 자리가 살아 있는 항목보다 많아지면 한 번 다시 만든다.
  • 해시 시드는 실행마다 다르지만(RandomState), 순서는 항목 벡터가 정하므로 출력은 항상 같다.

작은 컬렉션은 예전 그대로

스크립트의 컬렉션은 대부분 작다(설정, 인자, 헤더, 한 줄의 필드). 그래서 리스트는 32개, 맵은 16개 이하면 평평한 배열(맵은 넣은 순서대로 둔 (키, 값) 쌍의 배열을 처음부터 훑는다)로 두고, 넘으면 트리로 바꾼다. 경계값은 M10에서 fung 스크립트로 재서 정했다.

  • 읽기는 경계 16·32·64 어디서도 차이가 없었다(±3%). 몇 ns 차이는 해석기 비용에 묻힌다.
  • 리스트는 32와 64가 같아서 트리 노드 하나 크기인 32로 두었다.
  • 그 결과 크기 8·24·48의 작은 컬렉션 만들기·읽기는 M10 전 대비 ±3% 안이었다.

동시성

트리의 노드는 원자적이지 않은 참조 계수 Rc로 공유한다. fung 값은 실행 스레드 하나만 만지므로(동시성 런타임) 여러 태스크가 같은 리스트나 맵에서 새 값을 만들어도 잠금이 필요 없다. 내장 함수가 결과를 만들 때 쓰는 빌더(ListBuilder, MapBuilder)만 제자리에서 바뀌고, 다 만든 뒤 굳혀서 넘긴다.

모듈 적재

  1. 그래프 먼저. 진입 파일을 컴파일할 때 import 그래프 전체를 읽고 컴파일한다. 순환 import, 비공개 이름 접근, 라이브러리 파일의 최상위 단독 문장, 없는 이름 가져오기는 모두 실행 전에 걸린다(종료 코드 2).
  2. 실행은 처음 쓸 때 한 번. IMPORT 명령이 모듈 본문을 처음 만났을 때 그 태스크에서 실행하고 모듈 값(공개 이름들의 불변 레코드)을 캐시한다. 뒤의 import는 캐시된 값을 받는다.
  3. 모듈마다 전역 표. 함수 값은 자기 모듈의 전역 표를 들고 다니므로, 다른 모듈에서 불려도 자기 전역을 본다.

내장 모듈(fs, json, http, conc …)의 fung 소스는 include_str!로 실행 파일 안에 들어 있고(crates/fung-front/src/extras.rs), import될 때 컴파일된다. prelude(extras/prelude.fung)만 시작할 때 컴파일된다. 스크립트 시작 시간을 지키기 위해서다.

구현은 크레이트 셋이다: 앞단 fung-front(렉서~컴파일러, 포맷터, 로더), 값과 런타임 fung-vm, 명령 fung-cli. 크레이트 의존성은 허용 목록으로 막는다(deny.toml, crates/fung-cli/tests/deps.rs): 앞단은 0개, VM은 운영체제 접근(libc)·정규식 엔진(regex)·TLS(rustls)처럼 직접 짜면 위험한 것만 쓴다. 내장 fung 코드 안에서 난 런타임 에러는 사용자 코드의 가장 가까운 줄을 가리킨다(사용자는 내장 파일을 열 수 없으므로).

동시성 런타임

  • 실행 스레드 하나가 모든 태스크를 돈다(M:1). 태스크는 운영체제 스레드가 아니라 데이터다(Fiber: 스택, 프레임, 이어 가기 상자, 취소 노드, 깨움 표시). 명령을 부른 스레드가 실행 스레드이고, 실행 대기열 맨 앞의 태스크를 자기 Task에 맞바꿔 넣어 돌린 뒤 다시 치워 둔다(vm/sched.rs). 그래서 spawn(s, f)는 스레드를 만들지 않고(태스크 하나 약 1 µs) 실패하지 않으며, 기다리는 태스크 수만 개가 돈다. 값은 원자적이지 않은 Rc로 공유한다. 값을 만지는 스레드가 실행 스레드 하나뿐이기 때문이다. 다른 스레드(신호, 표준 입력 읽기, offload의 일)는 값을 만지지 않고, 실행 대기열에 태스크 번호를 넣거나 받은 편지함에 사건을 넣는다. 여러 코어는 여러 프로세스로 쓴다(reuse_port).
  • 막히는 곳은 하나. await·sleep·send·recv, 받는 끝 순회, 범위가 자식을 기다리는 것은 모두 실행 루프에 주차 요청을 돌려준다(이어 가기의 한 갈래, Next::Park). 기다리는 것에 자기 깨움 표시를 등록한 상자가 줄 맨 위에 남고, 실행 루프는 스케줄러로 돌아간다. 깨우면(Waiter::wake: 실행 대기열에 넣음) 상자가 조건을 다시 보고, 취소·기한은 상자의 되감기로 간다(이미 건너온 값은 취소보다 먼저). 소켓과 TLS는 이벤트 루프 위에서 기다린다(vm/poller.rs: macOS kqueue, Linux epoll, 준비 상태 기반 one-shot 등록). 소켓 연산은 기다리지 않고 한 번 해 보고, 막힐 자리면 어느 fd를 무엇 때문에 기다리는지 말한다. 태스크는 그 fd를 새 토큰으로 루프에 등록하고 주차했다가, 준비되면 처음부터 다시 해 본다(park_io). 그때까지 한 일은 연결(읽어 둔 버퍼, rustls 상태)이나 내장 함수(쓴 바이트 수, 연결 단계)에 남아 있다. 할 일이 없으면 실행 스레드가 그 루프에서 자고, 다른 스레드는 루프의 깨우개를 당긴다. 입출력을 기다리는 태스크가 있으면 차례마다 루프를 시간 제한 0으로 본다. 연결의 읽는 쪽과 쓰는 쪽은 각각 한 연산이 차지하고, 다음 연산은 차례 줄에서 주차한다. 그 밖에 운영체제를 기다리는 일(파일, 이름 조회, 정규식 컴파일)은 offload(일, 마무리)로 넘긴다. 일은 fung 값이 아닌 평범한 데이터만 가지고 다른 스레드에서 돌고, 그동안 태스크는 주차한다. 파일, 이름 조회, 정규식 컴파일은 스레드 풀(vm/pool.rs: 필요할 때 만들고 최대 64개, 10초 놀면 끝남, 꽉 차면 FIFO 줄)에서 돈다. 외부 명령도 이벤트 루프 위에서 기다린다(R4b): 명령의 끝(macOS EVFILT_PROC, Linux pidfd, pidfd가 없으면 풀의 waitid)과 파이프 셋(출력·에러 읽기, 입력 쓰기, 모두 블로킹하지 않는 모드)을 한 상자(CommandWait)가 함께 등록하므로, 두 출력을 채우면서 입력을 받는 명령도 멈추지 않는다. 운영체제를 기다리는 스레드는 표준 입력 읽기 스레드, 신호 스레드, 풀뿐이다. 표준 입력은 읽기 스레드가 줄을 넣고 기다리는 태스크를 깨운다. 계산만 하는 태스크는 호출 1,000번마다 차례를 넘긴다(YIELD_EVERY).
  • 기한은 노드에. timeout(d, f)는 기한이 실린 취소 노드를 만들고, 그 아래에 생기는 노드(범위, 그 안의 태스크)가 기한을 물려받는다(vm/deadline.rs). 타이머 스레드는 없다. 주차한 태스크의 기한은 스케줄러의 타이머 힙에 들어가고, 스케줄러는 가장 이른 기한까지만 잔다. 계산하는 태스크는 차례를 넘길 때 시계를 본다. 처음 본 쪽이 기한의 주인 노드를 만료시켜 아래를 모두 취소한다. 운영체제 스레드는 도중에 멈출 수 없으므로, 기한이나 취소가 오면 offload의 일을 버리거나 기다린다. 줄에서 아직 시작하지 않은 일은 언제나 버린다. 경로만 읽는 일(파일 읽기, 목록, stat, 정규식 컴파일)은 돌던 중이어도 태스크가 곧바로 되감고, 일의 결과는 그 스레드에서 버린다. 무엇을 바꾸는 일(쓰기, 지우기, 핸들)은 시작했으면 끝날 때까지 기다린 뒤 기한을 확인한다. 취소된 쓰기가 나중에 일어나지 않게 하려는 것이다.
  • 취소는 트리. 태스크마다 취소 노드가 있고 부모가 자식을 강하게 든다. 취소되면 원자적 표시가 서고, VM은 CALL·TAILCALL마다 이 표시를 읽는다. 노드에 등록된 잠든 태스크는 곧바로 깬다(소켓을 기다리는 태스크도 같다: 이벤트 루프의 등록은 그 기다림이 끝날 때 지운다).
  • 교착은 바로 판정한다. 모든 태스크는 도는 중이거나, 실행 대기열에 있거나, 스케줄러에 주차해 있다. 이 수는 실행 스레드에서만 바뀐다. 그래서 대기열이 비었을 때 주차한 태스크 중 타이머나 바깥(sleep, 기한, offload, 표준 입력, 정지 채널)이 깨울 것이 하나도 없으면 그것이 정확히 교착이다. 원자 변수도 유예 시간도 없이 E0702를 보고하고 루트를 취소하며 종료 코드 1로 끝낸다. 깨워졌지만 아직 돌지 않은 태스크는 대기열에 있으므로 막힌 것으로 세지 않는다.
  • 채널은 기다리는 쪽의 줄을 직접 둔 구조이고, fung 코드는 두 끝(Sender·Receiver, 각각 Rc 하나)으로만 만진다. 끝을 복사하면 그 Rc가 복사되므로, 참조 계수가 0이 되는 Drop이 곧 마지막 사본이 사라진 순간이다. 보내는 끝은 그때 채널을 닫고, 받는 끝은 닫고 버퍼를 버린다(버퍼는 명시적 스택으로 해제). 닫힌 채널에 보내면 Err({kind: 'closed})(채널을 닫는 것은 다른 태스크, 곧 외부 요인). 채널에 그 채널의 끝을 보내면 E0705다. 자기를 가리키는 고리는 참조 계수로 해제할 수 없으므로 send가 보내는 값을 훑어 막는다. 바뀌는 것을 품지 않은 값은 건너뛴다(큰 리스트·맵은 노드의 기억으로 O(1), 작은 것은 공유된 부분을 한 번씩 훑는다).
  • atom은 불변 값 하나를 가리키는 칸과 판 번호다(vm/atom.rs, Clojure의 atom과 같은 의미). swap은 비교 후 교체라서 f 도중에 다른 태스크가 바꿨으면 f를 다시 돌린다. 그래서 f는 순수해야 하고, VM은 f를 도는 동안(태스크의 pure 깊이) 효과 표에 있는 내장 함수를 부르면 E0707을 낸다. 표는 내장 함수의 주소 집합으로, 처음 쓸 때 한 번 만든다. atom에 담는 값은 변하는 것을 품으면 안 된다(E0708). 이 검사는 영속 벡터의 노드마다 "품었는지"를 기억해 두는 덕에 O(1)이다. 바뀐 노드는 make_mut을 지나며 기억을 잊으므로 복사된 경로만 다시 본다. 0.1의 atom을 3b에서 상태를 쥔 배경 태스크(에이전트)로 바꿨다가 동시성 v2 L5에서 되돌렸다. 순환과 재진입은 위의 두 규칙이 막는다.
  • 범위(구조적 동시성): 태스크는 scope·supervise가 연 범위 안에서만 띄운다(vm/scope.rs). 범위마다 취소 노드가 하나 있어 본문과 자식이 그 아래에서 돌고, 범위는 살아 있는 자식 수와 첫 실패를 든다. 자식 핸들은 쥐지 않으므로 자식이 범위 핸들을 붙잡아도 참조 계수 순환이 생기지 않는다. 본문이 끝나면 새 루트 노드 아래에서 자식이 0이 되기를 기다린다. 그래서 바깥 취소가 와도 자식이 다 끝난 뒤에야 되감고, 그 기다림은 교착 판정에 든다. supervise는 처리기 태스크를 따로 띄우지 않고, 처리하는 쪽이 없을 때 실패한 자식이 처리기가 되어 대기열을 비운다. 범위 밖에 사는 태스크가 없으므로 "아무도 확인하지 않은 실패"를 추적하는 장치가 없다.
  • 신호와 정지 요청: 명령은 시작하자마자 SIGINT·SIGTERM을 모든 스레드에서 막고, 전용 스레드가 sigwait로 받는다(fung-vm/src/signals.rs). 신호 처리기가 아무 스레드의 아무 지점에 끼어들지 않으므로, 신호는 보통 코드로 처리된다: 사건을 실행 대기열에 게시할 뿐 아무것도 기다리지 않는다. 첫 신호는 정지 요청이다(vm/stop.rs). 런타임은 정지 채널의 보내는 끝을 쥐고 받는 끝은 약한 참조로만 기억해서, 그 참조가 살아 있으면(누가 stop_signal()의 끝을 쥐고 있으면) 채널을 닫기만 하고, 아니면 exit처럼 루트를 취소한다. 두 번째 신호는 곧바로 끝낸다. 외부 프로세스는 신호 마스크를 비우고 띄운다(pre_exec).
  • 끝내기: 진입 파일(그 안의 범위가 태스크를 모두 기다린다; 에러나 exit면 취소하고 기다림). 배경 태스크는 없다. HTTP 서버도 자기 범위 안에서 돈다. exit(n)은 어느 태스크에서든 루트를 취소하고, 되감기가 모든 with의 release를 지난다. release는 새 루트 노드(차단 노드)에서 돌아 취소와 기한이 닿지 않고, 도는 동안 목록에 올라 교착 판정이 exit 뒤에도 그것을 보고 멈춘 것을 끊는다(vm/cleanup.rs). 출력은 잠금으로 감싸 한 번의 print가 한 번의 쓰기가 된다.
  • 내장 함수가 VM에 되묻는 길: 내장 함수는 &mut Task를 받아 출력, 입력, 주차, offload를 쓴다. 람다는 직접 부르지 않고 이어 가기로 부탁한다(VM의 이어 가기 프레임). 그래서 람다 안에서 막혀도 Rust 스택에는 VM의 실행 루프 하나만 있고, 막히는 원시 연산은 태스크를 주차한다.
  • 비용: 태스크 만들기 약 1 µs, 버퍼 없는 채널로 값 하나 약 0.5 µs(Apple M2 Max, R1b). 계산만 하는 프로그램은 차례 넘기기 비용이 보이지 않는다. 풀에서 도는 파일 시스템 호출 하나는 약 9 µs다(R3). 한 프로그램이 HTTP 연결 2,000개를 동시에 쥐어도 스레드는 넷이다(R4a). 입출력을 기다리는 태스크가 있으면 스케줄러는 차례가 넘어갈 때와 256바퀴마다 루프를 시간 제한 0으로 본다(한 번이 시스템 호출 하나).

도구

fung check
그래프 적재와 이름 해석까지만 하고 실행하지 않는다. 경고 W0101~W0104는 check와 test에서만 보인다.
fung test
test 블록은 함수로 컴파일되어 등록된다(TEST 명령). 파일마다 새 런타임에서 최상위를 먼저 실행하고 등록된 테스트를 차례로 돌린다. 그동안 명령 자신을 살아 있는 태스크 하나로 세어(Runtime::hold) 블록 사이의 틈을 교착으로 보지 않는다. assert가 실패하면 비교의 양쪽 값을 보여 준다. exit(n)이 불리거나 교착이 보고되면 그 파일의 나머지를 건너뛰고 실패 하나로 센다. 로드에 실패한 파일은 실패로 세고, 여러 파일이 같은 라이브러리 때문에 깨지면 그 에러는 한 번만 찍는다.
fung fmt
AST를 다시 찍지 않고 렉서의 토큰과 주석을 줄 단위로 다시 배치한다. 줄 시작마다 열린 블록·괄호의 스택을 보고 들여쓰기를 정하고, 토큰 쌍 표로 공백을 정하며, 연속 줄의 꼬리 주석과 match의 =>를 맞춘다. 출력을 다시 렉싱해 토큰 열이 입력과 같을 때만 쓴다. 그래서 포맷터 버그가 코드를 바꾸는 일은 사용자에게 닿지 않는다.
REPL
한 줄씩 지금까지의 전역 이름을 알려 주며 컴파일하고 같은 런타임에서 실행한다. 전역 표를 미리 큰 용량으로 잡아 두어, 앞 줄에서 만든 클로저도 뒤에 정의된 이름을 본다. 터미널이면 raw 모드 줄 편집기(직접 구현), 파이프면 단순 읽기다. 재정의를 허용한다. 세션 내내 런타임을 붙잡고 있어 다음 입력을 기다리는 태스크는 교착이 아니다. 한 입력 안의 교착은 그 입력만 실패시키고 새 실행 루트에서 계속하며, 전역(전역에 담은 atom 포함)은 남는다.
fung dump
위 단계들의 중간 결과(ast, core, bytecode)를 보여 준다.

spec/내장 이름 표와 에러 카탈로그(Rust 표에서 생성), 유니코드 표
