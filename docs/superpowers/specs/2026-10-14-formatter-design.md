# 포맷터 (`fung fmt`) 설계

2026-10-14 확정. 08 "포맷터"의 두 결정("옵션 없는 단일 스타일", "주석 보존")을 구체화한다. 결정은 08에도 반영했다.

## 목표

- `fung fmt`가 `.fung` 파일을 **옵션 없는 단일 스타일**로 바꾼다. `gofmt`처럼 공백·들여쓰기·빈 줄·정렬만 바로잡고
  **줄바꿈은 사용자가 쓴 대로** 둔다(긴 줄을 자동으로 접지 않는다).
- 멱등: 포맷한 결과를 다시 포맷하면 같다. 안전: 출력의 토큰 열(공백·줄바꿈 제외)이 입력과 같을 때만 쓴다.
- 저장소의 `.fung` 전부가 포맷터를 통과하고, 테스트가 그것을 지킨다.

## 범위 밖

- 줄 너비에 맞춘 재조판, 이름 바꾸기(camelCase 경고 등), 문장 재배열, 설정 파일. 편집기 연동(LSP)은 별도.

## 방식: 토큰 재배치

AST에서 다시 찍지 않는다. 렉서의 토큰 열(줄바꿈 토큰 포함)과 주석 목록을 받아 **줄 단위**로 다시 쓴다.

```
src ─lexer─▶ 토큰 + 주석 ─▶ 줄로 묶기 ─▶ 줄마다 (들여쓰기, 토큰 사이 공백, 꼬리 주석) ─▶ 정렬 ─▶ 출력
                 └─parser─▶ 구문 검사만 (실패면 포맷하지 않음)
```

- 모든 토큰은 원문 조각(`src[Off:End]`)을 그대로 쓴다. 문자열·원시 문자열(여러 줄 포함)·숫자(`1_000`, `0xff`)·기간·보간 `${…}` 안은 손대지 않는다.
- 파서는 **검사용**으로만 부른다. 구문 에러인 파일은 에러를 찍고 그대로 둔다.
- 이유: 들여쓰기가 의미 없는 문법(01)이라 들여쓰기만 바로잡아도 효과가 크고, 토큰 열 보존을 기계적으로 검증할 수 있으며,
  "한 줄 `match`"처럼 사용자가 고른 배치를 존중한다. 주석을 AST 노드에 붙이는 문제도 생기지 않는다.

## 줄의 구조

렉서의 `Newline` 토큰으로 토큰 열을 줄로 나눈다. 원시 문자열 토큰은 여러 줄이어도 토큰 하나다(그 안의 줄은 나누지 않는다).

- **코드 줄**: 토큰이 하나 이상. 같은 원문 줄에서 마지막 토큰 뒤의 주석은 그 줄의 **꼬리 주석**.
- **주석 줄**: 주석만 있는 줄.
- **빈 줄**: 토큰도 주석도 없는 줄.

## 들여쓰기

- 단위는 공백 2칸. 탭 없음.
- `depth` = 줄의 첫 토큰 앞에서 열려 있는 **블록 수 + 괄호 수**. 줄의 들여쓰기는 `depth`에서 아래 조정을 거친 값 × 2칸.
- **블록**: `fn … (…)`·`fn(…)`·`if …`·`else`·`match …`·`for … in …`·`test "…"`가 시작되면 "블록 대기"를 그 시점의 괄호 깊이와 함께 기록하고,
  **같은 괄호 깊이의 다음 `:`** 가 블록을 연다. `;;`가 가장 안쪽 블록을 닫는다.
  - 맵의 `:`(`{a: 1}`)과 타입 표기의 `:`(`fn f(x: int)`)는 괄호 하나 더 안쪽이라 블록을 열지 않는다. `fn f(x) -> int = e`는 `:`이 없다.
  - 람다 `x => e`는 블록이 아니다. 호출 인자 속 `fn(f): … ;;`는 호출 괄호 안쪽 깊이에서 `fn` 대기 → `:` → 블록.
- **닫는 토큰으로 시작하는 줄**(`;;` `)` `]` `}`): 그 토큰이 닫는 것의 깊이로 내린다(`;;)`는 `;;`가 결정). 예제의 `;;)`가 `map(` 줄과 같은 위치에 오는 규칙.
- **`if` 체인**: `else`·`else if`는 `if`와 같은 깊이. 블록 종류를 스택에 두어, 가장 안쪽 블록이 `if`일 때의 `else`는 체인의 `else`다.
  단, 같은 문장 안에 짝이 없는 `then`이 있으면 그 `else`는 `then … else` 식의 이어짐이다(아래).
- **`match` 절**: 블록 깊이에서 절 줄은 +0(= 블록 안 문장 위치), 절의 본문이 다음 줄로 넘어가면 +1. 어떤 줄이 절인지는 파서와 같은 규칙으로
  판정한다: 그 줄에 괄호 밖 `=>`가 있으면 절. (`xs |> map(x => x)`의 `=>`는 괄호 안이라 절이 아니다.)
- **이어지는 줄**: 첫 토큰이 `|>` `.` `??` `and` `or` `then` `else`(이어짐인 경우)이거나 **앞 줄이 식을 끝낼 수 없는 토큰**
  (이항 연산자·`not`·`=`·`=>`·`->`·`.`, 01의 규칙 1)으로 끝났으면 그 문장의 첫 줄보다 +1. `fn f(x) =` 다음 줄의 본문이 그 예.
  열린 괄호 안에서 줄을 바꾸면 괄호를 연 줄보다 +1이고, 괄호 안에서는 이어짐이 더 들여쓰지 않는다(괄호 안의 줄은 모두 +1).
- 주석 줄은 **다음 코드 줄**과 같은 들여쓰기(블록 끝 직전이면 그 블록 안 깊이). 파일 첫 줄의 shebang은 그대로.

## 토큰 사이 공백

줄 안에서 인접한 두 토큰 사이에 공백 1칸을 둘지 0칸을 둘지 표로 정한다. 기본은 1칸이고 다음은 0칸이다.

| 0칸 | 예 |
|------|------|
| 여는 괄호 뒤, 닫는 괄호 앞 | `f(a, b)`, `[1, 2]`, `{a: 1}`, `()` |
| `,` `;` `:` 앞 | `a, b`, `a; b`, `if c:`, `{a: 1}` |
| `.` 양옆 (필드), `..`·`..=` 양옆 (범위), `...` 뒤 | `m.a.b`, `0..n`, `...rest` |
| 호출·인덱스의 여는 괄호 앞 | `f(x)`, `xs[0]`, `m["k"]`, `f(x)(y)` — 앞 토큰이 이름·태그·`)`·`]`·문자열일 때 |
| `fn` 뒤의 `(` (익명 함수) | `fn(x): … ;;` |
| 접두 `-` 뒤 | `-x`, `-5s` — 앞 토큰이 연산자·여는 괄호·`,`·`=>`·`=`·줄 시작·예약어일 때 |
| 후위 `!` `?` 앞 | `fs.read(p)!`, `parse(s)?` |
| 심볼·문자열·숫자 안 | 토큰 하나라 해당 없음 |

- `;;`: 앞은 1칸(`x ;;`; 줄 첫 토큰이면 들여쓰기만), 뒤에 닫는 괄호가 오면 0칸(`;;)`), 그 외 1칸(`;; else:`는 없음 — `else`는 `;;` 앞에 온다).
- 그 외 전부 1칸: 이항 연산자(`+ - * / // % ** == != < > <= >= = |> ?? -> => |`), `and or not in then else`, 예약어 뒤(`if (`, `return (`),
  맵·이름 인자·타입 표기의 `:` 뒤, `,` 뒤, `;` 뒤.
- 줄 끝 공백은 없다.

## 빈 줄과 파일 끝

- 연속 빈 줄은 하나로. 블록 시작 직후(`:` 다음 줄)와 파일 시작의 빈 줄은 지운다. `;;` 직전의 빈 줄도 지운다.
- 파일 끝은 줄바꿈 하나. 빈 파일은 빈 파일.

## 정렬 (연속 줄)

`gofmt`의 열 맞춤과 같은 메커니즘 하나로 둘을 처리한다. **연속 코드 줄**(사이에 빈 줄·주석 줄이 없고 같은 깊이)의 묶음 안에서:

1. **꼬리 주석**: 꼬리 주석이 있는 코드 줄이 연속되면 그 묶음 안에서 코드 너비의 최대값 + 2칸에 `#`를 맞춘다.
   꼬리 주석이 없는 줄이 끼면 묶음이 끊긴다(`gofmt`의 탭 정렬과 같다).
2. **`match` 절의 `=>`**: 같은 `match` 블록 안의 연속 절 줄들은 패턴(+`when` 조건) 너비의 최대값 + 1칸에 `=>`를 맞춘다.
   본문이 다음 줄로 넘어간 절도 포함한다(01의 예시 `Ok(text) =>` / `Err(e)   =>`).

너비는 **룬 수**가 아니라 **표시 폭**으로 세야 맞지만, 터미널 폭 표는 보류 항목(REPL과 같은 문제)이라 지금은 룬 수로 센다.
한글이 든 줄은 정렬이 한두 칸 어긋날 수 있다. 같은 보류 항목을 풀 때 함께 고친다.

## 명령

```
fung fmt <path>...        # 파일·디렉터리(재귀, `_`로 시작하는 디렉터리 제외). 제자리 수정, 바뀐 파일 이름 출력
fung fmt --check <path>...  # 바뀔 파일 이름만 출력. 있으면 종료 코드 1
fung fmt -                # 표준 입력 → 표준 출력
```

- 구문 에러(렉서·파서): 에러를 찍고 그 파일은 건드리지 않는다. 종료 코드 2. 다른 파일은 계속 처리한다.
- 내부 안전장치가 걸리면(토큰 열 불일치) `error: formatter changed the code of <file>; nothing was written`로 종료 코드 1. 이것은 버그다.
- 쓰기는 같은 권한으로 덮어쓴다. 바뀐 것이 없으면 쓰지 않는다.

## 안전장치

1. 출력을 다시 렉싱해 `Newline`을 뺀 토큰의 (종류, 원문) 열이 입력과 같은지 확인한다. 주석 열(내용)도 같아야 한다.
2. 출력을 다시 포맷하면 같아야 한다(테스트에서 저장소 전체로 확인).

## 구조

```
internal/format/format.go      Format(file, src string) (string, *diag.Error): 전체 파이프라인
internal/format/lines.go       토큰·주석 → 줄 (코드/주석/빈 줄), 꼬리 주석 붙이기
internal/format/layout.go      깊이 상태 기계: 블록 대기·열기·닫기, 괄호, if 체인, match 절, 이어지는 줄
internal/format/spacing.go     토큰 쌍 → 0/1칸
internal/format/align.go       연속 줄 정렬 (꼬리 주석, =>)
internal/format/format_test.go 표 기반 before/after, 멱등·토큰 보존 검사
cmd/fung/fmt.go                명령: 경로 수집, --check, stdin
tests/fmt_test.go              저장소의 모든 .fung이 --check를 통과한다
```

## 테스트

- 표 기반: 입력 조각 → 기대 출력. 들여쓰기(블록·괄호·람다·`if` 체인·`match` 절·이어지는 줄·`;;)`), 공백 표의 행마다 하나, 빈 줄 규칙,
  꼬리 주석·`=>` 정렬, 원시 문자열·보간 보존, shebang, 빈 파일, 줄 끝 공백.
- 성질: 저장소의 모든 `.fung`에 대해 (a) 포맷 후 토큰 열 동일, (b) 두 번 포맷하면 같다, (c) 골든 테스트가 그대로 통과한다
  (`# expect:` 주석이 제자리를 지킨다).
- 명령: `--check`의 종료 코드, stdin, 구문 에러 파일이 그대로인지, 바뀐 파일 이름 출력.
