# Rust 이식 3b단계: atom을 agent로, 채널 규칙 — 설계

2026-10-15. 이식 전체의 결정은 `docs/design/open-questions.md`의 "Rust 이전", 앞 단계는 `2026-10-15-rust-runtime-3a-design.md`(3a).
동시성의 언어 규칙은 `docs/design/05-concurrency.md`.

## 목표

Rust 구현에서 공유되는 변경 칸 `atom`을 없애고, 같은 일을 "상태를 쥔 태스크 + 채널"로 하는 `agent`로 대신한다.
채널에 그 채널 자신을 담아 보내는 것을 에러로 만든다. 이식 중 처음으로 **Go와 Rust가 언어 규칙에서 일부러 갈라지는** 단계이므로,
갈라지는 테스트를 다루는 장치(구현 표시, Rust 골든 실행기)를 함께 만든다.

Go 구현은 바꾸지 않는다(지금 릴리스이자 정답지). 예제·매뉴얼·CHANGELOG는 6단계(릴리스 전환)에서 고친다.

## 결정 사항 (2026-10-15)

| 항목 | 결정 |
|---|---|
| 갈라지는 테스트 | `tests/lang` 파일 맨 위 `# only: go` / `# only: rust`. Go 골든 실행기는 Rust 전용을, Go 대조는 표시된 파일을 건너뛴다. Rust 골든 실행기를 새로 만든다 |
| 대체 라이브러리 | prelude에 `agent(v)`·`swap(a, f)`·`deref(a)`. atom의 이름을 잇는다(옮겨 쓰기는 `atom(` → `agent(`) |
| 에이전트 종료 | **배경 태스크**: 프로그램이 끝나기를 막지 않고, 교착 집계에 들지 않으며, `at_exit` 뒤에 취소된다 |
| `f`의 실패·재진입 | 실패는 상태를 그대로 두고 같은 에러를 부른 쪽 `swap(` 위치에서 다시 낸다. 자기 `f` 안의 같은 에이전트 `swap`은 E0704 |
| 자동 닫힘 | 일반 채널에는 하지 않는다. 에이전트 핸들이 **닫개**: 마지막 사본이 사라지면 요청 채널을 닫아 에이전트가 끝난다 |
| 자기 자신 보내기 | 보내는 값을 깊이 훑어 그 채널이 들어 있으면 E0705. 에이전트 내부 요청은 예외 |
| Go 쪽 | 언어 동작은 그대로. 에러 카탈로그에 E0704·E0705 추가(명세), 골든 실행기에 `# only:` |

메일박스 모델(태스크 번호 + 골라 받기)은 범위 밖이다. 나중에 가더라도 `agent`의 겉모습은 유지하고 내부만 바꿀 수 있다.

## 1. 바뀌는 것과 놓이는 자리

| 무엇 | 어디 |
|---|---|
| 에이전트 fung 코드 | `extras/rust/agent.fung`. Rust 부팅만 읽고 공개 이름을 prelude에 더한다(Go에는 네이티브 `swap`·`deref`가 남아 이름이 부딪히므로 공용 `prelude.fung`에 두지 않는다) |
| 내부 도우미 (Rust 전용, 사용자에게 보이지 않음) | `_native.conc`에: 배경 태스크 띄우기, `f`의 에러를 잡아 값으로 돌려주는 호출, 잡은 에러를 다시 내기, 에이전트 핸들(닫개) 만들기, 검사 없이 보내기(에이전트 내부 요청용), 지금 태스크가 그 에이전트의 태스크인지 |
| E0704·E0705 | Go `internal/diag/catalog.go`에 추가하고 `spec/errors.txt` 재생성. Go는 쓰지 않는다 |
| atom | Rust에서 삭제: `vm/atom.rs`, `Value::Atom`과 그 쓰임새, `conc`의 네이티브 세 개, 테스트 탐침 |
| Go와의 내장 함수 차이 | `spec/builtins.txt`는 Go 기준 그대로. Rust는 차이 목록(빠짐: 네이티브 `atom`·`swap`·`deref`, 더함: `extras/agent.fung`의 공개 이름)을 코드 한 곳에 두고 앞단의 이름 해석과 부팅이 함께 읽는다. 6단계에서 명세에 합쳐진다(과도기 잔가지 목록에 올림) |

## 2. 동작

**에이전트 값.** `agent(v)`는 상태 `v`를 쥔 배경 태스크를 띄우고 핸들을 돌려준다. 핸들은 Rust 쪽 불투명 값(`Value`의 새 종류)이고 닫개다.
- 출력은 `<agent>`(현재 값을 보이지 않는다. 값을 보려면 에이전트에 물어야 해서 출력이 막히는 연산이 되기 때문). atom은 `<atom 1>`이었다.
- `type_of`는 `'agent`, `==`는 같은 에이전트인지.

**`swap(a, f)`.** 요청(`f`와 답장 채널)을 에이전트에 보내고 답을 기다린다. 에이전트는 받은 순서대로 하나씩 처리한다.
- `f(상태)`가 성공하면 상태를 바꾸고 새 값을 답장한다. `swap`은 새 값을 돌려준다.
- `f`가 실패하면 상태는 그대로, 에러를 답장한다. 부른 쪽은 그 에러(번호·문구 그대로)를 자기 `swap(` 위치에서 낸다.
- 에이전트 자신의 `f` 안에서 같은 에이전트에 `swap`하면 E0704 `agent called from inside its own swap`.
- 부른 쪽이 답을 기다리다 취소되면(`exit`, 교착 보고, `cancel(t)`) E0701로 끝나고, **그 요청의 `f`도 함께 취소된다. 갱신은 반영되지 않는다.**
  상태는 그대로이고 에이전트는 다음 요청을 처리한다. atom에서 `f`가 부른 태스크에서 돌아 그 태스크와 함께 취소되던 것과 같은 결과다.
  `f`는 에이전트의 태스크에서 돌지만 부른 태스크의 취소 노드 아래에도 걸린 노드에서 돈다(에이전트 태스크 자체는 취소되지 않는다).
  `f`가 띄운 태스크도 그 노드 아래라서 부른 태스크가 취소되거나 끝나면 함께 끝난다(atom과 같음).
  부른 쪽이 에이전트가 요청을 꺼내기 전에 이미 취소됐으면 그 요청은 건너뛴다(`f`를 부르지 않음).
  `f`가 이미 끝난 뒤에 취소가 오면 갱신은 반영된 채로 남는다(atom에서 `f`가 끝난 뒤의 취소와 같음).
  (2026-10-15 최종 리뷰 뒤 사용자 결정으로 고침. 처음 판은 "에이전트가 이미 요청을 꺼냈다면 갱신은 반영된다"였고, 그러면 바쁜 `f`가 `exit`·프로그램 끝을 붙잡거나 `at_exit` 출력을 잃었다.)

**`deref(a)`.** 현재 값을 물어 받는다(앞에 줄 선 `swap`이 처리된 뒤의 값). 에이전트 자신의 `f` 안에서는 기다리지 않고 바꾸기 전 값을 돌려준다
(atom에서 `swap` 안의 `deref`, Go `TestDerefAndPrintInsideSwap`의 의미를 잇는다).

**배경 태스크와 종료 순서.** 진입 파일 → 일반 태스크 대기 → `at_exit` 핸들러 → 배경 태스크 취소 → 꺼내지 않은 실패 보고.
- 배경 태스크는 핸들러 뒤에 취소한다(핸들러에서 카운터를 읽는 일이 흔하다).
- 배경 태스크는 교착 집계에 들지 않는다. 일반 태스크가 에이전트의 답을 기다리는 것은 교착이 아니다(에이전트가 곧 처리한다).
  일반 태스크가 아무도 보내지 않는 채널에서 막히면 배경 태스크가 살아 있어도 지금처럼 교착이다.

**닫개.** 에이전트 핸들의 마지막 사본이 사라지면 요청 채널을 닫는다. 에이전트 반복문은 `Err('closed)`를 받고 끝난다.
상태 안에 그 에이전트 자신을 넣으면(`swap(a, _ => a)`) 핸들이 사라지지 않아 그 에이전트는 프로그램 끝까지 남는다(배경 태스크라 멈추지 않음, 문서에 적음).

**E0705 `channel sent into itself`.** `send(ch, v)`에서 `v`를 깊이 훑어 `ch`가 들어 있으면 에러. 훑는 곳: 리스트, 맵, 튜플, 태그,
클로저가 붙잡은 값, 에이전트 핸들 안의 요청 채널. 안에 다른 값을 담지 않는 값(문자열, 숫자, 범위 등)은 건너뛴다. 비용은 보내는 값의 크기에 비례한다.
에이전트 내부 요청은 검사하지 않는다(`f`가 에이전트를 붙잡아도 메시지는 곧 꺼내지므로 순환이 남지 않는다). 채널 둘이 서로를 담는 간접 순환은 잡지 못한다(문서에 적음).

## 3. 검증

- **Rust 골든 실행기**(새로): Go `internal/golden`을 옮긴다. `# expect`, `# expect-error`, `# expect-exit`, `# args`, `# stdin`, `# only:`.
  `# only: go`가 아닌 `tests/lang` 파일 전부를 Rust CLI로 돌려 기대값과 비교한다. Go 없이 도는 검사다(6단계 뒤에도 남는다).
- **Go 골든 실행기**: `# only: rust`를 건너뛴다. 알 수 없는 `# only:` 값은 두 실행기 모두 에러.
- **Go 대조(run_parity)**: `# only:` 파일을 건너뛴다. 네이티브 모듈 제외 목록은 4단계까지 그대로.
- **테스트 파일**: `atoms`·`err_atom_reentry`에 `# only: go`. `conc_helpers`의 atom 부분은 Go 전용 파일로 떼어 내고 나머지는 공용.
  Rust 전용 새 테스트: 동시 `swap` 400번, `f` 실패(위치 포함), E0704, `f` 안의 `deref`, `at_exit` 안의 `deref`, 모듈 최상위 에이전트가 있어도 정상 종료,
  E0705(직접·리스트·클로저), 에이전트 내부 요청 예외. 핸들이 사라진 에이전트가 실행 중에 끝나는지는 테스트 전용 탐침(태스크 수)으로.

## 완료 기준

1. Rust 골든 실행기가 `# only: go`가 아닌 `tests/lang` 파일 전부를 통과한다.
2. Go 대조가 표시 없는 파일 전부에서 그대로 같다.
3. Go 테스트 전체가 통과한다(`# only: rust` 건너뛰기, 다시 만든 명세 파일 최신).
4. 커밋 전 검사(`gofmt`·`go vet`·`go test`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`,
   `FUNG_REQUIRE_PARITY=1 cargo test`, `FUNG_REQUIRE_PARITY=1 cargo test --release`)가 모두 통과한다.
5. 학습 노트가 있다.

## 범위 밖

Go 쪽 언어 변경, 예제·매뉴얼·CHANGELOG 수정(6단계), 일반 채널의 자동 닫힘, 메일박스 모델, 4단계(네이티브 모듈·`libc`).
