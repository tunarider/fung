# M10 영속 컬렉션 설계

2026-10-14 확정. 09 "값의 Go 표현"의 "처음엔 단순 복사, 성능이 문제가 되면 같은 인터페이스 뒤에서 영속 자료구조로"를 실행한다.

## 배경: 측정

불변 리스트·맵의 모든 "수정된 사본"이 원본 전체를 복사한다. 그래서 누적과 꼬리 재귀가 n²이다(2026-10-14, 2만 개).

| 패턴 | 5,000개 | 20,000개 |
|---|---|---|
| `fold`로 `put(acc, k, v)` 맵 누적 | 1.01s | 18.54s |
| `[_, ...rest]` 재귀 | 0.06s | 0.68s |
| `ys[1..]` 재귀 | 0.06s | 0.92s |
| `fold`로 `acc + [x]` 리스트 누적 | 0.06s | 0.85s |
| (비교) `map`·`group_by`·`join` 같은 Go 일괄 원시 | 0.03s | 0.03s |

원인: `Map.Put`은 새 키 배열과 새 Go 맵에 모든 항목을 옮긴다. 슬라이스(`value.Slice`)와 `match`의 `...rest`(`vm/match.go`)는 꼬리를 새 배열로 복사한다. `+`(`value.Add`)는 두 리스트를 새 배열에 복사한다.

## 목표

- 위 네 패턴을 2만 개에서 **0.1초 이하**로 만든다.
- 원소 32개 이하 컬렉션의 생성·읽기는 **지금 대비 10% 이내**로 유지한다.
- **언어의 의미는 바뀌지 않는다.** 문법, 값의 비교·출력·순서, 에러 번호와 메시지, 골든 테스트의 기대값, 매뉴얼이 그대로다.

## 범위 밖

- 문자열 누적(`acc + s`): Go 문자열은 연속 바이트라 트리로 바꾸지 않는다. `join`이 답이다(2만 개 0.31s).
- 앞에 붙이기 `[x] + acc`와 큰 리스트끼리의 이어 붙이기: 오른쪽 원소 수에 비례한다(RRB 트리는 복잡해서 제외).
- 튜플: 크기가 고정되고 작으므로 평평한 배열로 둔다.
- `flatten`을 fung으로 옮기기(이 작업 뒤에 측정해서 정한다).

## 두 개의 32

- **트리의 가지 수 32(확정)**: 깊이(읽기)와 노드 복사량(쓰기)의 균형점이다. 100만 개에 깊이 4, `put` 한 번에 포인터 약 128개 복사.
  32 = 2⁵라 인덱스·해시를 5비트씩 잘라 가지를 고르고, HAMT 비트맵이 `uint32` 하나에 들어가 `bits.OnesCount32`로 위치를 구한다.
  Clojure·Scala·Bagwell 논문의 값이다.
- **작은 표현의 경계 32(출발값)**: 이 크기 이하에서는 통째 복사가 트리의 노드 복사와 비용이 같아 트리의 이득이 없고, 스크립트의
  컬렉션 대부분이 이 안에 들어가 읽기 속도가 지금 그대로다. 가지 수와 같을 필요는 없다. **벤치마크로 16·32·64를 비교해 정한다**
  (작은 컬렉션 10% 기준과 누적 성능을 함께 본다). 리스트와 맵의 경계는 따로 정할 수 있다.
  → **측정 결과(Task 6): 리스트 32, 맵 16.** fung 수준에서 읽기는 16·32·64가 같았고(±3%), 평평한 맵의 `put`이 Go 맵 전체를
  복제해 커질수록 비싸므로 맵은 16으로 낮췄다(48개 맵 만들기 M10 전 대비 −31%).

## 리스트: 작은 배열 → 영속 벡터, 자르기는 보기

### 표현

```
List
  ├─ 작음(≤ 32): 평평한 []Value          지금과 같은 구현. 수정은 전체 복사(32개 이하라 싸다)
  └─ 큼(> 32):  view{vec *pvec, start, end}
                  pvec = 32갈래 트리(root, shift) + 끝 32개 tail 배열 + 원소 수
```

- **영속 벡터**(Clojure의 PersistentVector): 인덱스 `i`를 5비트씩 끊어 32갈래 트리를 내려간다. 마지막 32개는 `tail` 배열에 따로 둔다.
  - `At(i)`: 트리 깊이(log₃₂ n, 100만 개에 4)만큼 내려간다.
  - 끝에 붙이기: `tail`(최대 32개)만 복사한다. `tail`이 차면 트리에 끼우며 그 길만 복사한다.
- **보기(view)**: 큰 리스트는 항상 `{벡터, 시작, 끝}`이다. `xs[a..b]`, `drop`, `match`의 `...rest`는 같은 벡터에 위치만 다른 보기를 만든다(상수 시간).
  - 보기의 끝이 벡터의 끝일 때만 그 보기에 덧붙이는 연산이 벡터를 이어서 키운다(영속 벡터의 덧붙이기는 원본을 바꾸지 않으므로 안전하다).
  - 끝이 벡터의 끝이 아니면(앞쪽 조각에 덧붙이기) 보기의 원소로 새 벡터를 만든 뒤 덧붙인다.
  - 메모리 보존: 결과 보기의 길이가 바탕 벡터 길이의 1/4보다 작으면 원소를 복사해 독립한 리스트로 만든다. 작은 조각이 큰 원본을 붙잡지 않게 한다.
- **경계 넘기**: 평평한 리스트가 32개를 넘게 되는 순간 벡터로 바꾼다. 큰 리스트의 보기가 32개 이하가 되면 복사해 평평하게 만든다.

### 연산 비용

| 연산 | 지금 | 바뀐 뒤 |
|---|---|---|
| `xs[i]` | O(1) | 작음 O(1), 큼 O(log₃₂ n) |
| `xs[a..b]`, `drop`, `...rest` | O(b−a) 복사 | O(1) 보기(작아지면 복사) |
| `xs + [x]` | O(n) | 거의 O(1) |
| `xs + ys` | O(n+m) | O(m·log₃₂) |
| `[x] + xs` | O(n) | O(n) (범위 밖) |
| `len(xs)` | O(1) | O(1) |
| `map`·`filter` 등 생성 | O(n) | O(n)(빌더) |

## 맵: 작은 맵 → 순서 벡터 + HAMT

### 표현

```
Map
  ├─ 작음(≤ 16): 키 순서 []string + Go map   지금과 같은 구현. 수정은 전체 복사
  └─ 큼(> 32):  entries: 영속 벡터 [(key, value, live)]   넣은 순서
                index:   HAMT  key → entries 위치
                live, dead: 산 항목 수, 지운 자리 수
```

- **HAMT**(Hash Array Mapped Trie): 키를 `hash/maphash`(프로세스마다 다른 시드)로 32비트 해시하고 5비트씩 끊어 내려간다. 노드는 32비트 비트맵과 찬 칸만 담은 배열이다. 해시가 다 같은 키들은 마지막 층의 충돌 노드(작은 목록)에 둔다. `put`은 바뀐 길의 노드만 복사한다.
- **순서**: 출력·순회 순서는 `entries`가 정하므로 해시 시드와 무관하게 항상 넣은 순서다.
- **연산**
  - 새 키 `put`: `entries` 끝에 덧붙이고 `index`에 위치를 넣는다.
  - 기존 키 `put`: `index`에서 위치를 찾아 `entries`의 그 칸만 바꾼다. 순서가 유지된다(02의 `put` 규칙).
  - `remove`: `entries`의 그 칸을 죽은 자리로 표시하고 `index`에서 뺀다. 순회는 죽은 자리를 건너뛴다. 죽은 자리가 산 항목보다 많아지면 산 항목만으로 다시 만든다(분할 상환 O(1)).
  - `merge(a, b)`: `b`의 항목을 차례로 `put`한다. 비용은 `b`에 비례한다.
- **경계 넘기**: 작은 맵이 16개를 넘게 되는 순간 큰 표현으로 바꾼다. 큰 맵이 `remove`로 16개 이하가 되면 작은 표현으로 바꾼다.

### 연산 비용

| 연산 | 지금 | 바뀐 뒤 |
|---|---|---|
| `m[k]`, `k in m`, `get` | O(1) | 작음 O(1), 큼 O(log₃₂ n) |
| `put`(새 키·기존 키) | O(n) | 거의 O(1) |
| `remove` | O(n) | 거의 O(1) |
| `merge(a, b)` | O(n+m) | O(m·log₃₂) |
| 순회·`keys`·`pairs`·출력 | O(n) | O(n) |

## 동일성·비교·출력

- 규칙은 02 그대로다. 리스트 `==`는 원소를 차례로, 맵 `==`는 키 집합과 값(순서 무시), 순서 비교는 앞 원소부터다.
- 빠른 길: 두 값이 같은 바탕을 같은 범위로 가리키면 비교 없이 같다.
- 출력은 리스트는 차례로, 맵은 넣은 순서다.

## Go 쪽 API

값 층 밖(prelude, native, vm, nat, json)은 아래 API만 쓴다. 내부 표현은 `internal/value` 밖으로 나가지 않는다.

```go
// 리스트
func NewList(items []Value) *List          // 슬라이스를 넘겨받아 만든다(이후 호출자는 그 슬라이스를 바꾸지 않는다)
func (l *List) Len() int
func (l *List) At(i int) Value             // 0 <= i < Len(), 범위 검사는 호출자(index.go)가 한다
func (l *List) All() iter.Seq2[int, Value] // for i, v := range l.All()
func (l *List) Slice(lo, hi int) *List     // 보기 또는 복사(규칙은 위)
func (l *List) Append(v Value) *List
func (l *List) Concat(o *List) *List
func (l *List) ToSlice() []Value           // 새 슬라이스(O(n)). Go 함수가 배열이 꼭 필요할 때만

type ListBuilder struct{ … }               // 만드는 동안만 제자리로 쌓는다
func (b *ListBuilder) Add(v Value)
func (b *ListBuilder) List() *List         // 굳힌다. 이후 b는 쓰지 않는다

// 맵: 지금의 Get/Keys/Len/Put을 유지하고 아래를 더한다
func (m *Map) Remove(k string) *Map
func (m *Map) Merge(o *Map) *Map
func (m *Map) All() iter.Seq2[string, Value]
type MapBuilder struct{ … }                // Set(k, v), Map()
```

- 지금 공개 필드 `List.Items`를 쓰는 곳(11개 파일 43곳)은 위 메서드로 바꾼다.
- `Map.Set`(만드는 중 제자리 수정을 관례로 허용)은 `MapBuilder.Set`으로 옮긴다. "남이 볼 수 없는 맵만 바꾼다"를 관례가 아니라 타입이 보장하게 하기 위해서다.
- 튜플(`Tuple.Items`)은 그대로 둔다.

## 동시성

- 굳힌 리스트·맵은 다시 바뀌지 않으므로 태스크 사이에 잠금 없이 공유한다(지금과 같다).
- 영속 벡터의 덧붙이기도 기존 노드를 바꾸지 않고 새 노드를 만들므로 같은 값에서 두 태스크가 동시에 덧붙여도 안전하다.
- 빌더는 만든 태스크 안에서만 쓰고 굳힌 뒤 버린다.

## 구조

```
internal/value/pvec.go          영속 벡터(트리 + tail): at, append, 빌더
internal/value/list.go          List: 작은 배열 / 보기, Slice·Append·Concat·All·ToSlice, ListBuilder
internal/value/hamt.go          HAMT: get, set, delete, 충돌 노드
internal/value/omap.go          큰 맵: entries + index + live/dead, 다시 만들기
internal/value/collections.go   Map: 작은 표현 / 큰 표현 전환, MapBuilder (기존 파일)
internal/value/*_test.go        성질 테스트(참조 구현과 비교), 경계 테스트
internal/value/bench_test.go    벤치마크(누적·재귀·작은 컬렉션)
tests/perf_test.go              거친 회귀 테스트: 2만 개 누적·재귀 각 0.3초 이하(지금 13~60ms, n²로 돌아가면 0.74~7.5초)
```

## 테스트

- **성질 테스트**: 무작위 연산 열(`put`/`remove`/`merge`, `append`/`slice`/`concat`/`At`) 수천 개를 새 구조와 "평평한 배열·Go 맵으로 된 참조 구현"에 똑같이 적용해 결과(내용, 순서, 길이)가 같은지 본다. 매 단계 이전 버전들을 다시 읽어 **바뀌지 않았는지**(불변성)도 본다. 크기는 경계(31·32·33, 1,024, 32,768 근처)를 지나가게 한다.
- **HAMT 충돌**: 해시 함수를 테스트에서 바꿔 끼울 수 있게 두고, 모든 키가 같은 해시가 되게 해 충돌 노드를 시험한다.
- **동시성**: 같은 값에서 여러 고루틴이 `put`/`append`하는 테스트를 `-race`로 돌린다.
- **기존 테스트**: 골든과 단위 테스트가 기대값 변경 없이 통과한다.
- **성능**: 벤치마크로 목표를 확인하고, `tests/perf_test.go`가 n²로 되돌아가는 것을 막는다(0.3초 기준: 1초로는 리스트 쪽 회귀 0.74~0.8초를 놓친다).
