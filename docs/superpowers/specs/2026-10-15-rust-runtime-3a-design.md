# Rust 이식 3a단계: 동시성 런타임 (Go와 동등) — 설계

2026-10-15. 이식 전체의 결정은 `docs/design/open-questions.md`의 "Rust 이전", 앞 단계는 `2026-10-15-rust-vm-design.md`(2단계).
동시성의 언어 규칙은 `docs/design/05-concurrency.md`.

## 목표

fung의 동시성(태스크, 채널, 취소, 타임아웃, `atom`, 교착 감지, 꺼내지 않은 실패 보고, 어디서든 `exit`)을 Rust로 옮긴다.
동시성 골든 테스트 9개를 포함한 실행 비교 전체에서 `fung run`의 표준 출력·표준 에러·종료 코드가 Go 구현과 **바이트 단위로 같아야** 한다.

3단계는 둘로 나눈다(2026-10-15 결정).
- **3a(이 문서)**: Go와 같은 의미. `atom`도 Go 그대로 옮긴다. Go 대조로 런타임 전체를 검증한다.
- **3b(별도 스펙)**: Go와 일부러 달라지는 언어 변경. `atom` 제거와 대체 라이브러리, 채널에 자기 자신 보내기 에러, 보낼 쪽이 사라진 채널 자동 닫힘,
  구현별로 갈라지는 골든 테스트의 처리, CHANGELOG.
- 닫힌 파이프의 진짜 신호 죽음(`libc`)은 첫 크레이트를 들이는 4단계로 옮긴다.

공부를 겸한다. 운영체제 스레드와 그린 스레드, 잠금과 조건 변수, `unsafe`의 근거를 지키는 법을 학습 노트로 남긴다.

## 결정 사항

| 항목 | 결정 |
|---|---|
| 태스크 실행 | **태스크마다 운영체제 스레드 + 실행권 잠금 하나**(Python GIL, OCaml 4와 같은 모델). fung 코드는 실행권을 쥔 스레드 하나만 돌린다 |
| 그린 스레드 | 3a에서는 만들지 않는다. 막히는 지점을 함수 하나로 모아 나중에 갈아끼울 수 있게 한다. 4단계의 이벤트 루프와 함께 다시 판단 |
| 태스크별 힙·경계 복사 | 3a에서는 하지 않는다. 실행권 잠금 아래에서 값 공유가 안전하고, 불변 값이라 프로그램은 차이를 볼 수 없다. 여러 코어로 갈 때 한다 |
| `atom` | Go 그대로(3b에서 제거) |
| `libc` 신호 | 4단계 |
| 의존성 | 크레이트 0개(표준 라이브러리의 `Mutex`·`Condvar`·`thread`) |

기록해 둔 결정("스케줄러는 VM이 직접, 막힌 내장 함수는 대체 워커")과 다르게 가는 이유: 대체 워커도 운영체제 스레드 둘이 같은 `Rc` 값을
만지게 하므로 결국 실행권 잠금이 필요하다. 3a는 그 잠금만 먼저 만들고, 스케줄러는 실제로 필요해질 때(태스크 수만 개, HTTP 서버) 얹는다.

## 1. 구조

### 런타임 분할 (2단계 최종 리뷰)

`Task<'rt>`가 `&'rt mut Runtime`을 쥐는 지금 구조는 태스크 여럿이 동시에 살아 있을 수 없다. 둘로 나눈다.

| 부분 | 내용 |
|---|---|
| 공유 | 표준 출력·에러·입력, `at_exit` 목록, 종료 코드와 종료 요청, 모듈(초기화는 한 번만), 소스 맵, 태스크 수 집계(교착 감지), 꺼내지 않은 실패 |
| 태스크별 | 값 스택, 호출 프레임, 인자 버퍼, 취소 표시(부모·자식 트리), 결과 칸 |

내장 함수가 런타임을 쓰는 통로(`t.stdout()`·`t.at_exit`·`t.call` 등)는 그대로 두어 고칠 범위를 VM 안쪽에 묶는다.

### 실행권 잠금

- 실행권은 표준 라이브러리 `Mutex` 하나다. 공유 부분과 모든 동시성 상태(채널 버퍼, 태스크 결과, atom 상태)는 이 잠금 아래에 있어 따로 잠금이 없다.
- `Rc` 값을 스레드 사이로 넘기는 곳에 `unsafe impl Send`(또는 `Sync`) 감싸개가 필요하다. 근거는 하나다: **fung 값은 실행권을 쥔 스레드만 만진다.**
  - 놓치기 쉬운 곳: 값의 해제(`Drop`)도 참조 계수를 고치므로 실행권을 쥔 채로 한다. 태스크 스레드가 끝날 때 그 태스크의 값을 놓는 일 포함.
  - 내장 함수 값(`&'static Native`)은 지금 스레드마다 따로 만들어진다. 프로세스 전체에 하나만 두도록 바꾼다(안 그러면 스레드마다 누수, `print == print`가 태스크 사이에서 거짓).
  - 디버그 빌드는 막히는 지점, 태스크 시작·끝, 값 해제 경계에서 "지금 실행권을 쥐고 있는가"를 단언한다.
- **차례 넘기기**: 막히지 않고 계산만 하는 태스크가 다른 태스크를 굶기지 않도록, VM이 일정 횟수의 호출·뒤로 뛰기마다 실행권을 내려놓고
  줄 선 순서대로 넘긴다(표준 `Mutex`는 공정하지 않으므로 순번을 둔다). 태스크가 하나뿐이면 넘길 상대가 없어 비용이 거의 없어야 한다.

### 막히는 지점

`recv`·`send`·`await`·`sleep`·`swap`(다른 태스크가 쥔 atom)과 표준 입력·외부 프로세스 대기는 모두 하나의 함수를 거친다.
- 3a: 조건 변수(`Condvar`)로 기다린다. 잠금을 내려놓는 일과 잠드는 일이 한 번에 일어나 신호를 놓치지 않는다. 타임아웃은 시간 제한 대기,
  취소는 막힌 태스크를 깨워서.
- 표준 입력·외부 프로세스는 실행권만 내려놓고 운영체제 호출로 기다린다(교착 집계에 넣지 않음, 05와 같음).
- 나중에 그린 스레드로 바꿀 때 이 함수가 "태스크를 주차하고 스케줄러로 돌아간다"로 바뀐다.

### 스택

메인 태스크는 지금처럼 4 GiB. `spawn`한 태스크의 스레드는 고정 크기(1 GiB, Go 고루틴의 최대 크기와 같다. 가상 주소 예약일 뿐이다. 처음 256 MiB는 내장 함수가 람다를 깊이 겹쳐 부르는 프로그램에서 넘쳤다, 최종 리뷰).
fung 함수끼리의 재귀는 VM 힙의 프레임이라 Rust 스택을 쓰지 않는다. Rust 스택은 내장 함수가 람다를 부르며 겹칠 때만 쓴다. 정확한 크기는 계획에서 재서 정한다.

### 값

`Value`에 Go와 같은 동시성 값을 더한다: 태스크 핸들, 채널, atom. 16바이트를 유지한다(얇은 `Rc`).
출력 서식·`type_of`·같음 비교는 Go와 같다.

## 2. 동작

규칙은 05 문서와 Go 구현(`internal/vm/task.go`·`channel.go`·`atom.go`·`conc.go`·`runtime_conc.go`)을 따른다.

- **태스크**: `spawn(f)`은 새 스레드에서 `f`를 돌리고 핸들을 준다. `await(t, timeout:)`은 결과까지 기다리고 결과는 저장된다(두 번 불러도 같음,
  타임아웃으로 끝난 `await`는 꺼낸 것이 아님). 결과 모양(`Err({kind: 'error', message: …})`·`'cancelled`·`'timeout`)은 Go와 같다.
- **취소**: `cancel(t)`은 그 태스크와 자식 전체에 표시를 남기고 막힌 태스크를 깨운다. VM이 함수 호출·반복 지점과 막히는 연산에서 확인하고
  내부용 E0701로 되감는다. 취소된 태스크는 실패가 아니다. `sleep`도 취소되면 중간에 끝난다(2단계의 단순 대기를 대신함).
- **채널**: 버퍼 없는 채널은 받는 쪽이 가져갈 때까지 `send`가 기다린다(맞교환). 버퍼 있는 채널, `close`, 닫힌 뒤의 `Err({kind: 'closed})`,
  `recv`의 타임아웃. 채널은 순회 대상이라 순회하는 내장 함수가 닫힐 때까지 받는다. 내장 함수 안에서 막혀도 그대로 동작한다.
- **atom**: `swap(a, f)`이 도는 동안 그 atom을 붙잡는다. 다른 태스크의 `swap`은 기다리고, 같은 태스크의 재진입은 E0703. `deref`는 기다리지 않는다.
- **`_native.conc.spawn_awaited`**: 처음부터 꺼낸 것으로 치는 태스크(`pmap`·`fan_in`용).
- **종료**: 진입 파일이 끝나면 남은 태스크를 기다린다. `exit(n)`은 어느 태스크에서든 전체를 취소하고 `at_exit` 뒤 n. 진입 파일이 에러로 죽으면
  남은 태스크를 취소하고 `at_exit` 뒤 1. `at_exit` 핸들러도 살아 있는 태스크로 센다.

Go와 달라지는 곳(둘 다 05의 규칙 안에서 더 정확해지는 쪽):
- **꺼내지 않은 실패의 보고 시점**: Go는 버려진 핸들을 GC가 알아챌 때(수 초~2분 늦게) 보고한다. Rust는 마지막 핸들이 사라지는 순간을 안다.
  핸들이 사라질 때 이미 실패했으면 그때, 아직 실행 중이면 실패하는 순간 보고한다. 프로그램 끝의 훑기와 종료 코드 1은 그대로. 내용은 같고 시점만 이르다.
- **교착 감지**: Go는 "모두 막힘"이 50ms 변화 없이 이어지면 판정한다(깨어났지만 아직 스케줄되지 않은 태스크 때문의 거짓 양성을 피하려고).
  Rust는 깨우는 쪽이 잠금 안에서 "실행 가능"으로 바꿔 개수가 정확하므로 유예 없이 판정한다. 출력은 같다.

## 3. 검증

- **정답지 비교**: `crates/fung-cli/tests/run_parity_skip.txt`의 `concurrency` 9개를 지워 비교에 넣는다(네이티브 모듈 9개는 4단계까지 남음).
  최소 비교 건수를 늘린다. 직접 만든 `-e` 사례를 더한다: 내장 함수 안에서 막힘, 자식으로의 취소 전파, 태스크 안의 `exit`, 교착,
  `retry`·`pmap`·`fan_in`, 꺼내지 않은 실패, `await` 타임아웃, 닫힌 채널 순회.
  2단계의 "동시성 내장 함수는 E0805" 단언 테스트들은 실제 동작 테스트로 바꾼다.
- **Go 단위 테스트 이식**: `internal/vm`의 `conc_test.go`·`context_test.go`·`unretrieved_test.go`와 runtime_conc 관련 테스트. HTTP 테스트는 4단계.
- **흔들림 검사**: Rust에는 Go `-race` 같은 표준 도구가 없다. 동시성 테스트를 릴리스 빌드에서 반복(수십 번) 실행해 결과가 실행 순서에 따라 흔들리지 않는지 본다.
  `unsafe` 근거는 디버그 단언(1절)으로 지킨다.
- **성능**: 기존 벤치마크(fib·loop·str·map)가 5% 넘게 느려지지 않는다(태스크 하나일 때 잠금과 차례 넘기기의 비용). 새 벤치마크
  `bench/`에 채널 주고받기와 태스크 대량 생성을 더해 Go와 비교한다. 태스크 수천 개에서 Go보다 느린 것은 예상된 결과이고, 그린 스레드를 다시 판단할 자료로 노트에 남긴다.

## 완료 기준

1. 동시성 골든 테스트 9개를 포함한 실행 비교 전체가 Go와 바이트 단위로 같다.
2. 동시성 테스트를 반복 실행해도 결과가 흔들리지 않는다.
3. 기존 벤치마크가 5% 넘게 느려지지 않는다.
4. 커밋 전 검사(`gofmt`·`go vet`·`go test`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`,
   `FUNG_REQUIRE_PARITY=1 cargo test`, `FUNG_REQUIRE_PARITY=1 cargo test --release`)가 모두 통과한다.
5. 학습 노트가 있다.

## 범위 밖

3b(`atom` 제거, 채널 규칙 변경), 4단계(네이티브 모듈 `fs`·`path`·`json`·`time`·`regex`·`http`, `libc` 신호), 그린 스레드, 여러 코어, 태스크별 힙과 경계 복사, 도구(5단계).
