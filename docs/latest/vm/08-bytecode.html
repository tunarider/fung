바이트코드와 스택 머신

트리를 평평한 명령 목록으로 바꾸고, 값을 쌓았다 꺼내는 작은 기계로 실행한다. 명령 하나는 32비트, 기계의 상태는 값 스택과 프레임 목록이 전부다.

트리에서 목록으로

7장까지 소스는 이름이 모두 정해진 코어 트리가 되었다. 2장에서 본 것처럼 트리를 그대로 걸어 다니며 실행할 수도 있지만, fung은 트리를 한 번 더 바꿔 바이트코드라는 평평한 명령 목록을 만들고, 그것을 하나씩 실행하는 가상 기계(VM)를 둔다.

명령 목록으로 바꾸려면 "트리의 계산 순서"를 "명령의 순서"로 펴야 한다. 이때 가장 단순한 방법이 스택 머신(stack machine)이다.

스택 머신

스택(stack)은 접시 더미 같은 자료구조다. 맨 위에 올리고(push), 맨 위에서 꺼낸다(pop). 스택 머신의 명령은 대부분 이 스택만 다룬다.

  • 값을 만드는 명령은 값을 스택 위에 올린다. CONST 2는 2를 올린다.
  • 계산하는 명령은 필요한 값을 스택 위에서 꺼내 계산하고, 결과를 다시 올린다. MUL은 둘을 꺼내 곱한 값을 올린다.

명령에 "어느 값을"이 적혀 있지 않다. 늘 스택의 맨 위다. 그래서 명령이 짧고, 컴파일러는 트리를 자식 먼저, 부모 나중의 순서(후위 순회, post-order)로 걸으며 명령을 내기만 하면 된다. 1 + 2 * 3을 보자.

print(1 + 2 * 3)

트리에서 *가 +의 자식이었으므로(4장) MUL이 ADD보다 먼저 나왔다. 괄호도 우선순위 표도 필요 없다. 트리 모양이 이미 순서를 정해 두었다. 이렇게 연산자를 피연산자 뒤에 적는 표기를 후위 표기(역폴란드 표기)라고 하는데, 스택 머신의 바이트코드는 그 표기를 그대로 실행하는 것이다.

레지스터 머신

다른 길도 있다. 레지스터 머신(register machine)은 실제 CPU처럼 번호 붙은 칸(레지스터)을 두고, 명령이 칸 번호를 직접 말한다. MUL r3, r1, r2는 "1번 칸과 2번 칸을 곱해 3번 칸에". 같은 계산을 더 적은 명령으로 할 수 있어서 명령을 읽고 갈래를 타는 비용이 준다. 대신 컴파일러가 "어느 값을 어느 칸에 둘지" 배정해야 해서 복잡해지고, 명령 하나가 칸 번호를 여럿 담느라 길어진다.

명령 하나의 생김새

fung의 명령 하나는 32비트 단어 하나다. 위 8비트가 명령의 종류(opcode), 아래 24비트가 피연산자(operand)다.

 31        24 23                                 0
┌────────────┬────────────────────────────────────┐
│   명령     │            피연산자                │
│  (8비트)   │            (24비트)                │
└────────────┴────────────────────────────────────┘
 CONST 5  =  명령 0번(CONST) | 피연산자 5

8비트면 명령을 256가지까지 둘 수 있고, fung은 지금 53가지를 쓴다. 24비트면 피연산자로 1,600만 남짓까지 적을 수 있어서 상수 번호, 슬롯 번호, 점프할 명령 번호에 충분하다. 명령을 꺼낼 때는 비트 연산 둘(오른쪽으로 24칸 밀기, 아래 24비트 걸러내기)이면 된다.

피연산자에 수 두 개가 필요한 명령은 24비트를 나눠 쓴다. CALL은 아래 12비트에 위치 인자 수, 그 위 12비트에 이름 인자 수를 담는다. 역어셈블 출력의 ; 1 positional, 0 named가 그것을 풀어 보인 것이다.

함수 원형: Proto

컴파일러는 함수마다 명령 목록을 하나씩 만든다. 파일 본문도 <main>이라는 이름의 함수다. 그 결과물을 함수 원형(prototype, 코드에서 Proto)이라고 한다. 원형에는 명령만 있는 게 아니다.

  • code: 명령 목록.
  • consts: 상수 풀(constant pool). 명령에 큰 값을 직접 넣을 수 없으니, 수·문자열·내장 함수 같은 상수는 여기 두고 명령은 번호로 가리킨다. CONST 1은 "상수 풀 1번을 올려라"다. 같은 상수는 한 번만 넣고 다시 쓴다.
  • pos: 명령마다 소스 위치 하나. code와 나란한 배열이다(7장).
  • num_locals: 이 함수가 쓰는 슬롯 수(6장).
  • params: 매개변수 표(이름, 기본값이 있는가, ...rest인가, 타입 표기).
  • protos: 안쪽 함수들의 원형. CLOSURE n이 n번 자식을 가리킨다.
  • 그 밖에 붙잡을 값 목록(9장), 타입 표기, 패턴 트리 등.

원형이라고 부르는 이유는 이것이 아직 실행할 수 있는 함수 값이 아니라 함수의 "틀"이기 때문이다. 실행 중에 CLOSURE 명령이 이 틀과 붙잡은 값을 묶어 진짜 함수 값(클로저)을 만든다(9장).

이제 이 책의 두 줄을 읽어 보자.

fn double(x) = x * 2
print(double(21))

0002  2:1   CONST        0    ; <fn print>
0003  2:7   LOADGLOBAL   0    ; double
0004  2:14  CONST        1    ; 21
0005  2:13  CALL         1    ; 1 positional, 0 named
0006  2:6   CALL         1    ; 1 positional, 0 named
0007  2:1   POP
0008  2:1   CONST        2    ; nil

== double ==
0000  1:16  MOVELOCAL    0
0001  1:20  CONST        0    ; 2
0002  1:18  MUL
0003  1:14  RETURN
  • == <main> ==, == double ==: 원형 하나에 절 하나. 파일 본문 다음에 안쪽 함수들이 차례로 나온다.
  • 첫 열 0000: 명령 번호. 점프는 이 번호로 간다.
  • 둘째 열 1:16: 그 명령의 소스 위치(줄:칸). 호출(CALL)은 여는 괄호 (의 자리, 연산은 연산자의 자리를 갖는다. 그래서 double(21)의 호출은 2:13, print(…)의 호출은 2:6이다.
  • 셋째, 넷째 열: 명령 이름과 피연산자.
  • ; 뒤: 피연산자를 풀어 쓴 설명. 상수 번호면 그 상수의 값(; 21, ; <fn print>), 전역 번호면 그 이름(; double), CALL이면 인자 수.

print가 CONST 0 ; <fn print>인 것을 눈여겨보자. 6장에서 print는 (prelude print)로 해석되었고, 컴파일러는 그 내장 함수 자체를 상수 풀에 넣었다. 실행 중에 "print라는 이름의 함수"를 찾는 일이 없다.

따라가기: 명령 하나씩

VM은 <main>의 0번 명령부터 시작한다. 스택은 비어 있다.

번호명령하는 일스택(오른쪽이 맨 위)
0000CLOSURE 0자식 원형 0번(double)으로 함수 값을 만들어 올린다<fn double>
0001STOREGLOBAL 0꺼내서 전역 칸 0번에 둔다(빔)
0002CONST 0상수 0번 print를 올린다print
0003LOADGLOBAL 0전역 0번 double을 올린다print double
0004CONST 121을 올린다print double 21
0005CALL 1double을 인자 하나로 부른다(아래)print 42
0006CALL 1print를 인자 하나로 부른다. 42를 찍고 nil을 돌려준다nil
0007POP문장의 값을 버린다(빔)

CALL은 피연산자를 보고 스택에서 "함수, 그 위의 인자들"을 찾는다. 인자가 하나니까 맨 위가 인자, 그 아래가 함수다. 호출할 함수가 fung 함수(double)면 VM은 새 프레임(frame)을 쌓는다. 프레임은 "지금 실행 중인 함수 하나"의 기록이다.

Frame {
  proto  실행할 원형(double)
  ip     다음에 실행할 명령 번호(0부터)
  base   이 함수의 슬롯이 스택의 몇째 칸부터 시작하나
  …      클로저, 전역 표, 꼬리 호출 횟수
}

fung 함수를 매개변수 수 그대로 부르는 흔한 경우, 스택에 이미 놓인 인자가 그 자리에서 새 프레임의 첫 슬롯이 된다. 인자를 따로 복사하지 않는다. double의 프레임은 base가 인자 21이 놓인 칸이고, 슬롯 0(x)이 곧 그 21이다.

스택:  [ print | 21 ]
              ↑
          base(슬롯 0 = x)

이제 VM은 double의 0번 명령으로 간다.

번호명령하는 일스택(double의 칸부터)
0000LOADLOCAL 0슬롯 0(x)을 복사해 올린다. 실제 위치는 base + 021 │ 21
0001CONST 0double의 상수 0번, 2를 올린다21 │ 21 2
0002MUL둘을 꺼내 곱한 42를 올린다21 │ 42
0003RETURN맨 위 42를 꺼내고, 스택을 base까지 자르고, 프레임을 버리고, 부른 쪽 스택에 42를 올린다→ print 42

(│ 왼쪽이 슬롯, 오른쪽이 계산 중인 값이다.) 슬롯과 계산 중인 값이 같은 스택 하나에 이어서 산다. 함수를 부를 때마다 그 위에 새 프레임의 칸이 이어 붙고, 돌아오면 잘려 나간다. RETURN이 base까지 잘라 내므로 함수가 남긴 임시 값이 새어 나가지 않는다.

상수 풀이 원형마다 따로라는 점도 보자. <main>의 CONST 0은 print, double의 CONST 0은 2다.

print는 Rust로 쓴 내장 함수라 프레임을 쌓지 않는다. VM은 인자를 꺼내 Rust 함수를 바로 부르고, 돌려준 값을 스택에 올린다.

실행 루프

VM의 심장은 반복문 하나다.

반복:
  f = 맨 위 프레임
  명령 = f.proto.code[f.ip]
  f.ip = f.ip + 1
  명령의 종류에 따라:
    CONST     → 상수 풀[피연산자]를 올린다
    LOADLOCAL → 스택[f.base + 피연산자]를 올린다
    MUL       → 둘을 꺼내 곱하고 올린다(넘치거나 타입이 틀리면 에러)
    JUMP      → f.ip = 피연산자
    CALL      → 새 프레임을 쌓거나 내장 함수를 부른다
    RETURN    → 프레임을 버리고 값을 부른 쪽에 넘긴다
    …

명령을 가져오고(fetch), 무엇인지 보고(decode), 실행한다(execute). 실제 CPU가 하는 일과 같은 순환이다. 프레임은 VM의 목록에 쌓일 뿐이라, fung 함수가 함수를 불러도 이 반복문이 Rust 함수를 재귀로 부르지 않는다(2장).

정수끼리의 덧셈·곱셈에는 빠른 길이 있다. 두 값이 모두 정수면 바로 계산하고, 넘칠 때만 값 층의 일반 함수로 넘겨 E0503 integer overflow를 만든다. fung은 정수가 조용히 넘쳐 돌아가는 것을 허용하지 않는다.

fn double(x) = x * 2
print(double(9223372036854775807))
error[E0503]: integer overflow
  --> example.fung:1:18
  |
1 | fn double(x) = x * 2
  |                  ^
  |
 call path (innermost first):
   example.fung:1 double
   example.fung:2 <entry>

점프: if는 어떻게 되나

명령 목록에는 가지가 없다. 조건에 따라 다른 곳을 실행하려면 점프(jump)를 쓴다.

  • JUMPIFFALSE n: 맨 위 값을 꺼내 거짓이면 n번 명령으로 간다. 참이면 다음 명령으로. 불이 아니면 E0505.
  • JUMP n: 무조건 n번으로 간다.

if c then a else b는 이렇게 펴진다.

      c 계산
      JUMPIFFALSE  else로
      a 계산
      JUMP         끝으로
else: b 계산
끝:
fn sign(n) = n < 0 then "minus" else "plus"
print(sign(-3))

0003  2:7   LOADGLOBAL   0    ; sign

0006  2:11  CALL         1    ; 1 positional, 0 named
0007  2:6   CALL         1    ; 1 positional, 0 named
0008  2:1   POP

0010  1:1   RETURN

== sign ==
0000  1:14  MOVELOCAL    0

0002  1:16  LT
0003  1:16  JUMPIFFALSE  6

0005  1:20  JUMP         7
0006  1:38  CONST        2    ; "plus"

sign의 3번 JUMPIFFALSE 6은 조건이 거짓이면 6번("plus")으로, 참이면 4번("minus")을 올린 뒤 5번 JUMP 7로 끝(RETURN)에 간다. <main>의 CONST 1 ; 3 다음 NEG도 보자. 3장에서 말한 대로 -3은 토큰 둘이고, "3을 올리고 부호를 바꿔라"가 되었다.

컴파일러가 JUMPIFFALSE를 낼 때는 else가 몇 번에서 시작할지 아직 모른다. 그래서 피연산자를 0으로 두고 그 명령의 번호를 기억해 두었다가, else를 낼 차례가 되면 그때의 번호로 나중에 채운다(backpatching). 코드의 Proto::patch가 그 일이다.

문장과 지역 변수

블록 안의 문장들은 차례로 컴파일된다. 대입은 "값 계산, 그다음 STORELOCAL(블록 안) 또는 STOREGLOBAL(최상위)"이다. 식 문장은 값을 계산한 뒤 POP으로 버린다. 버리는 값이 Err이면 POP이 E0606을 낸다. 실패를 조용히 버리지 않게 하는 장치다.

fn report(xs):
  total = sum(xs)
  avg = total / len(xs)
  "total ${total}, avg ${avg}"
;;
print(report([3, 4, 5]))

  • CONCAT 4: 보간 조각 넷을 꺼내 하나의 문자열로 잇는다(5장의 concat).
  • 마지막 식은 POP 없이 RETURN이 된다. 함수의 값이기 때문이다.
다른 언어는
  • CPython: 스택 머신이다. 3.6부터 명령 하나가 2바이트(명령 1바이트 + 피연산자 1바이트, 더 크면 앞에 확장 명령) 단위인 "wordcode"를 쓴다.
  • JVM: 스택 머신이다. 명령은 가변 길이 바이트 열이다.
  • WebAssembly: 스택 머신 형식으로 적지만, 실행할 때는 대부분 기계어로 다시 컴파일된다.
  • Lua 5: 레지스터 머신이다. Lua 저자들의 논문은 레지스터 머신으로 바꾼 뒤 명령 수가 줄고 빨라졌다고 보고했다.
  • Dalvik(옛 안드로이드 VM): 같은 Java 프로그램을 JVM의 스택 바이트코드에서 레지스터 바이트코드로 바꿔 실행했다.
fung의 선택
  • 스택 머신. 설계 문서 09의 구조 그대로 "스택 VM"이다. 레지스터 머신과 인라인 캐시(같은 자리의 이름 조회 결과를 기억하는 기법)는 "측정을 보고 정한다"로 미뤄 두었다(open-questions "성능"). 2026-10-14 측정에서는 호출의 빠른 길(인자가 그 자리에서 슬롯이 되기)과 범위를 리스트로 펼치지 않는 반복으로 함수 호출과 반복이 2.3~2.5배 빨라졌고, 남은 시간은 명령 해석 루프 자체라고 기록했다.
  • 고정 폭 32비트 = 8비트 명령 + 24비트 피연산자. 디코딩과 점프 계산이 단순하고 역어셈블러가 쉽다. 24비트면 상수·슬롯·점프 위치에 충분하다. 가변 길이 바이트 열은 매 명령의 길이를 따져야 해서 택하지 않았다(설계 문서 09, 내부 구조 부록).
  • 내장 함수는 상수로 직접. prelude 이름은 컴파일러가 함수 값을 상수 풀에 넣는다. 실행 중에 이름을 찾지 않는다(6장).
  • 명령마다 소스 위치. 런타임 에러가 정확한 줄과 칸을 가리키는 이유다(7장).

아래 함수의 바이트코드를 예상해 보자. then … else가 두 번 겹쳐 있으니 JUMPIFFALSE와 JUMP가 각각 두 개씩 나올 것이다. 각 점프가 몇 번 명령으로 가는지 적은 뒤 확인하자.

정리

  • 스택 머신의 명령은 스택 맨 위의 값을 꺼내 계산하고 결과를 올린다. 컴파일러는 트리를 자식 먼저 걸으며 명령을 낸다.
  • 레지스터 머신은 명령이 칸 번호를 직접 말한다. 명령 수는 줄지만 컴파일러가 복잡해진다.
  • fung 명령은 32비트 한 단어(8비트 명령 + 24비트 피연산자)이고, 53가지다.
  • 함수마다 원형(Proto)이 하나: 명령 목록, 상수 풀, 명령마다 위치, 슬롯 수, 매개변수 표, 자식 원형들.
  • VM은 반복문 하나로 명령을 가져와 실행한다. 프레임마다 base가 있고, 슬롯 n은 stack[base + n]이다. 인자는 그 자리에서 슬롯이 된다.
  • if는 JUMPIFFALSE와 JUMP로 펴지고, 점프 위치는 나중에 채운다.

다음 장에서는 함수 값이 어떻게 만들어지는지, 클로저가 바깥 변수를 어떻게 붙잡는지, 기본값과 꼬리 호출이 바이트코드에서 어떻게 보이는지 본다. 명령줄 사용법은 명령줄 레퍼런스에 있다.
