cli — 명령줄 옵션

import cli. 명령줄 인자를 옵션(--name value)과 나머지로 나눈다. 일부러 작게 만들었다. 값의 검사와 변환은 보통의 fung 코드로 한다. fung으로 썼다.

명령줄 인자와 옵션

터미널에서 fung deploy.fung --env prod --dry-run web-1 web-2처럼 스크립트를 실행하면, 스크립트 이름 뒤의 단어들이 명령줄 인자(command-line arguments)다. fung은 이것을 prelude 값 args에 문자열 리스트로 넣어 준다: ["--env", "prod", "--dry-run", "web-1", "web-2"]. 셸이 따옴표를 풀고 공백에서 나눈 뒤의 모습이다.

인자 중 --로 시작하는 것은 관례상 옵션(option, 플래그)이다. 옵션은 값을 하나 받거나(--env prod, --env=prod), 켜고 끄는 스위치일 수 있다(--dry-run). 옵션이 아닌 인자(web-1 web-2)는 보통 작업 대상이다. cli.parse는 이 관례대로 args를 옵션 맵과 나머지 리스트로 나눈다. 받을 옵션은 모두 적어 준다: 스위치는 bools, 값을 받는 옵션은 values다. 적지 않은 옵션은 오타로 본다.

인자결과
--name valuevalues의 이름: flags.name = "value". 다음 인자가 없거나 --로 시작하면 실패(--name=--x로는 줄 수 있다)
--name=valuevalues의 이름: flags.name = "value"(값에 =가 더 있어도 첫 =에서만 나눈다). bools의 이름이면 값은 true·false만 받아 불리언이 된다
--namebools의 이름: flags.name = true
목록에 없는 --name실패
-v(- 하나로 시작)실패. 한 글자 옵션은 읽지 않는다
--그 뒤는 -로 시작해도 모두 rest
그 밖(file.txt, -)순서대로 rest

옵션 이름의 -는 _로 바뀐다(--dry-run → flags.dry_run). flags.dry_run처럼 점으로 바로 읽을 수 있게 하려는 것이다. 같은 옵션이 두 번 나오면(--a-b와 --a_b처럼 쓴 꼴만 달라도) 실패다. 어느 값을 뜻했는지 말없이 고르지 않는다. 한 글자 옵션(-v)과 묶음(-xvf)은 해석하지 않고 실패다. -로 시작하는 위치 인자(-5, -file)는 -- 뒤에 둔다.

명령줄은 스크립트 바깥에서 오는 입력이라, 사용자가 잘못 친 명령줄은 런타임 에러가 아니라 Err 값이다. 그래서 cli.parse는 Ok({flags, rest})나 Err({kind: 'invalid, message})를 돌려준다. 잘못된 명령줄에 그냥 멈추려면 cli.parse(args, …)!, 사용자에게 안내를 보이려면 match로 Err를 받는다.

왜 이렇게 작은가

cli는 도움말 생성, 필수 옵션 검사, 타입 변환을 하지 않는다. 그런 기능은 규칙이 많아 배울 것이 늘고, 스크립트마다 원하는 모양이 다르다. 대신 결과가 평범한 맵과 리스트이므로 get(flags, "port", "8080"), int(...), parse_dur, match로 필요한 만큼 직접 쓴다.

cli.parsefung으로 작성

명령줄 인자를 옵션 맵과 나머지 리스트로 나눈다.

cli.parse(argv, bools = [], values = [])

설명

argv를 앞에서부터 읽으며 위의 표대로 나눈다. 옵션은 닫힌 집합이다. bools에 적은 이름(앞의 -- 없이)은 값을 받지 않는 스위치, values에 적은 이름은 값 하나를 받는 옵션이고, 어디에도 없는 --이름은 실패다. 그래서 --dry-rnu 같은 오타가 말없이 "진짜로 실행"이 되지 않는다. 이름은 명령줄에 쓴 꼴("dry-run")로도 결과의 키 꼴("dry_run")로도 적을 수 있다. values의 값은 언제나 문자열이므로 숫자나 기간이 필요하면 직접 바꾼다. 스위치는 --dry-run=false처럼 =true·=false로 값을 줄 수 있고, 그 밖의 값은 실패다.

없는 옵션을 flags.port로 읽으면 E0508(없는 키)이다. 선택 옵션은 get의 기본값으로 읽는다(get(opts.flags, "port", "8080")). opts.flags.port ?? "8080"은 ??에 닿기 전에 E0508로 멈춘다.

매개변수

  • argv: 문자열 리스트. 보통 args를 그대로 넘긴다.
  • bools: 값을 받지 않는 옵션(스위치) 이름의 리스트.
  • values: 값 하나를 받는 옵션 이름의 리스트.

옵션 이름은 영문자·숫자·_·-로 쓰고 영문자나 _로 시작한다. 한 이름이 두 목록에 다 있을 수는 없다.

돌려주는 값

Ok({flags, rest}). flags는 이름(문자열 키) → 문자열 또는 불리언, rest는 옵션이 아닌 인자의 리스트(순서 유지).

명령줄이 잘못되었으면 Err({kind: 'invalid, message}). message는 사용자에게 그대로 보여 줄 수 있는 문장이다.

  • 목록에 없는 옵션(--dry-rnu): unknown flag `--dry-rnu`
  • -로 시작하는 옵션(-v): the flag `-v` is not supported: flags start with `--` (put `--` before an argument that starts with `-`)
  • 값을 받는 옵션에 값이 없음(--env가 끝이거나 뒤가 --로 시작): the flag `--env` needs a value
  • 이름이 없는 옵션(--=x): the flag `--=x` has no name
  • 같은 옵션이 두 번: the flag `--x` is given twice
  • 스위치에 true·false가 아닌 값(--dry-run=no): the switch `--dry-run` takes true or false, got `no`

에러

  • argv·bools·values가 문자열 리스트가 아니거나, bools·values의 이름이 옵션 이름 꼴이 아니거나, 한 이름이 두 목록에 다 있으면 런타임 에러 E0403. 에러는 그 인자의 이름을 말한다. 이것은 스크립트의 잘못이라 Err가 아니다.

예제

스크립트의 인자 나누기

실행 방법 
fung example.fung --env prod --dry-run web-1 web-2
import cli

opts = cli.parse(args, bools: ["dry-run"], values: ["env"])!
print(opts)
print(opts.flags.env, opts.rest)
{flags: {env: "prod", dry_run: true}, rest: ["web-1", "web-2"]}
prod ["web-1", "web-2"]

스위치와 값 옵션

import cli

print(cli.parse(["--dry-run", "web-1"], values: ["dry-run"])!)
print(cli.parse(["--dry-run", "web-1"], bools: ["dry-run"])!)
{flags: {dry_run: "web-1"}, rest: []}
{flags: {dry_run: true}, rest: ["web-1"]}

목록에 없는 옵션

import cli

print(cli.parse(["--dry-rnu", "web-1"], bools: ["dry-run"]))
print(cli.parse(["-v", "web-1"], bools: ["dry-run"]))
Err({kind: 'invalid, message: "unknown flag `--dry-rnu`"})
Err({kind: 'invalid, message: "the flag `-v` is not supported: flags start with `--` (put `--` before an argument that starts with `-`)"})

기본값과 변환

실행 방법 
fung example.fung --retries 5 --timeout 2s report.csv
import cli

opts = cli.parse(args, bools: ["verbose"], values: ["retries", "timeout"])!
retries = int(get(opts.flags, "retries", "3"))
wait = parse_dur(get(opts.flags, "timeout", "30s"))!
verbose = get(opts.flags, "verbose", false)
print(retries + 1, wait, verbose, opts.rest)
6 2s false ["report.csv"]

=와 --

import cli

print(cli.parse(["--label=env=prod", "--", "--not-a-flag", "-v"], values: ["label"])!)
{flags: {label: "env=prod"}, rest: ["--not-a-flag", "-v"]}

잘못된 명령줄 알리기

실행 방법 
fung example.fung --env prod --env dev
import cli

match cli.parse(args, values: ["env"]):
  Ok(opts) => print(opts.flags.env)
  Err(e)   => print("usage error:", e.message)
;;
usage error: the flag `--env` is given twice
