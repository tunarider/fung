http — HTTP

import http. HTTP/1.1 클라이언트(get, post, request)와 작은 서버(serve). 소켓·TLS 원시 기능 위에 fung으로 썼다. 응답을 받았으면 상태 코드와 무관하게 Ok다(404도 Ok).

HTTP란

HTTP(HyperText Transfer Protocol)는 웹 브라우저와 웹 서버, 그리고 대부분의 API가 쓰는 약속이다. 늘 한쪽이 요청(request)을 보내고 다른 쪽이 응답(response)을 돌려준다. 요청을 보내는 쪽이 클라이언트(client), 받아서 답하는 쪽이 서버(server)다. curl https://example.com은 클라이언트이고, nginx는 서버다.

요청은 네 부분이다.

  • 메서드(method): 무엇을 하려는지. GET(가져오기), POST(보내서 만들기), PUT(바꾸기), DELETE(지우기) 등.
  • URL: 어디에. https://api.example.com:8443/v1/hosts?env=prod는 스킴(https), 호스트(api.example.com), 포트(8443, 생략하면 http는 80, https는 443), 경로(/v1/hosts), 쿼리(env=prod)로 이루어진다.
  • 헤더(header): 덧붙이는 정보. Content-Type: application/json(본문의 종류), Authorization: Bearer …(인증) 같은 이름-값 쌍이다. 이름은 대소문자를 가리지 않는다.
  • 본문(body): 보내는 데이터. GET에는 보통 없다.

응답은 상태 코드(status code), 헤더, 본문이다. 상태 코드는 세 자리 숫자로, 첫 자리가 종류를 말한다: 2xx 성공(200 OK, 201 Created), 3xx 다른 곳으로 가라(리다이렉트), 4xx 요청이 잘못됨(404 Not Found, 401 Unauthorized), 5xx 서버 쪽 실패(500, 503).

https는 같은 HTTP를 TLS로 암호화한 연결 위에서 주고받는다. 클라이언트는 서버의 인증서(certificate)를 검사해 상대가 진짜 그 호스트인지 확인한다.

fung에서의 모양

  • 클라이언트 함수는 응답을 Ok({status, headers, body})로 준다. 응답을 받았으면 상태 코드가 무엇이든 Ok다. "서버가 404라고 답했다"와 "요청이 가지 못했다"는 다른 일이기 때문이다. 상태 코드는 직접 검사한다.
  • 요청이 가지 못하면(연결 거부, 없는 호스트, 인증서 오류 등) Err({kind: 'network, message}), 시간 안에 끝나지 않으면 Err({kind: 'timeout, message})다. message는 cannot request URL: 이유 꼴이고, 이유는 connection refused, no such host, unsupported scheme ftp , invalid URL: …, unknown certificate authority, certificate is not valid for host , certificate has expired (valid until …), too many redirects (limit 10) 같은 짧은 문구다. 시간 초과의 문구는 request to URL timed out이다.
  • 응답 headers는 맵이고 키는 소문자다(r.headers["content-type"]). 같은 이름의 헤더가 여럿이면 ", "로 이어 하나로 준다.
  • 본문은 문자열이다. JSON이면 json.parse로 읽는다. UTF-8이 아닌 바이트는 U+FFFD로 바뀌므로 이미지 같은 바이너리 본문은 그대로 받을 수 없다.
  • 태스크가 취소되면(바깥의 timeout, cancel) 요청도 멈춘다(E0701).

이 페이지의 예제는 네트워크나 열린 포트가 필요해서 실행하지 않고 검사만 한다. 출력 칸은 실제로 돌렸을 때의 예다.

클라이언트

http.getfung으로 작성

URL에 GET 요청을 보내고 응답을 돌려준다.

http.get(url, headers = {}, timeout = 30s)

설명

가장 흔한 요청이다. curl URL과 같다. 리다이렉트(3xx)는 10번까지 따라간다. 요청에는 Host, User-Agent: fung/<버전>이 자동으로 붙고, headers의 것이 같은 이름의 자동 헤더를 대신한다. URL에 user:pass@가 있으면 Authorization: Basic … 헤더가 된다. 프록시 환경 변수(HTTPS_PROXY 등)를 따른다. 자세한 규칙은 약속에 있다.

timeout은 이름 조회·연결·TLS 핸드셰이크·리다이렉트를 모두 포함한 요청 전체의 한도 하나다. 0s면 한도가 없다. 바깥에 더 짧은 timeout 범위가 있으면 그쪽이 먼저 끊는다(그때는 바깥 timeout의 Err({kind: 'timeout})).

매개변수

  • url: http://나 https://로 시작하는 URL.
  • headers: 보낼 헤더 맵({"Authorization": "Bearer ${token}"}). 맵 순서대로 보낸다.
  • timeout: 요청 전체의 한도(기간).

돌려주는 값

Ok({status, headers, body}). status는 정수, headers는 소문자 키의 맵, body는 문자열.

에러

  • Err({kind: 'network, message}): 연결·이름 조회·TLS·URL·리다이렉트 실패, 응답 본문이 64 MiB를 넘음.
  • Err({kind: 'timeout, message}): timeout 안에 끝나지 않았다.
  • 런타임 에러 E0403: 인자의 타입이 틀렸다(url이 문자열이 아님 등).

http.postfung으로 작성

URL에 POST 요청으로 본문을 보내고 응답을 돌려준다.

http.post(url, body, headers = {}, timeout = 30s)

설명

  • headers: 보낼 헤더 맵.
  • timeout: 요청 전체의 한도.

돌려주는 값

Ok({status, headers, body}).

에러

http.get과 같다.

http.requestfung으로 작성

아무 메서드로나 요청을 보낸다.

설명

매개변수

  • method: 메서드 이름(문자열).
  • url: 요청할 URL.
  • body: 보낼 문자열 또는 nil.
  • headers: 보낼 헤더 맵.
  • timeout: 요청 전체의 한도.

돌려주는 값

Ok({status, headers, body}).

에러

http.get과 같다.

서버

서버는 한 주소(호스트와 포트, 127.0.0.1:8080)에서 연결을 기다리다가, 요청이 오면 답하는 프로그램이다. 127.0.0.1은 자기 컴퓨터에서만 접속할 수 있고, :8080처럼 호스트를 비우면 모든 네트워크에서 받는다. 포트 0은 "남는 포트 아무거나"다.

http.servefung으로 작성

주소에서 HTTP 요청을 받아 handler로 답한다. 멈출 때까지 돌아오지 않는다.

http.serve(addr, handler, ready = nil, drain = 10s, reuse_port = false)

설명

addr에서 듣기 시작하고, 요청마다 새 태스크에서 handler(req)를 불러 그 결과로 답한다. 요청이 동시에 여럿 오면 핸들러도 동시에 돈다. 그래서 요청 수 같은 공유 상태는 atom에 둔다. 라우팅 기능은 따로 없고 match req.path:(또는 match (req.method, req.path):)로 나눈다.

req는 {method, path, query, headers, body} 맵이다.

  • method: "GET", "POST" …
  • path: 쿼리를 뺀 경로("/health").
  • query: 쿼리의 맵. 같은 이름이 여럿이면 첫 값, +는 공백, %20 같은 이스케이프는 풀린다. 잘못된 % 이스케이프가 든 쌍은 빠진다.
  • headers: 소문자 키의 맵.
  • body: 본문 문자열.

핸들러는 문자열(상태 200, text/plain; charset=utf-8)이나 맵 {status = 200, headers = {}, body = ""}(빠진 키는 기본값)을 돌려준다. 응답에는 Date와 Content-Length가 붙고, 본문이 있는데 content-type이 없으면 text/plain; charset=utf-8이 붙는다. 연결마다 요청 하나만 받으므로 응답에는 늘 Connection: close가 붙는다.

핸들러가 런타임 에러를 내면 500으로 답하고 표준 에러에 http: handler failed: … 한 줄을 쓴다. 문자열·맵이 아닌 것을 돌려주면 500과 http: bad handler response: …다. 어느 쪽이든 서버는 계속 돈다.

끝나는 길은 둘이다.

  • 정지 요청: 첫 SIGINT(Ctrl-C)·SIGTERM(kill, 컨테이너 종료)이나 request_stop()이 오면(stop_signal) 새 연결을 그만 받고(듣던 소켓을 닫음), 처리 중인 요청을 최대 drain까지 마저 끝낸 뒤, 그때도 남은 것은 취소해 503으로 답하고 Ok(nil)을 돌려준다. 정상 종료다.
  • 취소: 서버가 든 범위가 취소되면(바깥 timeout, cancel, exit) 기다리지 않고 곧바로 멈춘다. 핸들러 안의 exit도 503이다.

ready를 주면 듣기 시작한 직후 실제 주소("127.0.0.1:53121")로 한 번 부른다. 포트 0으로 띄운 서버의 포트를 아는 길이고, 시험에서 서버가 준비된 뒤에 요청을 보내는 데 쓴다. reuse_port: true는 SO_REUSEPORT를 켜서 프로세스 여럿이 한 포트에서 받게 한다(Linux는 연결을 나눠 주고, macOS는 받게만 한다). 여러 코어를 쓰는 방법이다.

서버의 한도: 헤더는 10초 안에 와야 하고(아니면 끊음), 요청 머리는 1 MiB·헤더 줄 500개까지(넘으면 431), 본문은 16 MiB까지(넘으면 413, 핸들러를 부르지 않음), 형식이 틀리면 400이다. 서버가 스스로 내는 답의 본문은 <코드> <이유 문구>다(500 Internal Server Error). 표준 이유 문구가 없는 코드(599)는 빈 문구로 보낸다.

매개변수

  • addr: 들을 주소(":8080", "127.0.0.1:0").
  • handler: req를 받아 문자열이나 응답 맵을 돌려주는 함수.
  • ready: 실제 주소를 받는 함수 또는 nil.
  • drain: 정지 요청 뒤 처리 중인 요청을 기다릴 최대 기간.
  • reuse_port: SO_REUSEPORT를 켤지.

돌려주는 값

정지 요청으로 끝나면 Ok(nil).

에러

  • Err({kind: 'network, message}): 듣기 시작하지 못했다(cannot listen on 127.0.0.1:80: permission denied, 이미 쓰는 포트, invalid address bogus (missing port)).

정상 종료가 Ok(nil)이므로 http.serve(…)!는 듣기에 실패했을 때만 멈추고, 깔끔하게 멈춘 서버는 종료 코드 0으로 끝난다. ! 없이 문장으로 써도 듣기 실패의 Err는 버려지는 Err(E0606)로 멈춘다.

예제

가장 작은 서버

import http

http.serve(":8080", req => match req.path:
  "/health" => "ok"
  _         => {status: 404, body: "not found"}
;;, ready: a => print("listening on", a))

검사만 하는 예제다. 아래 출력은 페이지를 만들 때 확인하지 않은 예상 출력이다.

다른 터미널에서 curl -i localhost:8080/health로 부르면 200과 ok, /nope는 404와 not found가 온다. Ctrl-C를 누르면 처리 중인 요청을 마치고 끝난다(종료 코드 0).

JSON API와 공유 상태

import http
import json

fn json_response(status, data) = {status, headers: {"Content-Type": "application/json"}, body: json.stringify(data)}

hits = atom(0)

fn handle(req):
  n = swap(hits, x => x + 1)
  match (req.method, req.path):
    ("GET", "/stats") => json_response(200, {requests: n})
    ("POST", "/echo") => match json.parse(req.body):
      Ok(data) => json_response(200, {received: data, from: get(req.headers, "user-agent")})
      Err(e)   => {status: 400, body: "bad json: ${e.message}"}
    ;;
    ("GET", "/hello") => "hello, ${get(req.query, "name", "stranger")}"
    _                 => {status: 404, body: "not found: ${req.path}"}
  ;;
;;

http.serve("127.0.0.1:8080", handle, drain: 5s)

시험 안에서 띄우고 부르기

포트 0과 ready로 남는 포트에 띄우고, 채널로 주소를 받은 뒤 요청한다. 마지막에 request_stop()으로 서버를 정상 종료시킨다.

import http

(tx, rx) = channel(1)
r = scope(fn(s):
  spawn(s, () => http.serve("127.0.0.1:0", req => "pong", ready: a => send(tx, a)!))
  base = "http://${recv(rx)!}"
  print(http.get("${base}/ping")!.body)
  request_stop()
  "stopped"
;;)
print(r)

약속하는 것과 하지 않는 것

http가 지키는 동작이다. 여기 없는 세부는 바뀔 수 있다.

  • 클라이언트 헤더: 요청에 Host, User-Agent: fung/<버전>, 본문이 있으면 Content-Length가 붙는다. 사용자 헤더는 이름을 표준 대소문자로 바꿔 맵 순서대로 보내고, 같은 이름이면 사용자 것이 이긴다(빈 User-Agent는 보내지 않는다). 비어 있지 않은 사용자 Host도 자동 값을 대신하고, 리다이렉트가 다른 호스트로 가면 그 요청부터 버린다. Content-Length·Transfer-Encoding·Trailer는 본문의 끝을 정하므로 언제나 클라이언트가 쓴다. URL의 user:pass@는 사용자 Authorization이 없을 때 Authorization: Basic이 된다. 응답 본문은 Content-Length, 조각 전송(chunked), 연결 닫힘 중 하나로 읽는다. 압축을 요청하지 않으므로 본문은 서버가 보낸 그대로다.
  • 리다이렉트: 301·302·303은 GET으로 바꿔(원래 HEAD면 HEAD) 본문 없이, 307·308은 메서드와 본문을 지켜 따라간다. 10번까지 따라가고 11번째는 Err({kind: 'network})(too many redirects (limit 10)). 리다이렉트 응답의 본문은 읽지 않는다. 첫 요청의 호스트나 그 하위 도메인이 아닌 곳으로 넘어가면 Authorization·Cookie 같은 민감한 헤더를 버린다. 다음 요청에는 Referer가 붙는다(사용자 정보 없이, https에서 http로 갈 때는 없음).
  • 프록시: 환경 변수 HTTP_PROXY(http용), HTTPS_PROXY(https용), NO_PROXY(이름·하위 도메인·IP·CIDR, 포트 선택)를 따르고 소문자 이름도 읽는다. localhost와 루프백 주소는 프록시를 거치지 않는다. CGI 프로그램(REQUEST_METHOD가 있음) 안에서는 HTTP_PROXY를 쓰지 않는다. https는 CONNECT 터널로 간다. SOCKS 프록시와 https 프록시 너머의 https는 지원하지 않는다(Err({kind: 'network})).
  • https: 운영체제의 루트 인증서(SSL_CERT_FILE·SSL_CERT_DIR이 있으면 그것)로 검증하고 SNI를 보낸다. 인증서 오류는 Err({kind: 'network})다.
  • 응답 본문 상한 64 MiB. 넘으면 Err({kind: 'network}).
  • 본문은 문자열이다. UTF-8이 아닌 바이트는 잘못된 부분마다 U+FFFD 하나로 바뀐다.
  • 없는 것: 연결 재사용(keep-alive)과 파이프라이닝, HTTP/2, 압축, 바이너리 본문. 서버는 연결마다 요청 하나만 받는다.

배우는 순서로는 13장 JSON과 HTTP를 본다.
