fs — 파일과 디렉터리

import fs. 파일을 읽고 쓰고, 디렉터리를 살피고, 만들고 지우고 옮긴다. 실패할 수 있는 연산은 모두 Ok/Err를 돌려준다.

모듈과 파일 시스템

모듈(module)은 관련 있는 함수를 한 이름 아래 묶은 것이다. print나 len처럼 어디서나 쓰는 함수는 prelude(프렐류드, 처음부터 들어 있는 이름들)에 있고, 파일·JSON·HTTP처럼 필요할 때만 쓰는 기능은 모듈로 나뉘어 있다. 모듈은 파일 맨 위에서 import fs로 불러오고, 그 안의 함수는 fs.read처럼 모듈.이름으로 부른다. 불러오지 않고 fs.read를 쓰면 fs라는 이름이 없다는 컴파일 에러(E0204)다. 자세한 규칙은 언어 명세의 모듈에 있다.

파일 시스템(file system)은 운영체제가 디스크의 데이터를 정리하는 방식이다. 데이터 한 덩어리가 파일이고, 파일을 담는 상자가 디렉터리(directory, 폴더)다. 디렉터리 안에 다시 디렉터리가 들어갈 수 있어서 전체는 나무 모양이 된다. 파일의 위치는 경로(path)로 적는다.

  • /var/log/app.log처럼 /로 시작하는 경로는 절대 경로다. 나무의 뿌리(/)부터 내려간다.
  • logs/app.log처럼 /로 시작하지 않는 경로는 상대 경로다. 프로그램을 실행한 현재 디렉터리에서부터 찾는다. .은 현재 디렉터리, ..은 한 단계 위다.

경로를 이어 붙이거나 확장자를 떼는 계산은 디스크를 건드리지 않으므로 path 모듈이 따로 맡는다.

파일 연산은 프로그램이 잘못하지 않아도 실패할 수 있다. 파일이 없거나, 권한이 없거나, 디스크가 찼을 수 있다. 그래서 fs의 함수는 실패를 런타임 에러로 멈추지 않고 값으로 돌려준다. 성공하면 Ok(값), 실패하면 Err({kind, message})다. kind는 실패의 종류를 나타내는 심볼이고 message는 사람이 읽을 문장이다.

kind뜻
'not_found경로가 없다(위의 디렉터리가 없는 경우도).
'exists이미 있다(mkdir할 자리에 파일이 있음, 비지 않은 디렉터리를 remove함, move할 자리에 이미 있음 등).
'permission권한이 없다.
'io그 밖의 입출력 실패(디렉터리를 파일처럼 읽음, 경로 중간이 파일임, 디스크가 참 등).
'invalid잘못된 glob 패턴(fs.glob), 읽기로 열지 않은 핸들로 읽기(또는 그 반대).
'closed닫힌 파일 핸들을 썼다(핸들 함수만).

message는 cannot read nope.txt: no such file or directory처럼 "무엇을 하려다 어디서 왜"의 꼴이다. 운영체제가 말한 이유는 소문자 짧은 문장이고, 흔한 이유는 어느 운영체제에서나 같은 문구다. 결과는 !(실패면 멈춤), ?(실패면 함수에서 돌려줌), match(종류별로 처리)로 다룬다. 결과를 쓰지 않고 버리면, 그 값이 Err일 때 E0606으로 멈춘다(결과값과 에러).

import fs

match fs.read("config.txt"):
  Ok(text)                => print(text)
  Err({kind: 'not_found}) => print("no config, using defaults")
  Err(e)                  => print(e.message)
;;
no config, using defaults

파일 내용은 문자열로 읽는다. fung의 문자열은 UTF-8 텍스트이므로, UTF-8이 아닌 바이트는 잘못된 부분마다 U+FFFD("\u{FFFD}") 하나로 바뀐다. 이미지 같은 바이너리 파일은 그대로 다룰 수 없다.

이름이 같은 다른 함수

fs.remove·fs.close는 prelude의 remove(맵에서 키 빼기)·close(채널 닫기)와 이름만 같은 다른 함수다. 파일에는 반드시 fs.를 붙인다. 붙이지 않으면 prelude 함수가 불려 인자가 모자라거나(E0407) 타입이 맞지 않는(E0403) 런타임 에러가 난다.

통째로 읽고 쓰기

작은 파일(설정, 로그 한 개, 목록)은 한 번에 읽고 한 번에 쓰는 것이 가장 쉽다. 수백 MB 이상의 큰 파일을 한 줄씩 다룰 때는 파일 핸들을 쓴다.

fs.read

파일 전체를 문자열 하나로 읽는다.

fs.read(path)

설명

path의 내용을 처음부터 끝까지 읽어 문자열로 돌려준다. 줄바꿈도 그대로 들어 있다. 줄 단위로 다루려면 fs.read_lines가 편하다. UTF-8이 아닌 바이트는 U+FFFD로 바뀐다.

매개변수

  • path: 읽을 파일의 경로(문자열).

돌려주는 값

Ok(문자열).

에러

  • Err({kind: 'not_found}): 파일이 없다. 빈 경로 ""도 같다.
  • Err({kind: 'io}): 디렉터리를 읽으려 했다(is a directory) 등.
  • Err({kind: 'permission}): 읽을 권한이 없다.
  • path가 문자열이 아니면 런타임 에러 E0403.

fs.read_linesfung으로 작성

파일을 줄 리스트로 읽는다.

fs.read_lines(path)

설명

fs.read로 읽은 뒤 prelude의 lines로 나눈다. 규칙도 lines와 같다: \n에서 나누고, 줄 끝의 \r은 떼고(Windows 줄바꿈), 파일 끝의 줄바꿈 하나는 빈 줄을 만들지 않는다. 빈 파일은 빈 리스트다. 파일을 통째로 메모리에 올리므로 아주 큰 파일에는 fs.with_open과 read_line을 쓴다.

매개변수

  • path: 읽을 파일의 경로.

돌려주는 값

Ok(줄 리스트). 각 줄에는 줄바꿈이 없다.

에러

fs.read와 같다.

fs.write

파일에 문자열을 쓴다. 있던 내용은 지운다.

fs.write(path, text, perm = nil)

설명

path에 text를 쓴다. 파일이 없으면 새로 만들고, 있으면 내용을 모두 지우고 덮어쓴다(셸의 >와 같다). 새 파일의 권한은 0666에서 umask를 뺀 것이다(셸과 같다). perm을 주면 파일은 정확히 그 권한이 된다(아래). 위의 디렉터리는 만들지 않으므로, 필요하면 먼저 fs.mkdir를 부른다. 줄바꿈은 자동으로 붙지 않는다.

매개변수

  • path: 쓸 파일의 경로.
  • text: 쓸 내용(문자열). 다른 값은 str(x)나 json.stringify로 바꿔서 넘긴다.
  • perm: 파일의 권한 비트(0o600처럼 8진수로, 0부터 0o777까지). 주면 내용을 쓰기 전에 파일을 정확히 이 권한으로 맞춘다. umask를 빼지 않고, 이미 있는 파일도 바꾼다(셸의 install -m과 같다). 기본 nil이면 새 파일은 0666에서 umask를 뺀 것이고 있던 파일은 그대로다. 범위 밖이면 런타임 에러 E0403.

돌려주는 값

Ok(nil).

에러

  • Err({kind: 'not_found}): 위의 디렉터리가 없다.
  • Err({kind: 'io}): 경로가 디렉터리다.
  • Err({kind: 'permission}): 쓸 권한이 없다. perm을 줬는데 권한을 바꿀 수 없는 파일(다른 사용자의 것)이어도 그렇다. 그때는 아무것도 쓰지 않는다.

print(fs.read_lines("hosts.txt")!)
fs.write("hosts.txt", "db-1\n")!
print(fs.read_lines("hosts.txt")!)
["web-1", "web-2"]
["db-1"]

비밀값은 perm으로

토큰이나 비밀번호가 든 파일은 다른 사용자가 읽지 못하게 처음부터 0o600으로 쓴다. 쓴 뒤에 권한을 바꾸면 그 사이에 열려 있는 틈이 생긴다.

import fs

fs.write("token.txt", token, perm: 0o600)!

perm은 이미 있는 파일에도 적용된다. 지난 실행이 남긴 임시 파일이 0644여도 비밀값을 쓰기 전에 0600이 된다. 다만 그 전에 다른 프로세스가 열어 둔 핸들은 막지 못한다. 그런 걱정이 있으면 먼저 fs.remove로 지운다.

fs.append

디렉터리 살펴보기

fs.list

디렉터리 바로 안의 이름들을 돌려준다.

fs.list(dir, full = false)

설명

dir 바로 안에 있는 파일과 디렉터리의 이름을 이름의 바이트 순서(영문은 알파벳순, 대문자가 소문자보다 앞)로 돌려준다. 하위 디렉터리 안으로 내려가지 않는다(그것은 fs.walk). .으로 시작하는 숨은 파일도 들어 있고, .과 ..은 들어 있지 않다. 디렉터리인지 파일인지는 fs.stat으로 알아본다.

full: true면 이름 대신 dir을 앞에 붙인 경로를 준다(정리된 꼴이라 "./logs"는 "logs/…"가 된다). 받은 값을 곧바로 다른 fs 함수에 넘길 때 편하다.

매개변수

  • dir: 디렉터리 경로.
  • full: true면 경로, false(기본)면 이름만.

돌려주는 값

Ok(문자열 리스트).

에러

  • Err({kind: 'not_found}): 디렉터리가 없다.
  • Err({kind: 'io}): 디렉터리가 아니다.

예제

이름과 경로

import fs

fs.mkdir("logs")!
fs.write("logs/b.log", "")!
fs.write("logs/a.log", "")!
fs.write("logs/.keep", "")!
print(fs.list("logs")!)
print(fs.list("logs", full: true)!)
[".keep", "a.log", "b.log"]
["logs/.keep", "logs/a.log", "logs/b.log"]

fs.mkdir("site/assets")!
fs.write("site/index.html", "")!

print(dirs)
["site/assets"]

fs.glob

와일드카드 패턴에 맞는 경로들을 돌려준다.

fs.glob(pattern)

설명

셸의 ls *.log처럼 패턴으로 파일을 고른다. 패턴은 /로 나눈 단계마다 맞추고, 결과는 디렉터리마다 이름의 바이트 순서다. 맞는 것이 없으면 빈 리스트다(셸처럼 패턴 그대로를 돌려주지 않는다).

기호뜻
*/가 아닌 아무 글자 0개 이상
?/가 아닌 아무 글자 하나
[abc] [a-z]괄호 안의 글자 하나. -는 범위
[^abc]괄호 안에 없는 글자 하나
\다음 글자를 그대로(\*는 별표 글자)

셸과 다른 점이 셋 있다. *는 .으로 시작하는 숨은 파일에도 맞는다. **는 특별하지 않아서 *와 같다(하위 디렉터리까지 찾으려면 fs.walk와 filter를 쓴다). !는 보통 글자다(여집합은 [^…]). 읽지 못하는 디렉터리는 조용히 건너뛴다.

매개변수

  • pattern: 패턴 문자열. 상대 패턴이면 현재 디렉터리 기준이다.

돌려주는 값

Ok(경로 리스트). 경로는 패턴과 같은 꼴(상대 패턴이면 상대 경로)이다.

에러

  • Err({kind: 'invalid}): 패턴이 잘못되었다(bad glob pattern [a: syntax error in pattern). 파일을 읽기 전에 검사한다.

예제

확장자로 고르기

import fs

fs.mkdir("logs/old")!
each(["a.log", "b.log", "notes.txt", ".hidden.log", "old/c.log"], n => fs.write("logs/${n}", "")!)
print(fs.glob("logs/*.log")!)
print(fs.glob("logs/*/*.log")!)
print(fs.glob("logs/[ab].*")!)
["logs/.hidden.log", "logs/a.log", "logs/b.log"]
["logs/old/c.log"]
["logs/a.log", "logs/b.log"]

잘못된 패턴

import fs

print(fs.glob("logs/[a"))
Err({kind: 'invalid, message: "bad glob pattern `logs/[a`: syntax error in pattern"})

fs.walk

디렉터리 아래의 모든 파일 경로를 하위 디렉터리까지 돌려준다.

fs.walk(dir)

설명

dir에서 시작해 하위 디렉터리로 끝까지 내려가며 파일의 경로만 모은다(디렉터리 자체는 들어 있지 않다). 경로는 dir을 앞에 붙인 정리된 꼴이고, 디렉터리마다 이름의 바이트 순서로 깊이 우선(한 디렉터리를 다 본 뒤 다음으로) 나온다. 셸의 find dir -type f와 비슷하다. 도중에 읽지 못하는 디렉터리가 있으면 그 경로로 Err다.

매개변수

  • dir: 시작할 디렉터리.

돌려주는 값

Ok(경로 리스트).

에러

fs.move

파일이나 디렉터리의 이름을 바꾸거나 다른 곳으로 옮긴다.

설명

셸의 mv와 비슷하지만 이미 있는 것을 덮어쓰지 않는다: to가 있으면 Err({kind: 'exists})다(셸의 mv -n과 같고, 실패를 알린다). 파일을 덮어쓰려면 overwrite: true를 준다. 새 내용을 임시 파일에 다 쓴 뒤 바꿔치기할 때 쓴다. 이름 바꾸기는 한 번에 일어나서, 그 사이에 멈춰도 원래 파일은 옛 내용 그대로다. 확인과 옮기기가 운영체제의 호출 하나라서(Linux renameat2, macOS renamex_np), 확인한 뒤 옮기기 전에 다른 프로그램이 같은 이름을 만들어도 덮어쓰지 않는다. 이미 있는 디렉터리는 overwrite를 줘도 덮지 않는다(mv a dir처럼 그 안으로 옮기지도 않는다). 디렉터리 안으로 옮기려면 대상 경로에 이름까지 적는다: fs.move("a.txt", "dir/a.txt"). 같은 디렉터리에서 대소문자만 바꾸는 이름 바꾸기도 된다.

  • to: 새 경로.

Ok(nil).

에러

파일 핸들

fs.read와 fs.write는 파일을 한 번에 다룬다. 아주 큰 로그를 한 줄씩 읽거나, 결과를 조금씩 써 나갈 때는 파일을 열어서(open) 받은 핸들(handle, 열린 파일을 가리키는 값)로 읽고 쓴 뒤 닫는다(close). 핸들로는 prelude의 read_line·read_lines로 읽고 fs.write_line으로 쓴다.

열었으면 반드시 닫아야 한다. 쓴 내용은 64 KiB 버퍼에 모였다가 버퍼가 차거나 닫을 때 디스크에 닿기 때문이다. 직접 open·close를 짝짓기보다 fs.with_open을 권한다. 중간에 에러가 나도 닫아 준다.

핸들은 태스크 사이에 나눠 써도 된다. read_line·write_line·close 같은 연산 하나하나가 차례로 처리되어 줄이 찢어지거나 섞이지 않는다. 다만 어느 태스크가 어느 줄을 받는지는 정해지지 않는다.

fs.open

파일을 열어 핸들을 돌려준다.

fs.open(path, mode = 'read, perm = nil)

설명

mode에 따라 읽기, 새로 쓰기, 덧붙이기로 연다. 출력하면 <file "경로">, type_of는 'file이다. 다 쓴 핸들은 fs.close로 닫는다. 대부분은 fs.with_open이 더 안전하다.

FIFO(mkfifo로 만든 이름 있는 파이프)는 기다림을 이벤트 루프에서 한다. 그래서 timeout과 취소가 곧바로 끊고, 끊긴 read_line이 받은 바이트는 다음 읽기에 남는다. 읽기로 열면 곧바로 열리고 첫 읽기가 쓰는 쪽을 기다린다. 쓰기로 열면 읽는 쪽이 열 때까지 기다린다. FIFO에 쓴 줄은 버퍼에 모으지 않고 곧바로 보낸다.

mode뜻
'read읽기(기본). 파일이 있어야 한다.
'write새로 쓰기. 없으면 만들고, 있으면 내용을 지운다.
'append덧붙이기. 없으면 만들고, 끝에 이어 쓴다.

매개변수

  • path: 열 파일.
  • mode: 'read, 'write, 'append 중 하나.
  • perm: 'write·'append일 때 파일의 권한. fs.write와 같다. 'read에 주면 런타임 에러 E0403.

돌려주는 값

Ok(file).

에러

  • Err({kind: 'not_found}): 'read로 여는데 파일이 없다, 또는 위의 디렉터리가 없다.
  • Err({kind: 'permission}): 권한이 없다.
  • mode가 셋 중 하나가 아니거나 perm이 맞지 않으면 런타임 에러 E0403.

fs.close

파일 핸들을 닫는다.

fs.close(f)

설명

버퍼에 남은 쓰기를 디스크에 비우고 핸들을 닫는다. 비우기나 닫기가 실패하면 그 에러를 돌려준다(NFS처럼 닫을 때에야 쓰기를 보내는 파일 시스템에서는 디스크 가득 참이 여기서 나온다). 닫힌 핸들로 읽고 쓰면 Err({kind: 'closed})이고, 한 번 더 닫아도 같다.

닫지 않은 핸들은 그 값의 마지막 사본이 사라지면 런타임의 닫기 스레드가 비우고 닫는다. 그래서 데이터가 파일에 닿는 때는 정해져 있지 않다(버린 바로 뒤의 fs.read가 그 줄을 못 볼 수 있다). 프로그램이 끝날 때는 모두 닫힌 뒤에 끝나므로 데이터를 잃지는 않는다. 그 비우기나 닫기가 실패하면 돌려받을 곳이 없으므로 표준 에러에 E0810을 쓰고 종료 코드가 1이 된다. 그래서 쓴 핸들은 직접 닫거나 fs.with_open을 쓴다.

prelude의 close(채널 닫기)와는 다른 함수다.

매개변수

돌려주는 값

Ok(nil).

에러

  • Err({kind: 'closed}): 이미 닫혔다.
  • Err({kind: 'io}): 버퍼를 비우다 실패했다(디스크가 참 등).

fs.with_open(path, f, mode = 'read, perm = nil)

설명

path를 mode로 열고 f(핸들)을 부른 뒤, f가 값을 돌려주든 ?로 Err를 돌려주든 런타임 에러로 멈추든 핸들을 닫는다. 결과는 f가 돌려준 값 그대로다. 열지 못하면 f를 부르지 않고 그 Err를 돌려준다. prelude의 with로 만들었다. 다른 언어의 defer나 with open(...) 블록 대신 쓰는 모양이다.

f 안에서 ?를 쓰면 f(람다)에서 Err를 돌려주는 것이므로, 핸들이 닫힌 뒤 그 Err가 with_open의 결과가 된다. f가 스스로 핸들을 닫아도 실패가 아니다. 닫기가 실패하면(버퍼를 비우지 못함) 런타임 에러다. 핸들을 f 밖으로 돌려줘도 막지 않지만, 그때는 이미 닫혀 있어 쓰는 순간 'closed다.

매개변수

  • path: 열 파일.
  • f: 핸들을 받는 함수. 그 결과가 with_open의 결과가 된다.
  • mode: fs.open과 같다.
  • perm: fs.open과 같다.

돌려주는 값

f의 결과, 또는 열지 못했을 때의 Err.

에러

  • 열 때의 Err(fs.open과 같다).
  • f가 돌려준 Err(그대로 전달).

예제

첫 줄만 읽기

준비물: notes.txt

notes.txt

first line
second line
import fs

first = fs.with_open("notes.txt", h => read_line(h))!
print(first)
first line

?로 중간에 나가도 닫힌다

import fs

r = fs.with_open("log.txt", fn(h):
  fs.write_line(h, "first")?
  fs.write_line(h, "second")?
  Ok("wrote 2 lines")
;;, mode: 'write)
print(r, fs.read_lines("log.txt")!)
print(fs.with_open("missing.txt", h => read_line(h)))
Ok("wrote 2 lines") ["first", "second"]
Err({kind: 'not_found, message: "cannot open `missing.txt`: no such file or directory"})

밖으로 꺼낸 핸들은 닫혀 있다

import fs

fs.write("a.txt", "x\n")!
h = fs.with_open("a.txt", h => h)
print(read_line(h))
Err({kind: 'closed, message: "file `a.txt` is closed"})

fs.with_temp_dirfung으로 작성

임시 디렉터리를 만들어 함수에 넘기고, 끝나면 통째로 지운다.

fs.with_temp_dir(f)

설명

운영체제의 임시 디렉터리(TMPDIR, 없으면 /tmp) 아래에 이름이 겹치지 않는 새 디렉터리(fung-…)를 만들고 f(경로)를 부른다. f가 어떻게 끝나든(값, Err, 런타임 에러) 디렉터리를 안의 것까지 지운다. 중간 파일을 잠시 두거나, 테스트에서 깨끗한 작업 공간이 필요할 때 쓴다. 결과는 f의 결과이고, 지우기가 실패하면 런타임 에러다.

매개변수

  • f: 디렉터리 경로(문자열)를 받는 함수.

돌려주는 값

f의 결과, 또는 디렉터리를 만들지 못했을 때의 Err.

예제

작업 후 사라진다

import fs
import path

kept = fs.with_temp_dir(fn(dir):
  p = path.join(dir, "part.txt")
  fs.write(p, "partial")!
  print(fs.read(p)!)
  dir
;;)
print(fs.exists(kept))
partial
false

경로는 실행마다 다르다

import fs

print(fs.with_temp_dir(dir => dir))
