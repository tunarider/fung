에러 카탈로그

에러 번호는 한 번 붙이면 바뀌지 않는다. 메시지 첫 줄의 error[E0606] 같은 번호로 이 쪽에서 찾는다.

프로그램이 잘못되면 fung은 멈추고 에러(error) 메시지를 표준 에러로 찍는다. 메시지마다 번호가 붙어 있고, 이 쪽은 번호마다 뜻, 흔한 원인, 에러를 내는 짧은 예, 고치는 법을 모았다. 경고(warning)는 프로그램을 멈추지 않는 알림이다.

에러 메시지 읽는 법

예를 하나 돌려 보자. 정수를 받아야 하는 함수에 문자열을 넘겼다.

fn backoff(n: int) = n * 2
print(backoff("3"))
error[E0403]: argument `n` must be int, got str
  --> example.fung:1:12
  |
1 | fn backoff(n: int) = n * 2
  |            ^
  |
 call path (innermost first):
   example.fung:1 backoff
   example.fung:2 <entry>

메시지는 위에서부터 이렇게 읽는다.

  1. 첫 줄 error[E0403]: …: 에러 번호와 한 줄 설명. 번호로 이 쪽의 항목을 찾는다.
  2. 위치 --> example.fung:1:12: 파일 이름, 줄, 칸(열). 칸은 1부터 센다.
  3. 소스 발췌: 그 줄을 그대로 보이고 아래에 ^로 문제의 자리를 가리킨다. ^ 옆에 짧은 설명(예: not found in this scope)이 붙기도 한다.
  4. 호출 경로 call path (innermost first): 실행 중의 에러에만 붙는다. 에러가 난 함수부터 바깥쪽으로, 누가 누구를 불렀는지 보여 준다. <entry>는 실행한 파일의 최상위, <lambda>는 이름 없는 함수다. 아주 깊은 재귀는 가운데를 … n more로 줄인다.
  5. 도움말 help: …: 고치는 방법의 힌트. 카탈로그에 적힌 문구가 기본이고, 상황에 맞춰 바뀌기도 한다(비슷한 이름을 알려 주는 E0204처럼). 아래 각 번호의 "기본 도움말"이 그 기본 문구이고, 기본이 없는 번호도 상황에 따라 도움말이 붙을 수 있다.
  6. 덧붙임: note: … 줄이나 assert가 비교한 양쪽 값(E0807)처럼 그 에러에만 있는 정보가 더 붙을 수 있다.

컴파일 에러(실행 전에 찾은 에러)에는 호출 경로가 없다. 아직 아무것도 실행하지 않았기 때문이다.

files = ["a.log", "b.log"]
print(len(fiels))
error[E0204]: undefined name `fiels`
  --> example.fung:2:11
  |
2 | print(len(fiels))
  |           ^^^^^ not found in this scope
  |
 help: a similar name exists: `files`

이 쪽의 에러 예는 모두 페이지를 만들 때 실제로 돌린 출력이 붙는다(출력 칸 머리의 종료 코드도 실제 값이다). fung test·REPL에서만 나는 에러만 그 명령의 실제 출력을 옮겨 적었다. 고친 코드도 실제로 실행된다.

종료 코드

프로그램이 끝나면 운영 체제에 종료 코드(exit code)라는 숫자를 남긴다. 셸에서는 echo $?로 본다. fung의 종료 코드는 다음과 같다(자세한 것은 명령줄 도구).

종료 코드뜻
0정상 종료. 경고만 있으면 0이다.
1실행 중 실패: 런타임 에러, !가 Err를 만남, 아무도 확인하지 않은 태스크의 실패, 테스트 실패.
2컴파일 실패: 문법·이름·import 에러(E01xx~E03xx). 아무것도 실행하지 않는다.
3fung 명령을 잘못 썼다(없는 명령, 읽을 수 없는 파일 등).

fung check는 실행하지 않고 컴파일 단계만 검사하므로 종료 코드 2의 에러와 경고만 찾는다. 인자 개수나 타입(E04xx), 0으로 나누기(E05xx) 같은 것은 실행해야 드러난다.

E01xx: 문법(렉서·파서)

소스는 먼저 렉서(lexer)가 글자를 토큰(token, 숫자·이름·연산자 같은 낱말)으로 자르고, 파서(parser)가 토큰을 문장과 식의 구조로 묶는다. 이 단계에서 글자나 구조가 규칙에 맞지 않으면 E01xx다. 실행 전에 찾는 컴파일 에러라 종료 코드는 2이고, 문법 에러가 있으면 파일의 어떤 줄도 실행하지 않는다. 어휘와 문장과 블록이 규칙이다.

E0101

unexpected character %q

fung이 쓰지 않는 글자가 코드에 나왔다. 문자열과 주석 밖에서는 정해진 연산자와 괄호, 이름에 쓰는 글자만 올 수 있다.

흔한 원인: 다른 언어의 연산자(@, &&의 &, $ 등)를 그대로 썼거나, 복사해 온 코드에 보이지 않는 특수 문자가 섞였다. 옛 Mac 줄 끝처럼 \n 없이 홀로 선 CR(\r)도 이 에러다(주석 안에서도). 양방향 제어 문자(U+202A~U+202E, U+2066~U+2069)는 주석과 문자열 안에서도 이 에러다: 글자가 읽히는 순서와 다르게 보여, 주석이나 문자열처럼 보이는 곳에 코드를 숨길 수 있기 때문이다(문자열에 필요하면 "\u{202E}"처럼 이스케이프로 쓴다). 에러 발췌는 그런 제어 문자를 \r처럼 보인다.

used = 75
print(used @ 100)
error[E0101]: unexpected character "@"
  --> example.fung:2:12
  |
2 | print(used @ 100)
  |            ^
  |

고치는 법: 뜻한 fung 연산자로 바꾼다. 논리 연산은 and·or·not이다.

used = 75
print(used * 100)
7500

E0102

malformed number %q

숫자 모양으로 시작했는데 숫자 규칙에 맞지 않는다. 숫자 바로 뒤에 글자가 붙으면 하나의 잘못된 숫자로 본다.

흔한 원인: 3x처럼 숫자와 글자를 붙여 씀, 16진수에 없는 글자(0xfg), 기간 단위가 아닌 글자(30sec; 기간 단위는 ms·s·m·h뿐이다), 소수부 없는 1.(정수 바로 뒤의 .는 소수부나 범위 ..만 된다). 대문자 접두사·16진 숫자·지수(0XFF, 0xFF, 1E5; 소문자만 된다). 모양은 맞는데 값이 타입에 담기지 않는 수는 E0135다. 1.2.3 같은 버전 문자열은 숫자 1.2 뒤의 필드 접근으로 읽혀 E0112가 된다. 버전은 문자열 "1.2.3"으로 쓴다.

retries = 3x
error[E0102]: malformed number "3x"
  --> example.fung:1:11
  |
1 | retries = 3x
  |           ^^
  |

고치는 법: 숫자만 쓰거나, 글자가 필요하면 문자열로 만든다.

retries = 3
print(retries)
3

E0103

unknown escape %s in string

문자열 "…" 안의 \ 뒤에 fung이 모르는 글자가 왔다. 아는 이스케이프는 \n \t \r \\ \" \$ \u{…} \xHH뿐이고, 나머지는 실수로 보고 에러로 막는다. \x 뒤에는 16진 숫자가 꼭 둘 와야 한다(\x4 다음에 숫자가 아닌 글자가 오면 이 에러다). 메시지는 이스케이프를 쓴 그대로 보인다(unknown escape `\l` ). 보이지 않는 글자(탭)가 \ 뒤에 오면 그 코드 포인트를 적는다. \u{…}의 값이 글자가 아니면 E0106이다.

흔한 원인: Windows 경로나 정규식을 보통 문자열에 그대로 썼다.

print("C:\temp\logs")
error[E0103]: unknown escape `\l` in string
  --> example.fung:1:15
  |
1 | print("C:\temp\logs")
  |               ^
  |

\t는 탭이라 통과하고 \l에서 멈췄다. 경로가 조용히 탭으로 바뀌는 것도 버그이니, 고치는 법은 같다: 백틱 원시 문자열(raw string)을 쓰거나 \\로 쓴다.

print(`C:\temp\logs`)
print("C:\\temp\\logs")
C:\temp\logs
C:\temp\logs

E0104

unterminated string

문자열을 열었는데 같은 줄에서 닫는 "가 없다. 보통 문자열에는 실제 줄바꿈을 넣을 수 없다.

흔한 원인: 닫는 따옴표를 빠뜨림, 여러 줄 문자열을 "…"로 씀(여러 줄은 백틱 원시 문자열이나 \n). 줄 끝의 \도 줄을 잇지 않는다(이스케이프할 글자가 없어 이 에러다).

print("hello)
error[E0104]: unterminated string
  --> example.fung:1:7
  |
1 | print("hello)
  |       ^
  |

위치는 문자열이 시작한 자리를 가리킨다.

print("hello")
hello

E0105

malformed duration %q

기간(duration) 리터럴의 모양이 틀렸다. 기간은 숫자와 단위(ms s m h)의 쌍을 큰 단위부터 붙여 쓴다.

흔한 원인: 작은 단위를 먼저 씀(30s5m), 마지막 숫자에 단위를 빠뜨림(1h30), 성분을 0으로 시작함(1h05m), 마지막이 아닌 성분의 소수점(1.5h30m), 0 ns로 반올림되는 0이 아닌 값(0.0000004ms).

wait = 30s5m
error[E0105]: malformed duration "30s5m"
  --> example.fung:1:8
  |
1 | wait = 30s5m
  |        ^^^^^
  |
wait = 5m30s
print(wait)
5m30s

E0106

`\u{%s}` is not a Unicode scalar value

\u{…} 이스케이프의 값이 유니코드 글자(스칼라 값)가 아니다. \u{…}는 10FFFF까지의 코드 포인트를 받되, UTF-16이 쓰는 서로게이트(D800~DFFF)는 글자가 아니라서 받지 않는다.

흔한 원인: 다른 언어의 UTF-16 서로게이트 짝(\ud83d\ude00)을 옮겨 씀. 글자 하나는 코드 포인트 하나로 쓴다(\u{1f600}). 글자가 아닌 바이트가 필요하면 \xHH다.

print("\u{d83d}")
error[E0106]: `\u{d83d}` is not a Unicode scalar value
  --> example.fung:1:8
  |
1 | print("\u{d83d}")
  |        ^
  |
 help: `\u{…}` takes a code point up to 10FFFF that is not a surrogate (D800–DFFF); for a byte, write `\xHH`
print("\u{1f600}")

  • elif·elsif·elseif → else if
  • while·loop → for x in xs:, 재귀, until·iterate

  • switch·case → match
  • try·catch·except·raise·throw → 예외가 없다. Err(…)를 돌려주고 ?·!·match로 다룬다
  • from → import m (a, b)
  • end·endif·fi·done → 블록은 ;;로 닫는다(줄에 홀로 선 end는 이름으로 읽히므로 닫지 않은 블록의 E0112에 도움말로 붙는다)

이 낱말을 이름으로 쓰는 것은 그대로 된다(let = 1, while(x) 같은 호출). 낱말 바로 뒤(또는 바로 뒤 괄호 다음)에서 문법 에러가 날 때만 이 에러다.

  --> example.fung:4:1
  |
4 | elif x == 2:
  | ^^^^
  |

x = 2

  print("one")

  print("two")
;;

E02xx: 이름과 스코프

문법이 맞으면 fung은 이름(변수, 함수, 타입)이 어디서 무엇을 가리키는지 정한다. 이것을 이름 해석(resolve)이라 하고, 이름이 보이는 범위를 스코프(scope)라 한다. 이 단계의 에러가 E02xx다. 역시 실행 전에 찾는 컴파일 에러라 종료 코드는 2이고, 한 번에 여러 개를 보고할 수 있다. 규칙은 변수와 스코프에 있다: 이름은 위에서 아래로 묶이고, 블록은 바깥 변수를 읽을 수만 있고, 블록 안의 이름은 밖으로 새지 않는다.

E0205

블록 안에서 블록 바깥의 변수에 다시 대입했다. fung의 블록(if·for·함수 본문 등)은 바깥 이름을 읽을 수만 있다. 값이 어디서 바뀌는지 찾아 헤매지 않게 하려는 규칙이다. 최상위 fn 안에서 파일의 최상위 이름(상수)에 대입하는 것도 같다(본문의 맨 바깥 블록에서도). 노트가 바깥 이름을 묶은 줄을 알려 준다. 함수·import한 이름·prelude 함수처럼 변수가 아닌 이름을 다시 묶으면 E0240이다.

흔한 원인: 셸이나 다른 언어처럼 반복문 안에서 카운터를 늘림.

files = ["a.log", "b.txt", "c.log"]

  if ends_with(f, ".log"): count = count + 1 ;;
;;

error[E0205]: cannot reassign `count` here: it was defined outside this block
  --> example.fung:4:28
  |
4 |   if ends_with(f, ".log"): count = count + 1 ;;
  |                            ^^^^^
  |
  note: `count` is a top-level name bound on line 2
 help: a block cannot change an outer variable; build the value with an expression instead, e.g. `x = if … ;;` or `fold`

고치는 법: 값을 식으로 만든다. 세기는 filter와 len, 누적은 fold다.

files = ["a.log", "b.txt", "c.log"]

total = fold(files, 0, (n, f) => n + len(f))

기본 도움말: a block cannot change an outer variable; build the value with an expression instead, e.g. `x = if … ;;` or `fold`

E0208

fn is_even(n) = n == 0 then true else is_odd(n - 1)
fn is_odd(n) = n == 0 then false else is_even(n - 1)

E0234

%s is computed and discarded

버려지는 자리(마지막이 아닌 문장, 그런 자리의 if·match 가지의 끝, 파일의 마지막 식, 문장 for·test 블록 본문의 끝)에 아무 일도 하지 않는 식이 있다. 이름, 리터럴, 람다·익명 fn, 이름과 리터럴만 넘긴 부분 적용(f(_, x)), 그리고 그것들만으로 된 연산자·필드·인덱스·튜플·리스트·맵·태그 값(Ok(1), Red)은 값을 만들 뿐이라, 버리면 쓴 보람이 없다. 대개 실수다: 괄호를 잊은 호출(cleanup), = 대신 쓴 ==(test 블록 안이면 빠뜨린 assert), 앞 줄을 이어 쓰려던 줄 앞의 -(-로 시작하는 줄은 새 문장이다).

error[E0234]: the value of `cleanup` is computed and discarded
  --> example.fung:2:1
  |
2 | cleanup
  | ^^^^^^^
  |
 help: to call it, add `()`: `cleanup()`; to discard it on purpose, write `_ = cleanup`

효과가 없다고 알려진 내장 함수·표준 모듈 함수(put, sort, replace, path.join, json.parse 등 값을 계산해 돌려줄 뿐인 것)를 문장으로 부른 것도 같다(메시지 the result of `put(…)` is computed and discarded). put(m, k, v)가 m을 바꾼다고 여긴 실수가 흔하다. 함수를 받는 내장 함수(map·each 등)와 사용자 함수는 무엇을 할지 모르므로 해당하지 않는다.

고치는 법: 호출이면 ()를 붙이고, 대입이면 =를 쓰고, 효과 없는 함수면 결과를 이름에 담고(m = put(m, k, v)), 여러 줄 식이면 연산자를 줄 끝에 둔다. fung -e의 마지막 값도 버려지므로 보려면 print(…)로 감싼다. 일부러 버리려면 _ = 식. 예외는 맨 nil 하나다: 문장으로 쓴 match에서 할 일이 없는 절을 _ => nil로 적게 둔다. 실행 중에 계산된 Err를 버리는 것은 여전히 E0606이다. 0.6.0까지는 말없이 버렸다.

fn cleanup() = print("cleaned")
cleanup()
cleaned

기본 도움말: use the value, or write `_ = …` to discard it on purpose

E0235

this arm %s

match에 결코 돌지 않는 절이 있다. 두 경우다. guard 없는 절의 패턴이 모든 값에 맞는데(_, 맨 이름, 그런 갈래가 하나라도 있는 | 대안, 예: 1 | _) 그 뒤에 절이 더 있으면, 앞 절이 모든 값을 가져가므로 뒤 절은 결코 돌지 않는다(에러가 앞 절을 가리킨다). guard 없는 앞 절이 이미 맞는 리터럴(쓴 그대로 같은 수·문자열·심볼·nil 등)을 패턴으로 쓴 절도 결코 돌지 않는다(에러가 뒤 절을 가리킨다). 패턴의 이름은 바깥 변수와 비교하지 않고 새 이름을 묶으므로 limit => …도 모든 값에 맞는다. 절 본문 안의 y => y + 1 줄도 새 절로 읽혀 여기에 걸린다.

limit = 5
fn f(x) = match x:
  limit => "at limit"
  _     => "other"
;;
print(f(3))
error[E0235]: this arm matches everything, so the arms after it never run
  --> example.fung:3:3
  |
3 |   limit => "at limit"
  |   ^^^^^
  |
 help: a name in a pattern binds a new name, so `limit` here is not the variable; compare with a guard: `v when v == limit =>`
error[E0240]: `limit` hides a top-level name
  --> example.fung:3:3
  |
3 |   limit => "at limit"
  |   ^^^^^
  |
  note: `limit` is a top-level name bound on line 1
 help: a visible name means one thing: give the new one a name of its own

고치는 법: 모든 값에 맞는 절을 마지막에 둔다. 바깥 변수와 비교하려면 guard를 쓴다(v when v == limit =>). 절의 값인 람다는 괄호로 감싼다(1 => (y => y + 1)). 겹친 리터럴 절은 하나를 지우거나 본문을 한 절로 합친다. 0.6.0까지는 말없이 뒤 절을 버렸다.

limit = 5
fn f(x) = match x:
  v when v == limit => "at limit"
  _                 => "other"
;;
print(f(3), f(5))
other at limit

기본 도움말: move it last, or give it a guard: `n when n > 0 =>`

E0236

`%s` takes exactly one value, found %d

Ok·Err에 값을 하나가 아닌 개수로 주었다. 결과값은 값을 정확히 하나 담는다. 식에서도 패턴에서도 같고, 파이프가 채운 값도 센다: x |> Ok(2)는 Ok(x, 2)라 이 에러다. 값이 없는 맨 Ok·Err도(개수 0) 이 에러다: 다른 태그라면 심볼이겠지만 결과값의 이름은 값 없이 쓰지 않는다. 파이프의 오른쪽 x |> Ok만 파이프가 값을 채우므로 된다. 0.6.0까지는 Ok(1, 2)가 "같은 이름의 보통 태그"였고 맨 Ok는 심볼이었다.

fn divmod(a, b) = b == 0 then Err("division by zero") else Ok(a // b, a % b)
print(divmod(7, 2))
error[E0236]: `Ok` takes exactly one value, found 2
  --> example.fung:1:60
  |
1 | fn divmod(a, b) = b == 0 then Err("division by zero") else Ok(a // b, a % b)
  |                                                            ^
  |
 help: put several values in a tuple: `Ok((a, b))` or `Err((a, b))`

고치는 법: 여러 값은 튜플 하나에 담는다.

fn divmod(a, b) = b == 0 then Err("division by zero") else Ok((a // b, a % b))
print(divmod(7, 2))
Ok((3, 1))

기본 도움말: put several values in a tuple: `Ok((a, b))` or `Err((a, b))`

E0237

`%s` inside %s

람다 =>나 for 본문 안에서 return이나 ?를 썼다. 람다는 일찍 돌아갈 수 없다. 허락하면 return·?는 바깥 함수가 아니라 람다에서 돌아오고, 그 값은 받은 함수가 쓰는 대로 쓰인다: map이면 Err가 결과 리스트의 원소가 되고, filter면 조건 자리에서 런타임 에러가 된다. for 본문도 map이 부르는 람다라 같다. 0.6.0까지는 for 본문(E0213·E0220)과 map·conc.pmap에 바로 넘긴 람다의 ?(E0226)만 막았다.

fn ports(xs) = map(xs, s => parse_int(s)?)
error[E0237]: `?` inside a lambda `=>`
  --> example.fung:1:41
  |
1 | fn ports(xs) = map(xs, s => parse_int(s)?)
  |                                         ^
  |
 help: a lambda `=>` and a `for` body cannot return early; write an anonymous `fn(x): … ;;` to return from, or use `try_map`, `find`, `all`/`any` or `fold`

고치는 법: 실패할 수 있는 변환은 첫 Err에서 멈추는 try_map, 찾기는 find, 검사는 all·any, 누적은 fold를 쓴다. 정말 일찍 돌아가야 하면 익명 함수 fn(x): … ;;로 쓴다.

fn ports(xs) = try_map(xs, parse_int)
print(ports(["80", "443"]), ports(["80", "http"]))
fn first_big(xs) = find(xs, fn(x):
  if x < 0: return false ;;
  x > 100
;;)
print(first_big([10, 300]))
Ok([80, 443]) Err({kind: 'parse, message: "not an integer: \"http\""})
300

기본 도움말: a lambda `=>` and a `for` body cannot return early; write an anonymous `fn(x): … ;;` to return from, or use `try_map`, `find`, `all`/`any` or `fold`

E0238

cannot bind `%s` again: a top-level name is bound once

파일의 맨 바깥(최상위)에서 이미 묶은 이름을 다시 대입하거나 패턴으로 다시 묶었다. 최상위 이름은 한 번만 묶이고, 그래서 모두 상수라 최상위 fn이 언제든 읽을 수 있다. 블록(함수 본문, if 가지 등) 안에서는 같은 이름에 다시 대입할 수 있다. 노트가 처음 묶은 줄을 알려 준다.

  --> example.fung:2:1
  |
2 | retries = retries + 1
  | ^^^^^^^
  |
  note: `retries` is first bound on line 1
 help: give the new value a name of its own, or compute it in one expression (`x = if … ;;`, `fold`)

고치는 법: 바뀐 값에 새 이름을 붙이거나, 식 하나로 계산하거나, 함수 안에서 계산한다.

retries = 3

기본 도움말: give the new value a name of its own, or compute it in one expression (`x = if … ;;`, `fold`)

E0239

unused %s `%s`

묶고 한 번도 읽지 않은 이름이 있다. 지역 변수, 매개변수(람다·for·match 패턴이 묶는 이름 포함), import가 모두 해당한다. 다시 대입하기만 하는 것은 읽는 것이 아니다. 진입 파일의 최상위 이름도 지역으로 센다. 계산해 놓고 쓰는 것을 잊었거나, 이름을 잘못 적었을 가능성이 크다. 메시지가 어떤 이름인지(variable, parameter, import) 알려 준다.

이 에러는 파일에 다른 에러가 없을 때만 나온다. 쓰지 않는 이름은 다른 에러(오타로 읽지 못한 이름, 다시 묶지 못한 이름)의 결과일 때가 많기 때문이다. 세지 않는 것: _로 시작하는 이름, 최상위 fn, import된 파일의 공개 이름(그 모듈의 인터페이스). 이전에는 경고 W0101·W0102였다.

fn total(xs):
  count = len(xs)
  fold(xs, 0, (a, b) => a + b)
;;
print(total([1, 2]))
error[E0239]: unused variable `count`
  --> example.fung:2:3
  |
2 |   count = len(xs)
  |   ^^^^^
  |
 help: remove it, or start its name with `_` if it is kept on purpose

고치는 법: 쓰지 않는 대입·매개변수·import를 지운다. 일부러 쥐고 있는 값이나 받기만 하는 매개변수는 이름을 _로 시작한다(채널의 끝을 함수가 끝날 때까지 살려 둠, 콜백이 넘겨 주는 값을 쓰지 않음).

fn total(xs) = fold(xs, 0, (a, b) => a + b)
fn on_fail(_e) = nil
(name, _size) = ("a.txt", 3)
print(total([1, 2]), on_fail(1), name)
3 nil a.txt

기본 도움말: remove it, or start its name with `_` if it is kept on purpose

E0240

`%s` hides %s

새로 묶는 이름이 그 자리에서 보이는 바깥 이름을 가린다. 바깥 블록이나 바깥 함수의 이름, 최상위 이름과 최상위 fn, import한 이름, prelude 함수, 지역 fn 자신의 이름이 해당하고, 묶는 방법(매개변수, 람다의 매개변수, for의 변수, match 절의 패턴, 구조 분해, 지역 fn, 최상위 fn, import, 함수·prelude 이름에 대한 대입)과 상관없다. 한 자리에서 이름 하나는 한 가지만 뜻하게 하려는 규칙이다: 가려진 이름을 읽으려다 내 값을 읽는 실수(match x: x => …는 x와 비교하지 않는다)가 없어진다. 메시지가 무엇을 가리는지, 노트가 그 이름을 묶은 줄을 알려 준다. 바깥 변수에 대입하는 것은 E0205, 모듈 이름을 가리는 것은 E0308이다. 이전에는 prelude 이름을 가리는 것만 경고 W0103이었다.

limit = 10
fn clamp(xs, limit) = map(xs, x => x > limit then limit else x)
print(clamp([5, 20], limit))
error[E0240]: `limit` hides a top-level name
  --> example.fung:2:14
  |
2 | fn clamp(xs, limit) = map(xs, x => x > limit then limit else x)
  |              ^^^^^
  |
  note: `limit` is a top-level name bound on line 1
 help: a visible name means one thing: give the new one a name of its own
fn summary(xs):
  max = 0
  len(xs) + max
;;
print(summary([1]))
error[E0240]: `max` hides a prelude function
  --> example.fung:2:3
  |
2 |   max = 0
  |   ^^^
  |
 help: a visible name means one thing: give the new one a name of its own

고치는 법: 새 이름에 다른 이름을 붙인다(cap, biggest).

limit = 10
fn clamp(xs, cap) = map(xs, x => x > cap then cap else x)
print(clamp([5, 20], limit))
[5, 10]

import된 파일의 인터페이스, 곧 공개 최상위 이름과 공개 fn의 매개변수는 prelude 함수와 같은 이름이어도 된다(http.get, path.join, timeout:). 부르는 쪽은 그것을 모듈 이름을 붙여 읽거나 인자 이름으로만 쓴다(모듈).

기본 도움말: a visible name means one thing: give the new one a name of its own

this alternative never matches: %s

E03xx: 모듈과 import

모듈(module)은 다른 파일에 둔 코드를 가져다 쓰는 단위다. 파일 하나가 모듈 하나이고, import fs처럼 표준 라이브러리는 이름으로, import "./lib/x"처럼 내 파일은 경로로 가져온다(모듈). 가져올 파일을 찾고 읽고 이름을 잇는 일은 실행 전에 하므로, E03xx도 컴파일 에러(종료 코드 2)다. 에러가 가져온 파일 안에서 났으면 위치도 그 파일을 가리킨다.

E0301

cannot find module `%s`

가져올 모듈을 찾지 못했다.

흔한 원인: 내 파일을 경로 없이 이름으로 가져옴(import util; 이름은 표준 라이브러리만 찾는다), 경로 오타, 없는 표준 모듈 이름. 경로로 가져올 때는 메시지에 찾아본 파일이 위치와 같은 모양으로 나온다(작업 디렉터리 아래면 상대 경로, 아니면 절대 경로). 파일은 있는데 읽지 못하면 E0312다.

import util
error[E0301]: cannot find module `util`
  --> example.fung:1:1
  |
1 | import util
  | ^
  |
 help: standard library modules are imported by name (`import fs`); your own files by path (`import "./lib/x"`)

고치는 법: 내 파일은 import하는 파일을 기준으로 한 상대 경로로 가져온다. .fung은 생략한다.

준비물: util.fung

HI!

기본 도움말: standard library modules are imported by name (`import fs`); your own files by path (`import "./lib/x"`)

E0302

모듈들이 서로를 고리처럼 가져온다(순환 import). a를 읽으려면 b가 필요하고 b를 읽으려면 다시 a가 필요하니 끝나지 않는다. 메시지에 고리 전체가 나온다. 파일이 자기 자신을 가져와도 이 에러다.

준비물: a.fung, b.fung

fn one() = 1

b.fung

error[E0302]: circular import: a.fung → b.fung → a.fung
  --> b.fung:1:1
  |
1 | import "./a"
  | ^
  |

고치는 법: 둘이 함께 쓰는 부분을 세 번째 모듈로 떼어 내고, 두 모듈이 그것을 가져오게 한다.

준비물: shared.fung, a.fung, b.fung

shared.fung

fn one() = 1

a.fung

import "./shared"
fn one() = shared.one()

b.fung

import "./shared"
fn two() = shared.one() + 1
import "./a"
import "./b"

E0310

_native.으로 시작하는 내부 모듈을 가져오려 했다. 이것은 표준 모듈이 안에서 쓰는 Rust 쪽 다리라서 직접 가져올 수 없다. 메시지가 그것을 감싼 쪽을 알려 준다: 같은 이름의 모듈(_native.fs → fs), _native.net이면 http, _native.process·_native.range이면 prelude 함수(exec·sh·take 등), _native.arg이면 표준 모듈이 인자를 검사하는 데 쓴다는 것.

E0312

cannot read module `%s`: %s

가져온 모듈 파일이 있는데 읽지 못했다. 메시지가 까닭을 말한다: 권한이 없음(cannot read module `lib/x.fung`: permission denied), 파일이 아니라 디렉터리(is a directory), UTF-8이 아님. 파일이 없으면 E0301이다.

가장 흔한 것은 UTF-8이 아닌 파일이다. fung 소스는 UTF-8 글이어야 한다. 잘못된 바이트를 U+FFFD(�)로 바꿔 읽으면 프로그램에 아무도 쓰지 않은 글자가 말없이 끼어들므로, 읽지 않고 멈춘다. 메시지가 처음 잘못된 바이트의 줄과 칸을 알려 준다: cannot read module `lib.fung`: not valid UTF-8 at line 3, column 7. 실행하는 파일 자체나 fung -e의 코드가 UTF-8이 아니면 같은 이유로 error: cannot read `x.fung`: not valid UTF-8 at line 1, column 5(종료 코드 3)다.

흔한 원인: 다른 인코딩(EUC-KR, Latin-1)으로 저장한 파일.

고치는 법: 파일을 UTF-8로 다시 저장한다(iconv -f euc-kr -t utf-8). 이때만 도움말 fung source is UTF-8 text가 붙는다. 바이트 값 자체가 필요하면 문자열 안에 \xHH로 쓴다.

print(["caf\xe9", "caf\u{e9}"])
["caf\xe9", "café"]

E0313

`import` after another statement

파일의 다른 문장 뒤에 import를 썼다. import는 파일 맨 앞, 다른 모든 문장보다 먼저 온다. 가져온 모듈은 파일의 첫 문장보다 먼저 실행되므로, 그 순서가 코드의 모양에도 드러나게 한다. 0.6.0까지는 어디에 쓰든 파일 맨 앞으로 끌어올렸다.

print("start")
import json
error[E0313]: `import` after another statement
  --> example.fung:2:1
  |
2 | import json
  | ^^^^^^
  |
 help: put every import at the top of the file, before the other statements

고치는 법: 모든 import를 파일 맨 위로 옮긴다.

print("start", json.stringify([1]))
start [1]

기본 도움말: put every import at the top of the file, before the other statements

E04xx: 호출과 타입 표기

함수를 부를 때 인자가 맞지 않거나, 인자와 반환값이 적어 둔 타입과 다르면 E04xx다. fung은 동적 타입 언어라서 이것들은 대개 실행 중에, 그 호출이 실제로 일어날 때 검사하고, 종료 코드는 1이다. 메시지의 호출 경로가 어느 호출에서 났는지 알려 준다. 다만 호출 대상이 컴파일 때 정해지는 호출(가려지지 않은 최상위 fn, prelude 함수, import한 모듈의 함수)의 인자 개수와 이름(E0402·E0405·E0406·E0407)은 실행 전에 같은 번호와 문구로 잡고, 그때는 컴파일 에러라 fung check도 찾고 종료 코드는 2다. 규칙은 함수와 타입 표기에 있다.

E0401

cannot call a value of type %s

함수가 아닌 값을 함수처럼 불렀다. 메시지에 그 값의 타입이 나온다.

흔한 원인: 같은 이름의 변수가 함수를 가렸음(prelude 변수 args는 함수가 아니라 리스트다), 괄호를 잘못 붙임.

  --> example.fung:2:11
  |

  |           ^
  |

   example.fung:2 <entry>

deploying

E0402

위치 인자를 함수가 받는 것보다 많이 넘겼다. 메시지는 함수 이름, 받는 개수, 넘긴 개수를 적는다. 내장 함수도 같다. 호출 대상이 컴파일 때 정해지면 실행 전에 잡는다(종료 코드 2). 변수에 든 함수 값이나 펼친 인자(...xs)는 부를 때 센다(종료 코드 1).

  --> example.fung:2:14
  |
2 | print(connect("db1", 5432, 10s))
  |              ^
  |

print(connect("db1", 5432, 10s))
error[E0402]: the function takes 2 argument(s), got 3
  --> example.fung:2:14
  |
2 | print(connect("db1", 5432, 10s))
  |              ^
  |
 call path (innermost first):
   example.fung:2 <entry>

고치는 법: 남는 인자를 지우거나, 함수에 기본값 있는 매개변수를 더한다.

fn connect(host, port, wait = 5s) = "${host}:${port} (${wait})"
print(connect("db1", 5432, 10s))

E0403

argument `%s` must be %s, got %s

인자가 매개변수에 적은 타입이 아니다. 위치는 그 매개변수를 가리키고, 호출 경로의 두 번째 줄이 누가 불렀는지 보여 준다.

흔한 원인: 명령줄 인자나 파일에서 읽은 문자열을 숫자로 바꾸지 않고 넘김, 열거형 별칭(type color = Red | Green)에 없는 태그를 넘김.

6

E0404

함수가 돌려준 값이 -> 뒤에 적은 반환 타입이 아니다.

E05xx: 런타임 연산

산술, 비교, 인덱스, 변환 같은 연산이 받은 값으로는 할 수 없을 때 E05xx다. fung은 값을 조용히 다른 타입으로 바꾸지 않는다("a" + 1은 "a1"이 아니라 에러). 숫자가 넘치거나 0으로 나누는 것도 이상한 값을 만들어 계속 가는 대신 그 자리에서 멈춘다. 모두 실행 중의 에러라 종료 코드는 1이다(값과 타입, 연산자).

E0501

cannot %s %s and %s

이항 연산자가 받은 두 값의 타입 조합으로는 계산할 수 없다. 메시지는 연산(add, subtract …)과 두 타입을 적는다. 함수는 같음이 없어서 ==·!=로 견주거나 unique에 넣어도 이 에러다(cannot compare fn and fn).

흔한 원인: 문자열과 숫자를 +로 이음, nil(없는 값)로 계산함, 기간을 정수로 // 나눔.

count = 3
print("found " + count + " files")
error[E0501]: cannot add str and int
  --> example.fung:2:16
  |
2 | print("found " + count + " files")
  |                ^
  |
 call path (innermost first):
   example.fung:2 <entry>
 help: put the value into the text with `"${…}"`, or convert it with `str(…)`

고치는 법: 문자열 보간 ${…}을 쓰거나 str로 바꾼다.

count = 3
print("found ${count} files")
print("found " + str(count) + " files")
found 3 files
found 3 files

E0502

division by zero

0으로 나눴다. /, //, % 모두, 기간끼리의 나눗셈도 같다.

흔한 원인: 빈 리스트의 평균을 구함.

fn average(xs) = sum(xs) / len(xs)

고치는 법: 나누기 전에 0인 경우를 따로 처리한다.

fn average(xs) = len(xs) == 0 then 0 else sum(xs) / len(xs)
print(average([]), average([2, 4]))
0 3.0

E0503

정수 계산 결과가 64비트 정수의 범위(약 ±9.2×1018)를 넘었다. fung은 넘친 값을 조용히 감아 돌리지 않고 멈춘다.

흔한 원인: 큰 거듭제곱(2 ** 64), 끝없이 커지는 누적.

  --> example.fung:1:27
  |

고치는 법: 값의 범위를 미리 확인한다. 정확도가 조금 떨어져도 괜찮으면 실수로 계산한다.

fn add_safe(a, b) = a > 9223372036854775807 - b then Err("too big") else Ok(a + b)
print(add_safe(9223372036854775807, 1))
Err("too big")

E0504

E0505

조건 자리(if, then, when, and·or·not의 피연산자)에 bool이 아닌 값이 왔다. fung은 0, 빈 리스트, 빈 문자열을 거짓으로 보지 않는다.

not empty

E0506

흔한 원인: 문자열에 단항 -, 숫자에 len, 문자열에 리스트 함수(first("abc"); 문자열은 chars로 리스트로 바꾼다).

print(-"5")
error[E0506]: cannot negate str
  --> example.fung:1:7
  |
1 | print(-"5")
  |       ^

정수를 음의 정수로 거듭제곱했다(2 ** -1). 결과가 정수가 아니므로, 결과의 타입이 지수의 값에 따라 바뀌지 않게 에러로 한다.

n = -1
print(2 ** n)
error[E0524]: `2 ** -1`: an int to a negative int power is not an int
  --> example.fung:2:9
  |
2 | print(2 ** n)
  |         ^
  |
 call path (innermost first):
   example.fung:2 <entry>
 help: write the exponent as a float: `2 ** -1.0`

고치는 법: 지수(나 밑)를 실수로 쓴다. 0.6.0까지는 실수를 돌려줬다.

n = -1
print(2 ** float(n), 2.0 ** n)
0.5 0.5

기본 도움말: write the exponent as a float: `2 ** -1.0`

E06xx: 패턴과 결과값

match와 구조 분해 대입은 값을 패턴(pattern)에 맞춰 본다. 맞는 패턴이 없으면 E0601·E0602다. fung은 실패할 수 있는 일의 결과를 예외(exception)로 던지지 않고 Ok(값)·Err(내용)이라는 값으로 돌려준다. 이 결과값을 !·?로 잘못 다루거나 확인하지 않고 버리면 E0603~E0606이다(match와 패턴, 결과값과 에러). 모두 실행 중의 에러다.

E0601

no pattern matched %s

match의 어떤 절도 값에 맞지 않았다. 메시지에 맞지 않은 값이 나온다.

흔한 원인: 몇 가지 값만 적고 나머지 경우를 잊음.

fn status_text(code) = match code:
  200 => "ok"
  404 => "not found"
;;
print(status_text(500))
error[E0601]: no pattern matched 500
  --> example.fung:1:24
  |
1 | fn status_text(code) = match code:
  |                        ^
  |
 call path (innermost first):
   example.fung:1 status_text
   example.fung:5 <entry>

고치는 법: 마지막에 나머지를 받는 절(_ =>나 이름 하나)을 둔다.

fn status_text(code) = match code:
  200 => "ok"
  404 => "not found"
  c   => "other (${c})"
;;
print(status_text(500))
other (500)

E0602

value %s does not match the pattern

구조 분해 대입의 왼쪽 패턴에 값이 맞지 않는다. 메시지에 실제 값이 나온다.

흔한 원인: split 결과의 개수가 생각과 다름, 튜플의 원소 개수가 다름.

line = "web1 10.0.0.1"
[_name, _addr, _role] = split(line, " ")
error[E0602]: value ["web1", "10.0.0.1"] does not match the pattern
  --> example.fung:2:1
  |
2 | [_name, _addr, _role] = split(line, " ")
  | ^
  |
 call path (innermost first):
   example.fung:2 <entry>

고치는 법: 개수가 달라질 수 있으면 ...rest로 나머지를 받거나 match로 경우를 나눈다.

line = "web1 10.0.0.1"
[name, addr, ...rest] = split(line, " ")
print(name, addr, rest)
web1 10.0.0.1 []

E0603

unhandled Err: %s

!가 Err를 만났다. x!는 "실패하면 프로그램을 멈춘다"는 뜻이라, 이것은 의도한 멈춤이다. 메시지에 Err의 내용(표준 라이브러리면 message)이 나온다.

import fs
_text = fs.read("config.json")!
error[E0603]: unhandled Err: cannot read `config.json`: no such file or directory
  --> example.fung:2:31
  |
2 | _text = fs.read("config.json")!
  |                               ^
  |
 call path (innermost first):
   example.fung:2 <entry>

고치는 법: 실패를 정말 멈춤으로 다루려면 그대로 둔다. 어떤 실패는 넘어가야 하면 match로 종류(kind)를 가려 처리한다.

import fs
text = match fs.read("config.json"):
  Ok(t)                   => t
  Err({kind: 'not_found}) => "{}"
  Err(e)                  => fail(e.message)
;;
print(text)
{}

E0604

`%s` on nil

nil에 !·?나 그 규칙을 따르는 함수(try_map)를 썼다. 이들은 Ok/Err만 받는데, nil은 "없음"이지 실패가 아니다. 메시지 앞의 이름이 연산자나 함수다.

흔한 원인: nil을 돌려줄 수 있는 함수(get, find, first, env 등)의 결과에 !나 ?를 붙임.

cfg = {host: "db1"}
_port = get(cfg, "port")!
error[E0604]: `!` on nil
  --> example.fung:2:25
  |
2 | _port = get(cfg, "port")!
  |                         ^
  |
 call path (innermost first):
   example.fung:2 <entry>

고치는 법: nil에는 ??로 기본값을 준다. 없을 때 호출자에게 넘기려면 match나 if x == nil: return nil ;;로 드러내 쓴다.

cfg = {host: "db1"}
port = get(cfg, "port") ?? 5432
print(port)
5432

E0605

`%s` on %s, which is not a result (Ok(x) or Err(e))

!·?나 그 규칙을 따르는 함수(try_map)가 결과값이 아닌 값을 받았다. 결과값은 Ok(v)·Err(e)뿐이다(nil은 E0604). 메시지 앞의 이름이 연산자나 함수다.

흔한 원인: 실패하지 않는 함수(len 등)에 !를 붙임, try_map에 결과값이 아닌 값을 돌려주는 함수를 줌(그때는 map을 쓴다).

print(try_map([1, 2], x => x * 2))
error[E0605]: `try_map` on a value of type int, which is not a result (Ok(x) or Err(e))
  --> example.fung:1:14
  |
1 | print(try_map([1, 2], x => x * 2))
  |              ^
  |
 call path (innermost first):
   example.fung:1 <entry>
print(try_map(["1", "2"], parse_int), map([1, 2], x => x * 2))
Ok([1, 2]) [2, 4]

E0606

discarded Err: %s

값을 쓰지 않는 자리에서 Err가 나와 버려졌다. 실패가 아무도 모르게 지나가지 않도록 fung은 버려지는 Err를 에러로 만든다. 셸의 set -e를 늘 켜 둔 것과 같다.

버려지는 자리: 문장으로 쓴 호출, 그런 자리의 if·match 가지의 끝, for 문장의 본문, 파일의 마지막 식, each에 준 함수, with의 release, supervise의 on_fail, test 블록이 돌려준 값. 외부 명령이 실패해도 exec가 Err를 돌려주므로 같다.

버려지는 값이 리스트·맵·튜플·태그면 그 안을 깊이와 상관없이 본다. for로 끝나는 함수를 문장으로 부르거나 map(…)을 문장으로 쓰면 리스트가 버려지는데, 그 안의 첫 Err가 E0606이 되고 note: element 2 of the discarded list (of 3)처럼 어디 있는지 덧붙는다(더 깊으면 note: key "db" of the discarded map, then the value of Ok(…)``처럼 길을 잇는다). 0.6.0까지는 리스트의 한 겹만 봤다.

import fs
fs.write("missing/out.txt", "data")
print("saved")
error[E0606]: discarded Err: cannot write `missing/out.txt`: no such file or directory
  --> example.fung:2:1
  |
2 | fs.write("missing/out.txt", "data")
  | ^ this value is discarded
  |
 call path (innermost first):
   example.fung:2 <entry>
 help: handle it with `!`, `?` or `match`, or discard it on purpose: `_ = ...`

고치는 법: !(실패하면 멈춤), ?(함수 안에서 호출자에게 넘김), match(경우마다 처리)로 다룬다. 실패해도 상관없으면 _ = 식으로 일부러 버린다.

import fs
match fs.write("missing/out.txt", "data"):
  Ok(_)  => print("saved")
  Err(e) => print("skip:", e.kind)
;;
_ = fs.remove("missing/old.txt")
print("done")
skip: 'not_found
done

기본 도움말: handle it with `!`, `?` or `match`, or discard it on purpose: `_ = ...`

E0607

task's Err was never awaited: %s

태스크의 함수가 Err를 돌려줬는데, 그 결과를 아무도 await로 읽지 않은 채 읽을 수 없게 되었다. 핸들을 버리고 띄운 일이 실패하면 아무도 모르게 지나가므로, 버려지는 Err(E0606)처럼 에러로 만든다. 에러는 spawn한 자리를 가리키고 그 범위를 실패시킨다(supervise면 on_fail이 받는다).

읽을 수 없게 되는 때는 셋이다. 태스크가 끝났을 때 핸들이 하나도 남지 않았거나, 끝난 뒤 마지막 핸들이 읽히지 않은 채 사라졌거나, 범위가 닫힐 때 읽지 않은 핸들이 범위 밖에 남았을 때다. 어느 경우든 에러인지 아닌지는 같고, 알리는 때만 다르다. 리스트·맵·튜플·태그를 돌려주면 그 안도 깊이와 상관없이 본다. 취소·시간 초과로 끝난 태스크의 Err는 런타임이 만든 것이라 세지 않는다.

import fs
scope(s => spawn(s, () => fs.write("missing/out.txt", "data")))
print("saved")
error[E0607]: task's Err was never awaited: cannot write `missing/out.txt`: no such file or directory
  --> example.fung:2:17
  |
2 | scope(s => spawn(s, () => fs.write("missing/out.txt", "data")))
  |                 ^ this task's result is discarded
  |
  note: scope opened at example.fung:2
 call path (innermost first):
   example.fung:2 <entry>
 help: `await` it, or end the task's function with `nil`

고치는 법: 결과를 await로 읽어 다루거나, 실패해도 상관없는 일이면 태스크의 함수를 nil로 맺는다.

import fs
scope(fn(s):
  t = spawn(s, () => fs.write("missing/out.txt", "data"))
  match await(t)!:
    Ok(_)  => print("saved")
    Err(e) => print("skip:", e.kind)
  ;;
  spawn(s, fn():
    _ = fs.remove("missing/old.txt")
    nil
  ;;)
;;)
skip: 'not_found

기본 도움말: `await` it, or end the task's function with `nil`

E07xx: 동시성

동시성(concurrency)은 여러 일(태스크, task)을 번갈아 진행하는 것이다. fung의 태스크는 scope 안에서 spawn으로 띄우고, 채널(channel)로 값을 주고받고, 여럿이 함께 보는 값은 atom에 둔다(동시성 내장 함수). 이 규칙을 어기거나 모든 태스크가 서로를 기다리며 멈추면 E07xx다. 모두 실행 중의 에러다.

E0701

task cancelled

태스크가 취소되었다. 취소는 보통 fung 안에서 조용히 처리된다: 태스크 범위가 끝나거나 다른 태스크가 실패하면 남은 태스크를 취소하고, 이 취소는 에러로 찍지 않는다. fung run에서는 이 번호를 거의 보지 않는다.

보이는 경우: fung test에서 테스트 블록 안의 태스크가 exit(n)을 불러 기다리던 쪽이 취소되면, 그 테스트의 실패 이유로 나온다. fung run에서 보이지 않으므로 아래 출력은 fung test example.fung을 실제로 돌려 옮겨 적었다.

test "a task exits":
  scope(fn(s):
    t = spawn(s, () => exit(3))
    await(t)
  ;;)
;;
FAIL example.fung: a task exits
  error[E0701]: task cancelled
    --> example.fung:4:10
    |
  4 |     await(t)
    |          ^
    |
   call path (innermost first):
     example.fung:4 <lambda>
     example.fung:2 test: a task exits
0 passed, 1 failed

고치는 법: 테스트 안에서는 exit를 부르지 않는다. 끝낼 이유는 Err나 fail로 돌려준다.

E0702

deadlock: all tasks are waiting

교착(deadlock): 모든 태스크가 무언가를 기다리고 있어서 아무도 더 나아갈 수 없다. fung은 영원히 멈춰 있는 대신 이것을 알아채고 에러로 끝낸다. 상황에 따라 도움말이 원인을 짚어 준다.

흔한 원인: 받는 쪽이 보내는 끝을 자기도 쥐고 있어서 채널이 닫히지 않음, 버퍼 없는 채널(channel())에 받는 태스크 없이 보냄.

(_tx, rx) = channel()
print(recv(rx))
error[E0702]: deadlock: all tasks are waiting
  --> example.fung:2:11
  |
2 | print(recv(rx))
  |           ^
  |
 call path (innermost first):
   example.fung:2 <entry>
 help: this task waits to receive, but it still holds that channel's sending end itself (the global `_tx`), so the channel cannot close: close it with `close(_tx)` first, or leave the sending end to the producers only

channel()은 버퍼가 없어서 받는 쪽이 준비될 때까지 send가 기다린다. 같은 태스크가 보내고 나서 받으려 하면 그것도 교착이다.

(tx, rx) = channel()
send(tx, "job")!
close(tx)
for job in rx: print(job) ;;
error[E0702]: deadlock: all tasks are waiting
  --> example.fung:2:5
  |
2 | send(tx, "job")!
  |     ^
  |
 call path (innermost first):
   example.fung:2 <entry>

고치는 법: 보내기는 다른 태스크에 맡기고, 보내는 끝은 보내는 쪽만 쥔다. 함수 안의 변수는 마지막으로 읽힌 뒤 놓이므로, 보내는 끝을 태스크에만 넘기면 그 태스크가 끝날 때 채널이 닫혀 for가 끝난다. 혼자 보내고 받아야 하면 버퍼가 있는 channel(n)을 쓰고 다 보낸 뒤 close한다.

fn collect() = scope(fn(s):
  (tx, rx) = channel()
  spawn(s, fn():
    send(tx, 1)!
    send(tx, 2)!
  ;;)
  for x in rx: x ;;
;;)!
print(collect())
[1, 2]

E0703

atom swapped inside its own swap

쓰지 않는 번호다. 예전 버전의 atom이 자기 swap 안에서 다시 바뀔 때 내던 에러였다. atom이 한때 에이전트(agent)가 되면서 E0704로 바뀌었고, 지금은 E0707이 그 경우를 맡는다. 번호는 한 번 붙이면 다른 뜻으로 다시 쓰지 않으므로 자리만 남아 있다. 지금의 fung에서는 나오지 않아 예가 없다.

기본 도움말: not used: atoms became agents, see E0704

E0704

agent called from inside its own swap

쓰지 않는 번호다. 에이전트를 자기 swap 안에서 부를 때 내던 에러였다. 에이전트가 다시 엄격한 atom이 되면서 이 경우는 E0707(swap의 함수 안의 효과)로 잡힌다. 지금의 fung에서는 나오지 않아 예가 없다.

기본 도움말: not used: agents became atoms, see E0707

E0705

channel sent into itself

쓰지 않는 번호다. 채널의 끝을 같은 채널로 보낼 때 내던 에러였는데, 다른 채널·태스크를 거쳐 닫히는 고리와 같은 원인이라 E0709로 합쳤다. 번호는 다시 쓰지 않는다. 나오지 않으므로 예가 없다.

기본 도움말: not used: merged into E0709

E0706

`%s` on a closed scope

이미 닫힌 태스크 범위의 핸들로 spawn하거나 cancel했다. 태스크 범위는 그 안의 태스크가 모두 끝나야 닫히는 울타리인데, 닫힌 뒤에 들어오는 태스크는 기다려 줄 사람이 없고, 취소할 것도 남아 있지 않다.

흔한 원인: scope의 함수가 태스크 범위 값 s를 돌려주고 밖에서 그것으로 spawn하거나 cancel함.

s = scope(s => s)!
spawn(s, () => print("late"))
error[E0706]: `spawn` on a closed scope
  --> example.fung:2:6
  |
2 | spawn(s, () => print("late"))
  |      ^
  |
 call path (innermost first):
   example.fung:2 <entry>
 help: use a scope's handle only inside the function `scope` or `supervise` runs
s = scope(s => s)!
cancel(s)
error[E0706]: `cancel` on a closed scope
  --> example.fung:2:7
  |
2 | cancel(s)
  |       ^
  |
 call path (innermost first):
   example.fung:2 <entry>
 help: use a scope's handle only inside the function `scope` or `supervise` runs

고치는 법: 범위 핸들은 태스크 범위의 함수 안에서만 쓴다.

scope(fn(s):
  spawn(s, () => print("inside"))
;;)
inside

기본 도움말: use a scope's handle only inside the function `scope` or `supervise` runs

E0707

`%s` has an effect, which a swap's function must not have

swap에 준 함수 안에서 효과(effect)가 있는 함수를 불렀다. 효과란 출력, 채널, 파일, 대기, 다른 atom의 변경처럼 바깥에 흔적을 남기는 일이다. swap의 함수는 옛 값을 받아 새 값을 계산하기만 해야 한다. 다른 태스크가 그사이 atom을 바꾸면 swap이 함수를 새 값으로 다시 돌리기 때문에, 효과가 있으면 두 번 일어날 수 있다. 다른 atom을 바꾸는 것(reset, swap)도 효과이고, 자기 swap 안에서 같은 atom을 다시 swap하는 것도 이 에러다.

hits = atom(0)
swap(hits, n => dbg(n) + 1)
error[E0707]: `dbg` has an effect, which a swap's function must not have
  --> example.fung:2:20
  |
2 | swap(hits, n => dbg(n) + 1)
  |                    ^
  |
 call path (innermost first):
   example.fung:2 <lambda>
   example.fung:2 <entry>

고치는 법: 효과는 swap 밖에서 한다. swap은 새 값을 돌려준다.

hits = atom(0)
new = swap(hits, n => n + 1)
print("hits:", new)
hits: 1

E0708

an atom cannot hold an atom, a channel end, a task, a scope, a file or a socket

atom에 담을 수 없는 값을 넣었다. atom은 평범한 데이터(숫자, 문자열, 리스트, 맵 …)만 담는다. 다른 atom, 채널의 끝, 태스크, 태스크 범위, 파일, 소켓은 상태가 있는 자원이라 담을 수 없다.

(tx, _rx) = channel()
_latest = atom(tx)
error[E0708]: an atom cannot hold an atom, a channel end, a task, a scope, a file or a socket
  --> example.fung:2:15
  |
2 | _latest = atom(tx)
  |               ^
  |
 call path (innermost first):
   example.fung:2 <entry>

고치는 법: 데이터만 atom에 둔다. 자원은 변수나 인자로 넘긴다.

latest = atom({host: "web1", up: true})
swap(latest, m => put(m, "up", false))
print(deref(latest))
{host: "web1", up: false}

E0709

this value would make a cycle through channels or tasks, which could never be freed

보내거나 돌려줄 값이 그 값을 넣으려는 채널(또는 그 태스크 자신)에 바로, 또는 다른 채널의 버퍼나 끝난 태스크의 결과를 거쳐 다시 닿는다. fung은 메모리를 참조 계수로 회수하므로, 서로를 가리키는 고리는 모두 버려도 계수가 0이 되지 않아 영영 해제되지 않는다(채널은 닫히지도 않는다). 값을 나중에 받는 칸은 채널의 버퍼와 태스크의 결과 둘뿐이라, 고리가 닫히는 그 순간(send, 태스크의 끝)에 막는다. 채널에 그 채널의 끝을 보내는 것(리스트나 맵 안에 넣어도)은 가장 짧은 고리다(전에는 따로 E0705였다).

흔한 원인: 채널에 그 채널의 끝을 보냄, 두 채널이 서로의 받는 끝을 버퍼에 담음, 태스크가 채널로 받은 자기 핸들을 결과로 돌려줌.

(tx, rx) = channel(1)
send(tx, rx)
error[E0709]: this value would make a cycle through channels or tasks, which could never be freed
  --> example.fung:2:5
  |
2 | send(tx, rx)
  |     ^
  |
 call path (innermost first):
   example.fung:2 <entry>
 help: send or return the data, not the channel end or task handle that leads back here
(ta, ra) = channel(1)
(tb, rb) = channel(1)
send(ta, rb)!
send(tb, ra)!
error[E0709]: this value would make a cycle through channels or tasks, which could never be freed
  --> example.fung:4:5
  |
4 | send(tb, ra)!
  |     ^
  |
 call path (innermost first):
   example.fung:4 <entry>
 help: send or return the data, not the channel end or task handle that leads back here

고치는 법: 채널의 끝이나 태스크 핸들 대신 데이터를 보내거나 돌려준다. 응답을 받을 채널을 요청과 함께 보내는 것은 고리가 아니므로 된다.

(req_tx, req_rx) = channel(4)
scope(fn(s):
  spawn(s, fn():
    for (x, reply) in req_rx: send(reply, x * 2)! ;;
    nil
  ;;)
  (rtx, rrx) = channel(1)
  send(req_tx, (21, rtx))!
  print(recv(rrx)!)
  close(req_tx)
;;)
42

기본 도움말: send or return the data, not the channel end or task handle that leads back here

E08xx: 한도와 환경

나머지는 fung 자체의 한도(너무 깊은 중첩, 너무 깊은 재귀, 너무 큰 문자열), 직접 내는 에러(fail, assert), 실행 순서와 관련된 에러다. 내부 오류 E0801을 빼면 모두 실행 중의 에러(종료 코드 1)다. 실행 전에 찾는 한도(중첩 E0115, 인자 개수 E0230)는 문법·이름 분류에 있다.

E0801

internal error: %v

fung 내부의 오류다. 사용자 코드가 아니라 fung 구현의 버그를 뜻한다. 정상적인 프로그램으로는 일부러 낼 수 없으므로 예가 없다. 이 에러를 보면 메시지와 그것을 낸 코드를 저장소의 이슈로 알려 주기 바란다.

E0802

expression nesting too deep (limit %d)

쓰지 않는 번호다. 0.4.0까지 식이나 패턴의 중첩 한도에 내던 에러였고, 지금은 문법 에러 E0115가 맡는다. 실행 전에 찾는 한도인데 실행 중 에러의 분류(E08xx)에 있어 옮겼다. 번호는 한 번 붙이면 다른 뜻으로 다시 쓰지 않으므로 자리만 남아 있다. 지금의 fung에서는 나오지 않아 예가 없다.

기본 도움말: not used: became the syntax error E0115

E0803

%s

fail(메시지)가 낸 에러다. 메시지가 그대로 에러의 메시지가 된다. "여기 오면 버그"라는 곳에서 직접 부른다. 표준 라이브러리 함수는 fung으로 쓴 것도 잘못된 인자를 이 번호가 아니라 E0403으로 알린다. 띄운 태스크가 fail하면 메시지에 note: scope opened at …이 붙어 그 태스크가 속한 태스크 범위를 알려 준다.

fn port_of(cfg) = cfg.port ?? fail("config.port is required")
print(port_of({port: nil}))
error[E0803]: config.port is required
  --> example.fung:1:35
  |
1 | fn port_of(cfg) = cfg.port ?? fail("config.port is required")
  |                                   ^
  |
 call path (innermost first):
   example.fung:1 port_of
   example.fung:2 <entry>

고치는 법: 메시지가 말하는 조건을 맞춘다. 실패가 정상적인 경우의 하나라면 fail 대신 Err를 돌려주거나 기본값을 쓴다.

fn port_of(cfg) = cfg.port ?? 8080
print(port_of({port: nil}))
8080

E0804

stack overflow: call depth exceeded %d

꼬리 호출이 아닌 재귀가 너무 깊어졌다(한도 100,000단계). 호출 경로의 가운데는 … n more로 줄인다.

흔한 원인: 큰 입력에 1 + f(n - 1) 꼴의 재귀를 씀. 더하기가 재귀 호출이 돌아온 뒤에 일어나므로 호출이 하나씩 쌓인다.

fn depth(n) = n == 0 then 0 else 1 + depth(n - 1)
print(depth(200_000))
error[E0804]: stack overflow: call depth exceeded 100000
  --> example.fung:1:43
  |
1 | fn depth(n) = n == 0 then 0 else 1 + depth(n - 1)
  |                                           ^
  |
 call path (innermost first):
   example.fung:1 depth
   example.fung:1 depth
   example.fung:1 depth
   example.fung:1 depth
   example.fung:1 depth
   example.fung:1 depth
   example.fung:1 depth
   example.fung:1 depth
   … 99990 more
   example.fung:1 depth
   example.fung:2 <entry>
 help: make the recursion a tail call or use `fold`

고치는 법: 누적값을 인자로 넘겨 꼬리 호출로 바꾼다. 꼬리 호출은 프레임을 다시 쓰므로 깊이 한도가 없다. 리스트를 도는 것이라면 fold를 쓴다.

fn depth(n, acc = 0) = n == 0 then acc else depth(n - 1, acc + 1)
print(depth(200_000))
200000

기본 도움말: make the recursion a tail call or use `fold`

E0805

not supported yet: %s

쓰지 않는 번호다. 구현을 옮기던 동안 아직 만들지 않은 기능을 부르면 내던 자리표시 에러였고, 지금은 모든 내장 함수가 구현되어 나오지 않는다. 그래서 예가 없다(카탈로그의 도움말도 not used: every builtin is implemented).

기본 도움말: not used: every builtin is implemented

E0806

too many %s (limit %d)

fung의 크기 한도를 넘었다. 메시지가 무엇이(characters, elements) 한도를 넘었는지 적는다. 문자열은 1억 글자, 리스트(와 맵)는 1억 원소가 한도다. 리스트를 만드는 모든 길(+, flatten, put·merge, 범위나 받는 끝에서 만드는 map·filter 등, 펼치기)이 검사하고, 되도록 결과를 만들기 전에 검사하므로 메모리를 다 쓰기 전에 멈춘다(종료 코드 1). 값 하나의 한도이고 전체 메모리 한도는 없다. 값을 글로 바꾸는 str·보간·print·fail도 글이 한도의 바이트(글자당 4바이트)를 넘는 순간 멈춘다: 부분을 나눠 쓴 리스트는 작아도 글이 끝없이 길 수 있다. 인자·매개변수 개수 한도는 컴파일할 때 검사하는 E0230이다(0.4.0까지는 그것도 E0806이었다).

_line = repeat("=", 200_000_000)
error[E0806]: too many characters (limit 100000000)
  --> example.fung:1:15
  |
1 | _line = repeat("=", 200_000_000)
  |               ^
  |
 call path (innermost first):
   example.fung:1 <entry>

고치는 법: 한 번에 거대한 값을 만들지 말고 나눠서 처리한다(파일은 줄 단위로 읽고 쓰는 식).

line = repeat("=", 20)
print(line)
====================

E0807

assertion failed: %s

assert 식의 식이 거짓이었다. 비교였다면 메시지 아래에 양쪽 식의 실제 값이 찍힌다. assert는 테스트 블록 밖에서도 쓰이고, 그때는 프로그램을 멈춘다.

fn half(n) = n // 2
assert half(5) == 3
error[E0807]: assertion failed: half(5) == 3
  --> example.fung:2:1
  |
2 | assert half(5) == 3
  | ^
  |

고치는 법: 찍힌 값을 보고 코드나 기대값 중 틀린 쪽을 고친다.

fn half(n) = n // 2
assert half(5) == 2
print("ok")
ok

E0808

`%s` has no value: the statement that assigned it failed

이전에 실패한 대입의 이름을 읽었다. REPL(대화형 실행)에서만 나온다. REPL에서는 한 줄이 실패해도 세션이 이어지는데, 그 줄이 대입하려던 이름은 값이 없는 채로 남는다. 파일 실행에서는 대입이 실패하면 프로그램이 바로 멈추므로 이 에러가 나오지 않는다. 아래는 fung을 그냥 실행해 REPL에서 두 줄을 입력한 실제 화면이다(>가 입력 줄이다).

> x = 1 / 0
error[E0502]: division by zero
  --> <repl>:1:7
  |
1 | x = 1 / 0
  |       ^
  |
 call path (innermost first):
   <repl>:1   <entry>
> x
error[E0808]: `x` has no value: the statement that assigned it failed
  --> <repl>:1:1
  |
1 | x
  | ^
  |
 call path (innermost first):
   <repl>:1   <entry>

고치는 법: 실패한 대입을 고쳐 다시 입력한다.

E0809

`%s` is read before its assignment ran

파일이 시작하는 동안, 최상위 상수의 대입이 실행되기 전에 그 상수를 읽는 함수를 불렀다. 최상위 fn은 시작 전에 모두 만들어지지만, 상수는 위에서 아래로 차례대로 대입된다.

x = twice()
limit = 10
fn twice() = limit * 2
print(x)
error[E0809]: `limit` is read before its assignment ran
  --> example.fung:3:14
  |
3 | fn twice() = limit * 2
  |              ^^^^^
  |
 call path (innermost first):
   example.fung:3 twice
   example.fung:1 <entry>
 help: a top-level fn that reads it was called while the file was starting, above the assignment; move the assignment up or the call down

고치는 법: 도움말대로 대입을 위로 올리거나 호출을 아래로 내린다.

limit = 10
fn twice() = limit * 2
x = twice()
print(x)
20

기본 도움말: a top-level fn that reads it was called while the file was starting, above the assignment; move the assignment up or the call down

E0810

a file dropped without `close` failed: %s

close 없이 버린 파일 핸들을 비우거나 닫다가 실패했다. 핸들의 마지막 사본이 사라지면 런타임의 닫기 스레드가 남은 버퍼를 비우고 파일을 닫는데, 그때 난 에러는 돌려줄 값이 없으므로 표준 에러에 이 번호로 알리고 종료 코드를 1로 한다. 실행은 멈추지 않는다(그 사이에 프로그램은 이미 다음 일을 하고 있다). NFS처럼 닫을 때 쓰기를 보내는 파일 시스템에서 할당량 초과·디스크 가득 참이 이렇게 드러난다.

고치는 법: 쓴 핸들은 close로 닫아 그 자리에서 에러를 받거나, fs.with_open으로 열어 끝나면 닫히게 한다.

import fs
r = fs.with_open("report.txt", fn(h):
  fs.write_line(h, "saved")
;;, mode: 'write)
print(r)
Ok(Ok(nil))

기본 도움말: close it with `close` (or use `fs.with_open`) to handle the error where it happens
