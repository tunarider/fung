에러 카탈로그

에러 번호는 한 번 붙이면 바뀌지 않는다. 메시지 첫 줄의 error[E0606] 같은 번호로 이 쪽에서 찾는다.

프로그램이 잘못되면 fung은 멈추고 에러(error) 메시지를 표준 에러로 찍는다. 메시지마다 번호가 붙어 있고, 이 쪽은 번호마다 뜻, 흔한 원인, 에러를 내는 짧은 예, 고치는 법을 모았다. 경고(warning)는 프로그램을 멈추지 않는 알림이다.

에러 메시지 읽는 법

예를 하나 돌려 보자. 정수를 받아야 하는 함수에 문자열을 넘겼다.

fn backoff(n: int) = n * 2
print(backoff("3"))
error[E0403]: argument `n` must be int, got str
  --> example.fung:1:12
  |
1 | fn backoff(n: int) = n * 2
  |            ^
  |
 call path (innermost first):
   example.fung:1 backoff
   example.fung:2 <entry>

메시지는 위에서부터 이렇게 읽는다.

  1. 첫 줄 error[E0403]: …: 에러 번호와 한 줄 설명. 번호로 이 쪽의 항목을 찾는다. 경고는 warning[W0102]처럼 시작한다.
  2. 위치 --> example.fung:1:12: 파일 이름, 줄, 칸(열). 칸은 1부터 센다.
  3. 소스 발췌: 그 줄을 그대로 보이고 아래에 ^로 문제의 자리를 가리킨다. ^ 옆에 짧은 설명(예: not found in this scope)이 붙기도 한다.
  4. 호출 경로 call path (innermost first): 실행 중의 에러에만 붙는다. 에러가 난 함수부터 바깥쪽으로, 누가 누구를 불렀는지 보여 준다. <entry>는 실행한 파일의 최상위, <lambda>는 이름 없는 함수다. 아주 깊은 재귀는 가운데를 … n more로 줄인다.
  5. 도움말 help: …: 고치는 방법의 힌트. 카탈로그에 적힌 문구가 기본이고, 상황에 맞춰 바뀌기도 한다(비슷한 이름을 알려 주는 E0204처럼).
  6. 덧붙임: note: … 줄이나 assert가 비교한 양쪽 값(E0807)처럼 그 에러에만 있는 정보가 더 붙을 수 있다.

컴파일 에러(실행 전에 찾은 에러)에는 호출 경로가 없다. 아직 아무것도 실행하지 않았기 때문이다.

files = ["a.log", "b.log"]
print(len(fiels))
error[E0204]: undefined name `fiels`
  --> example.fung:2:11
  |
2 | print(len(fiels))
  |           ^^^^^ not found in this scope
  |
 help: a similar name exists: `files`

이 쪽의 에러 예는 모두 페이지를 만들 때 실제로 돌린 출력이 붙는다(출력 칸 머리의 종료 코드도 실제 값이다). fung run으로는 보이지 않는 경고(W01xx, fung check가 보여 준다)와 fung test·REPL에서만 나는 에러만 그 명령의 실제 출력을 옮겨 적었다. 고친 코드도 실제로 실행된다.

종료 코드

프로그램이 끝나면 운영 체제에 종료 코드(exit code)라는 숫자를 남긴다. 셸에서는 echo $?로 본다. fung의 종료 코드는 다음과 같다(자세한 것은 명령줄 도구).

종료 코드뜻
0정상 종료. 경고만 있으면 0이다.
1실행 중 실패: 런타임 에러, !가 Err를 만남, 아무도 확인하지 않은 태스크의 실패, 테스트 실패.
2컴파일 실패: 문법·이름·import 에러(E01xx~E03xx, 그리고 E0802와 인자 개수의 E0806). 아무것도 실행하지 않는다.
3fung 명령을 잘못 썼다(없는 명령, 읽을 수 없는 파일 등).
n스크립트가 exit(n)을 불렀다.

fung check는 실행하지 않고 컴파일 단계만 검사하므로 종료 코드 2의 에러와 경고만 찾는다. 인자 개수나 타입(E04xx), 0으로 나누기(E05xx) 같은 것은 실행해야 드러난다.

E01xx: 문법(렉서·파서)

소스는 먼저 렉서(lexer)가 글자를 토큰(token, 숫자·이름·연산자 같은 낱말)으로 자르고, 파서(parser)가 토큰을 문장과 식의 구조로 묶는다. 이 단계에서 글자나 구조가 규칙에 맞지 않으면 E01xx다. 실행 전에 찾는 컴파일 에러라 종료 코드는 2이고, 문법 에러가 있으면 파일의 어떤 줄도 실행하지 않는다. 어휘와 문장과 블록이 규칙이다.

E0101

unexpected character %q

fung이 쓰지 않는 글자가 코드에 나왔다. 문자열과 주석 밖에서는 정해진 연산자와 괄호, 이름에 쓰는 글자만 올 수 있다.

흔한 원인: 다른 언어의 연산자(@, &&의 &, $ 등)를 그대로 썼거나, 복사해 온 코드에 보이지 않는 특수 문자가 섞였다.

used = 75
print(used @ 100)
error[E0101]: unexpected character "@"
  --> example.fung:2:12
  |
2 | print(used @ 100)
  |            ^
  |

고치는 법: 뜻한 fung 연산자로 바꾼다. 논리 연산은 and·or·not이다.

used = 75
print(used * 100)
7500

E0102

malformed number %q

숫자 모양으로 시작했는데 숫자 규칙에 맞지 않는다. 숫자 바로 뒤에 글자가 붙으면 하나의 잘못된 숫자로 본다.

흔한 원인: 3x처럼 숫자와 글자를 붙여 씀, 16진수에 없는 글자(0xfg), 기간 단위가 아닌 글자(30sec; 기간 단위는 ms·s·m·h뿐이다). 1.2.3 같은 버전 문자열은 숫자 1.2 뒤의 필드 접근으로 읽혀 E0112가 된다. 버전은 문자열 "1.2.3"으로 쓴다.

retries = 3x
error[E0102]: malformed number "3x"
  --> example.fung:1:11
  |
1 | retries = 3x
  |           ^
  |

고치는 법: 숫자만 쓰거나, 글자가 필요하면 문자열로 만든다.

retries = 3
print(retries)
3

E0103

unknown escape \%s in string

문자열 "…" 안의 \ 뒤에 fung이 모르는 글자가 왔다. 아는 이스케이프는 \n \t \r \\ \" \$ \u{…}뿐이고, 나머지는 실수로 보고 에러로 막는다.

흔한 원인: Windows 경로나 정규식을 보통 문자열에 그대로 썼다.

print("C:\temp\logs")
error[E0103]: unknown escape \l in string
  --> example.fung:1:15
  |
1 | print("C:\temp\logs")
  |               ^
  |

\t는 탭이라 통과하고 \l에서 멈췄다. 경로가 조용히 탭으로 바뀌는 것도 버그이니, 고치는 법은 같다: 백틱 원시 문자열(raw string)을 쓰거나 \\로 쓴다.

print(`C:\temp\logs`)
print("C:\\temp\\logs")
C:\temp\logs
C:\temp\logs

E0104

unterminated string

문자열을 열었는데 같은 줄에서 닫는 "가 없다. 보통 문자열에는 실제 줄바꿈을 넣을 수 없다.

흔한 원인: 닫는 따옴표를 빠뜨림, 여러 줄 문자열을 "…"로 씀(여러 줄은 백틱 원시 문자열이나 \n).

print("hello)
error[E0104]: unterminated string
  --> example.fung:1:7
  |
1 | print("hello)
  |       ^
  |

위치는 문자열이 시작한 자리를 가리킨다.

print("hello")
hello

E0105

malformed duration %q

기간(duration) 리터럴의 모양이 틀렸다. 기간은 숫자와 단위(ms s m h)의 쌍을 큰 단위부터 붙여 쓴다.

흔한 원인: 작은 단위를 먼저 씀(30s5m), 마지막 숫자에 단위를 빠뜨림(1h30).

wait = 30s5m
error[E0105]: malformed duration "30s5m"
  --> example.fung:1:8
  |
1 | wait = 30s5m
  |        ^
  |
wait = 5m30s
print(wait)
5m30s

E0110

unexpected %s

이 자리에 올 수 없는 토큰이 나왔다. %s 자리에 그 토큰이 무엇인지 적힌다.

흔한 원인: 인자 사이의 ,를 빠뜨림, ,를 두 번 씀, 보간 ${…} 안의 식이 덜 끝남, 태그에 이름 인자를 줌(Ok(a: 1)).

print("a" "b")
error[E0110]: unexpected string `"b"`
  --> example.fung:1:11
  |
1 | print("a" "b")
  |           ^
  |

a b

E0111

comparison operators cannot be chained

비교 연산자를 이어 썼다. 수학처럼 1 < x < 10이라고 쓰고 싶지만, fung은 비교를 연쇄하지 않는다. 다른 언어마다 뜻이 달라 헷갈리기 쉬운 문법이라 아예 막았다.

x = 5
print(1 < x < 10)
error[E0111]: comparison operators cannot be chained
  --> example.fung:2:13
  |
2 | print(1 < x < 10)
  |             ^
  |
 help: split it with `and`: a < b and b < c

고치는 법: 도움말대로 and로 나눈다.

x = 5
print(1 < x and x < 10)
true

도움말: split it with `and`: a < b and b < c

E0112

expected %s, found %s

파서가 특정 토큰을 기대했는데 다른 것이 나왔다. 메시지가 무엇을 기대했고(expected) 무엇을 만났는지(found) 알려 준다.

흔한 원인: if·for·match·fn 뒤의 블록을 여는 :를 빠뜨림, 블록을 닫는 ;;를 빠뜨림(그러면 found end of file), . 뒤에 이름이 아닌 것(1.2.3).

x = 5
if x > 0 print("positive") ;;
error[E0112]: expected `:` after the if condition, found name `print`
  --> example.fung:2:10
  |
2 | if x > 0 print("positive") ;;
  |          ^
  |
x = 5
if x > 0: print("positive") ;;
positive

;;를 빠뜨리면 파일 끝에서야 알아채므로, 위치가 파일의 마지막 줄 다음을 가리킨다(expected ;; to close the if, found end of file). 그때는 열어 둔 블록을 위로 거슬러 찾는다.

E0113

duplicate key `%s` in map literal

맵 리터럴 하나에 같은 키를 두 번 썼다. 어느 값을 뜻했는지 알 수 없으므로 에러다.

흔한 원인: 설정 맵을 고치다가 옛 줄을 지우지 않음.

cfg = {host: "db1", port: 5432, host: "db2"}
error[E0113]: duplicate key `host` in map literal
  --> example.fung:1:33
  |
1 | cfg = {host: "db1", port: 5432, host: "db2"}
  |                                 ^
  |

고치는 법: 하나만 남긴다. 실행 중에 값을 바꾼 사본이 필요하면 put이나 merge를 쓴다.

cfg = {host: "db2", port: 5432}
print(cfg)
{host: "db2", port: 5432}

E0114

test must be at the top level

test "이름": … ;; 블록이 파일 최상위가 아닌 곳(함수나 블록 안)에 있다. fung test는 최상위의 테스트 블록만 찾아 돌린다.

fn check_all():
  test "inside": assert true ;;
;;
error[E0114]: test must be at the top level
  --> example.fung:2:3
  |
2 |   test "inside": assert true ;;
  |   ^
  |

고치는 법: 테스트를 최상위로 꺼낸다. fung run은 테스트 블록을 무시한다. 함수 안에서 조건을 확인하고 싶으면 assert만 쓴다(테스트와 디버깅).

fn half(n) = n // 2

test "half": assert half(4) == 2 ;;
print(half(9))
4

E02xx: 이름과 스코프

문법이 맞으면 fung은 이름(변수, 함수, 타입)이 어디서 무엇을 가리키는지 정한다. 이것을 이름 해석(resolve)이라 하고, 이름이 보이는 범위를 스코프(scope)라 한다. 이 단계의 에러가 E02xx다. 역시 실행 전에 찾는 컴파일 에러라 종료 코드는 2이고, 한 번에 여러 개를 보고할 수 있다. 규칙은 변수와 스코프에 있다: 이름은 위에서 아래로 묶이고, 블록은 바깥 변수를 읽을 수만 있고, 블록 안의 이름은 밖으로 새지 않는다.

E0204

undefined name `%s`

그 자리에서 보이지 않는 이름을 썼다.

E0205

블록 안에서 블록 바깥의 변수에 다시 대입했다. fung의 블록(if·for·함수 본문 등)은 바깥 이름을 읽을 수만 있다. 값이 어디서 바뀌는지 찾아 헤매지 않게 하려는 규칙이다.

흔한 원인: 셸이나 다른 언어처럼 반복문 안에서 카운터를 늘림.

files = ["a.log", "b.txt", "c.log"]

;;

  --> example.fung:4:28
  |
4 |   if ends_with(f, ".log"): count = count + 1 ;;
  |                            ^^^^^
  |
 help: a block cannot change an outer variable; build the value with an expression instead, e.g. `x = if … ;;` or `fold`

고치는 법: 값을 식으로 만든다. 세기는 filter와 len, 누적은 fold다.

files = ["a.log", "b.txt", "c.log"]

total = fold(files, 0, (n, f) => n + len(f))

도움말: a block cannot change an outer variable; build the value with an expression instead, e.g. `x = if … ;;` or `fold`

E0208

함수 안에서 정의한 지역 함수가, 같은 블록에서 더 아래에 정의된 지역 함수를 불렀다. 지역 함수는 위에서 아래로 만들어지므로 아직 없는 함수를 부를 수 없다. 지역 함수가 부를 수 있는 것은 자기 자신(재귀)과 위에서 이미 만든 이름뿐이다.

흔한 원인: 서로를 부르는 두 함수(상호 재귀)를 함수 안에 둠.

  --> example.fung:2:41

2 |   fn is_even(n) = n == 0 then true else is_odd(n - 1)
  |                                         ^^^^^^
  |

고치는 법: 두 함수를 최상위로 옮긴다. 최상위 fn은 시작 전에 모두 만들어지므로 순서와 상관없이 서로 부른다.

fn is_even(n) = n == 0 then true else is_odd(n - 1)
fn is_odd(n) = n == 0 then false else is_even(n - 1)

fn main() = print(is_even(10))
main()
true

도움말: local functions can only call themselves; move both functions to the top level

|로 묶은 대안 패턴들이 서로 다른 이름을 묶는다. 어느 대안이 맞았느냐에 따라 어떤 변수는 있고 어떤 변수는 없게 되므로 에러다.

  --> example.fung:2:11

  |

고치는 법: 대안마다 같은 이름을 묶거나, 이름이 필요 없으면 _를 쓴다. 다른 처리가 필요하면 절을 나눈다.

fn describe(r) = match r:

E0218

타입 별칭이 자기 자신을 가리킨다(직접이든 다른 별칭을 거쳐서든). 별칭은 이미 있는 타입에 붙이는 다른 이름일 뿐이라, 자기를 풀면 끝이 없다.

흔한 원인: 트리 같은 재귀 구조를 별칭으로 표현하려 함. 그런 구조는 태그로 만든다. 태그 이름은 인자 모양을 검사하지 않으므로 Node(l, r)이 그대로 재귀 구조가 된다.

type tree = tree
fn size(t: tree) = 1
error[E0218]: type `tree` refers to itself
  --> example.fung:1:1
  |
1 | type tree = tree
  | ^^^^
  |
type tree = Leaf | Node
fn size(t: tree) = match t:
  Leaf       => 0
  Node(l, r) => 1 + size(l) + size(r)
;;
print(size(Node(Leaf, Node(Leaf, Leaf))))
2

for 본문 안에서 ?를 썼다. E0213과 같은 이유다: 본문은 람다라서 ?가 바깥 함수가 아니라 람다에서 Err를 돌려주고, 그 Err는 결과 리스트의 원소가 될 뿐이다.

  404 => "not found"

E0606

discarded Err: %s

값을 쓰지 않는 자리에서 Err가 나와 버려졌다. 실패가 아무도 모르게 지나가지 않도록 fung은 버려지는 Err를 에러로 만든다. 셸의 set -e를 늘 켜 둔 것과 같다.

버려지는 자리: 문장으로 쓴 호출, 그런 자리의 if·match 가지의 끝, for 문장의 본문, 파일의 마지막 식, each에 준 함수, with의 release, supervise의 on_fail. 외부 명령이 실패해도 exec가 Err를 돌려주므로 같다.

import fs
fs.write("missing/out.txt", "data")
print("saved")
error[E0606]: discarded Err: cannot write `missing/out.txt`: no such file or directory
  --> example.fung:2:1
  |
2 | fs.write("missing/out.txt", "data")
  | ^ this value is discarded
  |
 call path (innermost first):
   example.fung:2 <entry>
 help: handle it with `!`, `?` or `match`, or discard it on purpose: `_ = ...`

고치는 법: !(실패하면 멈춤), ?(함수 안에서 호출자에게 넘김), match(경우마다 처리)로 다룬다. 실패해도 상관없으면 _ = 식으로 일부러 버린다.

import fs
match fs.write("missing/out.txt", "data"):
  Ok(_)  => print("saved")
  Err(e) => print("skip:", e.kind)
;;
_ = fs.remove("missing/old.txt")
print("done")
skip: 'not_found
done

도움말: handle it with `!`, `?` or `match`, or discard it on purpose: `_ = ...`

E07xx: 동시성

동시성(concurrency)은 여러 일(태스크, task)을 번갈아 진행하는 것이다. fung의 태스크는 scope 안에서 spawn으로 띄우고, 채널(channel)로 값을 주고받고, 여럿이 함께 보는 값은 atom에 둔다(동시성 내장 함수). 이 규칙을 어기거나 모든 태스크가 서로를 기다리며 멈추면 E07xx다. 모두 실행 중의 에러다.

E0701

task cancelled

태스크가 취소되었다. 취소는 보통 fung 안에서 조용히 처리된다: 스코프가 끝나거나 다른 태스크가 실패하면 남은 태스크를 취소하고, 이 취소는 에러로 찍지 않는다. fung run에서는 이 번호를 거의 보지 않는다.

보이는 경우: fung test에서 테스트 블록 안의 태스크가 exit(n)을 불러 기다리던 쪽이 취소되면, 그 테스트의 실패 이유로 나온다. fung run에서 보이지 않으므로 아래 출력은 fung test example.fung을 실제로 돌려 옮겨 적었다.

test "a task exits":
  scope(fn(s):
    t = spawn(s, () => exit(3))
    await(t)
  ;;)
;;
FAIL example.fung: a task exits
  error[E0701]: task cancelled
    --> example.fung:4:10
    |
  4 |     await(t)
    |          ^
    |
   call path (innermost first):
     example.fung:4 <lambda>
     example.fung:2 test: a task exits
0 passed, 1 failed

고치는 법: 테스트 안에서는 exit를 부르지 않는다. 끝낼 이유는 Err나 fail로 돌려준다.

E0702

deadlock: all tasks are waiting

교착(deadlock): 모든 태스크가 무언가를 기다리고 있어서 아무도 더 나아갈 수 없다. fung은 영원히 멈춰 있는 대신 이것을 알아채고 에러로 끝낸다. 상황에 따라 도움말이 원인을 짚어 준다.

흔한 원인: 받는 쪽이 보내는 끝을 자기도 쥐고 있어서 채널이 닫히지 않음, 버퍼 없는 채널(channel())에 받는 태스크 없이 보냄.

(tx, rx) = channel()
print(recv(rx))
error[E0702]: deadlock: all tasks are waiting
  --> example.fung:2:11
  |
2 | print(recv(rx))
  |           ^
  |
 call path (innermost first):
   example.fung:2 <entry>
 help: this task waits to receive, but it still holds that channel's sending end itself (the global `tx`), so the channel cannot close: close it with `close(tx)` first, or leave the sending end to the producers only

channel()은 버퍼가 없어서 받는 쪽이 준비될 때까지 send가 기다린다. 같은 태스크가 보내고 나서 받으려 하면 그것도 교착이다.

(tx, rx) = channel()
send(tx, "job")!
close(tx)
for job in rx: print(job) ;;
error[E0702]: deadlock: all tasks are waiting
  --> example.fung:2:5
  |
2 | send(tx, "job")!
  |     ^
  |
 call path (innermost first):
   example.fung:2 <entry>

고치는 법: 보내기는 다른 태스크에 맡기고, 보내는 끝은 보내는 쪽만 쥔다. 함수 안의 변수는 마지막으로 읽힌 뒤 놓이므로, 보내는 끝을 태스크에만 넘기면 그 태스크가 끝날 때 채널이 닫혀 for가 끝난다. 혼자 보내고 받아야 하면 버퍼가 있는 channel(n)을 쓰고 다 보낸 뒤 close한다.

fn collect() = scope(fn(s):
  (tx, rx) = channel()
  spawn(s, fn():
    send(tx, 1)!
    send(tx, 2)!
  ;;)
  for x in rx: x ;;
;;)
print(collect())
[1, 2]

E0703

atom swapped inside its own swap

쓰지 않는 번호다. 예전 버전의 atom이 자기 swap 안에서 다시 바뀔 때 내던 에러였다. atom이 한때 에이전트(agent)가 되면서 E0704로 바뀌었고, 지금은 E0707이 그 경우를 맡는다. 번호는 한 번 붙이면 다른 뜻으로 다시 쓰지 않으므로 자리만 남아 있다. 지금의 fung에서는 나오지 않아 예가 없다.

도움말: not used: atoms became agents, see E0704

E0704

agent called from inside its own swap

쓰지 않는 번호다. 에이전트를 자기 swap 안에서 부를 때 내던 에러였다. 에이전트가 다시 엄격한 atom이 되면서 이 경우는 E0707(swap의 함수 안의 효과)로 잡힌다. 지금의 fung에서는 나오지 않아 예가 없다.

도움말: not used: agents became atoms, see E0707

E0705

channel sent into itself

채널의 끝을 같은 채널로 보냈다. 그러면 채널이 자기 자신을 붙잡게 되어 영원히 닫히지 않는다. 리스트나 맵 안에 넣어 보내도 같다.

(tx, rx) = channel(1)
send(tx, rx)
error[E0705]: channel sent into itself
  --> example.fung:2:5
  |
2 | send(tx, rx)
  |     ^
  |
 call path (innermost first):
   example.fung:2 <entry>

고치는 법: 답을 받을 통로가 필요하면 다른 채널을 만들어 그 끝을 보낸다.

(tx, rx) = channel(1)
(reply_tx, reply_rx) = channel(1)
send(tx, reply_tx)!
send(recv(rx)!, "pong")!
print(recv(reply_rx))
Ok("pong")

E0706

spawn into a closed scope

이미 끝난 스코프에 태스크를 띄웠다. 스코프는 그 안의 태스크가 모두 끝나야 닫히는 울타리인데, 닫힌 뒤에 들어오는 태스크는 기다려 줄 사람이 없다.

흔한 원인: scope의 함수가 스코프 값 s를 돌려주고 밖에서 그것으로 spawn함.

s = scope(s => s)
spawn(s, () => print("late"))
error[E0706]: spawn into a closed scope
  --> example.fung:2:6
  |
2 | spawn(s, () => print("late"))
  |      ^
  |
 call path (innermost first):
   example.fung:2 <entry>

고치는 법: spawn은 스코프의 함수 안에서 부른다.

scope(fn(s):
  spawn(s, () => print("inside"))
;;)
inside

E0707

`%s` has an effect, which a swap's function must not have

swap에 준 함수 안에서 효과(effect)가 있는 함수를 불렀다. 효과란 출력, 채널, 파일, 대기, 다른 atom의 변경처럼 바깥에 흔적을 남기는 일이다. swap의 함수는 옛 값을 받아 새 값을 계산하기만 해야 한다. 다른 태스크가 그사이 atom을 바꾸면 swap이 함수를 새 값으로 다시 돌리기 때문에, 효과가 있으면 두 번 일어날 수 있다. 다른 atom을 바꾸는 것(reset, swap)도 효과이고, 자기 swap 안에서 같은 atom을 다시 swap하는 것도 이 에러다.

hits = atom(0)
swap(hits, n => dbg(n) + 1)
error[E0707]: `dbg` has an effect, which a swap's function must not have
  --> example.fung:2:20
  |
2 | swap(hits, n => dbg(n) + 1)
  |                    ^
  |
 call path (innermost first):
   example.fung:2 <lambda>
   example.fung:2 <entry>

고치는 법: 효과는 swap 밖에서 한다. swap은 새 값을 돌려준다.

hits = atom(0)
new = swap(hits, n => n + 1)
print("hits:", new)
hits: 1

E0708

an atom cannot hold an atom, a channel end, a task, a scope, a file or a socket

atom에 담을 수 없는 값을 넣었다. atom은 평범한 데이터(숫자, 문자열, 리스트, 맵 …)만 담는다. 다른 atom, 채널의 끝, 태스크, 스코프, 파일, 소켓은 상태가 있는 자원이라 담을 수 없다.

(tx, rx) = channel()
latest = atom(tx)
error[E0708]: an atom cannot hold an atom, a channel end, a task, a scope, a file or a socket
  --> example.fung:2:14
  |
2 | latest = atom(tx)
  |              ^
  |
 call path (innermost first):
   example.fung:2 <entry>

고치는 법: 데이터만 atom에 둔다. 자원은 변수나 인자로 넘긴다.

latest = atom({host: "web1", up: true})
swap(latest, m => put(m, "up", false))
print(deref(latest))
{host: "web1", up: false}

E08xx: 한도와 환경

나머지는 fung 자체의 한도(너무 깊은 중첩, 너무 깊은 재귀, 너무 큰 문자열), 직접 내는 에러(fail, assert), 실행 순서와 관련된 에러다. E0802와 E0806의 인자·매개변수 개수 한도는 실행 전에 찾는 컴파일 에러(종료 코드 2)이고, 나머지는 실행 중의 에러(종료 코드 1)다.

E0801

internal error: %v

fung 내부의 오류다. 사용자 코드가 아니라 fung 구현의 버그를 뜻한다. 정상적인 프로그램으로는 일부러 낼 수 없으므로 예가 없다. 이 에러를 보면 메시지와 그것을 낸 코드를 저장소의 이슈로 알려 주기 바란다.

E0802

expression nesting too deep (limit %d)

식이나 패턴이 너무 깊이 중첩되었다(한도 10,000단계). 파서가 끝없는 중첩으로 메모리를 다 쓰지 않도록 둔 한도이고, 실행 전에 찾는 컴파일 에러(종료 코드 2)다. 사람이 쓰는 코드에서는 거의 나오지 않고, 프로그램이 만든 코드에서 날 수 있다. 예는 괄호를 만 개 넘게 겹쳐야 해서 싣지 않는다. x = ((((…1…))))처럼 괄호를 10,001겹 쓴 파일은 error[E0802]: expression nesting too deep (limit 10000)으로 멈춘다.

고치는 법: 중첩을 풀어 중간값을 변수에 담는다.

E0803

%s

fail(메시지)가 낸 에러다. 메시지가 그대로 에러의 메시지가 된다. "여기 오면 버그"라는 곳에서 직접 부르고, 일부 표준 라이브러리 함수도 잘못 쓰였을 때 이 번호로 알린다(예: take의 개수가 정수가 아니면 take expects an int count, got 'str). 띄운 태스크가 fail하면 메시지에 note: scope opened at …이 붙어 그 태스크의 스코프를 알려 준다.

fn port_of(cfg) = cfg.port ?? fail("config.port is required")
print(port_of({port: nil}))
error[E0803]: config.port is required
  --> example.fung:1:35
  |
1 | fn port_of(cfg) = cfg.port ?? fail("config.port is required")
  |                                   ^
  |
 call path (innermost first):
   example.fung:1 port_of
   example.fung:2 <entry>

고치는 법: 메시지가 말하는 조건을 맞춘다. 실패가 정상적인 경우의 하나라면 fail 대신 Err를 돌려주거나 기본값을 쓴다.

fn port_of(cfg) = cfg.port ?? 8080
print(port_of({port: nil}))
8080

E0804

stack overflow: call depth exceeded %d

꼬리 호출이 아닌 재귀가 너무 깊어졌다(한도 100,000단계). 호출 경로의 가운데는 … n more로 줄인다.

흔한 원인: 큰 입력에 1 + f(n - 1) 꼴의 재귀를 씀. 더하기가 재귀 호출이 돌아온 뒤에 일어나므로 호출이 하나씩 쌓인다.

fn depth(n) = n == 0 then 0 else 1 + depth(n - 1)
print(depth(200_000))
error[E0804]: stack overflow: call depth exceeded 100000
  --> example.fung:1:43
  |
1 | fn depth(n) = n == 0 then 0 else 1 + depth(n - 1)
  |                                           ^
  |
 call path (innermost first):
   example.fung:1 depth
   example.fung:1 depth
   example.fung:1 depth
   example.fung:1 depth
   example.fung:1 depth
   example.fung:1 depth
   example.fung:1 depth
   example.fung:1 depth
   … 99990 more
   example.fung:1 depth
   example.fung:2 <entry>
 help: make the recursion a tail call or use `fold`

고치는 법: 누적값을 인자로 넘겨 꼬리 호출로 바꾼다. 꼬리 호출은 프레임을 다시 쓰므로 깊이 한도가 없다. 리스트를 도는 것이라면 fold를 쓴다.

fn depth(n, acc = 0) = n == 0 then acc else depth(n - 1, acc + 1)
print(depth(200_000))
200000

도움말: make the recursion a tail call or use `fold`

E0805

not supported yet: %s

쓰지 않는 번호다. 구현을 옮기던 동안 아직 만들지 않은 기능을 부르면 내던 자리표시 에러였고, 지금은 모든 내장 함수가 구현되어 나오지 않는다. 그래서 예가 없다.

E0806

too many %s (limit %d)

fung의 크기 한도를 넘었다. 메시지가 무엇이(characters, elements, arguments, parameters) 한도를 넘었는지 적는다. 문자열은 1억 글자, map 등이 만드는 리스트는 1억 원소가 한도이고, 실행 중에 결과를 만들기 전에 검사하므로 메모리를 다 쓰기 전에 멈춘다(종료 코드 1). 한 호출의 인자와 한 함수의 매개변수는 4,095개까지이고, 이것은 컴파일할 때 검사한다(종료 코드 2).

line = repeat("=", 200_000_000)
error[E0806]: too many characters (limit 100000000)
  --> example.fung:1:14
  |
1 | line = repeat("=", 200_000_000)
  |              ^
  |
 call path (innermost first):
   example.fung:1 <entry>

고치는 법: 한 번에 거대한 값을 만들지 말고 나눠서 처리한다(파일은 줄 단위로 읽고 쓰는 식).

line = repeat("=", 20)
print(line)
====================

E0807

assertion failed: %s

assert 식의 식이 거짓이었다. 비교였다면 메시지 아래에 양쪽 식의 실제 값이 찍힌다. assert는 테스트 블록 밖에서도 쓰이고, 그때는 프로그램을 멈춘다.

fn half(n) = n // 2
assert half(5) == 3
error[E0807]: assertion failed: half(5) == 3
  --> example.fung:2:1
  |
2 | assert half(5) == 3
  | ^
  |
  half(5) = 2
 call path (innermost first):
   example.fung:2 <entry>

고치는 법: 찍힌 값을 보고 코드나 기대값 중 틀린 쪽을 고친다.

fn half(n) = n // 2
assert half(5) == 2
print("ok")
ok

E0808

`%s` has no value: the statement that assigned it failed

이전에 실패한 대입의 이름을 읽었다. REPL(대화형 실행)에서만 나온다. REPL에서는 한 줄이 실패해도 세션이 이어지는데, 그 줄이 대입하려던 이름은 값이 없는 채로 남는다. 파일 실행에서는 대입이 실패하면 프로그램이 바로 멈추므로 이 에러가 나오지 않는다. 아래는 fung을 그냥 실행해 REPL에서 두 줄을 입력한 실제 화면이다(>가 입력 줄이다).

> x = 1 / 0
error[E0502]: division by zero
  --> <repl>:1:7
  |
1 | x = 1 / 0
  |       ^
  |
 call path (innermost first):
   <repl>:1   <entry>
> x
error[E0808]: `x` has no value: the statement that assigned it failed
  --> <repl>:1:1
  |
1 | x
  | ^
  |
 call path (innermost first):
   <repl>:1   <entry>

고치는 법: 실패한 대입을 고쳐 다시 입력한다.

E0809

`%s` is read before its assignment ran

파일이 시작하는 동안, 최상위 상수의 대입이 실행되기 전에 그 상수를 읽는 함수를 불렀다. 최상위 fn은 시작 전에 모두 만들어지지만, 상수는 위에서 아래로 차례대로 대입된다.

x = twice()
limit = 10
fn twice() = limit * 2
print(x)
error[E0809]: `limit` is read before its assignment ran
  --> example.fung:3:14
  |
3 | fn twice() = limit * 2
  |              ^^^^^
  |
 call path (innermost first):
   example.fung:3 twice
   example.fung:1 <entry>

W01xx: 경고

경고는 틀렸다고 단정할 수는 없지만 실수일 가능성이 큰 코드를 알려 준다. 프로그램을 멈추지 않고 종료 코드도 바꾸지 않는다. 경고는 fung check와 fung test가 찍는다. fung run은 경고를 찍지 않고 그대로 실행한다. 그래서 아래 예의 출력은 fung check example.fung을 실제로 돌려 옮겨 적었다.

W0103

`%s` shadows a prelude function

변수나 매개변수가 같은 이름의 prelude 함수를 가린다. 그 아래에서는 그 이름이 내장 함수가 아니라 내 변수를 가리키므로, 나중에 내장 함수를 부르려 하면 헷갈린다.

fn summary(xs):
  max = 0
  len(xs) + max
;;
print(summary([1]))
warning[W0103]: `max` shadows a prelude function
  --> example.fung:2:3
  |
2 |   max = 0
  |   ^^^
  |

고치는 법: 다른 이름(biggest, limit 등)을 쓴다.
