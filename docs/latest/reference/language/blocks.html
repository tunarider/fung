문장과 블록

문장과 블록(: … ;;), 줄 이어짐.

  • 문장은 줄바꿈이나 ;로 나눈다. 빈 문장은 괜찮다.
  • 블록은 :로 열고 ;;로 닫는다. 블록의 값은 마지막 식의 값이다.
  • 값을 아무도 쓰지 않는 자리(마지막이 아닌 식, 그런 자리의 if·match 가지의 끝과 then … else의 두 가지, 파일의 마지막 식)의 값은 버려진다. 버려지는 값이 Err면 E0606이다(결과값과 에러).
  • 버려지는 자리의 식은 무언가를 해야 한다. 이름, 리터럴, 람다·익명 fn, 이름과 리터럴만 넘긴 부분 적용(f(_, x)), 그리고 그것들만으로 된 연산자·필드·인덱스·튜플·리스트·맵·태그 값(Ok(1), Red, Point(x, y))은 계산해도 아무 일이 없으므로 컴파일 에러다(E0234). 호출, 대입, assert, return, 효과가 있을 수 있는 호출이 든 식(Ok(f()), h(g(), _))은 된다. 다만 효과가 없다고 알려진 내장 함수·표준 모듈 함수의 호출(put(m, k, v), sort(xs), path.join(a, b)처럼 값을 계산해 돌려줄 뿐인 것)은 인자와 상관없이 E0234다: 결과를 버리면 아무 일도 없었던 것이다. 그런 함수가 묶인 이름이나 그 부분 적용으로 불러도 같다(s = sort이면 s(xs), 함수의 컴파일 때 정해지는 호출). 그 호출의 인자가 모두 위의 효과 없는 식이면 호출도 효과 없는 식이라, 그것이 든 식(len(xs) == 2, [sort(xs)], Ok(upper(s)))도 E0234다. 함수를 받아 값을 계산하는 내장 함수(map·filter·fold·find·any·all·sort_by·group_by·try_map·iterate·until)도 같다: 부수효과만 하는 순회는 each나 문장 for로 쓴다. each와 사용자 함수는 된다. 맨 nil도 리터럴이라 같다: 할 일이 없는 가지는 비워 둔다(else 없는 if, 본문이 빈 match 절 _ =>). 일부러 버리려면 _ = 식. 받는 끝에서 값을 꺼내는 first(rx)·take(rx, n)·zip(rx, …)도 효과가 없다고 알려진 내장 함수의 호출이라 문장으로는 E0234다: 꺼낸 값을 일부러 버리는 것이면 _ = take(rx, 2)로 쓴다(swap 안에서는 같은 호출이 효과가 있는 호출이라 E0707이다). 실행 중에 계산된 Err를 버리면 여전히 E0606이다.
  • 들여쓰기는 의미가 없다. 같은 코드를 한 줄로도 쓸 수 있다.
fn classify(n):
  if n < 0:
    "negative"
  else if n == 0:
    "zero"
  else:
    "positive"
  ;;
;;

fn classify_short(n) = if n < 0: "negative" else if n == 0: "zero" else: "positive" ;;

;;는 렉서가 항상 가장 길게 자른다. a;;는 a와 블록 끝이다.

줄 이어짐

줄바꿈은 문장 끝이지만, 다음 둘 중 하나면 식이 다음 줄로 이어진다. 괄호 안에서도 밖에서도 같다.

  1. 줄이 식을 끝낼 수 없는 토큰으로 끝날 때: 이항 연산자(+ - * / // % ** == != < > <= >= in ?? |> .. ..= and or), not, ,, =, =>, ->, ., 패턴 대안과 타입 유니온의 |, for 머리의 in, then, else, 여는 괄호, :(블록 시작, 맵의 키·이름 붙인 인자·매개변수 뒤).
  2. 다음 줄이 이어짐 전용 토큰으로 시작할 때: |> . ?? and or then else. 이 토큰들로는 문장을 시작할 수 없으니 모호하지 않다.

괄호 () [] {} 안의 줄바꿈은 원소 사이와 여닫는 괄호 옆에서 공백이다. 그래서 원소를 줄마다 쓸 수 있다. 그러나 두 줄을 한 식으로 잇지는 않는다: 원소 하나가 줄을 넘으려면 위의 두 규칙을 따른다. 맵 항목의 키와 :, 슬라이스의 끝과 .., 매개변수와 :·=, if·for·fn의 머리와 블록의 :도 한 원소 안이라 같은 줄에 쓴다({a⏎: 1}, xs[1⏎..]는 E0112). 쉼표를 빠뜨린 [1⏎ -1]은 [1 - 1]이 아니라 에러다(E0112, 쉼표가 와야 한다). 괄호 안에서 fn(x):처럼 블록이 열리면 그 ;;까지는 줄바꿈이 다시 문장 구분자다.

-는 이어짐 전용 토큰이 아니다(-x는 그것만으로 식이다). 그래서 앞 문장의 다음 줄을 -로 시작하면 컴파일 에러 E0136이다: 앞 줄을 이으려던 것이라면 앞 줄은 버려지는 문장이 되고 -2가 그 자리의 값이 되기 때문이다. 여러 줄에 걸친 식은 연산자를 줄 끝에 두고, 음수 값을 한 줄에 홀로 쓰려면 괄호로 감싼다((-x)). 파일과 블록의 첫 문장, 여는 것과 같은 줄의 문장(_ => -1, if c: -1 else: 1 ;;), ; 뒤의 문장은 이을 앞 줄이 없으므로 된다.

names = ["b.log", "a.txt", "c.log"]
logs = names
  |> filter(n => ends_with(n, ".log"))
  |> sort
ok = len(logs) > 0
  and all(logs, n => n != "")
print(logs, ok)
["b.log", "c.log"] true

경계 사례와 에러

버려지는 자리에서 아무 일도 하지 않는 식은 에러다. 괄호를 잊은 호출과 = 대신 쓴 ==가 흔한 경우다.

count = 3
count == 4
print(count)
error[E0234]: the comparison `==` is computed and discarded
  --> example.fung:2:7
  |
2 | count == 4
  |       ^^
  |
 help: did you mean `=`? `==` compares; `=` assigns

앞 문장의 다음 줄은 -로 시작할 수 없다. 앞 줄이 호출이면 조용히 버려지고 -a가 반환값이 되기 때문이다.

fn double(n) = n * 2
fn f(a):
  double(a)
  -a
;;
print(f(5))
error[E0136]: a statement after another cannot begin its line with `-`
  --> example.fung:4:3
  |
4 |   -a
  |   ^
  |
 help: to continue the line before, end that line with the `-`; a negative value on a line of its own is written in parentheses: `(-x)`

괄호 안에서도 줄바꿈이 두 줄을 한 식으로 잇지 않는다. 쉼표를 빠뜨리면 에러다.

xs = [
  1
  -1
]
print(xs)
error[E0112]: expected `,` or `]`, found `-`
  --> example.fung:3:3
  |
3 |   -1
  |   ^
  |
  note: the `[` opened at 1:6

한 원소 안의 줄바꿈도 같다. 맵 항목의 키와 : 사이에서 줄을 바꾸면 에러다(:로 끝난 줄은 규칙 1로 이어진다).

m = {
  name
    : "fung"
}
print(m)
error[E0112]: expected `:` after the map key, found newline
  --> example.fung:2:7
  |
2 |   name
  |       ^
  |

연산자를 줄 끝에 두면 한 식으로 이어진다.

fn f(a) = a -
  2
print(f(5))
3

블록은 ;;로 닫는다. 닫지 않고 파일이 끝나면 어디서 시작했는지와 함께 멈춘다.

fn f(x):
  x + 1
print(f(1))
error[E0112]: expected `;;` to close the function, found end of file
  --> example.fung:4:1
  |
4 | 
  | ^
  |
  note: the `fn` opened at 1:1
  note: line 3 is not indented under the `fn`: was the block meant to close before it?

블록의 값은 마지막 식이다. 마지막 문장이 대입이면 그 블록의 값은 nil이라, 값으로 쓰면 에러다(E0224). 빈 블록이나 assert·fn 정의로 끝나는 블록도 값으로 쓰면 같은 에러다. nil이 뜻이면 마지막 줄에 nil을 쓴다.

fn f(x):
  y = x + 1
;;
print(f(1))
error[E0224]: a block used as a value ends with an assignment to `y`, so the value is nil
  --> example.fung:2:3
  |
2 |   y = x + 1
  |   ^
  |
 help: end the block with the value it stands for, e.g. the assigned name on its own line; write `nil` last if nil is meant

효과가 없다고 알려진 내장 함수를 문장으로 부르는 것도 같다. put은 바뀐 사본을 돌려줄 뿐 m을 바꾸지 않는다.

m = {a: 1}
put(m, "b", 2)
print(m)
error[E0234]: the result of `put(…)` is computed and discarded
  --> example.fung:2:1
  |
2 | put(m, "b", 2)
  | ^^^
  |
 help: `put` has no effect: it only computes its result (a changed copy, a converted value); use the result, or write `_ = …` to discard it on purpose

그런 호출만으로 된 식도 아무 일을 하지 않는다. = 대신 쓴 ==가 호출과 견주어도 E0234다.

xs = [1, 2]
count = 0
count == len(xs)
print(count)
error[E0234]: the comparison `==` is computed and discarded
  --> example.fung:3:7
  |
3 | count == len(xs)
  |       ^^
  |
 help: did you mean `=`? `==` compares; `=` assigns
