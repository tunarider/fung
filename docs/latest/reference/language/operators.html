연산자

산술·비교·논리 연산자, 파이프 |>, 우선순위.

산술

  • + - *, /는 항상 실수 결과(7 / 2 == 3.5), //는 내림 나눗셈(7 // 2 == 3), %는 //와 짝인 나머지(-7 % 3 == 2, 실수도 정확한 나머지라 나누는 수보다 작다), **는 거듭제곱(2 ** 10 == 1024, 2 ** -1 == 0.5).
  • 정수와 실수를 섞으면 실수. 0으로 나누기(0의 음수 거듭제곱 0 ** -1도), 정수 오버플로, NaN·Inf는 에러.
  • +는 문자열·리스트를 이어 붙인다. "a" + 1은 에러, 반복은 repeat(s, n). 문자열은 1억 글자를 넘으면 E0806(보간도 같다).

비교·논리·포함

  • ==와 !=는 값 비교. 비교는 연쇄하지 않는다: a < b < c는 문법 에러(a < b and b < c).
  • and or not은 bool만 받고 단락 평가한다. 빈 리스트나 0을 거짓으로 보지 않는다.
  • 이항 연산의 두 피연산자는 왼쪽부터 평가한다. and·or·then … else·??만 오른쪽을 필요할 때 평가한다(함수의 "평가 순서").
  • x in c / x not in c: 리스트는 원소, 맵은 키, 문자열은 부분 문자열, 범위는 정수 포함 여부.

범위

a..b는 b를 빼고, a..=b는 넣는다. 정수만 된다. 시작이 끝보다 뒤면 에러다(E0522): a..b는 a > b, a..=b는 a > b + 1일 때. 빈 범위는 n..n과 n..=n-1뿐이다. 그래서 거꾸로 세려던 for i in n..0이 말없이 아무것도 하지 않는 일이 없다. 끝이 시작보다 작아질 수 있는 계산이면 a..max(a, b)처럼 드러낸다. 범위 값으로 하는 색인 xs[r]은 같은 끝의 슬라이스와 같다.

xs = []
print(0..len(xs), 0..=len(xs) - 1)
print(0..len(xs) - 1)
0..0 0..=-1

  --> example.fung:3:8
  |

 help: the empty ranges are `n..n` and `n..=n-1`; if the end may fall below the start, say so: `a..max(a, b)`

파이프

|>는 실행 중의 연산이 아니라 컴파일할 때 평범한 호출로 바뀌는 문법 설탕이다. 규칙은 하나다: 오른쪽이 괄호 없이 쓴 호출이나 태그면 왼쪽 값을 그 맨 앞 인자로 끼워 넣고, 그 밖의 식은 값을 구해 왼쪽 값으로 부른다.

  • x |> f(a, b)는 f(x, a, b): 호출 모양이라 끼워 넣는다.
  • x |> f는 f(x), x |> m.f는 m.f(x), x |> (n => n + 1)은 람다를 부른다: 호출 모양이 아니니 값으로 부른다.
  • x |> (f(a))는 f(a)(x): 괄호는 묶음이라 괄호 친 호출은 호출 모양이 아니라 값이다. 함수를 돌려주는 함수의 결과로 부를 때 쓴다.

태그도 같다. x |> Ok는 Ok(x), x |> Pair(2)는 Pair(x, 2)다(태그의 Ok(x)는 호출 형태이므로). 따옴표 심볼 'Ok는 태그가 아니라 값이라 x |> 'Ok는 심볼을 부르는 에러다. 괄호 친 x |> (Ok)도 마찬가지다: 괄호 안의 인자 없는 태그는 심볼 값이라 그것을 부르는 E0401이고, 태그 모양은 괄호 없는 Ok다.

이어 쓰면 안쪽부터 감싸는 호출이 된다. xs |> filter(f) |> map(g)는 map(filter(xs, f), g)와 바이트코드까지 같다. 비용은 없고, 데이터가 흐르는 순서대로 읽힌다는 것이 전부다. 이름 인자도 그대로 따라간다: xs |> conc.pmap(f, limit: 2)는 conc.pmap(xs, f, limit: 2).

그래서 내장 함수는 모두 다루는 대상을 첫 번째 매개변수에 둔다: 리스트 함수는 리스트가(filter(xs, f)), 문자열 함수는 문자열이(split(s, sep)), 맵 함수는 맵이(put(m, k, v)) 먼저다. Python의 map(f, xs)나 데이터를 마지막에 두는 Haskell·OCaml과 달리 Elixir와 같은 쪽이다. 직접 만드는 함수도 이렇게 두면 파이프에 그대로 이어진다.

line = " ERROR,disk full "
fields = line |> trim |> lower |> split(",")
cfg = {host: "localhost"} |> put("port", 8080) |> merge({debug: false})
print(fields, cfg |> keys)
["error", "disk full"] ["host", "port", "debug"]

대상이 첫 자리가 아닌 함수에는 람다나 괄호 친 부분 적용으로 넘긴다: 5 |> (n => scale(2, n)), 5 |> (scale(2, _)).

파이프 오른쪽 호출의 인자에 _를 쓰면 컴파일 에러 E0227이다. 파이프 값은 늘 첫 인자로 들어가므로 "a.txt" |> path.join("/tmp", _)는 path.join("a.txt", "/tmp", _), 곧 함수가 되어 버리던 함정이다. 다른 자리에 넣으려면 람다나 괄호 친 부분 적용("a.txt" |> (path.join("/tmp", _)))을 쓴다. 더 안쪽 호출의 _는 그대로 부분 적용이다.

파이프 오른쪽 끝의 후위 ?·!도 컴파일 에러 E0229다. 후위 연산자가 |>보다 먼저 묶여 xs |> try_map(f)?는 try_map(f)?를 파이프에 넘기는 것이 되기 때문이다. 파이프 전체의 결과를 꺼내려면 (xs |> try_map(f))?로 감싼다.

"a.txt" |> path.join("/tmp", _)            # E0227
"a.txt" |> (f => path.join("/tmp", f))     # "/tmp/a.txt"
"a.txt" |> (path.join("/tmp", _))          # "/tmp/a.txt": 괄호 친 식은 값
files |> map(path.join("/tmp", _))         # _의 올바른 쓰임: map에 넘길 함수를 만든다

not은 비교보다 낮으므로 그보다 높은 연산자의 피연산자가 될 수 없다. a == not b, 1 + not c는 에러이고 괄호로 a == (not b)라고 쓴다. not a == b는 not (a == b)다.

경계 사례와 에러

비교 연산자는 잇지 않는다(a < b < c는 수학과 다르게 읽히기 쉽다).

b = 2
c = 3
print(a < b and b < c)
