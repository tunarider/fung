조건

if, then … else, and·or, 값 자리의 조건.

fn sign(n):
  if n > 0:
    "+"
  else if n < 0:
    "-"
  else:
    "0"
  ;;
;;
print(sign(5), 3 > 2 then "yes" else "no")
+ yes
  • if는 식이다. else가 없고 조건이 거짓이면 값은 nil. 그래서 값을 쓰는 자리(대입의 오른쪽, 인자, return, 연산자, fn f() = …와 람다 =>의 본문 등)의 if는 else가 있어야 한다(없으면 컴파일 에러 E0223, nil이 의도라면 else: nil). 같은 자리의 블록이 비었거나 대입 같은 문장으로 끝나도 E0224다. 함수 본문의 마지막 항목도 값을 쓰는 자리다(반환값이므로, 블록 본문 함수도). 돌려줄 것이 없는 함수는 else: nil이나 마지막 줄 nil로 맺는다. 문장으로 쓴 if, 문장 for의 본문, test 블록의 끝은 else 없이 써도 된다. 문장 for는 리스트를 만들지 않으므로(for) 본문의 값이 쓰이지 않는다. 같은 순회를 each(xs, x => if c: print(x) ;;)로 쓰면 E0223이다: 람다는 값을 돌려주는 함수이고, 그 값을 each가 버린다는 것은 컴파일러가 알 수 없다. 부수효과만 하는 순회는 문장 for로 쓴다.
  • c then a else b는 한 줄짜리 조건 식이다. else가 반드시 있어야 하고, 사슬로 이을 수 있다.
  • 조건은 bool이어야 한다. 다른 값이면 런타임 에러(E0505). 리터럴을 바로 쓴 if 1:·not 1·1 and true는 타입이 이미 드러나 있어 컴파일할 때 같은 번호로 멈춘다. 리터럴을 부르는 것(1(2), E0401), 두 리터럴에 뜻이 없는 연산(1 + "a", E0501), 수가 아닌 리터럴의 -(-"a", E0506), 리터럴 뒤의 ??(E0243)도 같다. 여기서 리터럴은 문법이 타입을 보이는 모든 값이다: 수·문자열(${…}가 든 것도)·불·nil·심볼·기간, 리스트·맵·튜플 리터럴, 태그 값(Red(1)), 범위(1..2), 람다·익명 fn·부분 적용(타입 fn). 에러의 문구와 도움말도 실행했을 때와 같다. 두 리스트나 두 튜플의 순서 비교처럼 원소가 정하는 것은 실행할 때 본다. 값이 정하는 에러(1 // 0, 정수 넘침)는 실행할 때 난다.

경계 사례와 에러

else 없는 if를 값으로 쓰면, 조건이 거짓일 때 nil이 되므로 에러다.

x = 5
label = if x > 3: "big" else: "small" ;;
print(label)
bad = if x > 3: "big" ;;
error[E0223]: `if` without `else` used as a value: it is nil when the condition is false
  --> example.fung:4:7
  |
4 | bad = if x > 3: "big" ;;
  |       ^^ this if has no else
  |
 help: add an `else:` branch; write `else: nil` if nil is meant (a function that returns nothing ends in `else: nil` or `nil`)

조건은 bool이어야 한다. 0이나 ""를 거짓으로 보지 않는다.

n = 0
print(n == 0 then "zero" else "some")
print(n then "yes" else "no")
zero
