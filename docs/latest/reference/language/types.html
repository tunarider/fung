타입 표기

매개변수와 반환의 타입 표기와 그 검사.

type shape = Circle | Rect  # 별칭: 같은 모듈 안에서만

fn area(s: shape) -> num = match s:
  Circle(r)  => 3 * r * r
  Rect(w, h) => w * h
;;
fn find_user(id: int) -> map | nil = id == 1 then {name: "ann"} else nil
fn load(p: str) -> Ok | Err = p == "" then Err("empty path") else Ok(p)

print(area(Circle(2)), area(Rect(2, 3)))
print(find_user(1), find_user(2))
print(load("a.txt"), load(""))
12 6
{name: "ann"} nil
Ok("a.txt") Err("empty path")
  • 타입 이름: int float num(int 또는 float) str bool nil sym dur time list map tuple range fn module task scope sender receiver atom file any, 그리고 태그 이름. 태그 이름은 인자 없는 태그(심볼)도 받으므로 열거형을 쓸 수 있다: type color = Red | Green | Blue, fn hex(c: color). 그래도 type_of(Red)는 'sym이다.
  • |로 유니온을 만든다. 원소 타입은 적지 않는다: 검사하지 않는 표기는 두지 않으므로 list[int]는 컴파일 에러 E0130이고 list라고 쓴다.
  • 인자와 반환 타입에만 쓴다. 맞지 않으면 에러다(인자는 E0403, 반환값은 E0404). 검사는 호출과 반환 때 하지만, 값이 리터럴이라 소스에 드러나면 컴파일 때 같은 번호와 문구로 잡는다: 매개변수의 기본값, 돌려주는 리터럴(본문의 끝, 그 끝의 if·match·then … else의 가지 끝, return의 값), 대상이 정해진 호출(함수)의 리터럴 인자. 별칭과 유니온을 풀어 판정하고, 태그 이름은 그 태그의 값과 심볼을 받는다. 이름에 든 값은 리터럴이 아니므로 부를 때 검사한다. 변수에는 쓰지 않는다. ...rest는 늘 리스트라 list만 적을 수 있다(다른 표기는 E0228).
  • 타입 이름은 값 이름과 다른 이름 공간이다. list = [1]이라는 변수가 있어도 x: list는 타입이다.
  • 별칭 이름은 소문자이고(대문자는 태그), 위의 타입 이름은 별칭으로 쓸 수 없다(type int = str은 E0222).

경계 사례와 에러

표기한 타입이 아니면 호출 자리에서 멈춘다.

fn twice(n: int) -> int = n * 2
count = "4"
print(twice(4))
print(twice(count))
8
error[E0403]: argument `n` must be int, got str
  --> example.fung:1:10
  |
1 | fn twice(n: int) -> int = n * 2
  |          ^
  |
 call path (innermost first):
   example.fung:1 twice
   example.fung:4 <entry>

리터럴은 소스만 보아도 타입이 드러나므로 실행하기 전에 같은 에러다. 기본값과 돌려주는 리터럴도 같다.

fn twice(n: int) -> int = n * 2
print("ran")
print(twice("4"))
error[E0403]: argument `n` must be int, got str
  --> example.fung:3:13
  |
3 | print(twice("4"))
  |             ^
  |
fn port(name) -> int = name == "db" then 5432 else "none"
print(port("db"))
error[E0404]: return value must be int, got str
  --> example.fung:1:52
  |
1 | fn port(name) -> int = name == "db" then 5432 else "none"
  |                                                    ^
  |

원소 타입은 적지 않는다. 런타임이 바깥 타입만 검사하므로 적어도 지켜지지 않기 때문이다.

fn total(xs: list) -> int = sum(xs)
print(total([1, 2]))
fn names(xs: list[str]) = xs
error[E0130]: a type annotation has no element type
  --> example.fung:3:18
  |
3 | fn names(xs: list[str]) = xs
  |                  ^
  |
 help: write `list` or `map` alone: the elements are not checked, so they are not written

반환 타입이 맞지 않으면 반환하는 자리에서 멈춘다.

fn half(n: int) -> int = n / 2
print(half(4))
