for

for의 값, 순회 대상, 버려지는 자리.

for는 map의 설탕이고 결과로 리스트를 돌려준다. 값을 버리는 자리의 for는 리스트를 만들지 않고 each처럼 돌며, 본문이 낸 Err는 E0606이다. 순회 대상은 리스트, 범위, 채널의 받는 끝(값이 올 때마다, 닫히면 끝)이다. 문자열과 맵은 chars(s), pairs(m)으로 리스트로 바꿔서 돈다.

squares = for x in 1..=3: x * x ;;
for (k, v) in pairs({a: 1, b: 2}):
  print("${k} = ${v}")
;;
print(squares)
a = 1
b = 2
[1, 4, 9]

본문이 사실은 람다이므로 for 본문 안의 return과 ?는 람다 안에서처럼 컴파일 에러 E0237이다(함수의 "람다의 본문"). 실패할 수 있는 변환은 첫 Err에서 멈추는 try_map, 찾기는 find, 검사는 all·any, 누적은 fold를 쓴다. while은 없다.

누적과 재귀의 비용. 리스트와 맵은 불변이지만 사본이 원본과 구조를 공유하므로, fold로 acc + [x]·[x] + acc나 put(acc, k, v)를 쌓는 것과 [x, ...rest]·xs[1..]로 꼬리를 떼는 재귀는 모두 선형이다(2만 개에 수십 ms). 두 리스트를 이으면 짧은 쪽을 긴 쪽에 붙이므로 비용은 짧은 쪽의 길이에 비례한다. 문자열을 뒤에 붙여 쌓는 것(acc + s, "${acc}…")과 s[1..]로 문자열의 앞을 떼는 재귀도 선형이다. 피할 것은 문자열을 앞에 붙여 쌓는 것(s + acc)이다: 매번 전체를 복사한다. 조각을 리스트에 모아 join한다. 자세한 것은 컬렉션의 내부.

경계 사례와 에러

for는 리스트를 만든다. 그래서 몸통에서 return으로 빠져나갈 수 없다(find·any·fold를 쓴다).

fn first_big(xs):
  for x in xs:
    if x > 2: return x else: nil ;;
  ;;
;;
print(first_big([1, 3]))
error[E0237]: `return` inside a `for` body
  --> example.fung:3:15
  |
3 |     if x > 2: return x else: nil ;;
  |               ^^^^^^
  |
 help: a lambda `=>` and a `for` body cannot return early; write an anonymous `fn(x): … ;;` to return from, or use `try_map`, `find`, `all`/`any` or `fold`

순회 대상은 리스트·범위·받는 끝이다. 맵은 pairs, 문자열은 chars로 먼저 바꾼다.

m = {a: 1}
for (k, v) in pairs(m): print(k, v) ;;
for ch in "ab": print(ch) ;;
a 1

  |
3 | for ch in "ab": print(ch) ;;
  | ^
  |
