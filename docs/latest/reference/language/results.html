결과값과 에러

Ok·Err, !·?·??, 버려지는 Err.

실패할 수 있는 함수는 Ok(값)이나 Err(내용)을 돌려준다. 표준 라이브러리의 Err 내용은 {kind: 심볼, message: 문자열, …} 맵이다. 세 축약 연산자로 다룬다.

왼쪽 값x!x?x ?? b
Ok(v)vvv
Err(e)프로그램 중단(종료 코드 1)현재 함수에서 Err(e)를 반환b
nil런타임 에러(E0604)런타임 에러(E0604)b
그 외런타임 에러(E0605)런타임 에러(E0605)그 값 그대로

규칙은 하나다: !·?는 결과값만 받는다. nil을 돌려주는 함수(get·find·env 등)에 붙이면 에러이고, 없을 때의 값은 ??로 준다. 없을 때 호출자에게 넘기려면 match나 if x == nil: return nil ;;로 드러내 쓴다.

text = fs.read("a.json")!                    # 스크립트: 실패하면 멈춘다
data = json.parse(text)?                      # 함수 안: 실패를 호출자에게 넘긴다
port = env("PORT") ?? "8080"                  # 없거나 실패하면 기본값(모든 Err)
match fs.read(p):
  Ok(text)                => use(text)
  Err({kind: 'not_found}) => print("no file")
  Err(e)                  => print(e.message)
;;

버려지는 Err는 에러다. 값을 쓰지 않는 자리(문장으로 쓴 호출, 그런 자리의 if·match 가지, for 문장의 본문, 파일의 마지막 식, each의 f, with의 release, supervise의 on_fail, test 블록이 돌려준 값)에서 Err가 나오면 E0606 discarded Err로 멈춘다. 버려지는 값이 리스트면 그 원소(한 겹만)를 보고, 처음 나온 Err를 몇 번째 원소인지와 함께 알린다. 그래서 for로 끝나는 함수를 문장으로 부르거나 map(…)을 문장으로 써도 실패가 사라지지 않는다. set -e를 늘 켜 둔 셸과 같다. 실패해도 상관없으면 _ = 식으로 일부러 버린다. 함수의 마지막 식은 반환값이라 버려지지 않고, REPL은 입력의 마지막 값을 출력한다.

fs.write(p, text)          # 실패하면 E0606
fs.write(p, text)!         # 실패하면 E0603으로 중단
_ = fs.remove(tmp)         # 실패해도 상관없다
each(rxs, r => send(tx, r))   # 닫힌 tx면 E0606

Ok·Err는 값을 정확히 하나 담는다. 식·패턴·파이프(x |> Ok(2)는 Ok(x, 2))에서 개수가 다르면 컴파일 에러 E0236이다. 여러 값을 돌려주려면 Ok((a, b))처럼 튜플 하나에 담는다. 그래서 이름이 Ok·Err인 태그는 모두 결과값이고, 연산자·패턴·is_ok·보간이 결과값을 같게 본다. 타입 표기 Ok·Err도 결과값만 받는다(심볼 'Ok는 받지 않는다).

??는 모든 Err를 기본값으로 바꾼다. fs.read(p) ?? "{}"는 파일이 없을 때만이 아니라 권한 오류일 때도 "{}"다. 종류를 가리려면 match로 Err({kind: 'not_found}) => "{}"처럼 쓰고 나머지는 !로 멈춘다.

결과값은 글에 말없이 넣지 않는다. 문자열 보간과 join에 Ok·Err가 들어가면 E0519다. 풀기를 잊은 "http://${recv(rx)}/"가 http://Ok("…")/라는 주소가 되지 않게 하려는 것이다. 결과 자체를 글로 쓰려면 str(r)로 바꾸고, print(r)은 그대로 보인다. 리스트·맵 안의 결과는 리스트의 모양 그대로 보인다.

"여기 오면 버그"를 말할 때는 fail(msg)로 런타임 에러를 낸다. x ?? fail("config.port is required")처럼 ??와 짝이 맞는다. 에러를 잡는 구문은 없고, 정리는 with(acquire, use, release)(와 그 위의 fs.with_open)로 한다.

경계 사례와 에러

!는 Err에서 프로그램을 멈춘다(메시지와 위치를 보인다).

print(parse_int("42")!)
print(parse_int("x")!)
42
error[E0603]: unhandled Err: not an integer: "x"
  --> example.fung:2:21
  |
2 | print(parse_int("x")!)
  |                     ^
  |
 call path (innermost first):
   example.fung:2 <entry>

Err를 문장으로 버리면 에러다. 일부러 버리려면 _ = ….

_ = parse_int("x")
parse_int("y")
error[E0606]: discarded Err: not an integer: "y"
  --> example.fung:2:1
  |
2 | parse_int("y")
  | ^ this value is discarded
  |
 call path (innermost first):
   example.fung:2 <entry>
 help: handle it with `!`, `?` or `match`, or discard it on purpose: `_ = ...`

?도 nil을 받지 않는다. nil을 돌려주는 함수에 붙인 ?는 E0604다.

fn home() = env("FUNG_NO_SUCH_VARIABLE")?
print(home())
error[E0604]: `?` on nil
  --> example.fung:1:41
  |
1 | fn home() = env("FUNG_NO_SUCH_VARIABLE")?
  |                                         ^
  |
 call path (innermost first):
   example.fung:1 home
   example.fung:2 <entry>

?는 함수 안에서만 쓴다. 최상위에서는 !를 쓴다.

n = parse_int("1")?
print(n)
error[E0214]: `?` outside a function
  --> example.fung:1:19
  |
1 | n = parse_int("1")?
  |                   ^
  |
 help: use `!` to stop the script on Err
