명령줄 도구

실행 파일 fung 하나가 실행, 검사, 테스트, 포맷, 내부 단계 보기, REPL을 모두 맡는다. 이 페이지는 명령마다 쓰는 법과 옵션, 출력, 종료 코드를 모았다.

한눈에

터미널(셸)에서 fung 뒤에 무엇을 쓰느냐로 하는 일이 정해진다. fung help가 같은 목록을 보인다.

명령하는 일
fung script.fung [args…]스크립트 실행. fung run script.fung [args…]와 같다.
fung -e 'code' [args…]명령줄에 적은 코드 실행.
fungREPL(대화형으로 한 줄씩 실행).
fung check script.fung실행하지 않고 문법·이름·import 검사, 경고 보이기.
fung test [path]test 블록 실행.
fung fmt [--check] path…|-코드 모양을 한 가지 스타일로 고치기.
fung dump ast|core|bytecode file컴파일의 중간 단계 보기.
fung version버전 보이기.
fung help사용법 보이기(-h, --help도 같다).
 
$ fung help
usage:
  fung <script.fung> [args...]            run a script (same as: fung run <script.fung>)
  fung                                    start the REPL
  fung -e '<code>'                        run one line of code
  fung check <script.fung>                check syntax and names without running
  fung fmt [--check] <path>...|-          format files in place (--check: list only; -: stdin)
  fung test [path]                        run tests
  fung dump ast|core|bytecode <script>    print an internal stage
  fung version                            print the version
  fung help                               print this text

모르는 명령이나 빠진 인자는 error: … 한 줄과 이 사용법을 표준 에러에 쓰고 종료 코드 3으로 끝난다.

$ fung bogus
error: unknown command `bogus`

usage:
  ...

스크립트 실행

fung script.fung은 파일을 컴파일하고(문법·이름 검사) 처음부터 끝까지 실행한다. 첫 인자가 .fung으로 끝나거나 /가 들어 있으면 스크립트로 본다. 그래서 확장자 없는 스크립트는 fung ./deploy나 fung run deploy로 부른다. -로 시작하는 이름은 스크립트로 보지 않는다.

스크립트 이름 뒤의 인자는 모두 스크립트의 것이다. prelude 값 args에 문자열 리스트로 들어간다(스크립트 이름은 들어 있지 않다). --로 시작해도 fung이 가로채지 않는다. 옵션으로 나누려면 cli.parse를 쓴다.

실행 방법 
fung example.fung --env prod web-1
print(args, len(args))
["--env", "prod", "web-1"] 3

표준 입력은 read_line·read_lines로 읽으므로 파이프 중간에 둘 수 있다.

grep ERROR app.log | fung count.fung --by-hour > report.txt

파일 첫 줄에 #!/usr/bin/env fung을 쓰고 실행 권한을 주면 스크립트를 명령처럼 바로 실행할 수 있다. 그 줄은 fung에게는 그냥 주석이다.

$ head -1 tool.fung
#!/usr/bin/env fung
$ chmod +x tool.fung
$ ./tool.fung x
from shebang ["x"]

스크립트 파일을 읽지 못하면 error: cannot read nofile.fung: no such file or directory를 쓰고 종료 코드 3으로 끝난다. 컴파일 에러가 하나라도 있으면 아무것도 실행하지 않고 모든 에러를 보인 뒤 2로 끝난다. 실행 중 에러는 1이다(종료 코드).

신호: 실행 중 첫 Ctrl-C(SIGINT)나 SIGTERM은 정지 요청이다. stop_signal을 보는 코드가 없으면 프로그램을 취소하고(with의 정리는 돈다) 130(SIGINT)·143(SIGTERM)으로 끝난다. 보는 코드가 있으면 그 코드가 스스로 정리하고 끝낸다(예: http.serve는 처리 중인 요청을 마치고 돌아온다). 두 번째 신호는 정리를 기다리지 않고 곧바로 끝낸다. 출력을 읽는 쪽이 사라지면(fung x.fung | head -1) 다른 셸 명령처럼 SIGPIPE로 조용히 끝난다(셸에는 141).

코드 한 줄 실행: -e

fung -e '코드'는 파일 없이 코드를 실행한다. 간단한 계산이나 셸 스크립트 안의 한 줄 처리에 쓴다. 코드 안의 줄바꿈도 된다. 뒤의 인자는 args가 된다. 에러 위치는 파일 이름 대신 -e로 보인다.

$ fung -e 'print(2 ** 10)'
1024
$ fung -e 'print(args)' a b
["a", "b"]
$ echo '{"n": 41}' | fung -e 'import json
print(json.parse(read_line()!)!.n + 1)'
42

fung check -e '코드'와 fung dump core -e '코드'처럼 check·dump도 -e를 받는다.

REPL

fung을 인자 없이 실행하면 REPL(Read-Eval-Print Loop)이 뜬다. 한 줄을 읽고(read), 실행하고(eval), 값을 보이고(print), 다시 묻는다(loop). 함수 하나를 시험해 보거나 내장 함수의 동작을 확인할 때 쓴다.

$ fung
> 1 + 2
3
> x = 10
> fn double(n) = n * 2
> double(x)
20
> "text"
"text"
> nums = [1, 2,
.   3]
> nums
[1, 2, 3]
> print("hi")
hi
nil
> nope
error[E0204]: undefined name `nope`
  --> <repl>:1:1
  |
1 | nope
  | ^^^^ not found in this scope
  |
> :quit
  • 프롬프트는 > 이다. 입력이 블록이나 괄호 중간에서 끝나면 . 프롬프트로 이어서 받는다.
  • 식을 입력하면 그 값을 리터럴 꼴로 보인다(문자열은 따옴표와 함께). 대입, fn, import, test, assert는 값을 보이지 않는다. print(…)는 출력한 뒤 자신의 값 nil을 보인다.
  • 정의(변수, 함수, import)는 세션 동안 남는다. 같은 이름을 다시 정의할 수 있고, 앞서 만든 함수도 새 정의를 본다.
  • 에러는 그 입력만 실패시키고 세션은 계속된다. 에러 위치는 <repl>:줄:열이고, 앞 입력에서 정의한 함수 안의 에러는 그 입력의 줄을 보인다. 한 입력 안에서 생긴 교착(deadlock, 모든 태스크가 서로를 기다림)도 그 입력만 실패시킨다. 다음 입력을 기다리는 동안 살아 있는 태스크는 교착으로 보지 않는다.
  • exit(n)(띄운 태스크에서 부른 것도)은 세션을 코드 n으로 끝낸다. request_stop()은 보는 쪽이 없으면 exit(0)처럼 끝낸다. 세션이 끝나면 남은 태스크는 취소된다(with의 정리는 돈다).
REPL 명령하는 일
:help명령 목록을 보인다.
:quit끝낸다(빈 줄에서 Ctrl-D도 같다). 종료 코드 0.
:load file.fung파일을 이 세션에서 실행한다. 그 파일의 정의가 세션에 남는다.

모르는 : 명령은 unknown command :what을 쓰고 계속한다.

터미널에서 띄우면 줄 편집이 된다: ←→로 커서 이동, Home·End(Ctrl-A·Ctrl-E), Backspace·Delete, ↑↓로 이전 입력, Ctrl-L로 화면 지우기, Ctrl-C로 지금 줄 버리기. 입력 기록은 ~/.fung_history(HOME이 없으면 메모리에만)에 최근 1,000줄까지 남는다. 실행 중의 Ctrl-C는 그 입력을 취소하고 프롬프트로 돌아온다. 정리가 끝나지 않을 때 한 번 더 누르면 그 입력의 태스크를 버린다.

표준 입력이 터미널이 아니면(파이프, 파일) 줄 편집 없이 한 줄씩 읽는다. 그래서 fung < inputs.txt로 입력을 차례로 넣어 볼 수 있다.

검사: check

fung check script.fung은 실행하지 않고 컴파일만 해서 문법 에러, 없는 이름, 잘못된 import를 찾는다. 경고(쓰지 않는 import·지역 변수, prelude 이름을 가림)는 check와 test에서만 보인다. 서버에 올리기 전이나 편집기의 저장 훅에서 쓴다. 파일은 하나만 받고 디렉터리는 받지 않는다. fung check -e '코드'도 된다.

$ fung check w.fung
warning[W0101]: unused import `fs`
  --> w.fung:1:1
  |
1 | import fs
  | ^^
  |
warning[W0103]: `len` shadows a prelude function
  --> w.fung:6:1
  |
6 | len = 3
  | ^^^
  |
$ echo $?
0

에러가 없으면(경고만 있어도) 0, 컴파일 에러가 있으면 모두 보이고 2, 파일을 읽지 못하면 3이다. 검사는 실행하지 않으므로 런타임 에러(0으로 나누기, 없는 키, 버려진 Err)는 찾지 못한다.

테스트: test

fung test [path]는 파일 안의 test "이름": … ;; 블록을 돌린다(테스트 문법). path가 없으면 현재 디렉터리다.

  • path가 파일이면 그 파일만, 디렉터리면 그 아래의 .fung 파일을 모두 이름 순서로 돈다. _나 .으로 시작하는 디렉터리(_fixtures, .git)에는 들어가지 않는다. 그 아래에서 디렉터리를 가리키는 링크는 따라가지 않는다(.fung 파일을 가리키는 링크는 파일처럼 센다). fmt와 같은 규칙이다.
  • test 블록이 없는 파일은 실행하지도, 목록에 올리지도 않는다.
  • 파일마다 따로 실행된다. 최상위 코드가 먼저 돌고(그 출력도 보인다), 이어서 test 블록이 차례로 돈다. 한 파일이 띄운 태스크는 다음 파일로 넘어가지 않는다.
  • 블록마다 ok 파일: 이름이나 FAIL 파일: 이름과 그 에러를 쓰고, 끝에 N passed, M failed를 쓴다.
  • 읽지 못한 파일, 컴파일하지 못한 파일은 FAIL 파일: <load>로 실패 하나로 센다.
  • 파일 안에서 exit(n)이 불리거나(띄운 태스크에서도) 교착이 생기면 그 파일의 나머지 블록을 건너뛰고 실패 하나로 센다. 그 n은 명령의 종료 코드가 되지 않는다.
$ fung test
ok   lib/text.fung: shout adds a bang
FAIL lib/text.fung: this one fails
  error[E0807]: assertion failed: shout("a") == "a!"
    --> lib/text.fung:14:3
     |
  14 |   assert shout("a") == "a!"
     |   ^
     |
    shout("a") = "A!"
   call path (innermost first):
     lib/text.fung:14 test: this one fails
ok   math.fung: add
2 passed, 1 failed
$ echo $?
1

assert가 실패하면 식과 함께 그 안의 하위 식의 값(shout("a") = "A!")을 보인다. 종료 코드는 컴파일하지 못한 파일이 있으면 2, 아니면 실패한 테스트가 있으면 1, 모두 통과하면 0이다. 인자가 둘 이상이거나 경로가 없으면 3이다. 도중에 신호가 오면 그때 돌던 파일에 정지 요청을 보내고, 다음 파일은 돌리지 않고 128 + 신호 번호로 끝난다.

포맷: fmt

fung fmt path…는 코드의 공백·들여쓰기·정렬을 한 가지 스타일로 고친다. 팀의 모든 코드가 같은 모양이면 읽기 쉽고, 모양을 두고 다툴 일이 없다. 줄바꿈 위치는 그대로 두고, 줄 안의 공백과 들여쓰기, 연속된 줄의 정렬(match 갈래의 =>, 맵의 값 등)만 맞춘다. 정렬은 화면 칸 수로 맞춘다(한글·한자는 2칸).

$ cat ugly.fung
x=1
fn f(a,b)=a+b
print( f(x,2) )
$ fung fmt ugly.fung
ugly.fung
$ cat ugly.fung
x = 1
fn f(a, b) = a + b
print(f(x, 2))
  • 파일을 그 자리에서 고치고, 고친 파일의 경로를 한 줄씩 쓴다. 이미 맞는 파일은 건드리지도 쓰지도 않는다.
  • 디렉터리를 주면 test와 같은 규칙으로 그 아래의 .fung 파일을 모두 고친다: fung fmt .
  • --check는 고치지 않고 고쳐야 할 파일만 쓴다. 하나라도 있으면 종료 코드 1이라 CI에서 쓴다.
  • -는 표준 입력을 읽어 고친 결과를 표준 출력에 쓴다(편집기 연동용). --check -는 고칠 게 있으면 <stdin>을 쓰고 1, 없으면 아무것도 쓰지 않고 0이다.
  • 문법 에러가 있는 파일은 에러를 보이고 그대로 둔다(종료 코드 2).
$ fung fmt --check .
ugly.fung
$ echo $?
1
$ fung fmt - < ugly.fung > fixed.fung

종료 코드는 문법 에러가 있으면 2, --check에서 고칠 파일이 있거나 읽고 쓰지 못한 파일이 있으면 1, 아니면 0, 경로가 없거나 모르는 옵션이면 3이다.

내부 단계 보기: dump

fung dump 단계 file은 fung이 소스를 실행하기 전에 거치는 중간 결과를 보인다. 언어가 어떻게 만들어지는지 공부하거나 버그를 좁힐 때 쓴다. 단계는 셋이다.

  • ast: 파서가 만든 구문 트리(쓴 그대로의 모양).
  • core: 문법 설탕을 걷어 낸 코어 트리(이름이 global·local·prelude 칸으로 풀린다).
  • bytecode: VM이 실행하는 명령의 목록. 함수마다 == 이름 == 아래에 번호 줄:열 명령 인자 ; 설명이 나온다.
fn double(x) = x * 2
print(double(21))
$ fung dump bytecode example.fung

0001  1:1   STOREGLOBAL  0    ; double
0002  2:1   CONST        0    ; <fn print>
0003  2:7   LOADGLOBAL   0    ; double
0004  2:14  CONST        1    ; 21
0005  2:13  CALL         1    ; 1 positional, 0 named
0006  2:6   CALL         1    ; 1 positional, 0 named
0007  2:1   POP
0008  2:1   CONST        2    ; nil
0009  1:1   RETURN

== double ==
0000  1:16  LOADLOCAL    0

fung dump core -e 'x = 1'처럼 -e도 받는다. 컴파일 에러가 있으면 에러를 보이고 2로 끝난다. 각 단계의 뜻은 fung VM 책에서 다룬다.

버전과 도움말

fung version은 fung 0.4.0처럼 버전 한 줄을 쓴다. 릴리스가 아닌 개발 빌드는 fung 0.0.0-dev다. fung help(-h, --help)는 위의 사용법을 표준 출력에 쓰고 0으로 끝난다. --version은 모르는 명령이다.

에러 메시지 읽는 법

fung의 에러는 모두 같은 꼴이다. 내부 구현의 패닉이나 스택 추적은 나오지 않는다.

fn ratio(done, total) = done * 100 // total

fn report(jobs) = "${ratio(len(jobs), 0)}% done"

print(report(["a", "b"]))
error[E0502]: division by zero
  --> example.fung:1:36
  |

에러 번호의 첫 두 자리가 분류다.

번호분류
E01xx문법(렉서·파서)
E02xx이름과 스코프
E03xx모듈과 import
E04xx호출과 타입 표기(인자 수, 인자 타입)
E05xx런타임 연산(타입 불일치, 0 나누기, 오버플로, 범위 밖 인덱스, 없는 키)
E06xx패턴과 결과값(맞는 패턴 없음, !가 Err를 만남, 버려진 Err)
E07xx동시성(취소, 교착, 닫힌 범위, atom 규칙)
E08xx한도와 환경(스택 깊이, fail, assert, 내부 오류)
W01xx경고(check·test에서만): 안 쓰는 import·변수, prelude 이름 가리기

종료 코드

프로그램이 끝날 때 운영체제에 돌려주는 숫자가 종료 코드(exit code)다. 셸에서는 $?로 보고, &&·||·set -e가 이것으로 성공과 실패를 가른다. 0이 성공이다.

종료 코드뜻
0정상 종료(정지 요청을 받아 스스로 정리하고 끝난 경우도)
1실행 중 실패: 런타임 에러, !가 Err를 만남, 버려진 Err, 끝내 아무도 확인하지 않은 태스크의 실패, 테스트 실패, fmt --check에서 고칠 파일이 있음
2컴파일 실패: 문법·이름·import 에러
3fung 명령을 잘못 씀: 모르는 명령·옵션, 빠진 인자, 읽을 수 없는 스크립트 파일
n스크립트가 exit(n)을 부름. 운영체제는 0~255만 전하므로 256으로 나눈 나머지가 된다(exit(300)은 44, exit(-1)은 255)
130 143SIGINT·SIGTERM으로 취소됨(128 + 신호 번호). 두 번째 신호로 곧바로 끝난 경우도 같다
141출력을 읽는 쪽이 사라짐(SIGPIPE, 셸이 보이는 값)
 
import fs

match fs.read("config.txt"):
  Ok(_)  => print("loaded")
  Err(e) =>
    eprint("fatal:", e.message)
    exit(4)
;;
fatal: cannot read `config.txt`: no such file or directory
