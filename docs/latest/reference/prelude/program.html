에러와 종료

프로그램이 받은 인자, 프로그램을 끝내는 법, 버그를 알리는 법, 무슨 일이 있어도 정리를 하는 법을 다룬다.

프로그램의 시작과 끝

명령줄 프로그램은 인자(argument)를 받아 시작하고 종료 코드(exit code)를 남기고 끝난다. 인자는 fung run deploy.fung prod web-1에서 스크립트 경로 뒤의 낱말들(prod, web-1)이고, fung에서는 args로 읽는다. 종료 코드는 0부터 255까지의 수로, 0은 성공, 그 밖은 실패를 뜻한다. 셸의 $?, &&·||, CI, cron, systemd가 모두 이 수로 성공을 판단한다.

fung 프로그램이 끝나는 길은 다음과 같다.

끝나는 길종료 코드
진입 파일의 마지막 줄까지 실행0
exit(n)n
런타임 에러(fail, r!의 Err, 0으로 나누기, 없는 키 …)1
컴파일 에러(문법, 정의되지 않은 이름 …): 실행 전에 멈춘다2
SIGINT·SIGTERM(Ctrl-C, kill)으로 취소130·143(stop_signal)

런타임 에러는 "여기 오면 코드가 틀린 것"을 알리는 멈춤이다. 메시지, 에러 번호, 난 곳과 호출 경로를 표준 에러에 찍고 끝난다. 실패할 수 있는 일(파일 없음, 수가 아닌 입력)은 결과값으로 돌려주고, 런타임 에러는 버그에만 쓴다는 것이 fung의 나눔이다. 런타임 에러를 잡아 되살리는 try/catch는 없다. 그 대신 끝나기 전에 꼭 해야 하는 정리(임시 파일 지우기, 잠금 풀기, 연결 닫기)는 with로 묶어 두면 어떻게 끝나든 돈다.

함수

fail

인자를 print처럼 이은 메시지로 런타임 에러(E0803)를 내고 멈춘다.

fail(...args)

설명

"여기 오면 버그"라고 말할 때 쓴다. 메시지는 print와 같은 규칙으로 인자를 공백으로 이은 것이다. 인자가 없으면 메시지는 fail이다. 런타임 에러이므로 종료 코드는 1이고, 지나는 with의 정리는 돈다. 태스크 안에서 부르면 그 태스크가 실패하고, 태스크 범위가 그 실패를 받는다(scope, supervise).

fail은 값을 돌려주지 않으므로 어떤 식 자리에도 쓸 수 있다. 특히 ??와 짝이 맞는다: cfg.port ?? fail("config.port is required"). 사용자가 고칠 수 있는 실패(잘못된 입력, 없는 파일)라면 fail 대신 eprint로 이유를 알리고 exit(1)하거나 Err를 돌려주는 편이 친절하다. fail의 메시지에는 소스 위치와 호출 경로가 붙기 때문이다.

매개변수

  • args: 메시지를 이룰 값들.

돌려주는 값

돌아오지 않는다.

에러

언제나 런타임 에러 E0803.

예제

필수 값이 없을 때

cfg = {host: "db-1"}
port = get(cfg, "port") ?? fail("config.port is required")
print(port)
error[E0803]: config.port is required
  --> example.fung:2:32
  |
2 | port = get(cfg, "port") ?? fail("config.port is required")
  |                                ^
  |
 call path (innermost first):
   example.fung:2 <entry>

여러 값으로 메시지 만들기

fn check_port(n) = n > 0 and n < 65536 then n else fail("bad port:", n, "(want 1..65535)")

print(check_port(443))
print(check_port(70000))
443
error[E0803]: bad port: 70000 (want 1..65535)
  --> example.fung:1:56
  |
1 | fn check_port(n) = n > 0 and n < 65536 then n else fail("bad port:", n, "(want 1..65535)")
  |                                                        ^
  |
 call path (innermost first):
   example.fung:1 check_port
   example.fung:4 <entry>

with

acquire()로 얻은 것을 use에 넘기고, use가 어떻게 끝나든 release를 부른다.

with(acquire, use, release)

설명

자원(resource)을 빌리고 돌려주는 모양을 한 함수로 묶는다. 파일, 잠금, 임시 디렉터리, 서버 연결처럼 "얻었으면 반드시 돌려줘야 하는 것"에 쓴다.

  1. acquire()를 부른다. 여기서 런타임 에러가 나면 얻은 것이 없으므로 release는 돌지 않는다.
  2. 얻은 값 r로 use(r)를 부른다.
  3. use가 어떻게 끝나든, 곧 값을 돌려주든, Err를 돌려주든, 런타임 에러가 나든, 취소되든, exit가 불리든 release(r)를 부른다.
  4. use가 정상으로 끝났으면 그 값이 with의 결과다.

acquire가 Err를 돌려줘도 그것이 "얻은 값"이다. use와 release는 그 Err를 그대로 받으므로 열기에 실패할 수 있는 자원은 둘 다에서 match로 가른다. fs.with_open과 fs.with_temp_dir이 이것을 대신 해 주는 with이므로 파일과 임시 디렉터리에는 그쪽을 쓴다.

release는 그것을 부르게 만든 취소나 기한(timeout)에 끊기지 않는다. 정리가 반쯤 하다 마는 일이 없게 하려는 것이다.

release의 실패는 버리지 않는다. use도 실패했으면 use의 에러에 note: also failed in release로 붙고, 아니면 release의 에러가 난다. release의 결과는 버리는 값이라 Err를 돌려주면 E0606이다. 실패해도 되는 정리는 fn(c): _ = close(c) ;;처럼 일부러 버린다. 프로그램이 끝날 때의 정리도 with로 한다(따로 at_exit 같은 것은 없다). 프로그램 전체를 with의 use 안에 두면 된다.

매개변수

  • acquire: 인자 없이 불려 자원을 돌려주는 함수.
  • use: 자원을 받아 일을 하는 함수. 그 결과가 with의 결과다.
  • release: 자원을 받아 정리하는 함수. 결과는 버린다.

돌려주는 값

use의 결과.

에러

  • use나 release의 런타임 에러는 그대로 난다(둘 다면 use의 에러에 release의 것이 붙는다).
  • release가 Err를 돌려주면 E0606.

예제

정상으로 끝날 때

print(with(() => "conn", c => c + " used", c => print("closed", c)))
closed conn
conn used

release가 먼저 돌고, 그 뒤에 with의 결과가 찍힌다.

use가 실패해도 정리는 돈다

with(() => "/tmp/lock", fn(lock):
  print("working with", lock)
  fail("disk full")
;;, lock => print("removed", lock))
working with /tmp/lock
removed /tmp/lock
error[E0803]: disk full
  --> example.fung:3:7
  |
3 |   fail("disk full")
  |       ^
  |
 call path (innermost first):
   example.fung:3 <lambda>
   example.fung:1 <entry>

exit와 기한에도 정리는 돈다

r = timeout(20ms, () => with(() => "lock", fn(c):
  sleep(1s)
  "done"
;;, fn(c):
  sleep(30ms)
  print("released", c)
;;))
print(r)
released lock
Err({kind: 'timeout, message: "timed out after 20ms"})

release의 sleep(30ms)는 이미 지난 기한에 끊기지 않고 끝까지 돈다.

실패해도 되는 정리

fn cleanup(path) = exec(["rm", path])

r = with(() => "./no-such-file", p => "used ${p}", fn(p):
  _ = cleanup(p)
;;)
print(r)
used ./no-such-file

rm은 실패하지만 _ =로 일부러 버렸으므로 멈추지 않는다.

exit

프로그램을 끝내고 종료 코드 code를 남긴다.

exit(code = 0)

설명

어느 태스크에서 불러도 프로그램 전체를 끝낸다. 남은 태스크는 모두 취소되고, 되감기가 지나는 모든 with의 release가 돈 뒤 그 코드로 끝난다. 성공은 exit()이나 exit(0), 실패는 보통 exit(1)이다. 진입 파일의 끝까지 가면 저절로 0으로 끝나므로 성공 때는 exit를 쓸 필요가 없다.

종료 코드는 운영체제가 하위 8비트만 남기므로 0부터 255까지를 쓴다. 그 밖의 수는 256으로 나눈 나머지가 된다(exit(256)은 0, exit(-1)은 255).

매개변수

  • code: 정수. 기본은 0.

돌려주는 값

돌아오지 않는다.

에러

code가 정수가 아니면 런타임 에러 E0403.

예제

실패를 알리고 끝내기

missing = ["DB_HOST", "DB_USER"] |> filter(k => env(k) == nil)
if not is_empty(missing):
  eprint("missing env:", join(missing, ", "))
  exit(2)
;;
print("all set")
missing env: DB_HOST, DB_USER

exit 뒤에도 정리는 돈다

with(() => "tmp", fn(t):
  print("exiting")
  exit(3)
;;, t => print("cleaned", t))
exiting
cleaned tmp

args

스크립트 경로 뒤의 명령행 인자를 담은 문자열 리스트. 함수가 아니라 값이다.

args

설명

fung run deploy.fung prod --dry-run이면 args는 ["prod", "--dry-run"]이다. 스크립트 경로와 fung run은 들어가지 않는다. 인자가 없으면 []다. 함수가 아니므로 괄호 없이 args로 쓴다.

인자는 언제나 문자열이라 수나 기간이 필요하면 parse_int·parse_dur로 바꾼다. --name value 같은 옵션과 도움말이 필요하면 cli 모듈이 args를 읽어 준다.

매개변수

없다(값이다).

돌려주는 값

문자열의 리스트.

에러

없다.

예제

인자 읽기

실행 방법 
fung example.fung prod web-1 web-2
match args:
  []                   => print("usage: deploy ENV HOST...")
  [env_name, ...hosts] => print("deploying to", env_name, hosts)
;;
deploying to prod ["web-1", "web-2"]

인자가 없을 때

if is_empty(args):
