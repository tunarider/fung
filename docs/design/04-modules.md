# 04. 모듈 체계

## 단위

- **파일 하나 = 모듈 하나.** `utils.fung`은 `utils` 모듈이다.
- 모듈 이름은 파일명에서 자동으로 정해진다. 바꾸려면 `as`를 쓴다.
- 파일 이름이 이름 규칙에 맞지 않으면(`my-lib.fung`) `as`가 필수. 없으면 컴파일 에러.

## import

```
import fs                                    # 표준 라이브러리: 이름
import "./lib/rename"                        # 내 파일: 경로 문자열 (.fung 생략)
import "./lib/rename" as rn                  # 별칭
import "./lib/rename" (slugify, to_kebab)     # 일부 이름만 직접 가져오기

fs.read("a.txt")
rn.run(files)
slugify("Hello World")
```

- 표준 라이브러리(내장 extras, 06)는 이름, 내 파일은 경로 문자열로 가져온다.
  - `./` `../` `/`로 시작하지 않는 문자열 경로는 외부 패키지(프로젝트 extras)용으로 남겨둔다 (추후). 이름 해석 우선순위는
    core > 내장 extras > 프로젝트 extras.
- 상대 경로는 **import하는 파일의 위치 기준**. 실행한 위치(cwd)와 무관하다.
- 전부 풀어서 가져오기(`import *`)는 없다.
- `import "./x" as y (a, b)`처럼 `as`와 목록을 같이 쓰면 둘 다 묶인다. 목록만 쓰면 모듈 이름은 묶이지 않는다.
- **import한 이름은 다시 내보내지 않는다.** `import "./a" (x)`를 한 모듈 `b`를 가져와도 `b.x`는 없다.

## 공개/비공개

- 기본 공개.
- `_`로 시작하는 이름(`fn _helper()`, `_cache = ...`)은 비공개. 다른 모듈에서 접근하면 에러.
  `mod._x`처럼 정적으로 알면 컴파일 에러, 모듈 값을 변수에 담아 접근하면 런타임 에러.
- `type` 별칭은 **모듈 안에서만** 쓴다 (내보내지 않음). 호출하는 쪽은 별칭을 몰라도 된다. 타입 문법에 `mod.name`은 없다.
- 단독 `_`(패턴의 아무거나, 부분 적용 자리)와는 별개 토큰이다.

## 모듈은 값

- 모듈은 비공개가 아닌 최상위 `fn`과 변수들의 **불변 레코드 값**이다. `fs.read`의 `.`은 맵의 `m.name`과 같은 규칙.
- 함수 인자로 넘길 수 있다. `type_of(fs) == 'module`, `==`는 동일성 (02).

## 최상위 코드: 진입 파일과 라이브러리 파일

- **진입 파일**(직접 실행한 파일): 최상위에 무엇이든 쓸 수 있다.
- **import된 파일**: 최상위에는 `import`, `fn`, `type`, `test`, `이름 = 식`만 허용.
  `print(...)` 같은 단독 문장이 있으면 import 시점에 에러.
  - `이름 = 식`의 오른쪽은 **어떤 식이든** 된다 (함수 호출, 파일 읽기 포함). 모듈 초기화 용도.
    금지되는 것은 "값을 버리는 단독 식 문장"뿐이다. `x = print("hi")`가 허용되는 것은 의도된 구멍이다.
- 진입 파일을 다른 파일에서 import하면 에러. 판단 기준은 "지금 실행 중인 진입 파일과 같은 경로인가". 공용 코드는 별도 파일로 뺀다.
- 모듈은 **처음 import될 때 한 번** 최상위 문장을 위에서 아래로 실행하고 캐시한다. `test` 블록은 `fung test`에서만 실행된다.

## 순환 import

- 에러. 메시지에 순환 경로 전체를 보여 준다 (`a → b → c → a`).

## 적재 시점과 전역

- 진입 파일을 컴파일할 때 import 그래프 **전체를 읽고 컴파일**한다. 순환, 비공개 접근, 최상위 제한, 가져온 이름의 존재 여부는
  모두 이때 검사하며 종료 코드 2(컴파일 실패)다. `fung check`도 같은 경로를 쓴다.
- 모듈의 최상위 코드는 그 모듈의 `import` 문이 **처음 실행될 때** 한 번 실행되고 캐시된다 (위 "최상위 코드" 참고).
  `import` 문은 최상위 `fn`처럼 끌어올려져 파일의 다른 문장보다 **먼저** 실행된다 (끌어올린 `fn`이 모듈 이름을 봐야 하므로).
  따라서 `print("start")` 뒤에 쓴 `import`라도 그 모듈의 초기화가 `start`보다 먼저 일어난다.
- 모듈마다 **자기 전역 표**가 있다. 함수 값은 만들어질 때 자기 모듈의 전역 표를 함께 들고 다니므로,
  다른 모듈에서 불려도 자기 모듈의 최상위 `fn`과 변수를 본다.

## 기본 내장 (prelude)

- 자주 쓰는 함수는 import 없이 사용한다.
- **prelude 이름은 가릴 수 있다.** 최상위에 `fn map(...)`을 정의해도 에러가 아니다 (경고는 M6에서 검토).
  prelude 이름을 예약하면 나중에 함수를 하나 추가할 때마다 기존 스크립트가 깨지기 때문이다 (Python 내장 함수, Elixir Kernel과 같은 선택).
  가린 이름은 그 모듈 안에서만 바뀌고, 표준 라이브러리 내부는 영향을 받지 않는다.
- `fs`, `path`, `json`, `http`, `time`, `regex` 등 영역별 모듈은 import가 필요하다.
- 목록은 06. Go 연동 · 표준 라이브러리 참고.

## 실행

- `fung script.fung`으로 바로 실행. 프로젝트 설정 파일이 필요 없다.
- 첫 줄 `#!/usr/bin/env fung` + 실행 권한이면 `./script.fung`으로 실행.
- 프로젝트 설정 파일은 외부 패키지 관리를 다룰 때 필요하면 추가한다.

## 이름 가리기

- for 변수, 함수 인자, 패턴처럼 **새 이름을 만들 때** 바깥 이름을 가리는 것은 허용.
- 단, **import한 모듈 이름을 가리면 에러.**
- 블록 안에서 바깥 변수에 `=`로 재할당하는 것은 기존 규칙대로 에러 (01. 문법).

```
import path
for path in files:      # 에러: 모듈 path를 가림
  ...
;;

import path as p
for path in files:      # OK
  p.base(path)
;;
```
