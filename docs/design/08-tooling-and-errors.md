# 08. 도구와 에러 표시

## 에러 메시지

### 형식

코드 일부, 정확한 위치, 해결 힌트를 보여준다 (Rust / Elm 방식).

```
error[E0204]: undefined name `fiels`
  --> rename.fung:12:12
   |
12 |   for f in fiels:
   |            ^^^^^ not found in this scope
   |
 help: a similar name exists: `files` (line 10)
```

런타임 에러는 호출 경로(안쪽부터)를 덧붙인다. 구현 언어의 스택 추적은 보이지 않는다.
꼬리 호출로 재사용된 프레임은 경로에 없으므로 `… (tail calls elided)` 표시를 둔다 (03).

```
error[E0510]: cannot add str to int: 3 + "kb"
  --> report.fung:7:11
   |
 7 |   label = size // 1024 + "kb"
   |           ^^^^^^^^^^^^^^^^^^^
   |
 call path (innermost first):
   report.fung:7   format_size
   report.fung:15  report
   report.fung:22  <entry>
 help: use str(...) or "${...}" to convert to a string
```

- **바이트코드의 모든 명령은 소스 위치(파일, 줄, 칸)를 가진다.** 처음부터 설계에 포함한다.

### 에러 코드와 언어

- 모든 에러에 번호를 붙인다 (`E0204`). `fung explain E0204`는 추후.
- 메시지는 코드에 직접 쓰지 않고 **카탈로그(번호 → 메시지 + 힌트)**로 분리한다.
- 처음에는 **영어**만. 다른 언어는 카탈로그 추가로 지원.
- 번호는 한 번 붙으면 **바꾸지 않는다** (골든 테스트와 사용자가 의존한다). 쓸모가 없어진 번호는 폐기하고 재사용하지 않는다
  (폐기: E0207 "used before it is assigned" — 스코프 모델 변경으로 도달 불가, 2026-10-13).

### 번호 체계

앞 두 자리는 분류, 뒤 두 자리는 일련번호. 구체적인 번호는 카탈로그에서 구현하며 붙인다.

| 분류 | 내용 | 예 |
|------|------|----|
| E01xx | 문법 (렉서·파서) | 모르는 이스케이프, 비교 연쇄, `;;` 누락 |
| E02xx | 이름·스코프 (resolve) | 미정의 이름 `E0204`, 바깥 변수 재할당, 블록 밖 이름, `for` 안 `return` |
| E03xx | 모듈 | 순환 import, 비공개 접근, 진입 파일 import, 최상위 단독 문장 |
| E04xx | 호출·타입 표기 | 인자 개수·이름, 타입 표기 불일치 |
| E05xx | 런타임 연산 | 타입 불일치 `E0510`, 0 나누기, 오버플로, 범위 밖 인덱스, 없는 키, nil 연산 |
| E06xx | 패턴·결과값 | 맞는 패턴 없음, 구조 분해 실패, `!`가 Err를 만남, `!`·`?`를 결과값 아닌 값에 |
| E07xx | 동시성 | 취소(내부용), 교착, 에이전트 재진입 `E0704`, 채널에 자기 자신 보내기 `E0705` (05; `E0703`은 0.1의 atom 재진입이라 지금은 쓰지 않고 번호만 남음) |
| E08xx | 한도·환경 | 스택 깊이 초과, `fail(msg)` |
| W01xx | 경고 | 안 쓰는 import·지역 변수 |

### 보고 범위

- 문법 에러: 첫 번째 하나만.
- 의미 에러(미정의 이름, 모듈 가리기, 바깥 변수 재할당 등): 파일 전체를 검사한 뒤 모두.
  단, 같은 원인의 연쇄 에러(미정의 이름을 쓴 식의 타입 에러 등)는 억제한다.

### 경고

- 쓰지 않는 import
- 쓰지 않는 지역 변수 (`_`로 시작하면 경고 안 함. 비공개 의미는 모듈 최상위에서만이므로 충돌 없음)
- prelude 이름 가리기(04) — `fn map(…)`처럼 내장 이름을 덮어쓴 경우 (실수를 잘 잡고 비용이 작다)
- 보류: 값 자리의 블록이 문장으로 끝남(01). "값 자리"의 정의가 까다로워 알파 이후에 다시 본다.
- 번호: W0101 쓰지 않는 import, W0102 쓰지 않는 지역 변수, W0103 prelude 이름 가리기, W0104 값 자리의 블록이 대입문으로 끝남
  (`x = if c: y = 1 ;;`의 값은 `nil`; 대입의 오른쪽·인자·`return`에 온 `if`·`match`·블록만 본다, 2026-10-14). 형식은 `warning[W0101]: …`로 에러와 같다.
- 규칙은 파일을 어떻게 적재했든 같다(직접 검사하든 import되든). 내장 표준 라이브러리 자신의 경고는 사용자가 손댈 수 없으므로
  보여 주지 않는다. W0103은 최상위 이름에도 난다(`fn map(…)`, 모듈이 내보내는 `remove = …`): 가려도 되지만 알고 가리라는 뜻이다.
- **경고는 `fung check`와 `fung test`에서만 보여 준다. `fung run`은 경고를 내지 않는다.**
  매일 돌리는 스크립트가 stderr에 경고를 뿌리면 cron 메일과 로그가 더러워지고,
  골든 테스트의 "stderr는 비어 있어야 한다" 규칙과도 충돌한다. 편집기(LSP)가 생기면 경고는 거기서 보인다.

## `fung` 명령

```
fung script.fung [args...]                 # 실행 (fung run 의 축약)
fung                                       # REPL
fung -e 'code'                             # 한 줄 실행 (표준 입력 사용 가능)
fung check script.fung                     # 실행 없이 문법·의미 검사
fung fmt script.fung                       # 코드 정리
fung test [path]                           # 테스트 실행
fung dump ast|core|bytecode script.fung    # 내부 단계 출력
fung version
```

```
$ fung dump core -e 'files |> filter(is_log) |> map(size)'
(map (filter files is_log) size)
```

- `fung check`: 렉싱·파싱·desugar·이름 해석(스코프, 가리기, `for` 안 `return` 등 모든 의미 검사)·
  import 추적(가져오는 파일들도 같은 검사, 최상위 제한 확인)·타입 별칭 유효성. 실행은 하지 않는다. 문제가 있으면 종료 코드 2.
  성공이면 아무것도 출력하지 않는다. 경고만 있으면 경고를 보여 주고 0으로 끝난다. `-e`도 받는다.
- `fung dump ast`는 균일 트리를 S-식으로, `core`는 desugar 뒤 같은 형식, `bytecode`는 역어셈블.

### 종료 코드

쉘 스크립트(`set -e`, `&&`)와 골든 테스트 실행기가 실패 종류를 구분할 수 있도록 고정한다.

| 코드 | 의미 |
|------|------|
| 0 | 정상 종료 |
| 1 | 실행 중 실패 (처리 안 된 런타임 에러, `!`가 Err를 만남, `exit(1)` 등) |
| 2 | 컴파일 실패 (문법·의미 에러). `fung check`가 문제를 찾았을 때도 2 |
| 3 | `fung` 명령 자체의 사용 오류 (모르는 하위 명령, 잘못된 인자, 아직 구현되지 않은 기능) |

- `exit(n)`은 사용자가 원하는 코드를 그대로 낸다.
- 첫 인자가 `.fung`으로 끝나거나 경로 구분자를 포함하면 스크립트로 보고 실행한다.
  그 외의 단어는 하위 명령으로 해석하며, 모르는 단어면 3으로 끝난다. `fung run <파일>`은 언제나 쓸 수 있다.

## REPL

- 블록이 열려 있거나(`:` 뒤 `;;` 미달) 줄이 이어짐 토큰으로 끝나면(01) 다음 줄을 이어 받는다.
- 식 문장의 값은 출력하고, 대입·`fn` 정의는 출력하지 않는다.
- 입력 기록, 줄 편집 지원.
- 정의한 변수·함수는 유지된다. REPL에서는 함수 재정의 허용. 태스크가 도는 중의 재정의는 정의하지 않는다 (05).
- REPL 명령은 `:`로 시작: `:help`, `:quit`, `:load file.fung`. 그 이상은 두지 않는다.
  `:load`는 파일을 **그 세션의 모듈로** 실행하므로 파일의 정의가 세션에 남는다.
- 줄 편집은 표준 입력이 터미널일 때만 켠다(raw 모드: 좌우 이동, Home/End, Backspace/Delete, 위아래 기록, Ctrl-C는 줄 취소,
  Ctrl-D는 종료; 자동완성 없음). 파이프나 Windows에서는 보통 줄 읽기로 동작하므로 `echo 'print(1)' | fung`이 된다.
  기록은 `~/.fung_history`에 줄 단위로 저장한다 (2026-10-14): 시작할 때 읽고, 받아들인 줄마다 덧붙이며, 최근 1000줄만 남긴다.
  빈 줄과 바로 앞과 같은 줄은 저장하지 않는다. 홈 디렉터리를 모르거나 쓸 수 없으면 조용히 끈다. 파이프 입력은 기록하지 않는다.
- 태스크와 세션의 끝 (2026-10-17, Rust 5단계 사용자 결정; open-questions "Rust 이전" 5단계 항목):
  - 에이전트·배경 태스크는 **세션 끝**(`:quit`, 입력 끝, `exit(n)`)에 한 번 끝낸다. 입력 사이에는 정의가 남으므로 전역에 담은 에이전트도
    다음 입력에서 쓸 수 있어야 한다. 아무도 붙잡지 않은 에이전트는 핸들이 사라질 때(대개 그 입력 끝에) 끝난다.
    세션 끝의 순서: 태스크 취소 → 종료 핸들러 → 배경 태스크 끝내기 → 꺼내지 않은 실패 보고.
  - 다음 입력을 기다리는 태스크는 교착이 아니다(세션이 런타임을 붙잡고 있다). 사람이 천천히 쳐도 같다.
  - 한 입력 안의 교착은 **그 입력만** 실패시킨다(보고는 그대로). 세션은 새 실행 루트에서 계속되고, 앞 입력들이 막힌 채 남긴 태스크는
    취소되며, 전역과 에이전트는 남는다. 회복한 교착은 세션의 종료 코드를 바꾸지 않는다(그 뒤 정상으로 끝나면 0).
  - 띄운 태스크의 `exit(n)`은 프롬프트에서 친 `exit(n)`처럼 세션을 코드 n으로 끝낸다. 터미널에서는 줄 읽기가 기다리는 중이라
    다음 줄을 친 뒤에 끝나고, 그 줄은 실행하지 않는다.

## 값 출력 형식

- `print`에 문자열을 주면 따옴표 없이 출력.
- 그 외 값과 REPL 결과는 **fung 리터럴 형태**. 출력을 그대로 코드에 붙여도 동작한다.

```
> [1, "a", 'ok, Ok(3), {name: "x"}]
[1, "a", 'ok, Ok(3), {name: "x"}]
```

- 실수는 정수처럼 보여도 `5.0`. 큰 수는 `1e21` (Go의 `1e+21`이 아니라 fung 리터럴로 읽히는 형태).
- 맵 키는 이름 규칙에 맞으면 따옴표 없이, 아니면 `{"a b": 1}`.
- 리터럴이 없는 값: `<fn add>`, `<module fs>`, `<task>`, `<channel>`, `<agent>`.
- `print(a, b)`는 인자를 공백으로 이어 한 줄에 (06).

## dbg

값을 출력하고 그대로 돌려준다. 원래 식의 코드도 같이 보여준다.

```
files |> filter(is_log) |> dbg |> map(fs.size)
# [rename.fung:3] filter(is_log) = ["a.log", "b.log"]
```

- prelude에 포함. 단계 실행 디버거는 만들지 않는다.
- **표준 에러**로 출력한다 (표준 출력은 파이프라인 결과용으로 비워 둔다). 보여 주는 텍스트는 **인자 식 전체**:
  위 예시는 `[rename.fung:3] files |> filter(is_log) = ["a.log", "b.log"]`가 된다.
  `dbg`를 변수에 담아 간접으로 부르면 텍스트 없이 값만 찍힌다.

## 포맷터

- Go의 포매터처럼 옵션 없는 단일 스타일.
- 구현은 알파 이후. **단, 렉서·파서는 처음부터 주석을 보존한다.**
- 규칙 (2026-10-14 확정, 상세는 `docs/superpowers/specs/2026-10-14-formatter-design.md`):
  - **토큰 재배치**: 공백·들여쓰기·빈 줄·정렬만 바로잡고 **줄바꿈은 사용자가 쓴 대로** 둔다. 문자열·숫자 리터럴은 손대지 않는다.
  - 들여쓰기 2칸. 깊이 = 열린 블록(`fn`·`if`·`else`·`match`·`for`·`test` 뒤의 `:` … `;;`) + 열린 괄호.
    `fn`은 다음 토큰이 이름이나 `(`일 때만 블록 머리다. 타입 표기의 `fn`(`h: fn`, `-> fn:`)은 블록을 열지 않는다(2026-10-17 수정). 닫는 토큰으로 시작하는 줄은
    한 단계 내린다(`;;)`는 `map(` 줄 위치). `else`는 `if`와 같은 깊이, `match` 절 본문이 다음 줄이면 +1,
    `|>` `.` `??` `and` `or` `then` `else`로 시작하는 이어지는 줄은 +1.
  - 공백: 이항 연산자·`=>`·`->`·`=` 양옆 1칸, `,`·`:`·`;` 뒤 1칸, 괄호 안쪽·`.`·`..`·호출 괄호 앞·접두 `-` 뒤·후위 `!` `?` 앞은 0칸.
  - 빈 줄은 연속 하나로, 블록·파일 시작과 `;;` 직전의 빈 줄은 지운다. 파일 끝은 줄바꿈 하나.
  - 정렬: 연속 줄의 꼬리 주석은 코드 최대 너비 + 2칸에, `match`의 연속 절은 `=>`를 패턴 최대 너비 + 1칸에 맞춘다.
  - 명령: `fung fmt <path>...`(제자리, 바뀐 파일 이름 출력), `--check`(바뀔 파일이 있으면 종료 코드 1), `-`(stdin → stdout).
    `--check -`는 포맷 결과를 찍지 않고, 바뀔 게 있으면 `<stdin>`을 찍고 종료 코드 1, 없으면 아무것도 찍지 않고 0(2026-10-17).
    구문 에러 파일은 건드리지 않고 종료 코드 2. 맨 앞 BOM은 렉서처럼 건너뛰고 출력에 쓰지 않는다(2026-10-17).
  - 안전장치: 출력의 토큰 열(줄바꿈 제외)과 주석이 입력과 같을 때만 쓴다. 멱등.

## 편집기 지원

- 목표: **tree-sitter 문법 + LSP 서버.** (주 사용 환경: Emacs의 treesit + LSP 클라이언트)
- tree-sitter: Emacs 29+, Neovim, Helix, Zed, GitHub 코드 탐색 등에서 쓰인다.
  - VS Code는 기본 강조에 tree-sitter를 쓰지 않으므로, 필요해지면 TextMate 문법을 따로 두거나 LSP semantic tokens로 보완한다.
  - 줄바꿈 규칙(줄 이어짐), `;;` 처리 때문에 C로 작성하는 external scanner가 필요할 가능성이 높다.
- LSP: 거의 모든 편집기가 지원. fung 본체(Rust, `fung-front`)의 렉서·파서·의미 분석을 그대로 재사용한다.
  - 입력 도중의 깨진 코드도 다뤄야 하므로 **파서에 에러 복구가 필요해진다.** 지금은 첫 문법 에러에서 멈추지만,
    문장 경계(줄바꿈, `;`, `;;`)에서 다시 동기화할 수 있게 파서를 설계해 둔다.
- 순서: tree-sitter 문법 (알파 무렵) → LSP (베타 이후)

## 테스트

```
fn slugify(s) = s |> lower |> replace(" ", "-")

test "spaces become hyphens":
  assert slugify("Hello World") == "hello-world"
;;
```

- `test "이름": ... ;;` 블록은 같은 파일에 둘 수 있다. 일반 실행 때는 무시되고 `fung test`에서만 실행된다.
  본문은 **인자 없는 함수**다: 그 자리에서 만들어지므로(03, 그때 보이는 파일 변수를 복사) `return`과 `?`를 쓸 수 있고,
  하나가 실패해도 다음 테스트가 돈다. `fung test`는 파일의 최상위를 먼저 실행한 뒤 등록된 테스트를 순서대로 돌린다.
- `_test.fung`로 끝나는 별도 파일도 가능. 규칙은 보통 파일과 같다(테스트 블록이 있으면 돈다).
- `fung test [path]`: 인자가 없으면 현재 디렉터리 이하의 `.fung` 전부, 파일이면 그 파일, 디렉터리면 재귀(이름이 `_`로 시작하는
  디렉터리는 fixture로 보고 건너뜀). 테스트가 없는 파일은 최상위도 실행하지 않고 조용히 건너뛴다. 파일마다 새 Runtime에서 진입
  파일로 실행한다. import된 모듈 안의 테스트는 **그 파일을 직접 지정했을 때만** 돈다.
- 테스트 파일 안의 `exit(n)`은 **실패**로 기록되고 그 파일의 나머지를 건너뛴다. 조용히 끝나는 테스트 실행은 없다.
- 테스트 파일 안에서 교착이 보고되거나 띄운 태스크가 `exit(n)`을 부르면, 직접 부른 `exit(n)`처럼 **그 파일의 나머지를 건너뛴다**
  (2026-10-17, Rust 5단계 사용자 결정). 돌던 블록은 평소대로 `ok`/`FAIL` 줄을 내고, 남은 블록이 있을 때만 메모 한 줄
  (`a deadlock was reported; the rest of the file was skipped` 또는 `exit(n) called inside a test file; …`)이 붙는다. 건너뛴 블록은
  세지 않지만 **건너뛰기 자체는 실패 하나로 센다**: 메모 앞의 블록이 통과했으면 `FAIL path: <rest of file>` 줄을 먼저 내고 실패 하나를
  더한다(블록이 이미 실패했으면 그 실패로 충분하다). 조용히 끝나는 테스트 실행은 없다는 위 규칙 그대로다(2026-10-17 최종 리뷰).
  명령의 종료 코드는 n이 되지 않으며, 종료 핸들러·배경 태스크 끝내기·꺼내지 않은 실패 보고는 그대로 돈다.
  최상위가 정상으로 끝났는데 exit나 교착이 이미 걸려 있으면 `FAIL path: <top level>`에 같은 메모를 붙여 실패 하나로 센다.
  결정의 배경은 open-questions "Rust 이전" 5단계 항목.
- `test` 블록은 최상위에만 쓴다 (E0114).
- `assert`는 **키워드**이고 어디서나 쓴다. `fung run` 중 실패하면 런타임 에러(E0807, 종료 코드 1)이고, `fung test` 안에서는
  실행기가 그 에러를 `FAIL`로 기록하고 다음 테스트로 넘어간다. 실패 시 맨 바깥이 비교 연산이면 양쪽 값을, 아니면 식 전체의 값을
  보여준다 (더 깊이 분해하면 부수효과 있는 식을 두 번 평가하게 된다).

```
assertion failed: slugify("Hello World") == "hello-world"
  slugify("Hello World") = "hello world"
```

- `fung test`는 테스트마다 `ok   path: 이름` / `FAIL path: 이름` 한 줄(실패면 이유를 덧붙임) + 요약 `N passed, M failed`를
  출력한다. 하나라도 실패하면 종료 코드 1, 컴파일 실패면 2. 로드(컴파일)에 실패한 파일은 `FAIL path: <load>`로 실패에 센다; 여러 파일이
  같은 라이브러리 때문에 깨지면 그 에러는 **한 번만** 찍는다 (2026-10-14).
- fung 자체의 언어 기능 테스트도 fung 파일로 작성한다 (09. 구현 계획).
