# 07. 연산자와 타입 표기

## 논리

- `not`, `and`, `or`. `and` / `or`는 단락 평가.
- `not`은 비교보다 낮다(아래 우선순위). 그래서 `a == not b`, `1 + not c`는 에러이고 `a == (not b)`로 쓴다. `not a == b`는 `not (a == b)`다.
- **조건 자리에는 `true` / `false`만 허용.** 빈 리스트, 0, `""`, nil을 거짓으로 취급하지 않는다 (truthiness 없음). 다른 값이 오면 에러.

```
if not is_empty(files): ... ;;
```

## 산술

| 연산자 | 의미 |
|--------|------|
| `+ - *` | 덧셈, 뺄셈, 곱셈 |
| `/` | 나눗셈, 항상 실수 결과 |
| `//` | 내림 나눗셈. 실수에도 된다: `7.5 // 2 == 3.0` |
| `%` | 나머지. `//`와 짝을 맞춰 내림 기준: `-7 % 3 == 2`, `-7.5 % 2 == 0.5` |
| `**` | 거듭제곱 (오른쪽부터 결합). 정수 ^ 음이 아닌 정수면 정수, 지수가 음수이거나 실수가 섞이면 실수 (`2 ** 10 == 1024`, `2 ** -1 == 0.5`) |

- 정수와 실수를 섞으면 실수 결과 (`1 + 2.5 == 3.5`, `7 // 2.0 == 3.0`). Python과 같은 규칙.
- 실수의 `//`·`%`는 반올림된 몫이 아니라 **정확한 나머지**(`fmod`)에서 구한다(Python `float_divmod`와 같음, 2026-10-20).
  나머지는 나누는 수보다 작고 그 부호를 따르며, 몫은 `(x - 나머지) / y`를 가장 가까운 정수로 맞춘 값이다:
  `7.7e40 % 0.1 == 0.04850743287925943`, `1 // 0.1 == 9.0`. 나머지가 0이면 나누는 수의 부호를 가진 0이다(`6.0 % -3.0`은 `-0.0`).
- **0으로 나누면 런타임 에러.** 정수·실수, `/` `//` `%` 모두.
- **실수 연산 결과가 `Inf`나 `NaN`이면 런타임 에러.** fung 값에는 `Inf`·`NaN`이 없다.
  `NaN`은 `x == x`가 거짓이라 비교 표(02)를 깨고, `Inf`는 엉뚱한 곳에서 터진다. "조용히 넘어가는 동작은 에러"의 실수판.
- 정수 오버플로는 런타임 에러 (02). 검사 대상: `+ - * **`, `//`에서 최솟값 ÷ -1, `int(실수)`가 범위를 넘을 때.
- 단항 `-`는 기간에도 된다 (`-5s`). 음수 기간은 정상 값.
- 기간 `/` 정수는 정확히 나눠 기간 리터럴처럼 가장 가까운 나노초로 맞춘다(반은 0에서 먼 쪽, `d / 1 == d`; 2026-10-20).
  기간 `/` 실수와 기간 `*` 실수는 f64를 거친다.
- **기간끼리 나누기**(L5, 2026-10-20): 기간을 숫자로 바꾸는 길이다. 나누는 기간이 단위가 되어 식에 보인다(`elapsed / 1ms`는 ms 수).
  - `dur / dur` → 실수(늘 실수, 정수 `/`와 같다). 몫의 정수 부분과 나머지 비율을 따로 구해, 2⁵³ ns(약 104일)를 넘는 기간도 정확하다.
  - `dur // dur` → 정수, `dur % dur` → 기간. 정수와 같은 내림 규칙(나머지의 부호는 나누는 수)이고, 가장 작은 기간 `// -1ns`는 오버플로 에러, 0으로 나누면 에러.
  - 반대로 숫자를 기간으로는 `n * 1ms`. 섞인 `dur // 수`·`dur % 수`·`수 / dur`은 에러다(`dur / 수`는 위의 n등분).
  - 기각: 변환 함수(`time.ms(d)`; 단위마다 함수가 늘고 import가 필요), `int(d)`가 나노초(단위가 숨는다).
- 시각(02): `time + dur`, `dur + time`, `time - dur` → time, `time - time` → dur. 범위를 넘으면 오버플로 에러. 그 외(`time + time`, `time * 2`)는 에러.

## 이어 붙이기

- `"a" + "b"`, `[1] + [2]`는 이어 붙이기. `"a" + 1`은 에러. 문자열은 1억 글자 한도(02)를 넘으면 E0806(보간 `"${a}${b}"`도 같다).
- 맵 합치기는 `merge` 함수.
- `"a" * 3`, `[0] * 3` 같은 반복은 없다. `repeat(x, n)` 함수로.

## 비교

- `==` / `!=`는 값 비교. 리스트·맵·튜플은 내용이 같으면 같다.
- 타입이 다르면 에러가 아니라 `false`. 단, 숫자끼리는 값으로 비교 (`1 == 1.0`은 참).
- 비교는 연쇄하지 않는다. `a < b < c`는 문법 에러 (`a < b and b < c`로 쓴다).
- `< > <= >=`: 숫자, 문자열, 기간, 시각, 리스트·튜플(앞 원소부터 차례로). 그 외는 에러.

```
files |> sort_by(f => (path.ext(f), f))
```

## 포함 여부

```
if ext in [".jpg", ".png"]: ... ;;
if "key" not in config: ... ;;
```

- `in` / `not in`. `contains`의 축약. 리스트·문자열·맵(키)에 동작.

## 범위와 슬라이스

```
0..10        # 0 ~ 9
0..=10       # 0 ~ 10
s[1..3]      # 슬라이스
s[..3]       # 처음부터
s[-4..]      # 뒤에서 4번째부터 끝까지
s[-1]        # 음수 인덱스
for i in 0..10: ... ;;
```

- `range(...)` 함수와 같은 범위 값을 만든다.
- `list[1:3]` 형태는 `:`(블록 시작)와 겹쳐서 쓰지 않는다.

## 비트 연산

- 연산자 없음. `math.band`, `math.bor`, `math.bxor`, `math.shl`, `math.shr` 등 함수로.

## 우선순위 (낮음 → 높음)

| 순위 | 연산자 |
|------|--------|
| 1 | `then … else` |
| 2 | `or` |
| 3 | `and` |
| 4 | `not` |
| 5 | `==` `!=` `<` `>` `<=` `>=` `in` `not in` |
| 6 | `\|>` |
| 7 | `??` |
| 8 | `..` `..=` |
| 9 | `+` `-` |
| 10 | `*` `/` `//` `%` |
| 11 | 단항 `-` |
| 12 | `**` (오른쪽 결합) |
| 13 | 후위 `!` `?`, 호출 `()`, 인덱스 `[]`, 필드 `.` |

```
name |> ends_with(".log") and size > 0    # (name |> ends_with(".log")) and (size > 0)
files |> len > 3                          # (files |> len) > 3
a + b |> f                                # (a + b) |> f
fs.read(p) ?? "{}" |> json.parse          # (fs.read(p) ?? "{}") |> json.parse
-2 ** 2                                   # -(2 ** 2) == -4
```

- 파이프 오른쪽이 호출 `f(a)`면 `f(x, a)`, 이름만 있으면 `f(x)`. 태그도 같다(`x |> Ok`는 `Ok(x)`). 오른쪽 호출의 인자에 `_`가 있으면 E0227(01).

## 타입 표기

### 타입 이름

`int`, `float`, `num`(int 또는 float), `str`, `bool`, `nil`, `sym`, `dur`, `time`, `list`, `map`, `tuple`, `range`, `fn`, `module`, `task`, `scope`, `atom`, `sender`, `receiver`, `file`, `any`

- `file`(열린 파일 핸들, `type_of`는 `'file`)은 T2(2026-10-20)에서 더했다. `_native.net` 안쪽 값(`conn`·`listener`)은 표기에 두지 않는다.

- 태그 이름도 타입으로 쓴다: `s: Circle`은 `Circle` 태그가 붙은 값. **인자 없는 태그(심볼, 02)도 받는다**(T1, 2026-10-20):
  `c: Red | Green`은 `Red`(= `'Red`)와 `Red(…)`를 받는다. 패턴 `Red`가 심볼 `'Red`에 맞는 것(03)과 같은 규칙이고, 열거형을 타입으로 쓰는 길이다
  (`type color = Red | Green | Blue`). 대문자로 시작하는 타입 이름은 늘 태그다(내장 타입과 별칭은 소문자).
  `type_of(Red)`는 그대로 `'sym`이다(`type_of`는 값의 표현을 말한다). 기각: 타입의 심볼 표기(`'red | 'green`, 문법이 는다).
- 검사는 할당 없이 한다(P6): 적재 때 표기를 "값 종류 비트 집합 + 태그 심볼 목록"으로 바꿔 둔다.
- **타입 이름은 값 이름과 다른 이름 공간**이다. `list = [1]`이라는 변수가 있어도 `fn f(x: list)`의 `list`는 타입이다.
- 값의 타입을 묻는 함수는 `type_of(x)` (`type`은 별칭 선언 예약어라 함수 이름으로 쓰지 않는다). `'int`, `'Circle` 같은 심볼을 돌려준다.

### 유니온

```
fn find_user(id: int) -> map | nil
fn area(s: Circle | Rect) -> num
fn load(p: str) -> Ok | Err
```

### 원소 타입

- `list[int]`, `map[str]` 같은 표기는 문법상 허용한다.
- **런타임은 바깥 타입(`list`, `map`)만 검사한다.** 원소까지 검사하면 호출마다 전체를 훑어야 해서 비용이 크다.
- 원소 타입은 지금은 문서 역할이고, 추후 정적 검사기가 생기면 그때 검사한다.

### 쓸 수 있는 위치

- 함수 인자와 반환 타입. 호출할 때와 반환할 때 검사한다.
- `...rest`는 늘 리스트라 표기는 `list`(또는 `any`, 표기 없음)만 된다. 다른 표기는 컴파일 에러 E0228(T3, 2026-10-20; 전에는 모든 호출이 E0403으로 실패했다).
  원소 타입을 적고 싶으면 `...xs: list[int]`(원소는 검사하지 않는다, 위).
- 변수에는 쓰지 않는다 (`x: int = 5` 없음).
- 맞지 않으면 런타임 에러 (코드 오류이므로 `Err`가 아님).

### 타입 별칭

```
type shape = Circle | Rect | Tri
fn area(s: shape) -> num = ...
```

- 별칭 이름은 소문자 (대문자는 태그 전용).
- 내장 타입 이름(위 "타입 이름"의 목록)은 별칭 이름으로 쓸 수 없다: `type int = str`은 E0222. 같은 이름이 그 파일에서만 다른 뜻이 되기 때문이다(2026-10-20 사용자 결정).
