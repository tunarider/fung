# 05. 동시성 모델

## 원칙

- 언어/런타임은 **최소한의 원시 연산만** 제공한다.
- 병렬 map, 워커 풀, 채널 합치기, 액터 같은 고수준 패턴은 **fung 코드로 작성**한다 (표준 라이브러리도 가능한 한 fung으로).
- async/await 없음. 파일·네트워크 I/O는 평범한 함수 호출이고, 기다리는 동안 다른 태스크가 실행된다 (내부적으로 고루틴).
- 값은 불변이라 태스크 사이에서 그냥 공유해도 안전하다. 바뀌는 것은 atom뿐.

## 원시 연산

| 영역 | 연산 | 설명 |
|------|------|------|
| 태스크 | `spawn(f)` | f를 새 태스크로 실행, 태스크 핸들 반환 |
| | `await(t, timeout: d)` | 결과 대기. 아래 "결과" 참고 |
| | `cancel(t)` | 태스크 취소. 자식 태스크에도 전파 |
| 채널 | `channel(n = 0)` | 통로 생성 (n은 버퍼 크기. 0이면 받는 쪽이 있을 때까지 `send`가 막힌다) |
| | `send(ch, v)` | `Ok(nil)`, 닫혔으면 `Err({kind: 'closed})` |
| | `recv(ch, timeout: d)` | `Ok(v)`, 닫혔으면 `Err({kind: 'closed})`, 시간 초과면 `Err({kind: 'timeout})` |
| | `close(ch)` | 닫기 |
| 공유 상태 | `atom(v)` | 언어에서 유일하게 바뀔 수 있는 상자 |
| | `swap(a, f)` / `deref(a)` | 함수로 원자적 교체 / 현재 값 읽기 |
| 시간 | `sleep(d)` | 대기 |

- `for x in ch: ... ;;`는 `Ok`를 풀어서 주고, 채널이 닫히면 끝난다. 채널은 **순회 대상**이다(02): `each`·`map`·`filter`·`fold`처럼
  순회하는 모든 함수가 채널을 받으면 닫힐 때까지 받아서 처리한다. 규칙은 하나다.
- 닫힌 채널에 보내는 것이 Go처럼 패닉이 아니라 `Err`인 이유: 채널을 닫는 것은 다른 태스크가 하는 일, 즉 외부 요인이다 (06의 에러 규칙).
- `swap(a, f)`는 잠금 아래에서 `f`를 **정확히 한 번** 실행한다. `f` 안에서 같은 atom을 `swap`하면 교착이므로 금지: 같은 태스크의
  재진입은 E0703 런타임 에러로 잡는다.
- 원시 연산 이름은 Go 용어(`go`, `chan`, `select`, `context`)를 쓰지 않는다.

## 여러 채널 기다리기: `select` 없음

- Go `select`에 해당하는 원시 연산은 두지 않는다. 문법·VM 모두에 큰 추가다.
- 스크립트에서 필요한 것은 거의 "타임아웃 있는 받기"와 "여럿 중 먼저 온 것"이다.
  - 전자는 `recv(ch, timeout: d)`.
  - 후자는 표준 라이브러리 `fan_in(chs)` (fung 코드: 채널마다 전달 태스크를 띄워 하나로 모은다). 맵 `merge`와 이름이 겹치지 않게 했다.

## fung으로 작성하는 것들 (예)

- `pmap(list, f, limit: n)`: 병렬 map (Rust 구현은 처음에 워커 하나로 시작한다. 결과는 같고, 여러 코어를 쓰는지는 구현이 정한다. open-questions "Rust 이전")
- `fan_in(chs)`: 채널 합치기
- 워커 풀, 파이프라인, 액터식 상태 태스크

## 태스크의 결과와 에러

- `await(t)`는 다음 중 하나를 돌려준다.
  - 정상 종료: 함수의 반환값 그대로 (함수가 `Ok`/`Err`를 돌려줬다면 그것이 결과)
  - 런타임 에러로 죽음: `Err({kind: 'error', message: …})`
  - 취소됨: `Err({kind: 'cancelled})`
  - 시간 초과: `Err({kind: 'timeout})`
- `await(t)!`, `await(t)?`, `await(t) ?? v` 사용 가능.
- `await`를 두 번 하면 같은 결과를 돌려준다 (결과는 저장된다). 타임아웃으로 끝난 `await`는 결과를 꺼낸 것이 아니다.
- **아무도 확인하지 않은 태스크의 실패** (2026-10-14 개정): 실패한 태스크의 결과를 `await`로 한 번도 꺼내지 않은 채
  **더는 꺼낼 수 없게 되면** `task failed:` 머리말과 함께 표준 에러로 출력하고, 프로그램은 계속 실행한다. 꺼낼 수 없게 되는 때는 둘이다.
  - 핸들이 버려졌을 때: 핸들에 닿는 변수·컬렉션·클로저가 하나도 없으면 GC가 알아채고 보고한다. 보고 시각은 GC에 달려 있어
    보통 몇 초, 할당이 거의 없는 서버는 최대 약 2분(Go의 강제 GC 주기) 늦다.
  - 프로그램이 끝날 때: 진입 파일과 남은 태스크, `at_exit`까지 끝난 뒤 아직 꺼내지 않은 실패를 모두 보고한다.
  - 하나라도 보고되면 **종료 코드는 1**이 된다 (명시적으로 `exit(n)`을 부른 경우는 `n`). CI·cron이 실패를 알 수 있게 하기 위해서다.
  - 핸들을 들고 있는 한 기한 없이 나중에 `await`해도 된다. `pmap`·`fan_in`처럼 만든 태스크를 모두 기다리는 도우미의 태스크는
    처음부터 꺼낸 것으로 친다(`_native.conc.spawn_awaited`, 06).
  - 개정 이유: 이전 규칙("죽는 순간 `await`가 걸려 있지 않으면 보고")은 `t = spawn(f); await(t)`조차 태스크가 `await`보다 먼저
    죽으면 보고해 **같은 코드의 종료 코드가 실행 순서에 달렸다**(CI의 `-race`에서 드러남). 지금 규칙은 보고 여부가 결정적이고,
    보고된 실패는 언제나 진짜로 아무도 확인하지 못한 실패다. Python asyncio("Task exception was never retrieved")·.NET
    (`UnobservedTaskException`)과 같은 판정에, 프로그램 끝의 훑기와 종료 코드를 더한 것이다.
  - 대가: 핸들을 들고만 있고 영영 `await`하지 않는 서버는 끝날 때까지 보고되지 않는다. 버린 핸들의 보고는 원인보다 늦게 찍힌다.
  - 기각: 죽는 순간 판정(위의 이전 규칙), 짧은 유예 시간(운에 달린 것을 줄일 뿐), 모든 `spawn`에 실패 처리기 필수(빈 처리기가
    퍼지고 처리가 결과를 쓰는 곳과 떨어진다), 구조적 동시성(가장 강하지만 동시성 설계를 다시 하는 일, 보류).
- **취소된 태스크는 실패가 아니다.** 출력 없이 끝나고 종료 코드에 영향이 없다. `await`하면 `Err({kind: 'cancelled})`.
  - 기각: 즉시 중단 (Go 고루틴 패닉) → 서버에서 요청 하나가 모든 요청을 죽인다. 종료 코드 0 → 실패가 조용히 묻힌다.

## 종료

- 진입 파일이 끝나면 남은 태스크가 끝날 때까지 기다린다. (서버 스크립트가 살아 있는 방법이기도 하다.)
- 즉시 끝내려면 `exit()`. **어느 태스크에서 불려도** 프로그램을 끝낸다: 남은 태스크는 취소 신호를 받고, `at_exit`가 실행된 뒤
  프로세스가 끝난다 (03).
- 진입 파일이 **런타임 에러**로 죽으면 남은 태스크를 기다리지 않는다: 취소하고 `at_exit` 뒤 종료 코드 1 (03: 에러는 중단).
- 모든 태스크가 서로 기다려 멈추면 "deadlock: all tasks are waiting"(E0702, 종료 코드 1, `at_exit` 실행). 런타임이 **직접** 센다:
  살아 있는 태스크 수와 fung 원시 연산(`await` `recv` `send` `swap` `sleep`)에서 막힌 태스크 수, 그중 타이머가 깨울 수를 세고,
  "전부 막혔고 깨어날 것이 없는" 상태가 **50ms 동안 아무 변화 없이** 이어지면 교착이다(막히려는 순간 바로 판정하면 이미 깨어날 수
  있는데 아직 스케줄되지 않은 태스크 때문에 거짓 양성이 난다). Go 런타임의 교착 감지는 복구할 수 없는 치명 에러라(Go 스택 추적이
  나온다) 그보다 먼저 잡아야 한다. 표준 입력 같은 Go 차단은 세지 않는다(교착으로 몰지 않는 안전한 쪽).
  "살아 있는 태스크"는 fung 코드를 도는 모든 것이다: 진입 파일, `spawn`된 태스크, `fung test`의 테스트 본문, `at_exit` 핸들러,
  모듈 초기화. 마지막 실행 태스크가 끝날 때도 다시 판정한다(보낸 쪽이 보내지 않고 끝난 경우가 가장 흔한 교착이다).
- 교착 보고 뒤에도 `at_exit` 핸들러는 보통대로 돈다(자기 컨텍스트가 따로 있다). 핸들러 안의 태스크가 `exit(n)`을 부르면 핸들러도 끝나고
  종료 코드는 n이다.
- `swap` 안에서 같은 atom을 `deref`하거나 출력하는 것은 된다(교체 전 값을 본다): 값 읽기는 잠금을 쓰지 않는다.
- 표준 라이브러리의 `pmap`·`fan_in`은 자기가 띄운 태스크를 반드시 `await`하므로, 그 태스크의 실패는 호출자의 `Err`로만 전달되고
  "기다리지 않은 실패"로 보고되지 않는다(내장 파일 전용 `_native.conc.spawn_awaited`).

## 타임아웃·취소

- `await`와 `recv`의 `timeout:`, `cancel(t)` 지원.
- **취소는 자식 태스크에 전파된다** (Go `context` 트리와 같음). 안 그러면 취소된 태스크의 자식이 고아로 남아
  "남은 태스크를 기다린다" 규칙 때문에 프로그램 종료를 막는다.
- 취소는 협조적이다: VM이 함수 호출·반복 지점과 막히는 연산(`sleep`, `recv`, `send`, `await`, I/O)에서 확인하고,
  그 태스크를 런타임 에러처럼 끝낸다. 감싸는 함수의 정리는 실행되지 않는다 (03의 한계와 같음).
- 내부적으로 Go `context` 사용.

## 기간(duration) 리터럴

```
sleep(500ms)
await(t, timeout: 30s)
ttl = 1h30m
```

- 단위: `ms`, `s`, `m`, `h`. 글자 수준 규칙은 01, 값으로서의 성질은 02.

## 에러 번호

E0701 `task cancelled` (취소된 태스크의 내부 되감기용, 사용자에게 보이지 않음), E0702 `deadlock: all tasks are waiting`,
E0703 `atom swapped inside its own swap`.

## fung으로 쓰는 것의 자리

`prelude.fung`(06): `fan_in(chs)`, `pmap(xs, f, limit = 0)`(0은 제한 없음), `retry(f, times = 3, delay = 0ms)`(`f`가 `Err`를 돌려주면
`delay`만큼 쉬고 다시, 마지막 `Err` 반환).

## 출력과 공유 상태

- `print` 한 번은 한 번의 write이고 출력 writer는 뮤텍스로 감싼다: 태스크 둘이 동시에 찍어도 줄이 섞이지 않는다.
- 모듈 초기화는 모듈당 뮤텍스로 **한 번만** 일어난다 (두 태스크가 같은 모듈을 처음 import해도 안전).
- REPL에서 태스크가 도는 중에 전역을 재정의하는 것은 정의하지 않는다 (08).

## 구현 메모

- VM 상태(스택, 호출 프레임)는 태스크별로 분리한다. 모듈·상수는 불변이라 공유한다.
- Go로 만든 함수(`map` 등)가 사용자 람다를 다시 부를 때는 같은 태스크의 VM을 쓴다.
- GUI를 위해 운영체제 메인 스레드를 비워둔다. fung 코드는 처음부터 별도 고루틴에서 실행한다.
- 웹서버는 요청마다 런타임이 태스크를 띄운다. 핸들러는 평범한 함수.

## Rust 구현에서 바뀌는 것 (2026-10-14 결정)

- **`atom` 제거.** 공유되는 변경 칸을 없앤다. 상태는 그 상태를 쥔 태스크가 들고, 다른 태스크는 채널로 편지를 보낸다. 이 패턴은 fung
  라이브러리로 감싼다. Go 버전(0.x)에는 남아 있다.
- **채널에 그 채널 자신을 보내면 에러.** 참조 계수로 메모리를 회수하는 구현에서 순환을 막기 위해서다. 보낼 쪽이 모두 사라진 채널은 자동으로 닫힌다.
- 런타임은 Erlang VM식이다: 태스크마다 힙을 따로 두고 경계에서만 값을 복사한다(불변 값이라 프로그램은 차이를 볼 수 없다).
  자세한 내용과 이유는 open-questions의 "Rust 이전".
- **3a(2026-10-15, Go와 같은 의미)**: 태스크마다 운영체제 스레드 하나, fung 코드는 실행권 잠금을 쥔 스레드만 돌린다(그린 스레드·태스크별 힙은 뒤로).
  꺼내지 않은 실패는 마지막 핸들이 사라지는 순간 보고하고(Go는 GC 때), 교착은 집계가 정확해 50ms 유예 없이 바로 판정한다. 출력은 Go와 같다.
  설명은 `docs/notes/R3a-runtime.md`.
