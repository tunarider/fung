# 01. 문법

규범은 매뉴얼 언어 명세(`manual/reference/language/`)이고, 이 문서는 결정의 기록이다.

## 문장과 블록

- 문장 구분: 줄바꿈 또는 `;`
- 블록 시작: `:`, 블록 끝: `;;`
- 들여쓰기는 의미 없음. 한 줄로도, 여러 줄로도 쓸 수 있다.
- 빈 문장은 허용한다: `a; ;;`, `;a`, 빈 줄 모두 괜찮다.
- `;;`는 렉서가 항상 가장 길게 자른다. `a;;`는 `a` + 블록 끝, `;;;`는 블록 끝 + 빈 문장, `;;;;`는 블록 끝 둘.

```
fn myfun(a, v):
  somefn(a)
  somefn(v)
;;

# 같은 코드
a = 1; v = 2; fn myfun(a, v): somefn(a); somefn(v); ;;
```

### `:`의 두 역할

`:`는 블록 시작이기도 하고, 괄호 안에서는 구분자(이름 붙인 인자 `f(dir: ".")`, 맵 키 `{name: 1}`,
타입 표기 `fn f(a: int)`)이기도 하다. 렉서는 구분하지 않고 **파서가 문맥으로 정한다.**
`if`, `else`, `fn` 시그니처, `match` 대상, `for … in …`, `test "이름"` 뒤의 `:`만 블록 시작이다.
반환 타입을 `->`로 쓰는 이유도 `fn f() -> int:`에서 `:`와 겹치지 않게 하기 위해서다.

## 식과 문장

00의 "모든 것은 식"은 정확히는 **값을 만드는 구문은 모두 식이며, 문장 자리와 식 자리를 구분하지 않는다**는 뜻이다.

| 종류 | 구문 |
|------|------|
| 식 (값을 만든다) | 리터럴, 이름, 연산자 식, 호출, 인덱스·필드, 람다, 익명 함수, 블록 `if`, `then … else`, `match`, `for`, `return` |
| 문장 (값을 만들지 않는다) | `fn` 정의, `import`, `type`, `test`, `assert`, 대입 |

- **대입은 문장이다.** `y = x = 1`, `if x = f(): …`는 문법 에러. `=`와 `==` 혼동을 문법 단계에서 막는다.
- `return`은 문장이거나 가지의 끝(`if`·`match` 절의 본문, `then … else`의 가지, `fn f() = …`의 본문)에만 온다(SP43, 결정 D50, 2026-11-11).
  피연산자·인자·원소·대입의 오른쪽·괄호 안의 `return`은 E0132이고, 같은 블록에서 `return` 문장 뒤의 문장은 결코 돌지 않으므로 E0131이다.
  전에는 `return`이 어느 식 자리에나 오는 "절대 돌아오지 않는 식"이라 `x = 1 + return a`, `[a, return 2]`가 통과했다.
- **블록의 값**: 마지막 항목이 식이면 그 값, 문장이면 `nil`. `else` 없는 `if`가 거짓이면 `nil`.
  다만 **값을 쓰는 자리**에서는 이 `nil`이 조용한 버그라 컴파일 에러다(L3, 2026-10-20): `else` 없는 블록 `if`는 E0223,
  대입으로 끝나는 블록·`if` 가지·`match` 절은 E0224(전에는 경고 W0104). `nil`이 의도라면 `else: nil`처럼 쓴다.
  **값을 쓰는 자리의 블록은 식으로 끝나야 한다**(FE4, 2026-11-08, 사용자 결정): 빈 블록(`else: ;;`, `fn f(): ;;`)과 `assert`·이름 있는 `fn` 정의로 끝나는 블록도 E0224다(FE4가 붙인 E0231은 2026-11-10 SP24에 E0224로 합침, 결정 D33).
  패턴 매개변수를 푸는 숨은 대입(`fn f((a, b)): …`)은 본문의 문장으로 세지 않는다. 함수 본문의 끝도 값 자리이므로 효과만 내는 함수가 `assert`로 끝나면 끝에 `nil`을 쓴다.
  `fs.with_temp_dir(fn(d): … ;;)`처럼 콜백의 값을 돌려주는 함수에 넘긴 본문도 같다. 기각: 빈 블록만 막기(`assert`·`fn` 정의가 예외로 남는다),
  바깥 호출의 값을 버리면 콜백 본문을 값 자리로 보지 않기(`http.serve(addr, handler)`처럼 바깥 값은 버려도 콜백의 값은 쓰이는 경우를 놓친다).
- **값을 쓰는 자리**: 대입의 오른쪽, 호출 인자, `return`, 연산자 피연산자(`then`·`??` 포함), 리스트·맵·튜플·태그의 원소, 문자열 보간,
  인덱스·필드, `assert`, 매개변수 기본값, 함수 본문의 끝(`fn f() = 식`, 람다 `=>`, 블록 본문 `fn f(): … ;;` 모두), 값 자리의 `for` 본문,
  그리고 이런 자리에 있는 블록·`if` 가지·`match` 절의 끝.
  함수 본문의 끝은 반환값이다. 값을 쓰는지는 호출하는 쪽만 알기 때문에, 정의하는 쪽에서는 쓰는 자리로 본다(L2, 2026-10-27). 그래서 아무것도 돌려주지 않는 함수가
  `if`로 끝나면 `else: nil`로 맺고, 대입이나 문장 `for`로 끝나면 마지막 줄에 `nil`을 둔다. `each`·`with`의 `release`처럼 결과를 버리는 내장 함수에 넘긴 람다도 같은 규칙을 따른다(정적 판정은 받는 쪽을 모른다).
  `each(xs, fn(x): … ;;)` 대신 `for x in xs: … ;;` 문장을 쓰면, 문장 `for`의 본문은 값을 쓰는 자리가 아니라서 끝의 `if`에 `else`가 필요 없다.
  아닌 곳: 버려지는 자리(아래), `test` 블록 본문의 끝(`fung test`가 그 값을 버린다), REPL 입력의 끝.
- **버려지는 자리**: 값을 아무도 쓰지 않는 자리다. 블록의 마지막이 아닌 식, 버려지는 자리에 있는 블록·`if`·`match` 가지의 마지막 식,
  파일 최상위의 마지막 식(REPL은 값을 출력하므로 아님), `each`가 받은 `f`, `with`의 `release`, `supervise`의 `on_fail`이 돌려준 값, `test` 블록이 돌려준 값.
  함수 본문의 마지막 식은 반환값이라 버려지지 않는다.
  버려지는 값이 `Err`면 런타임 에러 E0606이다. 버려지는 값이 리스트면 그 원소도 본다(02 "버려지는 Err"). 그래서 `for`로 끝나는 함수를 문장으로 불러도 `Err`가 사라지지 않는다. 일부러 버릴 때는 `_ = 식`.
  버려지는 자리의 효과 없는 식(이름, 리터럴, 람다·익명 `fn`, 부분 적용, 그것들만으로 된 연산자·필드·인덱스·튜플·리스트·맵·태그 값)은 컴파일 에러 E0234다(FE24, 2026-11-10, 결정 D5).
  괄호를 잊은 호출, `=` 대신 쓴 `==`, 앞 줄을 이으려던 줄 앞의 `-`가 조용히 사라지지 않게 한다. 맨 `nil`은 "아무것도 하지 않음"이라 받는다(문장 `match`의 `_ => nil`).
  효과가 없다고 알려진 내장 함수·표준 모듈 함수의 문장 호출도 E0234다(SP31, 2026-11-11, 사용자 결정 D39: `put(m, k, v)`가 `m`을 바꾼다고 여긴 실수).
  목록은 E0707의 효과 표(`vm/atom.rs`의 `EFFECTS`·`PURE`)에서 뽑는다: 순수한 것 가운데 하는 일 때문에 부르는 것(`each`와 `scope`·`timeout`·`with`·`supervise`)과 일부러 에러를 내는 것(`fail`, `_native.arg`의 검사)을 뺀다(`has_no_effect`).
  함수를 받아 값을 계산하는 것(`map`·`filter`·`fold`·`find`·`any`·`all`·`sort_by`·`group_by`·`try_map`)의 문장 호출도 E0234다(2026-11-13, 사용자 결정 D90: 부수효과 순회는 `each`와 문장 `for`가 맡는다. 전에는 "무엇을 할지 모르므로" 뺐다).
  `spec/builtins.txt`가 그런 함수 줄 끝에 `pure`를 적고, resolve가 호출 대상이 컴파일 때 정해지는 호출(D43과 같은 판정: prelude, 모듈 멤버, 그 별칭)에서 이 표시를 본다.
  fung으로 쓴 prelude 함수(`take`·`first` 등)도 명시 목록(`PURE_FUNG`)으로 같은 표시를 받는다(VA47, 2026-11-13). 사용자 함수는 무엇을 할지 모르므로 해당하지 않는다.
  `test` 블록의 본문은 끝까지 버려지는 자리다(`fung test`가 값을 버린다): 끝의 `for`는 리스트를 만들지 않는 순회다(D90과 함께).

## 줄 이어짐 규칙

줄바꿈은 문장 끝이지만, 다음 둘 중 하나면 이어지는 줄로 본다(셋째 규칙은 D85로 바뀌었다).

1. **줄이 식을 끝낼 수 없는 토큰으로 끝날 때**: 모든 이항 연산자
   (`+ - * / // % ** == != < > <= >= in ?? |> .. ..= and or`), `not`, `,`, `=`, `=>`, `->`, `.`,
   패턴 대안과 타입 유니온의 `|`, `for` 머리의 `in`, 여는 괄호 `( [ {`, 블록 시작 `:`(FE7, 2026-11-08: `in`·`|`가 빠져 있던 것을 고침).
2. **다음 줄이 이어짐 전용 토큰으로 시작할 때**: `|>` `.` `??` `and` `or` `then` `else`.
   이 토큰들은 문장을 시작할 수 없으므로 모호함이 없다 (`.5` 같은 숫자를 불허한 이유).
3. ~~괄호 안의 줄바꿈은 공백~~ → **괄호 안에서도 식은 위의 두 규칙으로만 줄을 넘는다**(D85, 2026-11-13, 사용자 결정). `( ) [ ] { }` 안의 줄바꿈은 원소 사이와 여닫는 괄호 옆에서 공백이다.
   전에는 괄호 안의 모든 줄바꿈이 공백이라, 쉼표를 빠뜨린 `[1\n -1]`이 `[0]`, `[a\n [1]]`이 인덱스, `[f\n (3)]`이 호출이 되었다. 이제 E0112(쉼표나 닫는 괄호가 와야 한다)다.
   괄호 안에서 `fn(f):`처럼 블록이 열리면 그 `;;`까지는 줄바꿈이 다시 문장 구분자다. 패턴의 괄호, 람다 매개변수 목록, `import m (a, b)`의 목록 안의 줄바꿈은 원소 사이라 그대로 공백이다.
   `xs[1..` 다음 줄 `]`는 괄호 옆이라 그대로 된다. `not` 다음 줄 `in`은 규칙 1이라 괄호 밖에서도 된다(FE66). 한 원소 안의 두 토큰 사이는 같은 줄이어야 한다(FE6의 "괄호 안 어디서나 공백"을 뒤집음): 람다의 `=>`는 매개변수의 줄에(`=>`로 끝난 줄은 규칙 1로 이어진다), 태그의 `(`는 태그의 줄에(식과 패턴 모두, `[Ok\n(1)]`은 에러), 이름 인자의 `:`는 이름의 줄에.
4. **앞 문장의 다음 줄은 `-`로 시작할 수 없다**(E0136, D85): `-`는 이어짐 전용 토큰이 아니라, 앞 줄을 이으려던 `- 2`는 새 문장이 되고 앞 줄은 버려진다. 앞 줄이 호출이면 E0234도 잡지 못했다.
   파일·블록의 첫 문장, 여는 것과 같은 줄의 문장, `;` 뒤의 문장은 이을 앞 줄이 없어 된다(결정문 "문장은 `-`로 시작할 수 없다"를 구현하며 좁힘: 글자 그대로면 `_ => -1`과 REPL의 `-1`까지 막힌다).

```
sizes = fs.list("./logs")
  |> filter(is_log)
  |> map(f => fs.size(f))

ok = fs.exists(p)!
  and not is_dir(p)
```

줄바꿈 처리는 렉서가 아니라 **파서가** 한다. 렉서는 줄바꿈 토큰을 그대로 내보내고,
파서가 "호출 인자 안이면 무시"처럼 문맥에 따라 건너뛴다 (09. 구현 계획).

## 글자 수준 규칙

### 식별자

- 식별자는 유니코드 표준 UAX #31을 따른다: `XID_Start` 글자나 `_`로 시작하고, `XID_Continue` 글자(글자·숫자·결합 문자·`_` 등)가 이어진다.
  이름은 **NFC로 정규화**한다: 조합형 `é`(U+00E9)와 분해형 `é`(`e` + U+0301)는 같은 이름이다(UAX #31 권고, macOS 파일 이름처럼 분해형으로 온 글자를 위해).
  소스의 바이트는 그대로 두므로 포매터는 쓴 대로 남긴다. 문자열은 정규화하지 않는다(값이므로). 심볼 리터럴(`'name`), `sym(s)`, import 경로에서 나온 모듈 이름은 이름이라 정규화한다.
  **맵 키 자리의 식별자는 이름이 아니라 문자열이라 정규화하지 않는다**(L8, 2026-10-20): `.` 뒤(`m.k`), 맵 리터럴 키(`{k: 1}`), 맵 패턴 키(`{k: v}`).
  그래서 `m.k`는 쓴 그대로 `m["k"]`다. 축약 `{k}`·`{k} = m`은 키가 쓴 그대로, 변수 이름은 NFC다. `.` 뒤가 모듈 멤버면(`fs.read`) 이름이라 NFC로 찾는다.
  기각: 문자열 키도 NFC로 바꾸기(값을 바꾼다; 파일 이름 같은 키의 바이트가 망가진다).
  첫 글자가 **유니코드 대문자**(일반 범주 Lu)면 태그 (02. 값과 타입), 그 밖은 이름.
- 유니코드 글자를 허용한다. `파일목록 = fs.list(".")`, `हिंदी = 1`(모음 기호 같은 결합 문자가 이어짐). 한글은 대소문자가 없으므로 항상 이름이다.
- 판정 표는 `spec/unicode.txt`(Unicode 17.0.0)다. 유니코드 문자 데이터베이스의 `UnicodeData.txt`·`DerivedCoreProperties.txt`가 있는 디렉터리를 주고
  `FUNG_UPDATE_SPEC=1 FUNG_UCD=<디렉터리> cargo test -p fung-front unicode_spec_file`로 다시 만든다(정규화 데이터 `spec/unicode_nfc.txt`도 같은 명령, `CompositionExclusions.txt`·`EastAsianWidth.txt`, 글자 묶음 표에는 `GraphemeBreakProperty.txt`·`emoji-data.txt`, 시험에는 `GraphemeBreakTest.txt`가 더 필요; 모두 한 디렉터리에). 같은 표의 "보이는 글자"(L·M·N·P·S와 U+0020)가
  문자열을 보일 때 이스케이프하지 않는 글자다.
- **화면의 칸**(L17, 2026-11-08): fung이 칸을 세는 곳(포매터의 정렬, 진단의 밑줄, REPL의 커서)은 모두 **글자 묶음**(grapheme cluster, UAX #29의 확장 묶음) 단위로,
  같은 함수 하나(`fung_front::unicode::cluster_width`)로 센다. 묶음 하나의 너비: VS16(U+FE0F)이 있거나 첫 글자가 `Emoji_Presentation`이거나 국기(지역 표시 글자 쌍)면 2칸,
  VS15(U+FE0E)가 있으면 1칸, 그 밖에는 첫 글자의 UAX #11 너비(`wide`: East Asian Width W·F는 2칸; `zero`: Mn·Me·Cf(U+00AD 빼고), 한글 중성·종성 자모, 피부색 수식은 0칸, 그 밖은 1칸).
  그래서 ZWJ로 이은 가족 이모지는 2칸, `❤️`는 2칸, `é`(분해형)는 1칸, 한글 자모 조합은 2칸이다. 잘못된 UTF-8 부분은 1칸.
  묶음 단위로 그리는 요즘 터미널(iTerm2·WezTerm·kitty·Ghostty 등)과 맞고, 코드 포인트 단위(`wcwidth`)로 그리는 터미널과는 이모지에서 다르다(그것은 한계로 둔다).
  `len`·`s[i]`·`chars`는 묶음이 아니라 글자(코드 포인트, L4의 규칙)다: 표시와 별개의 언어 규칙이다.
- 렉서는 첫 글자만 본다. `myVar` 같은 camelCase는 문법 에러가 아니고 검사하지도 않는다(snake_case는 규약).

| 정수 | `42`, `1_000_000` | `_`는 숫자 사이에만 |
| 실수 | `3.14`, `2.5e-3`, `1e9` | 소수점 양쪽에 숫자 필수 (`.5`, `1.` 불허). 지수가 있으면 항상 실수 |

- 10진 정수 바로 뒤의 `.`가 소수부(숫자)도 범위(`..`)도 아니면 E0102다(FE2, 2026-11-08): `1.`, `1.e5`, `1.foo`. 정수에는 필드가 없고,
  줄 끝의 `1.`이 다음 줄의 이름을 필드로 삼키지 않게 한다(`x = 1.` 다음 줄 `print(x)`가 `1.print(x)`로 읽히던 것).
| 진법 | `0xff`, `0o17`, `0b1010` | 정수 |

- 정수 리터럴의 범위는 64비트 부호 있는 정수. 넘으면 컴파일 에러. 진법 리터럴도 같다(`0xffffffffffffffff`는 에러). 가장 작은 정수의 특례도 진법에 같다(`-0x8000000000000000`; FE31, 결정 D9, 2026-11-10, 전에는 에러).
- 접두사와 지수는 소문자만이다(`0XFF`·`0O17`·`0B1`·`1E5`는 E0102, 도움말이 소문자 모양을 보인다; SP27, 결정 D32, 2026-11-10). 같은 일을 하는 표기를 하나로 두고, `0O`처럼 `0`과 헷갈리는 모양을 없앤다.
  16진 숫자도 소문자만이다(`0xFF`는 E0102, 도움말 `0xff`; SP49-5, 결정 D56, 2026-11-11). 문자열 이스케이프(`\xFF`, `\u{1F600}`)는 숫자 리터럴이 아니라 그대로 둔다.
- 0이 아닌 실수 리터럴이 아래로 넘쳐 0.0이 되면 위로 넘칠 때처럼 E0102다(`1e-400`; FE31, 결정 D9). 비정규 수(`5e-324`)는 0이 아니라 된다.
- **10진 숫자는 0으로 시작하지 않는다**(FE1, 2026-11-08, 사용자 결정). 두 자리 이상인 정수, 실수의 정수부, 기간의 숫자가 `0`으로 시작하면 E0102이고,
  도움말이 8진수 `0o755`를 권한다. `0`, `0.5`, `0s`, `0x…`·`0o…`·`0b…`는 된다.
  셸(`chmod 0755`)과 C 계열 언어에서 `0755`는 8진수라, 10진수 755로 읽으면 `perm: 0444` 같은 권한이 말없이 틀린다. 8진수로 읽지 않는 것은 `0o`와 같은 일을 하는 길이 둘이 되기 때문이다(Python 3와 같음).
- 예외: 가장 작은 정수 `-9223372036854775808`은 렉서가 크기 `9223372036854775808`을 거부하기 전에
  파서가 `-` 바로 뒤의 이 값만 특례로 접어 허용한다 (Go·Rust·Java와 같음). M2에서 구현.

### 문자열

- `"…"`: 보간 `${…}`과 이스케이프 지원. 실제 줄바꿈은 에러 (여러 줄은 원시 문자열 또는 `\n`). `${…}` 안의 코드도 따옴표 안이므로 줄바꿈은 에러다.
  줄 끝이나 파일 끝의 `\`는 아무것도 이스케이프하지 않으므로 닫히지 않은 문자열(E0104)이다(FE14).
- 이스케이프는 `\n` `\t` `\r` `\\` `\"` `\$` `\u{1F600}` `\xHH` **만**. 모르는 이스케이프는 컴파일 에러
  (`"C:\new"` 같은 함정을 잡는다). `${`를 글자 그대로 쓰려면 `\$`.
- `$` 바로 뒤가 이름의 첫 글자면 E0129다(SP40, 결정 D47, 2026-11-11): `"$name"`은 셸과 다른 언어에서 보간이라 값이 들어간 줄 알기 쉽다.
  값은 `${name}`, 글자는 `\$name`. 그 밖의 `$`(`"$5"`, 끝의 `$`)는 글자로 둔다. 기각: 모든 맨 `$`를 막기(무해한 `"$5"`까지 막는다). 원시 문자열은 그대로이고, 셸 명령은 원시 문자열로 쓴다.
- `\xHH`(16진수 꼭 두 자리)는 **바이트 하나**다(L4, 2026-11-07): `"\xe9"`는 글자 `é`가 아니라 바이트 0xE9, `"\xc3\xa9"`가 UTF-8로 `é`다.
  그래서 UTF-8이 아닌 문자열도 리터럴로 쓸 수 있고, 값의 표시(`"a\xff"`)를 그대로 다시 읽을 수 있다. 기각: `\xHH`를 U+0000~U+00FF 글자로(Python·JS),
  표시한 값이 같은 바이트로 다시 읽히지 않는다.
- 소스 파일과 `-e`의 코드는 UTF-8이어야 한다(L4). 아니면 실행·검사·가져오기가 읽기를 거절한다(진입 파일은 ``cannot read `x.fung`: not valid UTF-8 at line L, column C``,
  가져온 모듈은 E0312). 잘못된 바이트를 U+FFFD로 바꿔 읽으면 아무도 쓰지 않은 글자가 프로그램에 말없이 들어간다(원칙 1). 포매터도 같은 읽기로 그런 파일을 거절한다(건드리지 않음).
- 보간 `${…}` 안에는 어떤 식이든 올 수 있고 따옴표도 중첩 가능: `"${m["k"]}"`.
- `` `…` ``: 원시 문자열. 이스케이프·보간 없음, 여러 줄 가능, `` ` `` 자체는 넣을 수 없다 (Go와 같음).
  안의 `\r\n`은 값에서 `\n`이다(FE58, 결정 D58, 2026-11-11): 같은 소스를 LF와 CRLF로 저장해도 값이 같다. 홀로 선 `\r`은 전처럼 받는다(아래).
- `'`는 심볼 전용이라 문자열에 쓰지 않는다.

### 기간

- `500ms`, `30s`, `1.5s`, `1h30m`. 단위 `ms` `s` `m` `h`.
- 복합은 큰 단위부터 내림차순. 소수점은 마지막 성분에만(`1h30.5m`은 되고 `1.5h30m`은 E0105; FE31, 결정 D9, 2026-11-10, 전에는 어느 성분이든).
- 모든 성분이 10진 정수의 앞자리 0 규칙을 따른다(`1h05m`은 E0105; 첫 성분 `05m`은 전처럼 E0102).
- 0이 아닌 성분이 나노초로 반올림해 0이 되면 E0105다(`0.0000004ms`; 전에는 말없이 `0s`).
- 숫자 **바로 뒤에** 단위가 붙어야 한다. `30 s`는 숫자와 이름 `s`.

### 심볼, 주석

- 심볼: `'ok`, `'not_found`. `'` 뒤에 이름 모양의 식별자(예약어도). 대문자로 시작하는 심볼은 인자 없는 태그 `Red`로만 쓴다:
  `'Red`는 같은 값의 둘째 표기라 E0128이다(SP33, 결정 D41, 2026-11-11). `sym(s)`는 태그 모양의 글도 받는다(SP4, 2026-11-08, 사용자 결정):
  바깥 글 `"Red"`를 열거형 타입(07 T1)의 값으로 바꾸는 길이 `sym`이다.
- 맨 `Ok`·`Err`(값 0개)는 식에서도 패턴에서도 E0236이다(SP33, 결정 D41): 결과값은 값을 꼭 하나 담는다(11-10 D2). 파이프의 오른쪽 `x |> Ok`만 파이프가 값을 채우므로 된다.
  그래서 심볼 `Ok`·`Err`에는 리터럴이 없다(`type_of(Ok(1))`이 돌려주는 값이고, 결과값인지는 `is_ok`·`is_err`·`match`로 가린다).
- 주석: `#`만. (`//`는 정수 나눗셈이고, 같은 일을 하는 방법은 하나로.) shebang `#!/usr/bin/env fung`은 자연히 주석이다.
- 줄 끝은 `\n`이나 `\r\n`이다. 그 밖의 홀로 선 CR(`\r`)은 문자열·원시 문자열 안이 아니면 E0101이고, 주석 안에서도 그렇다(FE13, 2026-11-08, 사용자 결정).
  터미널은 CR 뒤의 코드를 주석 위에 덮어 그리고 편집기는 두 줄로 그려서, 어느 쪽도 렉서의 읽기(같은 줄)와 맞지 않기 때문이다.
- 같은 까닭으로 양방향 제어 문자(U+202A~U+202E, U+2066~U+2069)는 주석과 문자열(원시 문자열 포함) 안에서도 E0101이다(FE59, 결정 D59, 2026-11-11, "Trojan Source").
  문자열에 필요하면 `\u{202E}`로 쓴다.
  에러 발췌는 줄의 제어 문자를 이스케이프(`\r`, `\u{1B}`)로 보인다.

## 이름 표기

- 변수·함수·모듈 이름은 **snake_case**: `is_log`, `read_config`, `cache_ttl`
- 대문자로 시작하는 이름은 태그 전용 (02. 값과 타입). 변수를 묶는 자리에 오면 컴파일 에러 E0225다(L4, 2026-10-20):
  맵 축약 `{HOME} = cfg`·`{HOME}`, 왼쪽 전체가 태그 하나인 대입 `MAX_RETRIES = 3`. 대문자 키는 된다: `{HOME: home} = cfg`, `cfg.HOME`.
  태그가 패턴의 일부인 구조 분해(`Ok(x) = r`, `(Red, x) = p`)는 그대로다.
- `_`로 시작하는 이름은 비공개 (04. 모듈 체계)

## 함수

```
fn report(dir):                        # 여러 줄 함수
  ...
;;

fn add(a, b) = a + b                   # 식 하나짜리 짧은 함수

fn is_log(name: str) -> bool = ...      # 인자 타입 `:`, 반환 타입 `->`

files |> map(f => fs.size(f))          # 람다
spawn(s, () => work())                 # 인자 없는 람다
fold(xs, 0, (acc, x) => acc + x)       # 인자 여러 개 람다

files |> map(fn(f):                    # 여러 줄 익명 함수
  s = fs.size(f)
  s // 1024
;;)
```

### 람다

- `x => 식`, `(a, b) => 식`, `() => 식`. 본문은 식 하나이며 가능한 한 길게 읽는다 (`then`보다도 낮은 우선순위).
- 인자는 이름 또는 **패턴**(`((a, b)) => a + b`, `(Ok(x)) => x`, `_ => 0`). 기본값·타입 표기는 없다.
  `(a, b) => …`의 바깥 괄호는 인자 목록이다(인자 둘); 튜플 하나를 받으려면 `((a, b)) => …`. 맞지 않으면 E0602.
- 여러 문장, 기본값, 타입 표기가 필요하면 익명 함수 `fn(x): … ;;`. 람다 블록 `x => : … ;;`은 없다.
- 익명 함수는 블록 형태만 있다. `fn(x) = …`는 람다와 겹치므로 없다.
- `(a, b) => …`는 파서가 괄호식을 읽은 뒤 `=>`를 보면 인자 목록으로 다시 해석한다.

## 조건

```
# 여러 줄 블록: if-else 체인 전체를 ;; 하나로 닫는다
if n > 0:
  "양수"
else if n < 0:
  "음수"
else:
  "0"
;;

# 한 줄 값: then 연산자
label = n > 0 then "양수" else "음수"
label = n > 0 then "양수" else n < 0 then "음수" else "0"
```

- `then`은 대입 `=` 다음으로 우선순위가 낮다. 조건의 괄호는 선택.
- `then`을 쓸 때 `else`는 필수. 블록 `if`도 값을 쓰는 자리에서는 `else`가 필수다(E0223, "식과 문장").
- 삼항 연산자 `c ? a : b`는 `?`(에러 전파), `:`(블록 시작)와 충돌해서 채택하지 않음.

## match

```
match fs.read("a.json"):
  Ok(text) =>
    lines = split(text, "\n")
    len(lines)
  Err(e)   => print("실패: ${e}"); 0
;;

match x: 0 => "zero"; _ => "other" ;;      # 한 줄도 된다
```

- 절은 `패턴 [when 조건] => 본문`. **본문은 다음 절이 시작되거나 `;;`가 나올 때까지의 문장들**이다.
- 파서는 `match` 안에서 각 문장 시작마다 "`패턴 =>`로 읽히는가"를 먼저 시도한다. 되면 새 절, 안 되면 현재 절의 문장.
- 대가: 절 본문 안의 람다 단독 문장(`x => x + 1`)은 새 절로 읽힌다. 절의 값인 람다는 괄호로 감싼다(`1 => (y => y + 1)`).
  이렇게 읽힌 절은 모든 값에 맞으므로 뒤에 절이 있으면 E0235로 드러난다(아래).
- guard 없는 절의 패턴이 모든 값에 맞으면(`_`, 맨 이름, 그런 갈래가 하나라도 있는 `|` 대안, 예: `1 | _`) 뒤의 절은 돌 수 없으므로 컴파일 에러 E0235다(FE25, 2026-11-10, 결정 D6).
  맨 이름이 바깥 변수와 같으면 guard로 비교하라는 도움말을 붙인다(패턴의 이름은 늘 새로 묶는다).
  guard 없는 앞 절이 이미 맞는 리터럴(쓴 그대로 같은 것, 앞 절의 `|` 대안 하나여도)을 패턴으로 쓴 절도 E0235다(SP44, 결정 D51, 2026-11-11). 에러는 돌지 않는 뒤 절을 가리킨다.
- `when` 조건의 맨 바깥에서 `이름 =>`·`(이름들) =>`는 람다가 아니라 절의 화살표다 (`y when y == x => …`).
  조건 안에서 람다가 필요하면 괄호 안(호출 인자 등)에 쓴다: `n when any(xs, x => x > n) => …`.
- 패턴 목록은 03. 함수와 패턴 매칭.

## 변수와 재할당

- 같은 이름 재할당 허용. 값을 바꾸는 게 아니라 이름을 새 값에 다시 붙이는 것 (Elixir 방식).
- 데이터 내부 변경은 불가 (`list.push`, `user.name = ...` 없음). 수정된 사본을 만든다.
  - 사본은 `put`/`merge`/`remove` 함수로 만든다 (02).
- **블록 안에서 바깥 변수 이름에 재할당하면 컴파일 에러.** 아래 코드가 조용히 0을 출력하는 함정을 막기 위함.

```
total = 0
for f in files:
  total = total + fs.size(f)   # 에러: fold / sum 을 쓸 것
;;

total = files |> map(f => fs.size(f)) |> sum   # 올바른 방법
```

- 구조 분해 대입 `(q, r) = divmod(7, 2)`는 "패턴 = 식" 문장이다. 파서는 문장 시작에서 `패턴 =`를 먼저 시도하고,
  실패하면 식으로 읽는다 (`match` 절과 같은 기법).
- 클로저는 만들어진 시점의 값을 붙잡는다.

## for

- `map`의 문법 설탕. 결과로 리스트를 돌려준다.
- **버려지는 자리의 `for`는 `each`처럼 돈다**(L1, 2026-10-20): 리스트를 만들지 않고, 본문의 마지막 식도 버려지는 자리가 되어
  본문이 내는 `Err`가 E0606이 된다. 값 자리(대입의 오른쪽, 인자, 함수 본문의 마지막 식)의 `for`는 그대로 리스트를 만든다.
- `while`처럼 상태 변화에 의존하는 루프는 없다 (00. 기본 컨셉: 상태가 있는 반복은 꼬리 재귀).

```
for (k, v) in pairs(config):
  print("${k} = ${v}")
;;
```

## 파이프

- `x |> f(a)`는 `f(x, a)`. 파이프 대상은 **첫 번째 인자**로 들어간다 (Elixir 방식).
- 끼워 넣는 것은 오른쪽이 **괄호 없이 쓴 호출·태그**일 때뿐이고, 그 밖의 식은 값을 구해 부른다(FE27, 결정 D7, 2026-11-10).
  괄호는 트리에 남는 묶음이라 `x |> (mk(10))`은 `mk(10)(x)`, `5 |> (scale(2, _))`는 `scale(2, _)(5)`(E0227 아님)다. 전에는 괄호가 사라져 괄호 친 호출에도 끼워 넣었다.
  `x |> (Ok)`는 괄호 안의 심볼 값을 부르는 E0401이다(태그 모양은 괄호 없는 `Ok`). E0227의 도움말은 괄호 친 부분 적용 `x |> (f(1, _))`를 먼저 권한다.
- 오른쪽이 태그여도 같다(L6, 2026-10-20): `x |> Ok`는 `Ok(x)`, `x |> Pair(2)`는 `Pair(x, 2)`. 태그의 `Ok(x)`는 호출 형태이기 때문이다.
  태그는 파서가 태그로 읽은 것(대문자 Lu로 시작하는 맨 이름)만이다. 따옴표 심볼은 값이라 태그 자리에 오지 않는다(FE19, 2026-11-08: 전에는 첫 글자로 다시 짐작해 태그로 썼다). 대문자 심볼 리터럴 `'Ok`는 이제 쓸 수조차 없다(E0128, D41).
- 오른쪽 호출의 인자에 `_`(부분 적용)가 있으면 컴파일 에러 E0227이다(`3 |> h(_, 10)`은 `h(3, _, 10)`이라는 함수가 되던 함정).
  파이프 값은 늘 첫 인자다. 다른 자리에 넣으려면 `3 |> (v => h(10, v))`. 기각: 파이프 값이 첫 `_` 자리로 가기(규칙에 예외가 생긴다, 원칙 7).
  더 안쪽 호출의 `_`는 그대로 된다: `files |> map(path.join(dir, _))`.
- 오른쪽 끝에 후위 `?`·`!`가 있으면 컴파일 에러 E0229다(2026-10-24). 후위 연산자가 `|>`보다 세게 묶여 `xs |> try_map(f)?`는 `xs |> (try_map(f)?)`가 되기 때문이다. 우선순위는 그대로 두고 흔한 실수만 진단한다. 파이프 전체에는 `(xs |> try_map(f))?`.
- 표준 라이브러리 함수는 모두 "대상이 첫 번째 인자" 규칙을 따른다.

## 예약어

`fn` `if` `else` `then` `match` `when` `for` `in` `not` `and` `or` `return` `import` `as` `type` `test` `assert` `true` `false` `nil`

- **이름만 올 수 있는 자리에서는 예약어도 이름이다** (2026-10-14): `.` 뒤(`m.type`, `req.match`), 맵 리터럴 키(`{type: 1}`),
  맵 패턴 키(`{type: t}`). 그 자리에는 문법상 예약어가 올 일이 없어 모호함이 없고, JSON의 `type` 같은 흔한 키를 막지 않기 위해서다.
  변수·함수·매개변수 이름으로는 여전히 쓸 수 없다(`type = 1`은 에러).
- `with`는 예약어가 아니다 (맵 사본은 함수로, 02).
- `defer`는 없다. 자원 정리는 `with(acquire, use, release)` 하나로 (03).

## 형식 문법 (EBNF)

형식 문법은 매뉴얼 [`grammar.md`](../../manual/reference/language/grammar.md) 한 곳에만 둔다(2026-11-08 SP8: 두 벌이 서로, 그리고 파서와 어긋났다). 파서는 그 문법을 그대로 옮긴다. 아래는 문법을 정할 때의 결정이다.

문법에서 따라오는 것:

- 비교 연산자는 연쇄하지 않는다. `a < b < c`는 문법 에러이고 "`and`로 나누세요" 힌트를 붙인다.
- `not`은 비교보다 낮으므로 비교·산술·`??`·`..`·단항 `-`의 피연산자가 될 수 없다. `a == not b`는 문법 에러이고 `a == (not b)`로 쓴다(2026-10-20).
- 람다도 같다: 람다는 `expr` 층에만 있으므로 연산자의 피연산자 자리에서 괄호 없이 시작하면 E0110(도움말 "put the lambda in parentheses"; FE41, 2026-11-11). 전에는 `1 |> x => x + 1 |> str`의 람다가 뒤의 파이프를 모두 삼켰다.
- `??`와 `|>`를 괄호 없이 섞으면 E0127이다(SP28, 결정 D35, 2026-11-11). `x |> f ?? d`("파이프로 구한 뒤 기본값")와 `a ?? b |> f`("기본값을 채운 뒤 파이프")가 둘 다 자연스러워,
  어느 우선순위를 골라도 하나가 말없이 뒤집힌다(전에는 `??`가 먼저 묶여 `"x" |> env ?? "d"`가 `(env ?? "d")("x")`였다). 비교 연쇄(E0111)·`not`과 같은 "섞으면 괄호" 규칙이다. 기각: `??`를 `|>`보다 낮게(점검 문서의 추천, 매뉴얼 예 `Err(…) ?? "{}" |> json.parse`의 읽기가 뒤집힌다).
- `import`는 파일의 다른 모든 문장보다 앞에만 온다(뒤면 E0313; SP49-3, 결정 D55, 2026-11-11). 전에는 어디에 쓰든 끌어올렸다. 실행 순서가 코드의 모양과 같아지고 끌어올림 규칙이 사라진다.
- 인자 없는 태그 `Red`는 그대로 값(심볼)이고, `Ok(x)`는 TAG에 대한 호출 형태다.
- 슬라이스의 열린 끝(`s[..3]`, `s[4..]`)은 인덱스 안에서만 허용되는 특별 형태다.
- 슬라이스는 `[` 바로 안의 `..`·`..=`이고 두 끝은 다른 자리의 범위와 같이 `..`의 피연산자 층(`add`)이다(SP36, 결정 D36, 2026-11-11). 괄호 친 범위(`xs[(0..2)]`)나 더 안쪽의 범위는 범위 값 하나로 하는 인덱스다.
  끝의 맨 위가 `..`보다 약한 연산자(`??`, `|>`, 비교, `in`, `not`, `and`·`or`, `then … else`)면 E0125다(다른 자리에서는 `..`가 먼저 묶여 `a ?? 0..3`이 `a ?? (0..3)`이므로 괄호를 요구).
  11-10 D7은 `??`·`|>`까지 끝으로 받았는데(`xs[a ?? 1..b ?? 2]`), 그 근거("다른 자리에서는 `..`가 먼저 묶인다")와 스스로 어긋나 D36이 뒤집었다.
  `if` 조건·`match` 대상·`for` 순회 대상·`then` 가지 안의 `..`는 범위다.
  전에는 끝 자리가 `..`보다 강한 식만 받아 `xs[0..b ?? 2]`가 `(0..b) ?? 2`로 읽혔고, 괄호 친 범위도 슬라이스 문법이 되었다.
- 리스트 패턴의 `...rest`는 맨 끝에서만.
- `_` 부분 적용 자리는 호출 인자에서만 쓴다. `_ * 2` 같은 연산식에는 쓰지 않는다 (미결 사항이었음).
