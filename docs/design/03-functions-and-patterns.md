# 03. 함수와 패턴 매칭

## 반환

- 마지막 식의 값이 반환값.
- `return`으로 조기 반환도 허용 (스크립트에서 일찍 빠져나가는 용도).

```
fn process(path):
  if not fs.exists(path): return Err("없음") ;;
  ...
;;
```

### `return`이 돌아오는 곳

- 함수 본문, 그 안의 `if`·`match` 가지: 그 함수에서 돌아온다.
- 람다 `=>` 본문, 익명 `fn` 안: 그 람다에서 돌아온다.
- **`for` 본문 안의 `return`은 컴파일 에러.** `for`는 `map`의 설탕이라 본문이 사실은 람다이고,
  순진하게 두면 `return Err(f)`가 리스트의 원소가 되는 조용한 버그가 된다.
  힌트: "`for`는 값을 만드는 식입니다. 찾기는 `find`, 검사는 `all`/`any`, 누적은 `fold`를 쓰세요."
  같은 이유로 **`for` 본문 안의 `?`도 컴파일 에러**다 (`?`는 현재 함수, 즉 그 람다에서 `Err`를 돌려주므로
  `Err`가 조용히 리스트 원소가 된다). `match`로 처리하거나 `all`/`any`/`fold`를 쓴다.
- **진입 파일 최상위의 `return`도 컴파일 에러.** 힌트: `exit()`.
- 비지역 반환(람다 안에서 바깥 함수를 끝내기)은 채택하지 않는다. 여러 프레임 되감기가 필요하고,
  람다가 다른 태스크에서 불리면 정의할 수 없다.

## 자원 정리: `defer` 없음

`defer`는 제거했다. 이유:

- fung에는 런타임 에러를 잡는 구문이 없다 (런타임 에러 = 태스크 또는 프로그램 중단). 그래서 "에러 때도 실행"의 실익이 작다.
- `defer`는 프레임에 할 일을 매달아 두므로 꼬리 호출 최적화와 충돌한다.
- VM에 프레임별 defer 목록과 되감기 로직이 필요하다.

대신:

- **감싸는 함수**가 열고, 람다를 부르고, 반드시 닫는다. 표준 라이브러리가 fung 코드로 제공한다 (06):
  `fs.with_open`, `fs.with_temp_dir` 등. (`exec`의 작업 디렉터리는 `cwd:` 인자.) Haskell `bracket`, Ruby `File.open { }`과 같은 패턴.
- 프로그램 종료 시 정리는 `at_exit(f)`. 정상 종료, `exit()`, 에러 중단 모두에서 **등록의 역순**으로 실행된다.
  핸들러의 에러는 출력하되 다음 핸들러를 계속 실행하고, 종료 코드는 1이 된다.

```
fs.with_open(src, fn(f):
  first = read_line(f)?        # ?로 빠져나가도 with_open이 닫고 그 Err를 돌려준다
  fs.write(dst, first)
;;)
at_exit(() => fs.remove(tmp))
```

(본문이 문장 둘이라 람다 `f => …`가 아니라 익명 함수 `fn(f): … ;;`를 쓴다, 01.)

- 한계: 태스크 안에서 런타임 에러로 태스크가 죽으면 감싸는 함수의 정리는 실행되지 않는다.
  파일 핸들은 마지막 사본이 사라질 때 닫히므로(참조 계수) 스크립트 용도에선 받아들인다.
- 기각: `with f = fs.open(p)!: … ;;` 블록 문법 → "무엇을 어떻게 닫는가"를 언어가 알아야 해서 타입별 닫기 규약이 필요.

## 인자

```
fn greet(name, greeting = "안녕"):            # 기본값
fn sum(...nums):                              # 가변 인자 (리스트로 받음)
fn serve(port: int = 8080, dir = "."):
serve(dir: "./public")                        # 이름 붙인 인자
fn pad(s, width = len(s) + 2):                # 기본값은 앞 인자를 참조할 수 있다
```

- 정의 순서: 필수 → 기본값 있는 것 → 마지막에 `...rest` 하나. `...rest`는 기본값을 가질 수 없다.
- 기본값은 **호출할 때마다**, 왼쪽에서 오른쪽으로 평가한다. 앞의 인자를 참조할 수 있다.
- 호출: 위치 인자 먼저, 그 뒤에 이름 붙인 인자. 이름은 `...rest`를 제외한 어떤 인자든 가리킬 수 있다.
- 람다도 함수이므로 이름 붙인 인자를 받을 수 있다.
- 런타임 에러(코드 오류): 같은 인자를 위치와 이름으로 둘 다 줌, 모르는 이름, 필수 인자 누락, `...rest`가 없는데 위치 인자가 남음.
- 타입 표기 검사는 기본값을 채운 뒤 함수 진입 시점에, 반환 타입은 반환 시점에 (07).

## 평가 순서

- 항상 **왼쪽에서 오른쪽**: 호출 인자, 리스트·맵·튜플 리터럴의 원소, 이항 연산의 양쪽, 문자열 보간 조각.
- `and`, `or`, `then … else`, `??`는 단락 평가 (오른쪽은 필요할 때만).

## 패턴

```
match value:
  0                  => ...    # 리터럴 (음수 -1, 문자열, 심볼, 기간, true/false/nil 포함)
  'ok                => ...    # 심볼
  Ok(x)              => ...    # 태그
  (a, b)             => ...    # 튜플
  []                 => ...    # 빈 리스트
  [first, ...rest]   => ...    # 머리와 꼬리. 꼬리 이름은 생략 가능: [first, ...]
  {name: n}          => ...    # 맵 부분 매칭 (다른 키는 무시)
  x when x > 100     => ...    # guard
  'a | 'b            => ...    # 여러 패턴 중 하나
  _                  => ...    # 나머지 전부
;;
```

- 아무 패턴도 맞지 않으면 런타임 에러.
- 패턴 안의 이름은 **항상 새로 꺼내 담는다.** 바깥 변수와 비교하려면 guard를 쓴다.
- 대안 `|`가 이름을 묶으면 **모든 대안이 같은 이름들을 묶어야** 한다. 아니면 컴파일 에러.
- `when` 가드는 대안 전체에 걸린다: `'a | 'b when cond`.
- **괄호 없는 태그 패턴 `Ok`는 심볼 `'Ok`에만 맞고 `Ok(3)`에는 맞지 않는다.** 자주 밟는 함정이다.

```
match v:
  y when y == x => "x와 같음"
  _             => "다름"
;;
```

## 구조 분해 대입

대입의 왼쪽에도 같은 패턴 문법을 쓴다. 맞지 않으면 런타임 에러.
이름을 묶는 규칙은 **대입과 같다**: 같은 스코프의 재대입은 되고(`(a, b) = (b, a)`), 바깥 블록의 이름이면 E0205.
반면 `match` 절의 이름, `for`의 변수, **매개변수 패턴**(`fn f((a, b)) = …`, `((k, v)) => …`)의 이름은 새 이름이다(바깥 이름을 가린다).
매개변수 패턴은 호출 때 맞춰 보며 맞지 않으면 E0602다; 이름이 없으므로 이름 인자로 넘길 수 없다.
한 패턴 안에 같은 이름이 두 번 나오면(`[a, a]`) 컴파일 에러. "두 자리가 같다"는 guard로 쓴다(`[a, b] when a == b`).
`_ = 식`은 값을 평가하고 버린다 (`_`는 패턴의 아무거나).

```
(q, r) = divmod(7, 2)
[first, ...rest] = files
{name: n, port: p} = config
Ok(text) = fs.read("a.json")     # Err면 에러
```

## 여러 절 함수: 지원하지 않음

같은 이름의 함수를 패턴별로 나눠 정의하는 방식(Elixir, Haskell)은 채택하지 않는다.
대신 본문을 `match`로 바로 쓴다.

```
fn len(list) = match list:
  []           => 0
  [_, ...rest] => 1 + len(rest)
;;
```

## 꼬리 호출 최적화

00의 결정("상태가 있는 반복은 꼬리 재귀")의 전제 조건이다. 선택 기능이 아니다.

```
fn count(n, acc) = n == 0 then acc else count(n - 1, acc + 1)
count(1000000, 0)
```

### 꼬리 위치

여기 있는 호출만 프레임을 재사용한다 (VM에 꼬리 호출 명령).

- 함수 본문의 마지막 식, `= 식` 본문, 람다 본문.
- 꼬리 위치에 있는 `if`·`then … else`·`match`의 각 가지와 절의 마지막 식.
- 꼬리 위치의 `x |> f(a)`는 `f`의 꼬리 호출.
- 꼬리가 **아닌** 것: 연산자의 피연산자(`1 + f()`), `f()!`, `f()?`, `f() ?? b`, 다른 호출의 인자,
  `and`/`or`의 오른쪽(결과가 bool인지 검사해야 하므로).
- 자기 재귀뿐 아니라 **모든** 꼬리 호출이 대상이다 (상호 재귀, 상태 기계).

### 제약

- **반환 타입 표기가 있는 함수는 제외.** 반환값을 검사하려면 프레임이 남아야 한다. 깊은 재귀 함수에는 반환 타입을 쓰지 않는다.
- 에러의 호출 경로(08)에서는 재사용된 프레임이 사라진다. "꼬리 호출로 생략됨" 표시를 둔다.
- 꼬리가 아닌 재귀(`1 + len(rest)`)의 깊이에는 한도가 있다. 넘으면 구현 언어의 패닉이 아니라 fung 에러 "stack overflow"에
  "꼬리 재귀나 fold를 쓰세요" 힌트. 숫자는 09에서. 리스트 처리는 `map` / `fold` 등 표준 함수를 권장.

## 부분 적용

- 자동 커링 없음 (`add(1)`은 인자 부족 에러).
- `_` 자리 표시로 명시적 부분 적용. 호출 인자에서만 쓴다.

```
files |> map(path.join(dir, _))     # f => path.join(dir, f)
```

- `dir`은 **그 자리에서 한 번** 평가되어 붙잡힌다.
- `_`가 여럿이면 왼쪽부터 차례로 인자가 된다: `sub(_, _)`는 `(a, b) => sub(a, b)`.
- 중첩 호출에서 `_`는 **가장 안쪽 호출**에 속한다: `f(g(_))`는 `f(x => g(x))`.
- 이름 붙인 인자 자리(`f(a: _)`)에는 쓰지 않는다.
- 호출 인자의 `_`(부분 적용)와 패턴의 `_`(아무거나)는 쓰이는 자리가 달라 충돌하지 않는다.

## 스코프와 클로저

규칙은 넷이고 예외는 없다 (배경 문서의 원칙 7). 2026-10-13 재논의에서 "최상위 fn은 최상위 변수를 호출 시점에 찾는다"는 예외 조항을 없앴다.

1. **이름은 위에서 아래로 묶인다.** 대입보다 앞에서 읽으면 E0204.
2. **최상위 `fn` 정의는 프로그램 시작 전에 모두 만들어진다.** 그래서 순서와 상관없이 서로 부를 수 있다.
3. **함수 값은 만들어질 때 보이는 변수의 값을 복사한다.** 재할당은 이름을 새 값에 붙이는 것이지 클로저가 복사한 값을 바꾸지 않는다.
4. **블록(함수 본문, `if` 가지, `match` 절, `for` 본문)은 바깥 이름을 읽을 수 있고, 바깥 이름에 `=`로 대입할 수 없다** (E0205). 블록 안에서 만든 이름은 블록 밖으로 새지 않는다 (E0206).

이 넷에서 따라 나오는 것들:

- **최상위 `fn`은 최상위 변수를 볼 수 없다.** 시작 전에 만들어지므로(2) 그때는 변수가 하나도 없고, 복사할 것이 없다(3).
  다른 최상위 `fn`, import한 모듈, prelude는 변하지 않는 상수라 복사와 조회가 구별되지 않으므로 보인다. 설정 값은 인자로 넘긴다.
- **람다와 익명 함수는 그 자리에서 만들어지므로** 그때까지 대입된 변수를 (최상위 변수든 바깥 함수의 지역이든) 복사한다. 최상위와 함수 안의 동작이 같다.
- **블록 안의 이름 있는 `fn`도 그 자리에서 만들어진다.** 바깥 함수의 인자와 지역을 복사하고, 자기 자신은 `(self)`로 부른다. 같은 블록의 뒤에 정의된 지역 `fn`은 아직 없으므로 못 부른다 (E0208, 힌트: 최상위로).
- 함수 안의 `y = 1`은 `y`가 그 시점에 보이지 않으면 새 지역 변수다. 최상위 `fn` 안에서는 파일의 `y`가 어디에 있든 보이지 않으므로 항상 새 지역이다.

```
dir = "./logs"
fn clean() = fs.list(dir)      # E0204: clean은 dir이 생기기 전에 만들어졌다. 힌트: 인자로 넘기세요
fn clean(dir) = fs.list(dir)   # 맞는 방법

x = 1
f = () => x                    # f는 지금의 x(1)를 복사
x = 2
f()                            # 1. 함수 안에서도 똑같이 1

fn repeat(s, n):
  fn go(i) = i == 0 then "" else s + go(i - 1)   # 지역 fn은 바깥 인자 s를 복사한다
  go(n)
;;

double = x => x * 2
fn f(y) = double(y)            # E0204: double은 변수다. fn double(x) = x * 2 로 쓴다
```

- 변수가 절대 바뀌지 않으므로 클로저는 값을 **복사**하면 된다. Lua식 upvalue 상자가 필요 없다 (09).
- 기각한 대안 둘. (A) 최상위 `fn`이 최상위 변수를 호출 시점에 찾기: 예외 조항이 하나 생기고, 최상위와 함수 안에서 같은 코드의 답이 달라지며(`x = 1; f = () => x; x = 2; f()`가 최상위에서만 2), 런타임에만 잡히는 에러(E0207)가 생긴다.
  (B) Elixir처럼 함수 정의는 바깥 변수를 못 보고 람다만 보기: 정의/식 두 규칙이 생기고, 지역 `fn`이 바깥 인자를 못 써서 재귀 도우미마다 인자를 반복한다.

### 재귀와 이름 찾기

- 최상위 `fn` 이름은 **상수**다. 같은 파일에 `fn f` 둘은 E0210, `f = 1`로 덮어쓰기는 E0209 (REPL만 재정의 허용, 08).
- 블록 안의 지역 `fn`은 자기 자신만 참조할 수 있다. 서로 부르는 함수들은 최상위에 둔다.

### 블록 스코프

- 블록은 함수 본문, `if` 각 가지, `match` 각 절, `for` 본문.
- 새 이름(인자, `for` 변수, 패턴)이 바깥 이름을 가리는 것은 허용. import한 모듈 이름을 가리는 것은 에러 (04).

```
if c: x = 1 else: x = 2 ;;
print(x)                      # 에러: x는 if 안에서만 존재. 힌트: `x = if …`로 쓰세요
x = if c: 1 else: 2 ;;        # fung 방식 — if가 식이므로
```
