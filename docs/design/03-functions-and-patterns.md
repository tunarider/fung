# 03. 함수와 패턴 매칭

규범은 매뉴얼 언어 명세(`manual/reference/language/`)이고, 이 문서는 결정의 기록이다.

## 반환

- 마지막 식의 값이 반환값.
- `return`으로 조기 반환도 허용 (스크립트에서 일찍 빠져나가는 용도).

```
fn process(path):
  if not fs.exists(path)!: return Err("없음") ;;
  ...
;;
```

### `return`이 돌아오는 곳

- 함수 본문(이름 있는 `fn`, 익명 `fn`), 그 안의 `if`·`match` 가지: 그 함수에서 돌아온다.
- **람다 `=>`와 `for` 본문 안의 `return`·`?`는 컴파일 에러 E0237**(SP34, 결정 D42, 2026-11-11). 일찍 돌아가려면 익명 `fn(x): … ;;`.
  람다의 `return`·`?`는 람다에서 돌아올 뿐이라, 그 값은 받은 함수가 쓰는 대로 쓰인다: `map`이면 `Err`가 리스트의 원소가 되고(조용한 버그),
  `filter`면 조건 자리의 런타임 에러, 별칭(`m = map`)이면 막지 못했다. `for`는 `map`의 설탕이라 본문이 사실은 람다이므로 같은 규칙이 그대로 따라 나온다.
  힌트: 찾기는 `find`, 검사는 `all`/`any`, 누적은 `fold`, 실패할 수 있는 변환은 `try_map`.
  전에는 세 갈래였다: `for` 본문의 `return`(E0213)·`?`(E0220), "map 계열의 f"로 바로 쓴 람다의 `?`(E0226, L2·SP1, 부르는 함수의 이름으로 정하는 특례), 그 밖의 람다는 허용.
  세 번호는 은퇴했다. 기각: `for.md`의 이유만 고치기(규칙 셋이 남는다).
- **`try_map(xs, f)`**: 실패할 수 있는 변환을 돌다가 첫 실패에서 멈춘다. `f`가 모두 `Ok(v)`면 `Ok([v…])`, 처음 나온 `Err`는 그대로 돌려주고
  남은 원소는 부르지 않는다. `f`가 결과값이 아닌 값을 돌려주면 E0605(`!`·`?`와 같다). 순회 대상은 `map`과 같다. 이미 만든 결과값 리스트는 `try_map(rs, r => r)`.
  이름은 Gleam의 `list.try_map`을 따랐다(Rust의 `map_ok`은 "Ok만 변환"이라 다른 뜻). 기각: 경고만(`run`이 보이지 않음).
- **진입 파일 최상위의 `return`도 컴파일 에러.** 힌트: `exit()`.
- `return`은 문장이거나 가지의 끝에만 온다(E0132), `return` 문장 뒤의 문장은 E0131(결정 D50, 01 참고).
- **매개변수 기본값 안의 `return`과 `?`도 컴파일 에러**(E0211, FE38, 사용자 결정 D8 2026-11-10, `?`는 컨트롤러 판단으로 넓힘): 기본값은 본문보다 먼저 계산되므로 거기서 돌아가면 본문을 건너뛴다.
  `test` 블록의 본문은 함수 본문이라 `return`을 쓸 수 있다.
- 비지역 반환(람다 안에서 바깥 함수를 끝내기)은 채택하지 않는다. 여러 프레임 되감기가 필요하고,
  람다가 다른 태스크에서 불리면 정의할 수 없다.

## 값의 수명 (L7, 2026-10-20; P9, 2026-10-25; VM1·VM2, 2026-11-08; VM19, 2026-11-11)

- 지역 변수(매개변수, 함수 안에서 묶은 이름, 진입 파일·모듈 본문의 블록 안에서 묶은 이름)의 **마지막 읽기는 값을 넘겨준다**(P9, 2026-10-25, 사용자 결정). 복사하지 않고 칸을 비우므로,
  읽은 쪽(부른 함수, 만든 리스트 등)이 값을 쥐고, 그쪽이 놓으면 놓인다. 컴파일러가 함수 본문을 평가 순서의 뒤에서 앞으로 걸으며 "뒤에서 다시 읽히는가"를 보고,
  아니면 그 읽기를 `MOVELOCAL`로 낸다. 반복문이 없는 언어라(반복은 재귀, `for` 본문은 함수) 한 프레임의 코드는 가지만 있는 한 방향 길이다.
  - 가지(`if`·`and`·`or`·`??`)는 가지마다 따로 본다. `match`의 주제는 갈래마다 다시 읽히고 가드는 뒤 갈래보다 먼저 돌므로 둘은 넘기지 않는다
    (갈래의 마지막이 이름 하나면 그 갈래가 주제를 넘겨받는다).
  - 클로저가 붙잡는 것도 읽기다(만들 때 값을 복사한다, 넘기지 않음). 붙잡기가 마지막 읽기면 클로저를 만든 바로 뒤에 칸을 비운다(아래, VM19).
  - 그래서 홀로 쥔 맵·리스트를 받은 `put`·`+`는 복사하지 않고 제자리에서 고친다. `fold(xs, {}, (m, x) => put(m, …))`와 재귀 누적 `go(put(acc, k, v), rest)`가 그렇다.
  - 대입과 `match` 갈래의 패턴은 그 칸에 쓴다. 쓰기 앞의 읽기는 쓰기 뒤에서 다시 읽히지 않으므로, `x = f(x)`의 `x`도 넘어간다(제자리 수정).
    블록이 끝나면 그 칸을 옆 블록의 이름이 다시 쓰는데, 쓰기가 둘을 가르므로 뒤 블록의 이름이 앞 블록의 값을 붙잡지 않는다.
  - 넘기지 않은 읽기에도 칸을 비운다(`CLEARLOCAL`, L7). **변수는 그 길에서 더 읽힐 수 없게 된 곳에서 놓인다**(VM1, 2026-11-08; VM19·D61, 2026-11-11, 사용자 결정):
    문장이 끝날 때, 가지가 시작할 때(`if`의 두 쪽, `??`의 두 쪽, `and`·`or`의 오른쪽, `match` 갈래의 본문은 패턴과 가드를 지난 뒤),
    클로저가 붙잡는 것이 마지막 읽기면 그 `CLOSURE` 바로 뒤. 다른 가지에서만 읽히는 변수, `match`의 주제, 가드만 읽은 이름은 가지가 시작할 때 놓인다.
    함수 본문의 문장이든 가지 안이든, 식 하나뿐인 가지든 같다. 그 전 규칙("문장이 없는 자리의 읽기는 그 자리를 품은 문장 뒤에 놓인다")은
    품은 문장이 함수의 마지막 식이면 "문장 뒤"가 없어, `else` 아래 문장 하나의 유무로 교착이 생겼다 사라졌다(VM19 재현). 기각(VM19 다): 그대로 두고 매뉴얼에 적기.
    조건 자리의 `and`·`or`가 건너뛰는 쪽, `else` 없는 `if` 문장의 빈 쪽처럼 코드가 없는 길에서 죽은 값은 그 길의 다음 놓는 곳(문장 끝, 가지 시작)이 놓는다.
    함수를 부르지 않고 그대로 프레임이 끝나는 가지(꼬리 자리, `return`)는 놓는 명령을 내지 않는다: 돌아가며 놓이고, 그 사이에 값을 볼 수 있는 것이 없다(부르기만 값을 본다).
    기각(VM1): 함수 본문의 문장에서만 놓기(그 전 규칙). 같은 코드를 `if` 안으로 옮기면 채널이 닫히지 않아 교착했다.
  - 구현(VM23·VM24, 2026-11-11): `compiler/moves.rs`의 두 걷기가 노드 번호(`Node::id`)를 키로 "넘기는 읽기", "문장 뒤·가지 시작·`CLOSURE` 뒤에 놓을 칸"을 표로 내고, 컴파일러는 찾아 내기만 한다.
    뒤 걷기는 살아 있는 칸 집합 하나를 제자리에서 고치고 가지마다 바꾼 것을 기록해 되돌리므로(문장마다 집합을 복사하지 않음) 코드 크기에 선형이다. 앞 걷기는 코드가 없는 길에서 죽은 칸만 들고 간다.
    확실하지 않으면 놓지 않는다: 어떤 길에서도 다시 쓰기 전에 읽히지 않는 칸만 놓는다. 디버그 빌드의 바이트코드 검증기(VM22)가 빈 칸을 읽는 길이 없는지 확인한다.
  - 진입 파일과 모듈 본문의 블록도 같은 규칙이다(VM2, 2026-11-08, 사용자 결정). 기각: 그 블록의 지역도 프로그램 끝까지 살기(같은 코드가 함수 안에서는 되고 밖에서는 교착한다).
  - 기각(P9): 꼬리 호출 직전에만 놓기. 재귀 누적에서는 `put`이 꼬리 호출의 인자 안에서 먼저 돌아 효과가 없고, 규칙에 예외를 더한다.
- **한 번도 읽지 않는 변수는 함수가 돌아올 때까지 산다.** 쥐고 있는 것 자체가 뜻인 값(`_watch = stop_signal()`로 정지 요청을 계속 보기,
  보내는 끝을 일부러 열어 두기)을 위해서다(Rust의 `let _guard`와 같은 관용구). 지금 놓고 싶으면 `_ = 식`.
- 관찰되는 차이는 놓이는 때가 빨라지는 것뿐이다: 채널의 끝이 더 일찍 닫히고(05 "자동 닫힘"), 큰 값의 메모리가 더 일찍 풀린다.
  넘겨준 값은 그 문장이 끝나기 전에도 놓일 수 있다: `[drop_it(tx), recv(rx)]`에서 `drop_it`이 `tx`를 놓으면 `recv`는 닫힌 채널을 본다.
- 최상위 변수(전역)는 그대로 프로그램 끝까지 산다. 최상위 `fn`이 최상위 이름을 호출할 때 읽으므로(L9) 전역의 "마지막 읽기"는 정할 수 없다.
- 기각: 블록 끝에서 놓기(교착 예는 그대로 남는다), 정적 경고(`run`에서 보이지 않고 오탐이 있다).

## 자원 정리: `with` (2026-10-18, 동시성 v2 L3)

`with(acquire, use, release)`가 정리 장치 하나다. `acquire()`를 부르고, 그 값으로 `use(r)`를 부르고, `use`가 어떻게 끝나든
`release(r)`를 부른다: 값, `Err` 반환, 런타임 에러, 취소(`cancel`·`timeout`·범위 실패), `exit` 모두. 결과는 `use(r)`의 값이다.

```
fn copy_first_line(src, dst) = with(() => fs.open(src)!, fn(f):
  first = read_line(f)?
  fs.write(dst, first)
;;, f => close(f))
```

- `acquire`가 런타임 에러나 취소로 끝나면 `release`는 돌지 않는다(얻은 것이 없다). `acquire`가 돌아온 뒤에는 무엇이 와도 `release`가 돈다.
- `release`는 차단된 채 돈다: 그것을 부른 취소나 기한이 닿지 않는다(소켓 닫기, 풀에 돌려주기가 바로 끊기지 않게). 정리 중에 영원히 멈추면
  교착 판정이 끊는다(`exit` 뒤에도 판정한다).
- **버리지 않는다.** 무엇이 올라가는지는 종류가 먼저, 출처가 다음이다:
  1. `use`의 런타임 에러(`release`도 실패했으면 그것은 `note: also failed in release: …`로 붙는다)
  2. 아니면 `release`의 런타임 에러(`release`가 돌려준 `Err`도 버려지는 값이라 E0606 런타임 에러다, 02 "버려지는 Err")
  3. 아니면 `release` 자신이 멈춘 것: 그 안에서 부른 `exit`, 또는 교착 판정이 끊은 것
  4. 아니면 `use`의 결과(값, `Err`, 취소, `exit`)

  종료 코드는 처음 요청된 `exit(n)`이다. 명령은 `exit` 뒤에도 취소가 아닌 에러를 보고하고, `exit(0)`이었는데 에러를 보고했으면 1로 끝낸다.
- `use(r)` 호출은 꼬리 위치가 아니다(아래 "꼬리 위치").
- 표준 라이브러리의 감싸는 함수 `fs.with_open`·`fs.with_temp_dir`는 `with` 위의 fung 코드다(06).
- **`at_exit`는 없다.** `exit`·교착·진입 파일 에러는 모두 루트 취소이고, 되감기가 모든 `with`의 `release`를 지난다. 프로그램 끝의
  정리는 진입 파일의 본문을 `with`로 감싸서 한다. 정리 장치를 하나로 두려고 지웠다(0.2.0까지 있었다).
- 기각: `defer`(프레임에 할 일을 매달아 꼬리 호출 최적화와 충돌하고, VM에 프레임별 목록과 되감기 로직이 필요), `with f = …: … ;;` 블록 문법
  ("무엇을 어떻게 닫는가"를 언어가 알아야 해서 타입별 닫기 규약이 필요). `with`는 함수 하나의 호출이라 둘 다 피한다.

## 인자

```
fn greet(name, greeting = "안녕"):            # 기본값
fn sum(...nums):                              # 가변 인자 (리스트로 받음)
fn serve(port: int = 8080, dir = "."):
serve(dir: "./public")                        # 이름 붙인 인자
fn pad(s, width = len(s) + 2):                # 기본값은 앞 인자를 참조할 수 있다
```

- 정의 순서: 필수 → 기본값 있는 것 → 마지막에 `...rest` 하나. `...rest`는 기본값을 가질 수 없다. 기본값 뒤의 필수 매개변수는 E0120, 같은 이름을 묶는 매개변수 둘은 E0119(FE15, 2026-11-08).
- 기본값은 **호출할 때마다**, 왼쪽에서 오른쪽으로 평가한다. 앞의 인자를 참조할 수 있다. 앞의 패턴 매개변수가 묶은 이름도 된다(`fn f((a, b), c = a + b)`).
- 호출: 위치 인자 먼저, 그 뒤에 이름 붙인 인자. 이름은 `...rest`를 제외한 어떤 인자든 가리킬 수 있다.
- **펼침**: 마지막 위치 인자 자리에 `...xs` 하나(리스트·범위)를 쓰면 원소가 그 자리부터의 위치 인자다(`f(a, ...xs, k: v)`; 2026-11-11 SP38·D45).
  가변 인자 함수(`print`, `fail`, `path.join`, 사용자 `...rest`)를 감싸려면 필요하다. 리스트 리터럴에는 두지 않는다(`[a] + xs`와 방법이 둘이 된다). 다른 위치 인자 앞·리스트 리터럴·태그의 값은 E0133,
  리스트·범위가 아닌 값은 런타임 E0506. 부분 적용의 펼친 값도 다른 인자처럼 만들 때 한 번 평가한다. 기각: `apply(f, xs)`(부르는 자리의 모양이 달라진다), 가변 인자를 내장 특례로만.
- 람다도 함수이므로 이름 붙인 인자를 받을 수 있다.
- 인자 에러(코드 오류): 같은 인자를 위치와 이름으로 둘 다 줌(E0405), 모르는 이름(E0406), 필수 인자 누락(E0407), `...rest`가 없는데 위치 인자가 남음(E0402).
  **호출 대상이 컴파일 때 정해지면 컴파일 때** 같은 번호와 문구로 잡는다(2026-11-11 SP35·D43): 가려지지 않은 최상위 `fn`(최상위 이름은 다시 묶이지 않는다, D53),
  prelude 함수(`spec/builtins.txt`의 매개변수), import한 모듈의 최상위 `fn`과 `_native.*` 다리의 멤버(이름으로 가져온 것과 `read = _n.read` 같은 별칭 포함).
  그 밖(변수에 든 함수 값, 펼친 인자의 개수, REPL에서 다른 입력이 정의한 `fn`)은 런타임 에러다. REPL은 같은 이름의 `fn`을 뒤 입력에서 다시 정의할 수 있어, 최상위 `fn`으로의 호출은 그 입력 안에서도 검사하지 않는다.
- 컴파일 에러: 한 호출에 같은 이름 인자를 두 번 줌(`f(a: 1, a: 2)`, E0116; 2026-10-26, 전에는 런타임 E0405). 부르는 함수를 몰라도 알 수 있다.
- 타입 표기 검사는 기본값을 채운 뒤 함수 진입 시점에, 반환 타입은 반환 시점에 (07).

## 평가 순서

- 항상 **왼쪽에서 오른쪽**: 호출 인자, 리스트·맵·튜플 리터럴의 원소, 이항 연산의 양쪽, 문자열 보간 조각.
- 파이프도 이항 연산이라 왼쪽 값을 먼저 평가한다(FE48, 결정 D57, 2026-11-11). desugar는 오른쪽의 호출 대상이 이름이나 필드(`f`, `m.f`)가 아니면
  왼쪽 값을 숨은 변수에 먼저 담는다(`a() |> mk()(2)`는 `a`, `mk` 순서). 전에는 바꿔 쓴 호출 `mk()(a(), 2)`의 순서라 오른쪽의 모양에 따라 달랐다.
  기각: 명세에 "파이프는 바꿔 쓴 호출의 순서"를 적기(파이프에만 예외 문장이 생긴다).
- `and`, `or`, `then … else`, `??`는 단락 평가 (오른쪽은 필요할 때만).

## 패턴

```
match value:
  0                  => ...    # 리터럴 (음수 -1, 문자열, 심볼, 기간(음수 -1s도, FE32), true/false/nil 포함)
  'ok                => ...    # 심볼
  Ok(x)              => ...    # 태그
  (a, b)             => ...    # 튜플
  []                 => ...    # 빈 리스트
  [first, ...rest]   => ...    # 머리와 꼬리. 꼬리 이름은 생략 가능: [first, ...] (`..._`도 같다, FE11)
  {name: n}          => ...    # 맵 부분 매칭 (다른 키는 무시)
  x when x > 100     => ...    # guard
  'a | 'b            => ...    # 여러 패턴 중 하나
  _                  => ...    # 나머지 전부
;;
```

- 아무 패턴도 맞지 않으면 런타임 에러.
- 패턴 안의 이름은 **항상 새로 꺼내 담는다.** 바깥 변수와 비교하려면 guard를 쓴다.
- 대안 `|`가 이름을 묶으면 **모든 대안이 같은 이름들을 묶어야** 한다. 아니면 컴파일 에러.
- `when` 가드는 대안 전체에 걸린다: `'a | 'b when cond`. 가드는 맞는 대안마다 차례로 본다: 한 대안의 묶음으로 가드가 거짓이면 다음 대안을 맞춰 본다(`(a, _) | (_, a) when a > 1`은 `(0, 5)`에 맞아 `a`가 5; 2026-10-26, Rust와 같음. 전에는 첫 대안에서 가드가 거짓이면 갈래를 건너뛰었다).
  그래서 가드는 대안마다 한 번씩 돌 수 있다. 중첩된 대안도 펼쳐 보며(`Ok((a, _) | (_, a))`), 펼친 수가 256을 넘으면 컴파일 에러 E0230.
- **괄호 없는 태그 패턴 `Red`는 심볼 `Red`에만 맞고 `Red(3)`에는 맞지 않는다.** 태그 값은 `Red(_)`처럼 인자 모양까지 쓴다. 결과값의 이름은 값을 꼭 하나 담으므로 맨 `Ok`·`Err` 패턴은 컴파일 에러다(E0236, D41).

```
match v:
  y when y == x => "x와 같음"
  _             => "다름"
;;
```

## 구조 분해 대입

대입의 왼쪽에도 패턴 문법을 쓴다. 맞지 않으면 런타임 에러.
대입·`for`·매개변수(`fn`과 람다)는 같은 **구조 분해 패턴**(`grammar.md`의 `destructure`)을 받는다(FE32, 결정 D10, 2026-11-10): 이름, `_`, 튜플·리스트·맵, 값을 담은 태그, 그것들의 `|` 대안.
맨 바깥의 리터럴(숫자·문자열·심볼·인자 없는 태그·기간·`true`/`false`/`nil`)은 값을 고르기만 하므로 E0112이고, 안쪽의 리터럴은 된다(`(1, y) = p`).
전에는 대입은 첫 토큰이 `( [ { TAG`일 때만 패턴을 시도했고, `for`는 리터럴까지 다 받았고(`for 1 in xs`가 둘째 원소에서 E0602), 매개변수는 인자 없는 태그를 받았다.
이름을 묶는 규칙은 **대입과 같다**: 같은 스코프의 재대입은 되고(`(a, b) = (b, a)`), 바깥 블록의 이름이면 E0205, 함수·import·prelude 이름이면 E0240(D38).
반면 `match` 절의 이름, `for`의 변수, **매개변수 패턴**(`fn f((a, b)) = …`, `((k, v)) => …`)의 이름은 늘 새 이름이다. 보이는 바깥 이름과 같으면 가리지 않고 E0240이다(D38, 2026-11-11; 전에는 말없이 가렸다).
이 이름은 그 절·본문의 블록에 속하므로 그 안에서 다시 대입할 수 있다(`fn(v): v = v + 1; v ;;`; 람다 `=>`의 본문은 식 하나라 대입을 담지 못한다).
매개변수 패턴은 호출 때 맞춰 보며 맞지 않으면 E0602다; 이름이 없으므로 이름 인자로 넘길 수 없다.
한 패턴 안에 같은 이름이 두 번 나오면(`[a, a]`) 컴파일 에러. "두 자리가 같다"는 guard로 쓴다(`[a, b] when a == b`).
`_ = 식`은 값을 평가하고 버린다 (`_`는 패턴의 아무거나). 버려지는 `Err`를 에러로 하지 않는 명시적 버리기다(02 "버려지는 Err").

```
(q, r) = divmod(7, 2)
[first, ...rest] = files
{name: n, port: p} = config
Ok(text) = fs.read("a.json")     # Err면 에러
```

## 여러 절 함수: 지원하지 않음

같은 이름의 함수를 패턴별로 나눠 정의하는 방식(Elixir, Haskell)은 채택하지 않는다.
대신 본문을 `match`로 바로 쓴다.

```
fn len(list) = match list:
  []           => 0
  [_, ...rest] => 1 + len(rest)
;;
```

## 꼬리 호출 최적화

00의 결정("상태가 있는 반복은 꼬리 재귀")의 전제 조건이다. 선택 기능이 아니다.

```
fn count(n, acc) = n == 0 then acc else count(n - 1, acc + 1)
count(1000000, 0)
```

### 꼬리 위치

여기 있는 호출만 프레임을 재사용한다 (VM에 꼬리 호출 명령).

- 함수 본문의 마지막 식, `= 식` 본문, 람다 본문.
- 꼬리 위치에 있는 `if`·`then … else`·`match`의 각 가지와 절의 마지막 식.
- 꼬리 위치의 `x |> f(a)`는 `f`의 꼬리 호출.
- 꼬리가 **아닌** 것: 연산자의 피연산자(`1 + f()`), `f()!`, `f()?`, `f() ?? b`, 다른 호출의 인자,
  `and`/`or`의 오른쪽(결과가 bool인지 검사해야 하므로), 내장 함수가 부르는 함수(`map`의 `f`, `with`의 `use`: 그 뒤에 할 일이 남았다).
- 자기 재귀뿐 아니라 **모든** 꼬리 호출이 대상이다 (상호 재귀, 상태 기계).

### 제약

- **반환 타입 표기가 있는 함수도 모든 꼬리 호출이 프레임을 재사용한다**(2026-11-11 SP37·D44; 전에는 T4 2026-10-20대로 자기 자신으로의 꼬리 호출만이라, 타입 표기가 실행 의미를 바꿨다).
  다른 함수로의 꼬리 호출 앞에서 프레임이 그 함수의 반환 검사를 이어받고(`TAILCHECK`), 프레임이 돌아올 때 이어받은 검사를 최근 것부터 한다.
  이어받은 자리(함수와 위치)가 같은 검사는 하나로 합쳐 쌓이지 않으므로 `a` ↔ `b`처럼 도는 꼬리 호출도 일정한 공간이다. 자기 자신으로의 꼬리 호출은 자기 검사가 끝에서 하므로 이어받지 않는다.
  실패하면 E0404의 위치는 반환 타입을 적은 함수가 값을 돌려주는 자리(전과 같다)이고, 호출 경로의 맨 안쪽 줄은 프레임이 그때 돌고 있는 함수다.
- 에러의 호출 경로(08)에서는 재사용된 프레임이 사라진다. "꼬리 호출로 생략됨" 표시를 둔다.
  다만 **사용자 코드에서 fung으로 쓴 라이브러리 함수로의 꼬리 호출**은 사라지는 프레임의 함수·호출 자리·그전 꼬리 호출 수를 새 프레임에 적어 둔다(L8, 2026-10-27).
  06의 위치 규칙("사용자 코드의 가장 가까운 프레임")이 바로 그 프레임을 가리키기 때문이다. 그래서 에러 위치와 경로가 꼬리가 아닌 호출과 같다.
  경계를 넘을 때만 저장 하나를 치르고(사용자 함수끼리의 꼬리 재귀는 그대로), 스택은 자라지 않는다(적어 두는 칸은 프레임마다 하나, 다음 경계에서 덮어쓴다).
  꼬리 호출 수는 경계를 넘을 때마다 새로 센다: 라이브러리 안의 꼬리 호출은 사용자 프레임이나 사용자 콜백에 붙지 않는다.
  - 기각: 경계의 꼬리 호출을 보통 호출로 바꾸기(라이브러리가 사용자 콜백을 다시 꼬리 호출하는 고리가 있으면 스택이 자란다),
    모든 꼬리 호출을 최근 N개 남기기(MIT Scheme의 history: 꼬리 호출마다 저장 하나).
- 꼬리가 아닌 재귀(`1 + len(rest)`)의 깊이에는 한도가 있다. 넘으면 구현 언어의 패닉이 아니라 fung 에러 "stack overflow"에
  "꼬리 재귀나 fold를 쓰세요" 힌트. 숫자는 09에서. 리스트 처리는 `map` / `fold` 등 표준 함수를 권장.

## 부분 적용

- 자동 커링 없음 (`add(1)`은 인자 부족 에러).
- `_` 자리 표시로 명시적 부분 적용. 호출 인자에서만 쓴다. 태그의 인자도 호출 인자다(FE18, 2026-11-08, 사용자 결정): `Ok(_)`는 `x => Ok(x)`, `Pair(a, _)`는 `x => Pair(a, x)`.
  파이프가 이미 태그를 호출 형태로 다루므로(01 "파이프") 같은 규칙을 넓힌 것이다. 기각: 막고 전용 문구(흔한 `map(xs, Ok(_))`가 안 된다).

```
files |> map(path.join(dir, _))     # f => path.join(dir, f)
```

- `dir`은 **그 자리에서 한 번** 평가되어 붙잡힌다.
- `_`가 여럿이면 왼쪽부터 차례로 인자가 된다: `sub(_, _)`는 `(a, b) => sub(a, b)`.
- 중첩 호출에서 `_`는 **가장 안쪽 호출**에 속한다: `f(g(_))`는 `f(x => g(x))`.
- 이름 붙인 인자 자리(`f(a: _)`)에는 쓰지 않는다.
- 파이프 오른쪽 호출·태그의 인자 자리(`x |> f(_, 1)`, `x |> Pair(_, 1)`)에도 쓰지 않는다(E0227, 01 "파이프").
- 호출 인자의 `_`(부분 적용)와 패턴의 `_`(아무거나)는 쓰이는 자리가 달라 충돌하지 않는다.

## 스코프와 클로저

규칙은 일곱이다 (배경 문서의 원칙 7; 5·6은 2026-11-11 D38로 더함). 2026-10-13 재논의에서 "최상위 fn은 최상위 변수를 호출 시점에 찾는다"는 예외 조항을 없앴다.
최상위의 다시 대입 금지(1.5)는 2026-11-11 SP47·D53으로 더했다: 전에는 최상위에서 "한 번만 대입된 이름"과 "두 번 이상 대입된 이름"을 갈라, 앞의 것만 최상위 `fn`에서 보였다.

1. **이름은 위에서 아래로 묶인다.** 대입보다 앞에서 읽으면 E0204.
1.5. **최상위 이름은 한 번만 묶인다.** 파일 맨 바깥에서 이미 묶은 이름을 대입·구조 분해로 다시 묶으면 E0238이다(D53; REPL은 입력마다 다시 정의할 수 있다, 08).
2. **최상위 `fn` 정의는 프로그램 시작 전에 모두 만들어진다.** 그래서 순서와 상관없이 서로 부를 수 있다.
3. **함수 값은 만들어질 때 보이는 변수의 값을 복사한다.** 재할당은 이름을 새 값에 붙이는 것이지 클로저가 복사한 값을 바꾸지 않는다.
4. **블록(함수 본문, `if` 가지, `match` 절, `for` 본문)은 바깥 이름을 읽을 수 있고, 바깥 이름에 `=`로 대입할 수 없다** (E0205). 블록 안에서 만든 이름은 블록 밖으로 새지 않는다 (E0206).
5. **보이는 이름은 다시 묶을 수 없다**(2026-11-11 SP30·SP45·FE47, 사용자 결정 D38). 바깥 블록·바깥 함수의 이름, 최상위 이름(상수·`fn`), import한 이름, prelude 함수를
   묶는 방법(대입·구조 분해·매개변수·람다 매개변수·`for`·`match` 패턴·지역 `fn`·최상위 `fn`·import)과 상관없이 새로 묶으면 컴파일 에러다.
   바깥 변수에 대입하면 규칙 4의 E0205, 그 밖은 새 번호 E0240(노트가 바깥 이름을 묶은 줄을 보인다), 모듈 이름은 E0308. 같은 블록의 다시 대입은 그대로 된다.
   전에는 매개변수·`for`·`match` 패턴·람다가 조용히 가렸고(`match x: x => …`는 `x`와 비교하지 않는다), prelude 가리기만 경고 W0103이었고,
   최상위 `fn`의 맨 바깥 블록의 대입은 상수는 가리되 다른 최상위 `fn`·import 이름은 E0205라 종류마다 달랐다(FE47).
   예외 하나: import된 파일의 **인터페이스**(공개 최상위 이름과 공개 `fn`의 매개변수 이름)는 prelude 이름이어도 된다. 부르는 쪽은 그것을 `http.get`처럼 모듈 이름으로 읽거나
   `timeout:`처럼 인자 이름으로만 쓰므로 가림이 없고, 막으면 `http.get`·`path.join`·`regex.split`·`fs.remove`·`timeout:`을 쓸 수 없다(결정을 그대로 적용하면 생기는 구멍, 구현에서 정함).
6. **묶은 이름은 읽어야 한다**(D38). 한 번도 읽지 않는 지역 변수·매개변수(람다·`for`·`match` 패턴 포함)·import는 E0239다. `_`로 시작하는 이름은 빼고,
   진입 파일의 최상위도 지역으로 센다. import된 파일의 공개 이름과 최상위 `fn`은 세지 않는다. 다시 대입만 하는 이름은 읽지 않은 것이다.
   다른 에러가 있으면 E0239는 내지 않는다(쓰지 않는 이름은 오타나 E0240의 결과일 때가 많다; 08 "보고 범위"). 전에는 경고 W0101·W0102였다.

이 규칙들에서 따라 나오는 것들:

- **최상위 `fn`은 최상위 변수를 복사할 수 없다.** 시작 전에 만들어지므로(2) 그때는 변수가 하나도 없고, 복사할 것이 없다(3).
  다른 최상위 `fn`, import한 모듈, prelude는 변하지 않는 상수라 복사와 조회가 구별되지 않으므로 보인다.
- **최상위 이름은 모두 상수라 최상위 `fn`에서 보인다**(L9 2026-10-20, D53 2026-11-11). 같은 논리다: 다시 묶이지 않으니(1.5) 복사와 조회가 구별되지 않는다.
  최상위 `fn`(과 그 안의 함수)은 그 이름을 **호출할 때** 읽는다. 모듈 상태는 `counter = atom(0)`처럼 둔다(이름은 그대로, 내용은 `swap`으로 바뀐다).
  - 전에는(L9) 최상위에서 그 이름을 묶는 문장이 하나일 때만 상수였고, 두 번 이상 대입되는 이름은 보이지 않았다(E0204와 그 이유를 말하는 힌트).
    D53으로 두 번째 묶기가 E0238이 되어 이 구분과 힌트가 사라졌다. 기각안 (A)의 "같은 코드의 답이 달라진다"는 여전히 생기지 않는다.
  - 최상위 람다·익명 함수는 그대로 그 자리에서 복사한다(위에서 아래로, 규칙 1·3). 상수를 그 대입보다 위에서 람다로 읽으면 여전히 E0204다.
  - 대가 하나: 모듈이 시작하는 도중에, 상수의 대입보다 먼저 그것을 읽는 `fn`을 부르면 런타임 에러 E0809다(`x = f()` 뒤에 `f`가 읽는 `limit = 10`).
    정적으로 다 잡으려면 호출 그래프를 따라야 해서, 분명한 에러로 알린다.
  - REPL은 이름을 다시 대입할 수 있으므로(08), 최상위 `fn`은 전역을 늘 호출할 때 읽는다(앞 입력의 `fn`이 나중에 다시 대입된 값을 본다).
  - 최상위 `fn`이 언제든 읽을 수 있으므로 전역은 프로그램 끝까지 산다("값의 수명").
- **람다와 익명 함수는 그 자리에서 만들어지므로** 그때까지 대입된 변수를 (최상위 변수든 바깥 함수의 지역이든) 복사한다. 최상위와 함수 안의 동작이 같다.
- **블록 안의 이름 있는 `fn`도 그 자리에서 만들어진다.** 바깥 함수의 인자와 지역을 복사하고, 자기 자신은 `(self)`로 부른다. 같은 블록의 뒤에 정의된 지역 `fn`은 아직 없으므로 못 부른다 (E0208, 힌트: 최상위로).
- 함수 안의 `y = 1`은 `y`가 그 시점에 보이지 않으면 새 지역 변수다. 최상위 `fn` 안에서는 파일 상수가 어디서나 보이므로 그 이름에 대입하면
  본문의 맨 바깥 블록에서도 E0205다(규칙 4·5, D38 2026-11-11). 상수와 같은 이름의 지역은 만들 수 없다.
  - 그 전(L9 2026-10-20, FE23·D4 2026-11-10)에는 최상위 `fn`의 맨 바깥 블록에서 묶는 이름이 그 `fn` 전체의 지역이 되어 같은 이름의 상수를 가렸다(Python의 함수 지역처럼).
    D38이 이것을 뒤집었다: 가림이 묶는 방법마다 달랐고(FE47), 함수 앞부분에서 상수를 읽다가 아래에 같은 이름을 대입하면 앞의 읽기까지 E0204가 되는 일(FE49)이 사라진다.
    기각되었던 "E0205로 막기"가 이제 규칙이다. 겹치는 이름을 쓰던 코드는 이름을 바꿨다.

```
dir = "./logs"
fn clean() = fs.list(dir)      # 된다: 최상위 이름은 모두 한 번만 묶이는 상수다(D53)

level = 1
level = 2                      # E0238: 최상위 이름은 한 번만 묶인다(D53)

fn g():
  x = 1
  f = () => x                  # f는 지금의 x(1)를 복사
  x = 2
  f()                          # 1
;;

fn repeat(s, n):
  fn go(i) = i == 0 then "" else s + go(i - 1)   # 지역 fn은 바깥 인자 s를 복사한다
  go(n)
;;

double = x => x * 2
fn f(y) = double(y)            # 된다: double은 최상위 이름이라 상수다(L9, D53)
```

- 변수가 절대 바뀌지 않으므로 클로저는 값을 **복사**하면 된다. Lua식 upvalue 상자가 필요 없다 (09).
- 기각한 대안 둘. (A) 최상위 `fn`이 최상위 변수를 호출 시점에 찾기: 예외 조항이 하나 생기고, 최상위와 함수 안에서 같은 코드의 답이 달라지며(D53 전의 `x = 1; f = () => x; x = 2; f()`가 최상위에서만 2), 런타임에만 잡히는 에러(E0207)가 생긴다.
  (B) Elixir처럼 함수 정의는 바깥 변수를 못 보고 람다만 보기: 정의/식 두 규칙이 생기고, 지역 `fn`이 바깥 인자를 못 써서 재귀 도우미마다 인자를 반복한다.

### 재귀와 이름 찾기

- 최상위 `fn` 이름은 **상수**다. 같은 파일에 `fn f` 둘은 E0210, `f = 1`로 덮어쓰기는 E0209 (REPL만 재정의 허용, 08).
- 블록 안의 지역 `fn`은 자기 자신만 참조할 수 있다. 서로 부르는 함수들은 최상위에 둔다.

### 블록 스코프

- 블록은 함수 본문, `if` 각 가지, `match` 각 절, `for` 본문.
- 새 이름(인자, `for` 변수, 패턴)이 바깥 이름을 가리는 것은 허용. import한 모듈 이름을 가리는 것은 에러 (04).

```
if c: x = 1 else: x = 2 ;;
print(x)                      # 에러: x는 if 안에서만 존재. 힌트: `x = if …`로 쓰세요
x = if c: 1 else: 2 ;;        # fung 방식 — if가 식이므로
```
