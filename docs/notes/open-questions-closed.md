## 알파 이후

- [x] 프로젝트 extras에서 `_native.*` import 허용 여부 → **허용하지 않는다** (06, 2026-10-14). 측정해 보니 네이티브 원시 기능 대부분이
  공개 모듈에 같은 함수 값으로 이미 나와 있어(비용 없음) 열어도 얻는 성능이 없고, 숨김 층을 바꿀 자유만 잃는다(Node의
  `process.binding` 폐기 사례). 사용자가 네이티브 코드를 붙이는 확장도 열지 않는다. 필요한 원시 기능은 fung 본체에 추가한다.
- [x] 불변 컬렉션의 누적 비용 (2026-10-14 측정): `fold`로 `put(acc, k, v)`를 쌓으면 맵 전체를 매번 복사해 n²이다(2만 개에 18.5초).
  `acc + [x]`(2만 개 0.85초), `acc + s`(0.31초)도 같은 성질. 후보: 영속 자료구조(맵 HAMT·리스트 벡터 트라이), 소유자 확인 후 제자리
  덧붙이기, 일괄 구성 원시(`from_pairs`). → **영속 자료구조로 해결** (M10, 2026-10-14). 맵·리스트 누적과 꼬리 재귀는
  선형(2만 개 13~61ms). 문자열 `acc + s`는 그대로 n²이고, 리스트에 모아 `join`하라고 매뉴얼에 안내한다.

## 태스크 실패 후속 (2026-10-14 보류 → 2026-10-18 닫음)

동시성 v2 L1(구조적 동시성)으로 세 항목 모두 닫았다. 태스크는 범위 안에서만 띄우고, 실패는 범위를 연 코드로 가거나(`scope`)
처리기로 간다(`supervise`). "확인되지 않은 실패"가 생기지 않으므로 만들 때의 처리기·전역 처리기는 필요 없다.

- [x] `spawn(f, on_fail: e => …)` → `supervise(f, on_fail)`의 범위 단위 처리기로.
- [x] 전역 처리기 `on_task_failure` → 필요 없음(꺼내지 않은 실패 보고 자체를 지움).
- [x] 구조적 동시성(`scope`) → 유일한 방식으로 들임. 자유로운 `spawn(f)`는 지웠다.

## 성능 (2026-10-14 측정, 닫은 단계)

같은 기계에서 4가지 작업(`fib(30)`, 300만 번 산술 반복, 문자열 50만 개 잇기, 맵 20만 개)을 10개 언어로 쟀다. fung 0.1은
기하평균으로 8위(컴파일 언어 셋·Node·Perl·Python·Ruby 다음, Tcl·awk 앞), 호출·산술은 Python의 2~4배 느리고 문자열은
Python과 같으며 시작 시간(6ms)은 Python(22ms)보다 빠르다. fung 쪽 벤치마크는 `bench/`에 둔다.

- [x] 1단계: 산술 디스패치의 맵 조회(모든 명령에서 먼저 수행), 호출마다 다시 만드는 매개변수 표, `fold`·`map` 등이 범위를 리스트로 펼치는 것. → 완료 (2026-10-14)
- [x] 2단계: fung 함수 호출의 할당 0 빠른 길(위치 인자·개수 일치 시 인자를 VM 스택의 프레임으로 바로), 내장 함수가 람다를 부를 때 인자 버퍼 재사용. → 완료 (2026-10-14)
  - 결과(`bench/`, 5회 중 최고): fib 0.513→0.205초(2.5배), loop 0.563→0.241초(2.3배, Python 0.276초보다 빠름), str 0.065→0.053초,
    map 0.492→0.458초(맵은 영속 구조 비용이라 거의 그대로). 남은 시간은 명령 해석 루프 자체(3단계).
- [x] 3단계: 값 표현 변경(정수를 상자에 담지 않기), 정수 전용 명령, 묶음 명령. → 값 표현은 `enum`(정수·실수를 상자 없이 칸에)으로 해결(아래 "Rust 구현"),
  정수 전용·묶음 명령은 아래 레지스터 VM 항목과 함께 측정을 보고 정한다.
- 위 1·2단계는 태그 `v0.1.0` **뒤**에 들어가 릴리스된 적이 없다. 사용자가 가진 0.1.0은 최적화 전 속도다.
- 2026-10-17 측정(같은 `bench/` 여섯 개)은 `bench/README.md`. 지금 fung은 0.1.0에 견줘 fib·loop 약 2.6배 빠르고,
  spawn은 12.6배, chan은 2.2배 느리다(아래 "R7 스케줄러").

## Rust 구현: 정한 것 (대체된 결정)

동시성 v2(L4·L5, R1b~R5)에서 대체되었다. 지금의 모델은 open-questions "정한 것"과 `docs/notes/R7-scheduler.md`.

- [x] 동시성과 메모리 모델 → **태스크마다 운영체제 스레드 하나 + 실행권 잠금, 값은 참조 계수.** (3a, 2026-10-15; 노트 `docs/notes/R3a-runtime.md`)
  - fung 코드는 실행권을 쥔 스레드만 돌린다(Python GIL·OCaml 4 모델). 막히는 곳은 `crates/fung-vm/src/vm/block.rs`의 `block`과 소켓의 `vm/watch.rs`(`Watch`)로 모아,
    그린 스레드(R7)로 갈아끼울 자리를 남겼다. 비용: 태스크 생성 약 55 µs, 채널 주고받기 약 2.5 µs(태스크 하나일 때는 비용 없음; 측정은 R3a 노트 9절).
  - 값은 `enum`(종류 태그 + 값 칸, 16바이트). 정수·실수는 상자 없이 칸에 바로 들어간다. 긴 구조의 연쇄 해제는 재귀가 아니라 반복으로 한다.
    태스크 안은 원자적 연산 없는 `Rc`이고, 참조가 하나면 제자리 수정(Roc식, `Rc::make_mut`)도 가능하다.
  - 불변 값이라 태스크 사이의 "공유"와 "복사"를 프로그램이 구분할 수 없다. 여러 코어로 갈 때는 태스크마다 힙을 따로 두고 경계(`spawn`이 붙잡은 값,
    채널로 보낸 값, `await` 결과)에서만 복사한다(Erlang식; 큰 문자열만 공유하는 refc binary). 실행권 아래에서는 값 공유가 안전하므로 그때까지 미룬다.
  - 런타임은 `World`(공유, 실행권 아래)와 `Task`(태스크별)로 나뉘고, 내장 함수의 기본값은 `Lit`, 내장 함수 표는 프로세스에 하나(`OnceLock`)다.
- [x] `atom` → **없다. 공유되는 변경 칸 대신 `agent`** (3b, 2026-10-15; 노트 `docs/notes/R3b-agent.md`). **동시성 v2 L5(2026-10-18)에서 되돌렸다**: 엄격한 `atom`(05 "공유 상태: atom"). 아래는 3b 당시의 기록이다. 원칙 5·6에 맞추고 순환의 주된 원인을 없앤다.
  상태는 그 상태를 쥔 태스크가 들고 다른 태스크는 편지를 보낸다(Erlang·Elixir `Agent`). `agent(v)`·`swap(a, f)`·`deref(a)`, fung 코드 `extras/agent.fung`.
  - 에이전트는 배경 태스크다(프로그램 끝을 막지 않고 교착 집계에 따로 들며 되감기가 끝난 뒤에 취소). 핸들은 닫개: 마지막 사본이 사라지면 요청 채널을 닫아 에이전트가 끝난다.
  - `f`는 에이전트의 태스크에서 받은 순서대로 하나씩 돈다. 실패하면 상태는 그대로 두고 같은 에러를 부른 쪽 `swap(`에서 낸다. 자기 `f` 안의 같은 에이전트 `swap`은 E0704.
    `f`는 부른 태스크를 따른다: 부른 태스크가 취소되면 그 `f`도 취소되고 갱신은 반영되지 않는다(`CancelNode::also_under`).
  - 대가: 읽기·쓰기가 편지 왕복이라 자물쇠보다 느리다(`swap` 한 번 약 7 µs). 출력은 `<agent>`(값을 보이려면 에이전트에 물어야 해서).
- [x] 채널의 순환 → **유지하고, 채널에 그 채널 자신을 보내면 E0705** `channel sent into itself`(3b). `send(ch, v)`가 `v`를 재귀 없이 깊이 훑는다(공유된 부분은 한 번만, 에이전트 내부 요청은 검사 안 함).
  일반 채널은 보내는 쪽과 받는 쪽이 같은 값이라 자동으로 닫지 않는다(`close`로 닫음). 훑지 않는 곳과 비용은 아래 "알려진 한계".
