# M2. 변수와 흐름 — 무엇을 만들었고 왜 그렇게 했나

M2는 M1의 계산기에 **이름**과 **흐름**을 얹었다. 대입, 블록 스코프, `if`/`then`/`else`, 문자열·심볼·기간·`nil` 값,
스코프 규칙을 전부 검사하는 resolve, 소스 발췌가 붙은 에러 출력, `fail`. 그리고 M1 검토 후속 셋
(앞단 파이프라인 추출, 최소 정수 리터럴, 정확한 int/float 비교).

## 1. 한눈에

```
x = 1
if x > 0: y = x; print("y=${y}") ;;
```

**겉 문법 트리** (`fung dump ast`):
```
(program (assign x 1) (if (binary > x 0) (block (assign y x) (call print (interp "y=" y))) (nil)))
```

**코어 트리** (`fung dump core`, desugar + resolve 뒤):
```
(do (let (global 0) 1) (if (op > (global 0) 0) (do (let (local 0) (global 0)) (call (prelude print) (concat "y=" (local 0)))) (nil)))
```
이름이 사라졌다. `x`는 `(global 0)`, `y`는 `(local 0)`이다. 컴파일러와 VM은 이름 문자열을 모른다.

**바이트코드** (`fung dump bytecode`):
```
0000  1:5   CONST        0    ; 1
0001  1:1   STOREGLOBAL  0    ; x
0002  2:4   LOADGLOBAL   0    ; x
0003  2:8   CONST        1    ; 0
0004  2:6   GT
0005  2:6   JUMPIFFALSE  14
0006  2:15  LOADGLOBAL   0    ; x
0007  2:11  STORELOCAL   0
0008  2:18  CONST        2    ; <fn print>
0009  2:24  CONST        3    ; "y="
0010  2:29  LOADLOCAL    0
0011  2:24  CONCAT       2
0012  2:23  CALL         1
0013  2:1   JUMP         15
0014  2:1   CONST        4    ; nil
0015  1:1   RETURN
```

## 2. 이름 해석: 실행 중에 이름을 찾지 않는다

resolve(`internal/resolve`)가 트리를 한 번 훑으며 모든 이름을 **번호**로 바꾼다. 실행 중에는 맵 조회가 없다.
이것이 Python 같은 언어(실행 중 딕셔너리 조회)와 컴파일 언어의 중요한 차이이고, 09의 설계이기도 하다.

두 종류의 저장소가 있다.

- **전역** (`global n`): 파일 최상위에서 만든 이름. `Runtime`의 전역 표에 산다. M2에서는 슬롯으로도 충분하지만,
  M3에서 최상위 `fn` 안에서 최상위 변수를 "호출 시점에" 읽으려면 함수 프레임 바깥의 저장소가 필요하다. 지금 나눠 두면 M3가 재작업 없이 올라탄다.
- **슬롯** (`local n`): 블록(`if` 가지) 안에서 만든 이름. VM 스택의 프레임 칸에 산다. 블록이 끝나면 번호를 **재사용**한다.
  `if true: a = 1 ;; if true: c = 2 ;;`에서 `a`와 `c`는 둘 다 슬롯 0이다. `NumLocals`는 동시에 살아 있는 최대 개수(여기선 1)다.

`let`은 **오른쪽을 먼저** 해석하고 그 뒤에 이름을 묶는다. 그래서 `x = x + 1`에서 오른쪽 `x`는 이전 `x`이고,
처음 쓰는 자리라면 "정의 전 사용"(E0204)이다. 최상위도 위에서 아래 순서다: `print(x)` 다음 줄에 `x = 1`이 있으면 E0204.

## 3. 스코프 규칙의 구현

03의 규칙 세 개가 resolve의 판정 순서로 들어갔다.

| 상황 | 판정 | 에러 |
|------|------|------|
| `x = …`인데 **현재 스코프**에 `x`가 있다 | 재대입. 같은 칸 재사용 | 없음 |
| 현재 스코프엔 없고 **바깥 스코프**에 있다 | 바깥 변수 재할당 | E0205 + 힌트 |
| 어디에도 없다 | 새 이름. 파일 스코프면 전역, 아니면 슬롯 | 없음 |
| 이름을 **읽는데** 어느 스코프에도 없다, prelude도 아니다, **끝난 블록**에서 만든 이름이다 | 블록 밖 사용 | E0206 + 힌트 |
| 그 외 | 미정의 | E0204 (+ 비슷한 이름 힌트) |

"끝난 블록에서 만든 이름"은 블록이 닫힐 때 이름들을 `closed` 집합에 적어 두어 기억한다. 덕분에 `if c: y = 1 ;; print(y)`는
"정의되지 않았다"가 아니라 "블록 안에서 만든 이름이라 여기서 안 보인다"고 말하고, `y = if … ;;`로 쓰라고 안내한다:

```
error[E0206]: `y` is not visible here: it was defined inside a block
  --> -e:2:7
  |
2 | print(y)
  |       ^
  |
 help: assign the block's value instead: `x = if … ;;`
```

비슷한 이름 힌트는 편집 거리(Levenshtein)로 찾는다. 보이는 이름 전부 + prelude 중 거리 2 이하, 가장 가까운 것, 같으면 사전순 첫 것:

```
error[E0204]: undefined name `fiels`
  --> -e:2:7
  |
2 | print(fiels)
  |       ^^^^^ not found in this scope
  |
 help: a similar name exists: `files`
```

## 4. 블록과 값

`if … ;;`는 식이다. 각 가지는 코어 `(do …)`이고 값은 마지막 식의 값이다. 가지가 대입으로 끝나면 컴파일러가 `CONST nil`을 올린다
(01: 블록이 문장으로 끝나면 nil). `else` 없는 `if`의 else 가지는 `(nil)` 잎이다. 위 바이트코드의 14번 `CONST nil`이 그것이다.

파서의 작은 함정 하나: `print(if c:\n 1\nelse:\n 2\n;;)`처럼 **괄호 안에 블록**이 있으면, 괄호 안이라 줄바꿈을 무시하던 규칙을 블록 안에서는 다시 켜야 한다.
`body()`가 `nest`를 0으로 저장·복원해서 처리한다. 그리고 `if c: 1 ;; 2`는 에러다. 01의 EBNF에서 문장 구분자는 줄바꿈과 `;`뿐이고 `;;`는 아니다.

`then … else`는 우선순위가 가장 낮은 연산자다. 양쪽 가지는 완전한 식이라 `a then 1 else b then 2 else 3`이 오른쪽으로 묶인다.
`else`가 다음 줄 첫 토큰이면 줄 이어짐이다(01의 이어짐 전용 토큰 목록).

## 5. 문자열 보간

`"y=${y}"`는 렉서가 M1에서 이미 `[텍스트 "y=", 코드 "y"(위치 2:29)]`로 잘라 두었다. M2의 파서는 코드 조각을 `lexer.LexAt`로
**바깥 파일의 위치에서 이어서** 렉싱하고, 작은 파서를 하나 더 만들어 식으로 읽는다. 그래서 `"${1 +}"`의 에러 위치가 조각 안의 1:3이 아니라
파일 기준 줄·칸이다.

코어는 `(concat "y=" (local 0))`, 명령은 `CONCAT 2`다. VM은 n개를 꺼내 `FormatForPrint`로 이어 붙인다. 문자열은 따옴표 없이, 나머지는 리터럴 형태로.
`print`가 쓰는 규칙과 같다. 반대로 `Format`(리터럴 형태)은 문자열을 따옴표와 이스케이프로 감싸는데, `$`는 **`{`가 뒤따를 때만** `\$`로 쓴다.
`"cost $5"`는 그대로, `"tmpl ${x}"`는 `"tmpl \${x}"`로 나와야 다시 읽었을 때 보간이 되지 않는다.

## 6. 심볼, 기간, 정확한 비교

- **심볼**은 전역 인턴 표(이름 → 정수)로 만든다. `'ok == 'ok`는 정수 비교다. 표는 뮤텍스로 보호해 M7의 태스크들이 같이 써도 된다.
- **기간**은 `time.Duration`을 감싼 값이다. `+ -`는 기간끼리, `* /`는 숫자와, 비교는 값으로. 출력은 내림차순 성분(`1h30m`, `1s500ms`, `0.5ms`)이라 다시 읽힌다.
  곱셈·나눗셈 결과는 나노초로 **반올림**하고 int64를 넘으면 E0503이다 (M1 검토에서 렉서의 같은 문제를 고친 것과 같은 규칙).
- **정확한 비교**: `9007199254740993 == 9007199254740992.0`은 float64로 바꾸면 참이 되어 버린다(2^53 너머의 정수는 실수로 표현 불가).
  `cmpIntFloat`는 실수를 정수로 자른 뒤 정수끼리 비교하고, 같으면 소수 부분의 부호로 가른다. 실수가 int64 범위 밖이면 바로 답이 나온다.
- **최소 정수** `-9223372036854775808`: 렉서는 `9223372036854775808`만 특별 토큰으로 내보내고, 파서가 단항 `-` 바로 뒤에서만 접는다.
  `-(9223372036854775808)`처럼 괄호가 끼면 E0102다.

## 7. 에러 발췌

```
error[E0205]: cannot reassign `total` here: it was defined outside this block
  --> -e:4:10
  |
4 | if true: total = total + 1 ;;
  |          ^^^^^
  |
 help: a block cannot change an outer variable; build the value with an expression instead, e.g. `x = if … ;;` or `fold`
```

`diag.Error`에 `Len`(밑줄 길이)과 `Help`(개별 힌트)가 생겼다. resolve가 이름 길이를 `Span`으로 넣고, `Format(e, src)`가 해당 줄을 찾아
탭을 공백 4개로 바꾸고(그래야 `^`가 제자리를 가리킨다) 거터 너비를 줄 번호 자릿수에 맞춘다. 라벨(`not found in this scope`)은 번호별 표에서 온다.

## 8. 파이프라인 추출

M1 검토에서 "앞단 파이프라인이 다섯 군데에 복사되어 있다"는 지적이 있었다. `internal/frontend.Compile(file, src, prelude, stage)` 하나로 모았다.
`cmd/fung`과 VM 테스트가 쓰고, M5의 `import`와 M6의 REPL·`check`도 이것을 부른다. `desugar`·`resolve`·`compiler`의 자기 테스트는
frontend가 그 패키지들을 import하므로(순환) 작은 도우미를 그대로 둔다.

## 9. 테스트

골든 파일 20개 추가(총 33). 값·흐름 9개와 에러 11개. 단위 테스트는 패키지마다. 실행하면서 계획의 기대값이 틀린 곳이 셋 있었다:
`if c: 1 ;; 2`를 허용한다고 쓴 것(EBNF상 에러), `y = x`의 바이트코드를 `CONST`로 쓴 것(`LOADGLOBAL`), `"C:\new"`를 이스케이프 에러로 쓴 것(`\n`은 유효).
세 번 모두 **코드가 아니라 테스트를** 고쳤다. 사양이 기준이다.
