# M6. 개발 도구 — 무엇을 만들었고 왜 그렇게 했나

M6는 언어를 "쓸 수 있는 도구"로 만든다. `test "…": … ;;`와 `assert`, `fung test`, `fung check`, 경고(W0101·W0102·W0103),
REPL(줄 편집 직접 구현), `dbg`. 그리고 M4·M5에서 미룬 작은 결함을 정리했다. 이것으로 알파 기준(M0~M6)에 닿는다.

## 1. 한눈에

```
fn double(x) = x * 2
assert double(2) == 5
```

`fung dump bytecode`의 `<main>`:
```
0000  CLOSURE      0    ; double
0001  STOREGLOBAL  0    ; double
0002  LOADGLOBAL   0    ; double
0003  CONST        0    ; 2
0004  CALL         1
0005  CONST        1    ; 5
0006  ASSERT       0    ; double(2) == 5
0007  CONST        2    ; nil
0008  RETURN
```

`assert a == b`는 **양쪽을 따로 계산해 두고** `ASSERT k` 한 명령이 비교한다. k는 Proto의 `Asserts` 표를 가리키고 거기에
식 전체의 텍스트(`double(2) == 5`), 왼쪽 텍스트(`double(2)`), 오른쪽 텍스트(리터럴이라 빈 문자열), 연산자(`==`)가 있다.
실패하면:
```
error[E0807]: assertion failed: double(2) == 5
  --> t.fung:2:1
  ...
  double(2) = 4
```
양쪽을 **한 번씩만** 평가하는 것이 요점이다. 실패 메시지를 위해 식을 다시 평가하면 부수효과가 두 번 난다.

## 2. 소스 구간(span)을 토큰과 노드에 더한 이유

`assert`와 `dbg`는 "식의 소스 텍스트"를 보여 줘야 한다. 지금까지 노드는 시작 위치(줄·칸)만 알았다. M6에서 렉서가 토큰마다
바이트 오프셋(`Off`, `End`)을 기록하고, 파서의 `expr()`이 식 하나를 끝낼 때마다 "시작 토큰의 Off ~ 마지막으로 소비한 토큰의
End"를 노드에 적는다. 문장도 같다. desugar와 resolve는 노드를 새로 만들 때 **원래 노드의 구간을 물려받는다**(`walk`
포장 함수 한 곳에서). 그래서 컴파일러는 원문을 `src[n.Off:n.End]`로 자르기만 하면 된다. 바이트 단위라 한글이 섞여도 정확하다.

## 3. `test` 블록이 함수인 이유

`test "이름": … ;;`은 desugar가 **인자 없는 함수**로 바꾼다. 세 가지가 따라온다.
- 모델 C(03): 그 자리에서 만들어지므로 그때 보이는 파일 변수를 복사한다. 뒤에서 `x = 2`로 바뀌어도 테스트는 정의 당시의 `x`를 본다.
- 실패해도 다음 테스트가 돈다: 함수 호출 하나가 에러로 끝난 것뿐이다. 되감기 규칙을 새로 만들 필요가 없다.
- `return`과 `?`를 테스트 안에서 쓸 수 있다.
`fung run`은 이 함수를 **아예 만들지 않는다**(컴파일러 옵션 `Tests`가 꺼져 있으면 코드가 0줄). `fung test`·`check`만 `CLOSURE; TEST k`를 내고
`TEST`가 Runtime의 테스트 표에 등록한다. 최상위에서만 허용(E0114)하므로 "진입 파일의 코드에 `TEST`가 있는가"로 테스트 유무를 실행 전에 안다.

## 4. `fung test`의 실행 모델

파일마다 새 Runtime을 만들고, prelude를 부트하고, `Tests: true`로 적재한 뒤 **최상위를 먼저 실행**(변수와 함수가 생긴다),
등록된 테스트를 순서대로 `CallTest`한다. 테스트 없는 파일은 최상위도 돌리지 않고 건너뛴다 — 그렇지 않으면 `fung test .`가
디렉터리의 모든 스크립트를 실행해 버린다(실제로 `rename.fung`이 인자 없이 돌다 실패했다).
종료 코드 우선순위: 컴파일 실패 2 > 테스트 안 `exit(n)`의 n > 실패 1 > 0. `exit`는 그 파일의 남은 테스트를 멈춘다.
import된 모듈의 테스트는 그 파일을 직접 지정했을 때만 돈다 — importer를 테스트하는데 라이브러리 테스트가 딸려 돌면 "무엇을
테스트했는지"가 흐려진다.

## 5. 경고를 resolve가 내고 `run`은 침묵하는 이유

쓰지 않는 이름(W0102), 쓰지 않는 import(W0101), prelude 이름 가리기(W0103)는 전부 **이름이 어디서 묶이고 어디서 읽히는가**의
문제라 resolve가 이미 아는 정보다. 블록이 닫힐 때(`popBlock`) "읽힌 적 없는 이름"을 보고하면 된다. 매개변수와 `_`로 시작하는
이름, 파일 전역(모듈의 API)은 제외한다. 라이브러리 파일의 최상위 이름은 W0103에서도 제외한다 — `path.join`은 prelude의 `join`을
가리는 게 아니라 모듈의 이름이다(처음엔 이걸 놓쳐서 표준 라이브러리가 자기 경고를 냈다).
`fung run`이 경고를 내지 않는 것은 08의 결정이다: cron 로그와 골든 테스트의 "stderr는 비어 있다" 규칙을 지키기 위해서다.

## 6. REPL — 줄마다 컴파일, 이름은 유지

REPL의 한 줄은 **진입 파일 하나**로 컴파일된다. 다른 점은 resolve가 "지금까지의 전역 이름 목록"을 받아 같은 번호로 미리 묶는
것(`Options.Globals`)과, 함수·모듈 재정의를 허용하는 것(`Redefine`)뿐이다. 실행은 같은 Runtime 위에서 하므로 값도 남는다.

재정의가 **이전 클로저에도** 보여야 한다(`fn f() = g()` 뒤에 `g`를 다시 정의하면 `f()`가 새 `g`를 불러야 한다). 클로저는 전역
표의 슬라이스 헤더를 들고 있으므로 같은 배경 배열이면 보인다. 그래서 REPL은 전역 표를 **용량 65536으로 한 번에** 할당해
재할당이 일어나지 않게 한다(M5에서 미룬 "재할당 문제"의 답). 넘으면 E0806.

"더 입력을 받을지"는 파서에게 묻는다: 지금까지의 텍스트를 파싱해서 **에러 위치가 EOF 토큰이면** 아직 안 끝난 것이다. 블록이
열려 있거나 줄이 연산자로 끝나는 경우를 규칙 하나로 덮는다.

## 7. raw 모드 줄 편집기

터미널은 기본적으로 한 줄을 다 받은 뒤에야 프로그램에 넘긴다(canonical 모드). 화살표·기록을 지원하려면 키 하나하나를 받아야
하므로 `termios`로 ECHO·ICANON·ISIG를 끈다. Go 표준 라이브러리에는 `golang.org/x/term`이 없지만 `syscall`의 `Termios`와
`SYS_IOCTL`이 있어서 darwin(`TIOCGETA/TIOCSETA`)·linux(`TCGETS/TCSETS`) 두 파일로 끝난다. 화면 그리기는 `\r` + 프롬프트 +
텍스트 + `\x1b[K`(줄 끝 지움) + `\x1b[nD`(커서 왼쪽 이동)의 네 가지 이스케이프뿐이다.
편집 상태(`Editor`)는 터미널과 분리된 순수 타입이라 키 입력 시퀀스로 테스트한다. 터미널이 아니면(파이프, Windows) 보통 줄
읽기로 바뀌어 `echo 'print(1)' | fung`이 된다.

## 8. `dbg`가 컴파일러 특수화인 이유

`dbg(e)`는 `e`의 소스 텍스트를 보여 줘야 하는데, 보통 함수는 인자의 값만 받는다. 컴파일러가 "callee가 prelude의 `dbg`이고 위치
인자 하나"인 호출을 보면 텍스트와 `파일:줄` 상수를 인자로 덧붙인다. `dbg`를 변수에 담아 부르면 보통 호출이라 값만 찍힌다.
출력은 stderr다 — stdout은 파이프라인 결과용이다.

## 9. 정리한 결함

`int("1_")`처럼 `_` 위치가 틀린 수는 거부(01: 숫자 사이에만), `sym("a b")`는 이름 규칙에 맞을 때만, `repeat`·`pad_*`는 1억 룬
상한(E0806), 빈 pad 문자열은 E0403, 쓰기 전용 핸들의 `read_line`은 `'invalid`, 순환 import 메시지는 경로로, E0309 문구.

## 10. 알파 기준과 다음

M0~M6가 끝났고 골든 116개, `examples/kebab.fung`의 테스트가 `fung test examples/`로 돈다. 알파 기준의 나머지는 "실제 스크립트
2~3개를 fung으로 써서 일상에서 쓴다"이고, 그 경험으로 prelude와 모듈 목록을 조정한다(open-questions). 그 다음은 M7 동시성.
