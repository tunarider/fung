# M9 포맷터 — 무엇을 만들었고 왜 그렇게 했나

2026-10-14. 계획 `docs/plans/2026-10-14-m9-formatter.md`, 스펙 `docs/superpowers/specs/2026-10-14-formatter-design.md`.

`fung fmt`는 `.fung` 파일의 공백·들여쓰기·빈 줄·정렬을 단일 스타일로 바로잡는다. `gofmt`처럼 옵션이 없고, 줄바꿈은 사용자가
쓴 대로 둔다. 패키지 `internal/format` 약 450줄, 명령 `cmd/fung/fmt.go`.

## 1. 토큰 재배치 — AST로 다시 찍지 않은 이유

포맷터를 만드는 길은 둘이다. (A) 토큰 열을 받아 공백과 들여쓰기만 다시 쓰기, (B) AST에서 코드를 새로 찍어 줄 너비에 맞춰 접기(prettier).

(A)를 골랐다. 이유 셋.

- **주석.** (B)는 주석을 AST 노드에 붙여야 한다("이 주석은 어느 식에 속하나"). 그 규칙은 어떤 언어에서도 깔끔하지 않다. (A)는 주석이
  원래 줄에 그대로 남는다 — 렉서가 주석을 trivia 목록(`Comment{Pos, Text}`)으로 따로 돌려주므로(09의 결정), 줄 번호만으로 붙일 수 있다.
- **검증.** 출력을 다시 렉싱해 **토큰 열(줄바꿈 제외)이 입력과 같은지** 기계적으로 확인할 수 있다. 다르면 쓰지 않고 내부 오류로 거부한다.
  이 안전장치 덕에 "포맷터가 코드를 망가뜨리는" 종류의 버그는 원천적으로 사용자에게 닿지 않는다.
- **의도 존중.** `match x: 0 => 1; _ => 2 ;;`를 한 줄로 쓴 사람은 그렇게 두고 싶은 것이다. 들여쓰기가 의미 없는 문법(01)이라
  들여쓰기만 바로잡아도 효과의 대부분을 얻는다.

## 2. 들여쓰기 상태 기계

줄 시작마다 "지금 무엇이 열려 있나"를 보고 들여쓰기를 정한다. 핵심 자료구조는 **열린 것들의 스택**이고, 각 항목은 블록(`fn`·`if`·
`match`·`for`·`test` 뒤의 `:` … `;;`) 또는 괄호이며, **그것을 연 줄의 들여쓰기(base)** 를 기억한다.

- 보통 줄: 가장 안쪽 항목의 base + 1.
- 닫는 토큰(`;;` `)` `]` `}`)으로 시작하는 줄: 그 항목의 base. 이 규칙 하나로 `each(xs, fn(x):` … `;;)`가 자연스럽게 맞는다 —
  `;;`가 닫는 블록의 base는 `each(` 줄이므로 `;;)`는 그 줄 위치로 돌아간다. 괄호와 블록을 같은 스택에 두되 "줄의 들여쓰기"를
  기억하는 것이 이 문제의 열쇠였다. 깊이를 "열린 개수"로 세면 `each(xs, fn(x):` 뒤의 본문이 +2가 되어 버린다.

### 블록은 어디서 열리나

`:`은 맵 키·이름 인자·타입 표기에도 쓰이므로 `:`을 볼 때마다 블록을 열 수는 없다. 대신 블록 키워드를 보면 "**같은 괄호 깊이의 다음
`:`을 기다린다**"고 기록한다. `fn f(x: int) -> int:`에서 `x: int`의 `:`은 괄호 안(깊이 +1)이라 걸리지 않고, `->` 뒤의 `:`이 블록을 연다.
`fn f(x) = e`처럼 `:`이 안 오면 다음 문장이 시작될 때 기다림을 버린다.

### `else`의 두 뜻

`else`는 `if` 체인의 `else`(`if`와 같은 깊이)이기도 하고 `c then a else b`의 일부이기도 하다. 같은 문장에서 짝이 없는 `then`을
괄호 프레임마다 세어 두고, `else`가 오면 짝이 있으면 식의 이어짐(+1), 없으면 체인(`if` 블록을 닫고 `else …:`가 다시 연다)으로 본다.
파서와 같은 판단을 토큰 수준에서 흉내 낸 것이다.

### `match` 절

절 본문이 다음 줄로 넘어가면 절보다 +1이어야 한다. "이 줄이 절인가"는 파서와 같은 규칙으로 판정한다: **괄호 밖에 `=>`가 있으면
절**. `xs |> map(x => x)`의 `=>`는 괄호 안이라 절이 아니다. 01에 적힌 파서의 대가("절 본문의 람다 단독 문장은 새 절로 읽힌다")가
여기서도 그대로다 — 포맷터와 파서가 같은 모호함을 같은 쪽으로 푼다.

### 이어지는 줄

01의 줄 이어짐 규칙 둘을 그대로 쓴다: 다음 줄이 `|>` `.` `??` `and` `or` `then` `else`로 시작하거나, 앞 줄이 식을 끝낼 수 없는
토큰(이항 연산자·`=`·`=>`·`->`·`.`)으로 끝났으면 문장보다 +1. 두 번째 규칙은 저장소를 포맷해 보고 추가했다 — `fn f(x) =` 다음 줄의
본문이 0으로 떨어졌다. 괄호 안에서는 괄호가 이미 +1을 주므로 이어짐이 더 들여쓰지 않는다.

## 3. 토큰 사이 공백

인접한 토큰 쌍마다 0칸/1칸을 정하는 표 하나(`spacing.go`의 `gap`). 까다로운 것은 셋.

- **접두 `-`**: `a - b`와 `-x`는 토큰이 같다. 앞 토큰이 연산자·여는 괄호·`,`·`=>`·`=`·예약어이거나 줄 처음이면 접두다.
- **호출 괄호**: `f (x)` → `f(x)`. 앞 토큰이 이름·태그·`)`·`]`일 때만. 문자열은 호출할 수 없으므로 `import "./x" (a)`는 공백을
  지킨다(저장소를 포맷하다 잡은 버그). `import fs (read)`는 이름 뒤 괄호라 호출로 보이므로 import 줄은 따로 예외.
- **`;;)`**: `;;` 뒤에 닫는 괄호가 오면 붙인다.

문자열·숫자·기간은 토큰 원문(`src[Off:End]`)을 그대로 쓴다. `Token.Text`는 따옴표가 빠져 있어 쓰면 안 된다.

## 4. 정렬

꼬리 주석 열 맞춤과 `match` 절의 `=>` 맞춤은 **같은 메커니즘** 하나로 한다: 연속 줄 묶음에서 최대 너비를 재고 그에 맞춰 채운다.
`=>` 정렬에서는 절 본문 줄(더 깊은 줄)이 묶음을 끊지 않게 "통과 가능한 줄" 조건을 뒀다(01의 예시 `Ok(text) =>` / `Err(e)   =>`).
`=>`를 먼저, 주석을 나중에 맞춘다 — 반대로 하면 `=>`를 채운 뒤 주석 열이 틀어진다.

너비는 룬 수로 센다. 표시 폭 표는 REPL과 같은 보류 항목이라, 한글이 든 줄은 한두 칸 어긋날 수 있다.

## 5. 명령과 안전장치

`fung fmt <path>...`는 제자리에 쓰고 바뀐 파일 이름을 찍는다. `--check`는 이름만 찍고 종료 코드 1(CI용). `-`는 stdin → stdout.
구문 에러 파일은 에러를 찍고 건드리지 않는다(2). 디렉터리 순회는 `_`·`.`로 시작하는 디렉터리를 건너뛴다(`.git`, `.claude`의
작업 트리 복사본).

`tests/fmt_test.go`가 저장소의 모든 `.fung`이 `--check`를 통과하는지 지킨다. `tests/lang`의 `err_*.fung` 중 일부러 구문 에러인
파일은 포맷터가 거부하므로(2) 건너뛴다.

## 6. 저장소를 포맷하며 배운 것

- 버그 둘(import 괄호, 줄 끝 연산자 이어짐)은 **실제 코드를 돌려 봐야** 나왔다. 표 기반 테스트는 내가 떠올린 경우만 덮는다.
  스펙에 "저장소 전체를 포맷해 보는 단계"를 넣어 둔 것이 맞았다.
- 긴 `when` 조건이 있는 절과 `_` 절이 나란히 있으면 `=>`가 멀리 밀린다(`cli.fung`에서 39칸). `gofmt`의 구조체 정렬과 같은 성질이라
  받아들였다. 거슬리면 "너비 차가 N 이상이면 묶음을 끊는다" 같은 상한을 두는 것이 다음 손질 후보.
- 예제의 `else` 이어짐 줄이 모두 +1로 들어갔다. 원래는 첫 줄과 같은 깊이로 쓴 곳이 있었는데, 규칙이 하나인 편이 낫다.
