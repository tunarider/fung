# L17. 화면의 칸: 글자 묶음 단위로

0.5.0 큰 문제 L17(`docs/plans/0.5.0/17-display-width.md`)을 고치며 배운 것.

## 1. "글자"는 세 가지다

유니코드에서 "글자 하나"는 적어도 세 가지 뜻이다.

- **바이트**: UTF-8로 쓴 크기(`byte_len`). `é`는 2바이트, 👨‍👩‍👧는 18바이트.
- **코드 포인트**: 유니코드 번호 하나(fung의 `len`·`s[i]`·`chars`, L4). `é`를 미리 합친 꼴(U+00E9)은 1개, `e` + 결합 악센트(U+0301)는 2개, 👨‍👩‍👧는 5개(👨 ZWJ 👩 ZWJ 👧).
- **글자 묶음**(grapheme cluster, UAX #29): 사람이 "글자 하나"로 보는 것. 위의 셋은 모두 묶음 하나다.

터미널은 묶음을 한 덩어리로 그린다. 그래서 화면의 칸을 세는 일(포매터의 정렬, 에러 밑줄, REPL 커서)은 묶음 단위여야 한다.
전에는 코드 포인트마다 UAX #11 너비를 더해서, 가족 이모지를 6칸(2 + 0 + 2 + 0 + 2)으로, `❤️`(U+2764 + VS16)를 1칸으로 봤다. 터미널에서는 둘 다 2칸이다.
진단의 밑줄은 아예 글자 수로 그어서 한글 뒤에서도 어긋났다. 같은 "칸"을 세 곳이 세 규칙으로 셌다.

## 2. 묶음 나누기(UAX #29)

묶음의 경계는 이웃한 두 글자의 `Grapheme_Cluster_Break` 값과 몇 가지 앞쪽 상태로 정한다. 규칙은 번호가 붙어 있다.

- GB3~5: CR LF는 붙고, 제어 문자 앞뒤는 끊는다.
- GB6~8: 한글 자모 L·V·T와 음절 LV·LVT가 이어지면 붙는다(옛 한글 조합).
- GB9·9a·9b: 결합 문자(Extend)·ZWJ·SpacingMark 앞, Prepend 뒤는 붙는다.
- GB9c: 인도계 문자의 결합 자음(`InCB=Consonant` + 링커 + 자음).
- GB11: 이모지 + Extend* + ZWJ 뒤의 이모지는 붙는다(👨‍👩‍👧).
- GB12·13: 지역 표시 글자는 둘씩 짝(🇰🇷).
- 그 밖은 끊는다.

GB9c·GB11·GB12는 "앞에 무엇이 있었나"를 기억해야 해서 작은 상태(`Run`)를 들고 간다. 유니코드가 내는 `GraphemeBreakTest.txt`(1,000개 남짓의 사례)를 그대로 시험으로 돌린다.
앞단은 크레이트를 쓰지 않으므로(의존성 정책) 규칙은 직접 짜고, 표는 지금처럼 UCD에서 만들어 `spec/unicode.txt`에 넣는다.

## 3. 묶음 하나의 너비

정답이 하나가 아니다. 흔히 쓰는 규칙을 택했다: VS16(U+FE0F, "이모지로 그려라")이 있으면 2칸, VS15(U+FE0E, "글자로 그려라")면 1칸,
첫 글자가 `Emoji_Presentation`이거나 국기면 2칸, 그 밖에는 첫 글자의 UAX #11 너비. 첫 글자를 보는 까닭은 묶음의 나머지가 결합 문자·ZWJ·수식이라 칸을 늘리지 않기 때문이다.

이 규칙은 묶음 단위로 그리는 요즘 터미널과 맞는다. 코드 포인트 단위(`wcwidth`)로 그리는 터미널과는 이모지에서 다르다. 어느 쪽을 택해도 어떤 터미널과는 다르므로, 유니코드의 권고와 흐름을 따랐다.

## 4. 칸 번호와 화면의 칸은 다르다

에러의 `--> 파일:2:7`은 **글자 번호**로 두었다. 편집기가 커서 위치를 세는 방식이고, LSP 같은 도구가 쓰는 번호(코드 포인트·UTF-16·바이트)와도 표시는 섞지 않는 편이 낫다.
밑줄을 **그릴 때만** 화면의 칸으로 바꾼다: 밑줄 앞의 글과 밑줄 아래의 글을 재서 공백과 `^`의 수를 정한다. 그래서 `없는`(두 글자) 아래에 `^^^^`(네 칸)가 온다.
하나 걸린 것: 파일 맨 앞의 BOM(U+FEFF). 렉서는 BOM 뒤부터 칸을 세는데, 처음 짠 판은 발췌 줄의 BOM을 글자로 세어 밑줄이 한 칸 앞에 왔다.
전의 코드는 BOM을 글자로 세고 화면에서도 1칸으로 쳐서, 틀린 것 둘이 서로 지워 우연히 맞았다. 포매터 시험이 모든 시험 파일을 BOM을 붙여 다시 돌리는 덕에(`@bom` 변형) 잡혔다.

## 5. 한 함수로

칸을 세는 곳(포매터·진단·REPL)이 모두 `unicode::cluster_width`(와 그 합 `display_width`)를 거친다. 글자 하나의 너비 함수는 감췄다(`char_width`): 다시 글자 단위로 세는 코드가 생기지 않게.
REPL은 글자 배열을 들고 있으므로 묶음의 경계를 글자 번호로 주는 `char_boundaries`를 두어, 화살표·Backspace·Delete가 경계에서 경계로 움직인다.
