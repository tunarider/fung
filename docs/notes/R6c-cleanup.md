# R6c 이식 잔가지 정리: 무엇을 했고 왜 그렇게 했나

2026-10-17~18. 스펙 `docs/superpowers/specs/2026-10-17-rust-port-cleanup-6c-design.md`(4절에 하위 단계마다 결정표),
계획 `docs/plans/2026-10-17-rust-port-cleanup-6c-1.md` ~ `docs/plans/2026-10-18-rust-port-cleanup-6c-7.md`.
이식 전체의 기록은 `R-port-record.md`(open-questions에 있던 "Rust 이전" 절을 옮긴 것).

6b에서 Go 구현을 지웠지만, Rust 코드에는 Go와 바이트 단위로 같은 출력을 내려고 붙인 동작·이름·주석이 많이 남아 있었다.
에러 문구, 정규식 파서, 시간 서식, HTTP 문구, 도구의 경로 규칙 같은 것이다. 6c의 목표는 "처음부터 Rust로 짠 것 같은 저장소"다.
**완료 기준**은 코드에 "Go"라는 낱말이 없고, 현재 문서에는 언어 비교 문장만 남는 것이다. 지금은 지킴이 테스트
(`crates/fung-cli/tests/repo_rust_only.rs`)가 이를 지킨다.

## 1. 판단의 원칙

1. **"Go가 그랬다"는 이유가 아니다.** 흉내 동작마다 그 자체로 판단했다. 바른 규칙이면 남기고 이름과 주석만 고쳤다.
   (예: RFC 9110의 이유 문구 표, 레코드 사이의 TCP 끝을 스트림 끝으로 보는 TLS 규칙, SIGPIPE로 죽기)
2. **대체 동작이 Rust 표준 동작의 노출이어서도 안 된다.** `io::Error`의 `No such file or directory (os error 2)`를 그대로 내지 않는다.
   대신 fung의 규칙을 정하고 설계 문서에 적었다. "구현 언어가 새어 나오지 않게"(00)는 Rust에도 똑같이 적용된다.
3. **바른 동작을 먼저 정한다.** 설계 문서와 `tests/lang`·단위 테스트에 정한 뒤 코드를 바꿨다(TDD: 실패를 먼저 보고). 그다음 그 영역의
   기대 출력을 bless하고 diff를 검토했다.
4. **호환성은 고려하지 않는다.** 사용자가 아직 없다. 바뀐 점은 CHANGELOG `[Unreleased]`에 적는다.

## 2. 하위 단계

| 단계 | 영역 | 핵심 결정 | 커밋 |
|---|---|---|---|
| 6c-1 | 기반 | 이름은 UAX #31(+ NFC 정규화), `upper`·`lower`는 전체 매핑, 원소·글자 1억 개 한도(E0806), 표준 입력 64 KiB, `float`은 리터럴 문법, 채널 순회는 스트리밍, 안정 병합 정렬 | `14b3297..8195207` |
| 6c-2 | 파일 시스템·OS | 흔한 OS 에러는 종류별 fung 문구(플랫폼마다 같음), `remove_all`의 안전 규칙, `glob`은 패턴 전체를 먼저 검사, 버린 핸들도 비움, 따옴표는 fung 문자열 리터럴 | `f2adbd0..3be78a5` |
| 6c-3 | 시간·JSON | 시각은 유닉스 초 + 나노초(0000~9999년), C 라이브러리의 `TZ` 규칙과 POSIX 문자열, 서머타임 경계의 명시적 규칙, 엄격한 RFC 3339, JSON은 반복 파서·같은 키 거절·필요한 것만 이스케이프 | `185feba..e5301a9` |
| 6c-4 | 정규식 | 문법은 `regex` 크레이트의 것(유니코드 클래스), 옮긴 Go 파서와 데이터 삭제, `split`은 끝의 빈 매치로 자르지 않음 | `5e60595..7519228` |
| 6c-5 | 네트워크·HTTP | 네이티브는 짧은 이유만, `http`가 맥락을 붙임, rustls의 검증기, `User-Agent: fung/<버전>`, 요청 `timeout` 하나, 리다이렉트 본문을 읽지 않음, 사용자 `Host`, 서버의 `<코드> <이유>` 본문 | `8ad9a86..942a6e4` |

| 6c-7 | 마무리 | 기간 뺄셈과 슬라이스 에러의 인덱스, 줄 편집기의 디코딩·커서, 남은 주석과 이름, 문서, 06 파일 이름, 지킴이 | `b6e6b6c..` |

## 3. 언어를 만들며 배운 것

**에러 문구는 층을 나눈다.** 6c-5에서 소켓 네이티브는 `connection refused` 같은 짧은 이유만 돌려주고, `http`가
``cannot request `url`: `` 같은 "무엇을 하다가"를 붙이게 했다. 예전에는 Go처럼 층마다 자기 접두사(`Get "url": dial tcp …: connect: …`)를 붙여
같은 정보가 겹쳤다. 한 층이 한 가지만 말하면 읽기 쉽다. 대신 위층이 아래층의 문구를 비교해 분기하면 안 된다. 문구를 바꾸자 서버의 받기
루프가 닫힌 리스너를 알아보지 못하는 회귀가 실제로 났다(6c-5). 그래서 비교가 필요한 곳은 문구를 상수로 두고 테스트로 묶었다.

**유니코드는 표준을 고르면 결정이 쉬워진다.** 식별자(UAX #31), 정규화(NFC), 표시 너비(UAX #11), 잘못된 UTF-8(부분마다 U+FFFD 하나)이
모두 이미 정해진 답을 가진 문제였다. 표는 유니코드 데이터 파일에서 Rust 생성기로 만들고(`spec/unicode.txt`), 평소 테스트는 고정 파일을 읽는다.
"잘못된 UTF-8을 어떻게 읽는가"는 렉서·포매터·REPL·파일 읽기가 모두 같은 규칙을 써야 했다. 한 곳만 다르면 열 번호와 발췌가 어긋난다.

**경계에서 감기지 않게 한다.** `[1,2,3][0..=9223372036854775807]`의 에러가 감긴 음수를 보였고, 기간 뺄셈은 결과가 범위 안이어도 넘침이었다.
둘 다 내부 계산을 넓은 정수(i128)로 하거나 결과만 검사해서 고쳤다. 사용자에게 보이는 값은 **사용자가 쓴 값**이어야 한다.

**규칙이 둘이면 하나로.** `test`와 `fmt`가 디렉터리를 다르게 걷고, REPL의 두 읽기 길이 줄 끝을 다르게 떼었다. 원칙 7("규칙 하나에서 결과가
따라 나와야")에 따라 하나로 모았다.

**흉내를 걷어낼 때도 표준은 남는다.** HTTP의 Go 동작 상당수는 사실 RFC 9110·9112의 규칙이었다. 걷어낸 것은 Go의 문구와 Go가 연결
재사용을 위해 하던 일(리다이렉트 본문 2 KB 읽기)이고, 표준의 규칙(이유 문구, `Date` 형식, 1xx 처리)은 출처를 RFC로 바꿔 남겼다.

## 4. 검증

- 하위 단계마다: 고친 테스트만 돌려 실패와 통과를 보고, bless는 그 영역의 기대 출력만 했다. 3,500여 개를 한꺼번에 bless하면
  의도한 변경과 사고를 가려낼 수 없다.
- 하위 단계 끝마다: 다른 모델의 최종 리뷰(사소한 것까지 목록), 한 번에 고치기, 진행 기록에 판단을 남기기.
- 6c 끝에 한 번: 커밋 전 검사 전체(fmt, clippy 디버그·릴리스, 테스트 디버그·릴리스, deny, audit).
- 지킴이: 낱말 단위로 그 언어의 이름을 찾는다. 바늘은 조각으로 만들어 테스트 파일 자신에 걸리지 않는다. 범위에서 빼는 것은 역사 문서
  (`docs/notes`·`docs/plans`·`docs/superpowers`·`CHANGELOG.md`)뿐이고, 허용 목록은 언어 비교 문장의 (파일, 조각) 쌍이다.
