# M7. 동시성 — 무엇을 만들었고 왜 그렇게 했나

M7은 태스크(`spawn`·`await`·`cancel`), 채널(`channel`·`send`·`recv`·`close`, 채널 순회), `atom`(`swap`·`deref`), `sleep`,
종료 규칙(남은 태스크 대기, 기다리지 않은 실패는 종료 코드 1, 어느 태스크의 `exit`든 프로그램 종료), 런타임이 직접 세는
교착 감지, 출력 원자성, 그리고 fung으로 쓴 `fan_in`·`pmap`·`retry`다.

## 1. 한눈에: 새 명령이 없다

```
t = spawn(() => 1 + 1)
print(await(t))
```
```
0000  CONST        0    ; <fn spawn>
0001  CLOSURE      0    ; <lambda>
0002  CALL         1
0003  STOREGLOBAL  0    ; t
0004  CONST        1    ; <fn print>
0005  CONST        2    ; <fn await>
0006  LOADGLOBAL   0    ; t
0007  CALL         1
0008  CALL         1
```

`spawn`과 `await`는 **보통 내장 함수 호출**이다. 바이트코드에도 VM 루프에도 동시성 전용 명령이 하나도 없다. 가능한 이유는 두 가지:
값이 불변이라 태스크끼리 그냥 공유해도 안전하고(바뀌는 것은 atom뿐), VM 상태(스택·프레임)가 처음부터 `Task`별로 분리되어
있었기 때문이다(M1의 결정이 여기서 값을 했다). 동시성은 "값 세 종류 + 내장 함수 열한 개"로 끝난다.

## 2. 태스크 = 고루틴 + Task

`spawn(f)`는 새 `Task`(자기 스택·프레임)를 만들고 고루틴에서 `f`를 부른다. 결과는 `TaskHandle`에 저장되고 `done` 채널이 닫힌다.
`await`는 `done`을 기다렸다가 저장된 결과를 돌려주므로 몇 번을 불러도 같다. 태스크 값은 `Opaque`(리터럴 없음, 동일성 비교,
`<task>` 출력)다. 내장 함수가 사용자 람다를 되부를 때(`map`의 `f`)는 **같은 태스크의 VM**을 쓴다 — 그래서 `pmap`이 fung 코드로
`spawn`을 써서 병렬을 만들 수 있다.

## 3. 취소: context 트리와 플래그 하나

태스크마다 `context.Context`가 있고 자식은 부모의 `WithCancel`로 만든다. 그래서 부모를 `cancel`하면 손자까지 취소된다(고아가 남아
프로그램 종료를 막지 않는다). 취소를 **확인하는 곳**은 둘이다: VM의 `enter`(모든 호출)가 원자적 플래그 하나를 읽고, 막히는
연산(`sleep`·`recv`·`send`·`await`·`swap`)이 `ctx.Done()`을 같이 기다린다. 취소된 태스크는 E0701로 되감기는데, 이 번호는
사용자에게 보이지 않는다: `await`가 `Err({kind: 'cancelled})`로 바꾸고, 기다리는 이가 없으면 조용히 끝난다(취소는 실패가 아니다).
협조적 취소의 한계: 루프 없는 긴 계산은 다음 호출까지 멈추지 않고, 감싸는 함수의 정리(`with_open`의 `close`)는 실행되지 않는다(03).

## 4. 결과 네 가지와 "기다리지 않은 실패"

`await`의 결과는 값 / `Err cancelled` / `Err timeout` / `Err({kind: 'error, message})`다. 런타임 에러로 죽은 태스크를 아무도
기다리지 않으면 **죽는 순간** `task failed:`를 stderr에 찍고 Runtime의 `failed`를 세워 종료 코드를 1로 만든다. 끝날 때 모아서 찍지
않는 이유는 서버 스크립트가 끝나지 않기 때문이고, 즉시 중단하지 않는 이유는 요청 하나가 서버 전체를 죽이면 안 되기 때문이다(05).

## 5. 교착을 직접 세는 이유

Go 런타임의 "all goroutines are asleep"은 **복구할 수 없는 치명 에러**라 Go 스택 추적이 그대로 나온다. 그래서 런타임이 센다:
`live`(fung 코드를 도는 태스크 수), `blocked`(원시 연산에서 막힌 수), `waking`(그중 타이머가 깨울 수). 처음엔 "막히려는 순간
`blocked == live`이고 `waking == 0`이면 교착"으로 했다가 **거짓 양성**을 만났다: 가득 찬 채널에서 소비자는 이미 깨어날 수 있는데
아직 스케줄되지 않아 "막힘"으로 세어져 있고, 그때 생산자가 막히면 둘 다 막힌 것으로 보인다. 그래서 판정을 **감시자**로 바꿨다:
조건이 보이면 50ms 뒤에 다시 보고, 그동안 아무 변화도 없었으면(세대 카운터) 교착이다. 실제 교착은 50ms 늦게 잡히고, 거짓 양성은
사라진다. 교착이면 `error[E0702]: deadlock: all tasks are waiting`을 찍고 루트를 취소해 모두 깨운다(종료 코드 1).

표준 입력을 읽는 태스크는 세지 않는다(그냥 "실행 중"으로 보인다). 안전한 쪽으로 틀린다: 입력을 기다리는 프로그램을 교착으로 몰지 않는다.

리뷰에서 잡힌 구멍 하나: 감시자를 **막히는 순간에만** 걸었더니 "보낸 쪽이 보내지 않고 끝난" 가장 흔한 교착(마지막 실행 태스크가 끝나고
막힌 태스크만 남는 경우)을 놓쳐 Go의 치명 에러가 그대로 나왔다. 지금은 태스크가 끝날 때(`dropLive`)도 다시 판정하고, 테스트 본문·`at_exit`
핸들러·모듈 초기화도 "살아 있는 태스크"로 센다.

## 6. 채널을 닫지 않는 트릭

Go에서 닫힌 채널에 보내면 패닉이다. fung에서는 `Err({kind: 'closed})`여야 한다(닫는 것은 다른 태스크, 즉 외부 요인). 그래서 Go
채널은 **절대 닫지 않고**, 닫힘은 별도 `done` 채널로 알린다. `send`는 `select { ch <- v / <-done / <-ctx.Done() }`, `recv`는 먼저
비차단 수신(닫힌 뒤에도 버퍼에 남은 값은 준다) → 닫혔으면 `Err closed` → 아니면 `select`로 기다린다. 두 번 닫아도 `Ok(nil)`.
모든 원시 연산은 **비차단 경로를 먼저** 시도한다 — 교착 감시자가 "이미 만족된 기다림"을 세지 않게 하는 규칙이기도 하다.

채널은 `Iterable`이라 `for`·`each`·`map`·`fold`·`sort`… 순회하는 모든 함수가 닫힐 때까지 받아 처리한다. 규칙 하나.

## 7. atom과 재진입

`swap(a, f)`는 뮤텍스를 잡고 `f`를 **한 번** 부른다. 같은 태스크가 `f` 안에서 같은 atom을 `swap`하면 영원히 기다리므로, 잠근 태스크를
기록해 두었다가 E0703으로 잡는다. `f`가 런타임 에러를 내면 값은 바뀌지 않고 잠금은 풀린다. 값 자체는 원자적 포인터라 `deref`와 출력은
잠금 없이 읽는다 — 처음엔 읽기도 잠금을 잡아서 `swap` 안의 `deref`가 Go 수준 자기-교착이 됐다(리뷰에서 발견).

## 8. 경쟁이 있던 곳

`-race`로 돌리며 고친 것: 출력(태스크 둘의 `print`가 섞임 → writer를 뮤텍스로 감싸 한 번의 write를 원자적으로), 모듈 초기화(두
태스크가 같은 모듈을 처음 import → 모듈당 뮤텍스), Runtime의 카운터와 종료 코드(뮤텍스), 취소 플래그(atomic). 그리고 Go의 함정 하나:
`*diag.Error` nil을 `error` 인터페이스로 돌려주면 non-nil이 된다 — `enter`가 이것을 E0801로 잡게 했다.

## 9. `exit`가 어디서든 통하는 길

내장 `exit`는 종료 신호(`diag.CodeExit`)를 돌려주고, `enter`가 그것을 보면 `requestExit(n)`: 코드를 기록하고 **루트 ctx를 취소**한다.
그 태스크는 신호로, 나머지(진입 포함)는 E0701로 되감긴다. `fung` 명령은 `rt.ExitCode()`가 있으면 그 코드로 끝낸다(`at_exit`는 취소되지
않은 새 ctx에서 돈다). 진입 파일의 런타임 에러도 같은 길이다: 취소 → 대기 → 1.

## 10. fung으로 쓴 것

`fan_in`(입력 채널마다 전달 태스크, 전부 끝나면 출력을 닫음), `pmap`(청크 단위 `spawn`+`await`, `limit`), `retry`(`Err`면 `delay`
쉬고 다시). 전부 `prelude.fung`이고 Go 코드가 없다. 05의 "고수준 패턴은 fung으로"가 실제로 되는 것을 보인다.

## 11. 테스트

단위 테스트는 `-race`로도 통과한다(`go test -race ./internal/vm/ ./cmd/fung/`). 골든은 결정적인 것만 찍는다: `await` 결과, 정렬한 값,
카운터. 교착·미대기 실패·태스크 안 `exit`는 골든의 `expect-error`·`expect-exit`로.
