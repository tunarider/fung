# M5. 모듈과 실사용 — 무엇을 만들었고 왜 그렇게 했나

M5는 "파일 하나짜리 계산기"를 "여러 파일과 바깥세상(파일·프로세스·표준 입출력)에 닿는 스크립트 언어"로 바꾼다.
`import`, 모듈 값, 모듈별 전역, 숨은 원시 모듈 층과 실행 파일에 내장된 fung 표준 라이브러리, 내장 함수의 호출 규약 통일,
prelude 확장(컬렉션·문자열·변환·결과값·입출력·프로세스), 파일 핸들과 `with_open`, 그리고 실제 스크립트 `examples/rename.fung`.

## 1. 한눈에

```
import fs
print(fs.exists("x"))
```

`fung dump bytecode`:
```
== <main> ==
0000  1:1   IMPORT       0    ; fs
0001  1:1   STOREGLOBAL  0    ; fs
0002  2:1   CONST        1    ; <fn print>
0003  2:7   LOADGLOBAL   0    ; fs
0004  2:9   FIELD        2    ; exists
0005  2:17  CONST        3    ; "x"
0006  2:16  CALL         1    ; 1 positional, 0 named
0007  2:6   CALL         1    ; 1 positional, 0 named
0008  1:1   RETURN
```

`import fs`는 **`IMPORT` 한 명령 + 전역 저장**이다. `fs.exists`는 맵의 `m.name`과 같은 `FIELD`다 — 모듈이 값이기 때문이다(04).
보이지 않는 부분이 더 크다: 이 파일을 컴파일하기 **전에** 로더가 `fs`를 찾아(`extras/fs.fung`, 실행 파일에 내장; M7.5 전에는 `internal/stdlib/`),
그 파일이 import하는 `_native.fs`를 찾고, 둘을 먼저 컴파일한 뒤 `fs`의 공개 이름 목록을 들고 이 파일을 resolve한다.
그래서 `fs.exits`(오타)는 **실행 전에** E0303이다.

## 2. 모듈은 값이다

모듈 값(`*value.Module`)은 공개 이름 → 값의 **불변 레코드**다. `type_of(fs) == 'module`, `==`는 동일성, 출력은 `<module fs>`.
"값"으로 만든 대가와 이득:

- 이득: 특별한 문법이 거의 없다. 멤버 접근은 `FIELD`, 함수 인자로 넘기기·변수에 담기·`match`로 꺼내기가 전부 그냥 된다.
  `import "./x" (a, b)`는 "`IMPORT`하고 `FIELD`로 꺼내 전역에 저장"일 뿐이다.
- 대가: 모듈 값은 **스냅샷**이다. 모듈의 최상위가 한 번 실행된 뒤 전역 표를 읽어 만든다. 이것이 안전한 이유는 모델 C(03):
  최상위 코드는 한 번만 돌고, 함수는 전역에 대입할 수 없으며, 블록은 바깥 변수를 바꿀 수 없다. 즉 **그 뒤로 아무도 모듈의
  전역을 바꾸지 않는다.** 스코프 규칙을 엄격하게 둔 덕에 모듈 체계가 단순해진 경우다.

비공개(`_x`)는 두 곳에서 막는다. `fs._x`처럼 이름이 적혀 있으면 resolve가 E0304(컴파일), `m = fs; m._x`처럼 값을 거쳐 오면
`FIELD`가 같은 번호로 런타임 에러. 같은 규칙, 같은 번호, 잡히는 시점만 다르다.

## 3. 모듈별 전역: 함수 값이 전역 표를 들고 다닌다

M4까지 전역 표는 Runtime에 하나였다. 모듈이 생기면 `a.fung`의 `fn helper()`와 `b.fung`의 `fn helper()`가 서로 다른 전역 0번이다.
`b.run()`이 `helper()`를 부르면 **b의** `helper`여야 한다. 그런데 `b.run`은 `main.fung`에서 불린다 — 지금 실행 중인 파일의 전역
표를 쓰면 틀린다.

해법: **프레임이 전역 표를 들고 있고, 클로저가 만들어질 때 그 프레임의 전역 표를 복사(참조)해 둔다.** `CLOSURE`가 `Globals`를
채우고, `CALL`이 프레임을 만들 때 그 `Globals`를 프레임에 넣는다. `LOADGLOBAL`은 "현재 프레임의 전역 표"를 본다. 어디서 불리든
함수는 자기 모듈을 본다. M7에서 태스크가 늘어나도 전역 표는 모듈당 하나이므로 공유 규칙이 그대로다.

왜 "전역 표 하나에 모듈별 오프셋"(선택지 b)이 아니었나: 오프셋은 링크 단계를 요구하고(모듈을 적재하는 순서에 따라 번호가
바뀜), REPL처럼 전역이 자라는 경우를 복잡하게 만든다. 모듈당 슬라이스 하나는 그런 조정이 없다.

## 4. 적재 시점: 컴파일 때 그래프 전체, 실행 때 한 번

로더(`internal/frontend/load.go`)는 깊이 우선으로 import 그래프를 읽는다. 파일을 파싱 → import 문만 훑어 각 모듈을 먼저 적재
→ 그 공개 이름을 들고 resolve·컴파일. 순환은 "아직 적재 중인 모듈을 다시 만남"으로 잡고 경로 전체(`a → b → a`)를 보여 준다.
덕분에 모든 모듈의 문법·의미 에러가 **종료 코드 2**(컴파일 실패)로 모이고, M6의 `fung check`는 이 로더를 그대로 쓴다.

실행은 다르다. 모듈의 최상위 코드는 그 모듈의 `IMPORT`가 **처음 실행될 때** 현재 태스크 위에서 중첩 프레임으로 한 번 돌고
캐시된다(04). 컴파일은 전부 먼저, 실행은 필요할 때 한 번 — 두 시점을 나눈 것이 핵심이다.

## 5. 내장 함수의 호출 규약 통일

M4까지 내장 함수는 `func(ctx, args []Value)`였고 인자 개수를 손으로 검사했다. 이름 인자는 아예 거부했다. 06의 `exec(cmd, cwd: d)`
같은 API를 만들려면 두 가지 길이 있었다: 내장 함수만 따로 규약을 두거나, **fung 함수와 같은 규약을 쓰거나.** 후자를 택했다(원칙 7).

`Native`에 매개변수 목록(`Params`: 이름·기본값·`...rest`)을 선언하면 VM의 `bindArgs` **하나**가 fung 함수와 똑같이 인자를
배치한다. 위치·이름·중복·누락·초과가 같은 번호(E0402/E0405/E0406/E0407)로 나온다. 차이는 기본값뿐이다: fung 함수의 기본값은
식이라 서두(`JUMPIFSET`)가 채우고, 내장 함수의 기본값은 상수라 `bindArgs`가 바로 채운다. `print(a, b, …)`는 `...args`로
선언하고 Go 쪽은 `args[0].(*List)`를 받는다 — M4의 가변 인자가 그대로 쓰였다.

## 6. `exit`는 신호다

`exit(n)`을 Go의 `os.Exit`로 만들면 `at_exit` 핸들러가 돌지 않고, 버퍼에 남은 출력이 사라지며, 같은 프로세스에서 VM을 돌리는
단위 테스트가 통째로 죽는다. 대신 `exit`는 `diag.Error{Code: "exit"}`를 돌려준다. VM은 이것을 보통 에러처럼 **프레임을 되감으며**
위로 올리고, `fung` 명령이 받아 `at_exit`를 돌린 뒤 그 코드로 끝낸다. 에러 전파 경로를 재사용했으니 VM에 새 분기가 없다.
출력만 다르다: 번호도, 발췌도, 호출 경로도 찍지 않는다.

## 7. 2층 표준 라이브러리

```
fs.fung  ──import──▶  _native.fs (Go)
```

`fs.fung`은 `import _native.fs as _n` 뒤에 `read = _n.read` 식으로 **다시 내보내고**, `with_open`·`with_temp_dir`는 fung으로 쓴다.
`_native.*`는 내장 파일에서만 import할 수 있다(E0310). 이 구조의 이유:

- 공개 API의 이름·인자·기본값·에러 형태를 fung 쪽에서 정한다(06). Go 쪽은 "되도록 작은 원시 기능"만 둔다.
- `with_open`이 **fung 코드**라는 점이 중요하다. 03은 `defer`를 빼면서 "감싸는 함수가 열고, 부르고, 반드시 닫는다"를 대안으로
  들었다. 그 대안이 언어 안에서 실제로 쓰여지는 것을 M5가 보여 준다. `read_line(h)?`로 빠져나가도 닫히는 이유는 `?`가 **람다에서
  `Err`를 반환**하는 것일 뿐이라(비지역 반환이 없음) `with_open`의 다음 줄(`_n.close(h)!`)이 그대로 실행되기 때문이다.
- 파일은 `embed.FS`로 실행 파일에 들어가고 import될 때 컴파일된다. 배포는 여전히 `fung` 하나.

prelude의 fung 부분(`until`, `iterate`)은 시작할 때 `prelude.fung`을 모듈로 적재·실행해 그 공개 이름을 prelude 표에 합친다.

## 8. 파일 핸들

`file`은 fung의 다른 값과 성격이 다르다: 읽을 때마다 위치가 움직이고, 닫으면 끝이다(상태가 있는 자원). 그래서 `==`는 동일성이고,
닫힌 핸들의 읽기·쓰기는 `Err({kind: 'closed})`다(06의 kind 어휘). `with_open` 밖으로 핸들을 돌려주는 것을 막지는 않는다 —
쓰는 순간 `'closed`가 나오면 충분하다. 태스크 사이의 공유 규칙은 M7의 open question이다.

## 9. prelude 설계에서 정한 것

- 06의 에러 규칙이 함수 하나하나를 가른다. `int("x")`는 **런타임 에러**(E0513, "이건 숫자여야 한다"는 단언), `parse_int("x")`는
  **`Err`**(검사). 이름이 뜻을 말한다.
- `take`/`drop`은 길이로 잘라 주는 안전한 버전이고, `xs[a..b]`는 범위를 벗어나면 에러인 엄격한 버전이다. 둘 다 있는 이유는
  "값이 없는데 있는 척"은 안 되지만 "앞에서 n개"는 n이 길이보다 커도 뜻이 분명하기 때문이다.
- 없을 때 `nil`: `first`, `last`, `min`, `max`, `find`. nil은 "없음"이라는 정상 값(02)이고 `??`와 짝이 맞는다.
- 순회 대상은 리스트와 범위뿐. 문자열은 `chars`, 맵은 `pairs`/`keys`/`values`로 명시적으로 바꾼다(02).
- `join`은 원소를 `print`처럼 문자열로 바꾼다. `group_by`의 키는 문자열이어야 한다(E0514, 맵의 키가 문자열이므로).

## 10. `exec`와 `sh`

`exec(["mv", old, new])`는 쉘을 거치지 않는다. 인자가 공백·따옴표·`$`를 담아도 그대로 전달되므로 인젝션이 없다. 쉘 기능(파이프,
리다이렉트)이 필요할 때만 `sh("…")`를 쓴다 — 이름이 다르니 위험한 쪽이 눈에 띈다. 결과는 06의 형태: 종료 코드 0이면
`Ok({out, err, code})`, 아니면 `Err({kind: 'exit, code, out, err, message})`, 실행 자체가 안 되면 `Err({kind: 'not_found})`.
`exec([...])!`는 쉘의 `set -e`다.

## 11. `rename.fung`을 쓰며 느낀 것

- `first(args) ?? fail("usage: …")`가 인자 검사의 관용구로 잘 맞는다.
- 부수효과 순회에 `each(files, fn(file): … ;;)`를 쓰니 본문이 여러 줄일 때 `fn(): … ;;)`의 닫는 괄호가 눈에 거슬린다. `for`는
  리스트를 만들어 버린다. 알파에서 `each` 블록 문법(또는 `for … do`)을 검토할 만하다.
- kebab-case 변환에 `chars` + `for` + `join`을 썼다. `regex`(M8)가 오면 한 줄이 된다.
- `fs.list(dir)`는 이름만 돌려주므로 `path.join(dir, file)`을 두 번 썼다. `fs.list`에 전체 경로 옵션이 있으면 편하다.
- 한글 파일명은 ASCII 글자가 없어 이름이 사라지므로 "비면 원래 이름 유지"를 넣어야 했다 — 스크립트 작성자가 신경 쓸 함정.

이 항목들은 open-questions의 "알파에서 조정" 목록에 적었다.

## 12. 테스트와 다음

단위 테스트는 층마다(value·parser·resolve·compiler·frontend 로더·vm 모듈 런타임·native), 골든은 108개(모듈 fixture는
`tests/lang/_lib/`, `# args:` `# stdin:` `# expect-exit:` 지시어 추가). 실행 중 계획과 어긋난 것은 ledger의 ruling에 있다:
모델 C 때문에 fixture 몇 개가 `fn`으로 바뀌었고, `?`가 `Ok`를 푸는 것을 잊은 기대값을 고쳤고, 파이프 사슬 안의 람다가
두 번 desugar되던 버그를 잡았다.

다음은 M6 개발 도구: `test`/`assert`, `fung test`, `fung check`(로더가 이미 그래프를 검사한다), 경고, REPL, `dbg`.
