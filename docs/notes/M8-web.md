# M8 웹 — 무엇을 만들었고 왜 그렇게 했나

2026-10-14. 계획 `docs/plans/2026-10-14-m8-web.md`, 스펙 `docs/superpowers/specs/2026-10-14-m8-web-design.md`.

M8은 네 모듈(`time`·`json`·`regex`·`http`)과 core 값 타입 하나(`time`)를 더했다. 문법은 한 글자도 바뀌지 않았고,
렉서·파서도 열지 않았다. 바뀐 것은 값 층과 라이브러리, 그리고 native 다리가 VM에 요구하는 것 두 가지(`Done`, `RunTask`)뿐이다.

## 1. Go native를 언제 쓰는가 — 경계 기준의 수정

M7.5까지 native(`_native.*`)의 기준은 "fung으로 **쓸 수 없는** 것만"이었다. 파일·프로세스·네트워크처럼 Go가 꼭 필요한 다리.
M8에서 이 기준을 하나 넓혔다: **쓸 수는 있지만 안쪽 루프라 해석기 속도로는 성능이 나오지 않는 것**도 native에 둔다.

계기는 `json`이다. 09의 원래 계획은 "json은 fung으로"였다. 파싱은 글자 하나하나를 도는 루프이고, 해석기는 명령 하나에 수십 ns가
들므로 1MB JSON이면 수억 번의 명령 = 수 초다. `kubectl -o json`은 수 MB가 흔하다. 06의 extras 기준에는 처음부터 "**성능도 충분**"이
들어 있었고, `split`·`join`을 core(Go)에 둔 것도 같은 이유였다. 그래서 `json`도 Go 다리 + 얇은 fung 재내보내기로 갔다.

측정: 882KB JSON(객체 12,000개)을 `json.parse`로 읽는 스크립트 전체가 **18ms**. 해석기로 돌렸다면 초 단위였을 일이다.

원칙은 그대로다. "가급적 fung으로, 경계는 측정으로 옮긴다(`flatten`의 전례)". 다만 "fung으로 쓸 수 있다"가 곧 "fung으로 써야 한다"는
뜻은 아니라는 것을 06에 명시했다.

## 2. `time` 타입 — 왜 core인가

`time`은 모듈이 아니라 **값 타입**이다(`value.Time`). 모듈 `time`은 값을 만들고(`now`·`parse`·`from_unix`) 보여 줄(`format`·`parts`) 뿐이고,
`==` `<` `+ dur` `- dur` `time - time → dur`는 언어의 연산자가 처리한다. 연산자의 의미는 "언어가 보장하는 값 연산"이므로 core다.

- **리터럴이 없다.** `2026-10-14T09:00:00+09:00` 같은 리터럴을 문법에 넣으면 렉서·파서·패턴 상수까지 전부 열어야 한다. 시각은 거의 항상
  `now()`나 파싱으로 생기므로 리터럴의 이득이 작다. 패턴 상수로도 쓸 수 없다.
- **시간대를 보존한다.** `now()`는 로컬, `utc(t)`는 UTC로 찍힌다. 같은 순간이면 시간대가 달라도 `==`다(Go `Equal`). 로그 처리에서
  "언제인가"와 "어떻게 보여 주나"를 분리하기 위해서다.
- **출력은 ISO 8601**(RFC 3339). 소수 초는 0이 아닐 때만. `print`·`str`·보간 전부 같다.
- 산술 분기는 `Dur`와 같은 자리에 넣었다(`arith.go`의 `Add`·`Sub`, `compare.go`, `format.go`). `time - time`이 Go에서 포화(saturate)하면
  오버플로 E0503으로 바꾼다 — "조용히 넘어가지 않는다".

### 토큰 포맷을 직접 쓴 이유

Go의 시간 레이아웃(`2006-01-02 15:04:05`)으로 변환하는 길도 있었다. 하지만 Go 레이아웃은 **`MM`(월)과 `mm`(분)을 구분할 길이 없고**
(`01`과 `04`), 토큰에 없는 글자를 그대로 두는 규칙을 Go가 깨뜨릴 수 있다(`1`·`2`·`Z` 같은 글자가 레이아웃 토큰이다). 그래서 토큰 표
10개(`YYYY YY MM DD HH mm ss SSS Z ZZ`)를 긴 것부터 맞추는 직접 구현으로 갔다. 100줄이다.

파싱에서 하나 더: Go `time.Date`는 13월을 **다음 해 1월로 정규화**한다. 2월 30일도 3월 2일이 된다. 그래서 범위를 직접 검사하고, 만든 값의
월·일이 입력과 같은지 확인해 다르면 `Err 'parse`다.

## 3. JSON — 순서, 정수, 그리고 에러의 위치

- **키 순서 유지.** fung 맵은 삽입 순서를 지킨다(02). Go의 `json.Unmarshal(&map[string]any)`은 순서를 버리므로, `json.Decoder.Token()`으로
  토큰을 하나씩 읽어 맵을 직접 조립했다. 왕복(`parse` → `stringify`)하면 원문과 같은 순서가 나온다.
- **정수는 정수로.** `.`·`e`·`E`가 없는 숫자는 `int`, int64를 넘으면 `Err`. `1.0`은 `float`. 조용히 float로 바꾸지 않는다.
- **`stringify` 불가 타입은 런타임 에러**(E0513 `cannot convert dur to JSON`), `Err`가 아니다. 어떤 값을 JSON으로 만들지는 코드가 정하므로
  코드 오류다. 반대로 `parse`는 외부 입력이라 `Err({kind: 'parse, line, col, message})`.
- **에러의 열.** Go `SyntaxError.Offset`은 문제 글자 **다음** 바이트를 가리킨다. "invalid character" 에러는 하나 빼서 그 글자를, 그 외는
  값이 시작한 자리(앞 공백은 건너뛴 뒤)를 가리키게 했다. 규칙: 열은 메시지가 말하는 글자를 가리킨다.

## 4. regex — 룬 인덱스와 캐시

- Go `regexp`는 **바이트 오프셋**을 돌려준다. fung 문자열은 글자(룬) 단위(02)라 그대로 주면 `"가나다"[start..end]`가 틀어진다. 모든 위치를
  `utf8.RuneCountInString(s[:off])`로 바꿔 준다.
- 컴파일한 패턴은 Go 쪽 맵에 캐시한다(256개 넘으면 비움). 패턴은 보통 코드에 적힌 리터럴이라 몇 개 안 되고, 매 호출 컴파일은 아깝다.
  "컴파일된 regex 값" 타입은 두지 않았다 — 타입이 하나 늘면 `type_of`·비교·출력 표까지 늘어난다(YAGNI).
- 잘못된 패턴은 **런타임 에러 E0515**(코드 오류). 외부 입력 패턴은 지금은 다루지 않는다.
- **`regex.match`는 `regex.is_match`가 됐다.** `match`는 키워드라 `.` 뒤에 올 수 없다(E0112). 파서에 "키워드도 필드 이름이 된다"를 넣는
  대신 prelude 관례(`is_ok`·`is_empty`)를 따랐다. 키워드를 필드 이름으로 허용할지는 나중에 필요하면 다시 본다.

## 5. http — 서버는 태스크 위에서

### 클라이언트

- 응답을 받았으면 **상태 코드와 무관하게 `Ok`**. 404는 "서버가 그렇게 답했다"이지 "요청이 실패했다"가 아니다. 전송 실패만 `Err 'network`,
  시간 초과는 `Err 'timeout`.
- 응답 헤더 키는 **소문자**로 통일(`resp.headers["content-type"]`). Go의 정규화(`Content-Type`)를 그대로 내보내면 사용자가 대소문자를
  외워야 한다. 같은 이름이 여럿이면 `", "`로 잇는다(HTTP 규칙).
- 요청 중 태스크가 취소되면 다른 막히는 내장 함수처럼 E0701로 되감긴다(`await` → `Err 'cancelled`). Go 요청에 `context`를 넘겨서 끊는다.

### 서버

- `serve(addr, handler, ready = nil)`는 바인드한 뒤 **막힌 채로** 요청을 받는다. 끝나는 길은 그 태스크의 취소(`cancel(t)`) 또는 `exit`뿐이다.
  취소되면 `Shutdown`으로 소켓을 닫고 E0701로 되감긴다. 값을 돌려주는 경우는 바인드 실패 `Err 'network`뿐이다.
- `ready(addr)`: 리스닝 직후 실제 주소로 한 번 부른다. `":0"`으로 띄우면 포트를 알 길이 이것뿐이고, 테스트는 이것으로 "준비됨"을 안다
  (`port = channel(1)` + `ready: a => send(port, a)` + `recv(port)` 패턴).
- **요청마다 새 fung 태스크.** Go `net/http`는 요청마다 고루틴을 띄운다. VM 상태(스택·프레임)는 태스크별이므로 핸들러는 요청마다
  `RunTask`로 만든 자식 태스크에서 돈다. 핸들러들은 동시에 돌 수 있다 → 공유 상태는 `atom`.
- 핸들러가 런타임 에러를 내거나 맵·문자열이 아닌 것을 돌려주면 **500 + stderr**, 서버는 계속 돈다. 종료 코드에는 영향 없다.
  서버 하나가 요청 하나 때문에 죽으면 안 된다.
- 응답은 문자열(200 `text/plain`) 또는 맵 `{status = 200, headers = {}, body = ""}`. 라우팅은 없고 `match (req.method, req.path):`로 쓴다.

### `value.Context`에 더한 두 메서드

동시성 내장 함수(`sleep`·`await`…)는 vm 패키지 안에 있어 `ctx.(*Task)`로 태스크를 직접 쓴다. `http`는 다른 다리처럼 `internal/native`에
두고 싶었고, 그러려면 native가 vm을 모른 채 (1) 취소 신호를 받고 (2) 새 태스크에서 함수를 돌릴 수 있어야 했다. 그래서:

- `Done() <-chan struct{}`: 이 태스크의 취소 채널.
- `RunTask(fn, args)`: 호출한 고루틴 위에 자식 태스크를 만들어 끝까지 돌린다. 교착 감시자에 "살아 있는 태스크"로 센다.

`Call`(같은 태스크의 스택에서 재진입)과 `RunTask`(새 태스크)의 차이가 핵심이다. 핸들러를 `Call`로 돌리면 서버 태스크 하나의 스택을 여러
고루틴이 동시에 밟는다.

교착 감시자(05)는 `block()` 안의 대기만 세므로, `serve`가 Go에서 막혀 있어도 "모두 기다린다"로 오판하지 않는다. `fs.read`·`exec`과
같은 취급이다.

## 6. 실행 중 배운 것

- 계획에 쓴 테스트 값 둘이 틀렸다(unix 타임스탬프가 2025년 값, 맵 키 출력의 따옴표). 둘 다 테스트를 **먼저 돌려서** 잡혔다.
- 언어 규칙에 내가 걸린 것 셋: `match`가 키워드라 필드 이름 불가, 맵 리터럴·패턴에 `{key}` 축약 없음, 최상위 `fn`은 파일 변수를 못 본다
  (03 모델 C). 셋 다 언어가 맞고 계획이 틀렸다. 마지막 것은 에러 메시지의 help 줄("pass it as an argument")이 정확히 길을 알려 줬다.
- 핸들러 예제에서 `handler(started, requests)`가 람다를 돌려주는 모양이 자연스러웠다 — "서버의 상태는 클로저 안에, 변경은 `atom`으로".

## 7. 후속 작업 (2026-10-14, 같은 날 처리)

M8 직후 "언어 완성도 우선"으로 미결 사항을 한 번에 정리했다.

- 파서: 이름만 올 수 있는 자리(`.` 뒤, 맵 키, 패턴 키)에서 **예약어를 이름으로 허용** — JSON의 `type` 같은 키 때문. `{a, b}` **축약**
  (리터럴·패턴). 둘 다 01·02에 반영.
- 런타임: 파일 핸들 연산을 **뮤텍스로 직렬화**(태스크 간 공유 가능), `fs.list(dir, full: true)`.
- 도구: **W0104**(값 자리의 블록이 대입으로 끝남), `fung test`의 깨진 라이브러리 에러 한 번만 + `FAIL path: <load>` 집계,
  REPL 기록 파일 `~/.fung_history`.
- M8 라이브러리: `MMM`·`ddd` 토큰, `parse_dur`(core), `from_unix` 범위 검사, JSON 에러 열 보정, `http.serve` 한도(헤더 10초·본문 16MB),
  응답 키 타입 오류 메시지에 키 이름.
- 보류: REPL의 폭 2 글자 커서(CJK를 쳐 보다 불편하면), `fst`/`snd`, `each` 블록 문법, 12시간제·달력 산술, 스트리밍·쿠키·TLS,
  `regex.compile`. 목록은 open-questions.
