## 이름은 무엇을 가리키나 {#names}

`x = 21`이라고 쓰면 이름 `x`가 값 21을 가리키게 된다. 이름과 값의 이 연결을 **바인딩**(binding, 묶기)이라고 한다. 프로그램 어디에서나 `x`를 쓸 수 있는 것은 아니다. 함수 안에서 만든 이름은 함수 밖에서 보이지 않는다. 이름이 보이는 범위를 **스코프**(scope, 유효 범위)라고 한다.

fung의 스코프는 소스의 생김새만 보고 정해진다. "이 이름은 이 블록 안에 쓰였으니 이 블록의 이름이다"를 코드를 읽는 것만으로 알 수 있다. 이것을 **렉시컬 스코프**(lexical scope, 정적 스코프)라고 한다. 반대로 "실행 중에 누가 나를 불렀는가"에 따라 보이는 이름이 달라지는 방식을 **동적 스코프**(dynamic scope)라고 한다. 옛 Lisp들과 bash의 `local` 변수가 동적 스코프다. bash 함수 안에서 부른 다른 함수가 부른 쪽의 `local` 변수를 볼 수 있는 것이 그 때문이다.

실행 중의 어느 순간, 보이는 이름들과 그 값의 묶음을 **환경**(environment)이라고 한다. 그리고 컴파일러가 "지금까지 나온 이름들과 그 정보"를 적어 두는 표를 **심볼 테이블**(symbol table)이라고 한다. 이 장의 주인공은 그 심볼 테이블을 들고 코어 트리를 한 번 훑는 단계, **이름 해석**(name resolution, fung 코드에서는 resolve)이다.

## 실행 중에 찾기와 미리 번호 매기기 {#lookup}

이름을 값으로 바꾸는 방법은 크게 둘이다.

**실행 중에 찾기.** 환경을 "이름 → 값" 사전(해시 표)으로 들고 다니다가, 이름이 나올 때마다 문자열로 찾는다. 만들기 쉽고 유연하다. 대신 이름이 나올 때마다 문자열 해시를 계산하고 표를 뒤진다. 그리고 오타가 있어도 그 줄이 실행될 때까지 모른다.

**미리 번호 매기기.** 컴파일 시점에 모든 이름의 자리를 정해 번호를 붙인다. "이 함수의 `x`는 0번 칸, `total`은 1번 칸". 실행 중에는 "0번 칸을 읽어라"만 하면 된다. 배열 접근 한 번이다. 오타는 번호를 매기다가 "이런 이름은 없다"로 실행 전에 드러난다.

fung은 둘째 방식이다. 이름 해석이 끝나면 트리에 이름 문자열이 남지 않는다. 컴파일러와 VM은 이름을 다시 찾지 않는다.

## 따라가기: 이름이 번호로 {#follow}

```dump ast
fn double(x) = x * 2
print(double(21))
```

```dump core
fn double(x) = x * 2
print(double(21))
```

이름 셋이 세 갈래로 갈렸다.

- `x` → `(local 0)`: 함수 `double`의 **지역 슬롯** 0번. 매개변수도 지역 변수이고, 첫 매개변수가 0번이다.
- `double` → `(global 0)`: 이 파일(모듈)의 **전역 칸** 0번. 파일 최상위에서 만든 이름이다.
- `print` → `(prelude print)`: **prelude**(미리 들어 있는 내장 이름들)의 `print`. 내장 함수는 번호 대신 이름을 남기지만, 이것은 컴파일러가 그 함수 값을 상수로 직접 박아 넣으라는 표시다(8장의 `CONST 0 ; <fn print>`). 실행 중에 찾는 일은 없다.

### 다섯 갈래 {#five}

fung의 이름 해석은 모든 이름을 다섯 갈래 중 하나로 정한다.

<table>
  <thead><tr><th>코어 표기</th><th>뜻</th><th>어디에 사는가</th></tr></thead>
  <tbody>
    <tr><td><code>(local n)</code></td><td>지역 슬롯</td><td>함수의 매개변수와 블록 안의 변수. 실행 중에는 그 함수 호출의 스택 칸(8장)</td></tr>
    <tr><td><code>(captured n)</code></td><td>붙잡은 값</td><td>클로저가 만들어질 때 복사해 둔 바깥 변수(9장)</td></tr>
    <tr><td><code>(self)</code></td><td>자기 자신</td><td>블록 안의 이름 있는 <code>fn</code>이 자기를 부를 때(9장)</td></tr>
    <tr><td><code>(global n)</code></td><td>모듈 전역</td><td>파일 최상위의 변수와 <code>fn</code>. 모듈마다 있는 전역 표(11장)</td></tr>
    <tr><td><code>(prelude 이름)</code></td><td>prelude</td><td>내장 이름. 80개 남짓(<code>print</code>, <code>map</code>, <code>len</code> …)</td></tr>
  </tbody>
</table>

이 장에서는 지역·전역·prelude를 본다. 붙잡은 값과 자기 자신은 함수와 클로저를 다루는 9장에서 다시 만난다.

## 블록 스코프와 슬롯 {#slots}

fung에서 `if`·`else`·`match` 절의 본문은 각자 **블록**이고, 블록마다 스코프가 하나씩 생긴다. 블록 안에서 만든 이름은 블록이 끝나면 보이지 않는다. 이름 해석은 블록에 들어갈 때 스코프를 쌓고, 나올 때 버린다.

슬롯 번호는 이렇게 정한다. 함수마다 "다음에 줄 빈 번호"가 하나 있다. 새 지역 이름이 나오면 그 번호를 주고 하나 올린다. 블록이 끝나면 그 블록에 들어갈 때의 번호로 **되돌린다**. 블록이 끝난 이름의 칸은 더 이상 아무도 읽을 수 없으니, 다음 이름이 같은 칸을 다시 써도 된다.

```dump core
fn label(n):
  word = if n > 9:
    big = n * 10
    "big ${big}"
  else:
    small = n + 1
    "small ${small}"
  ;;
  word
;;
print(label(12))
```

- `n`은 매개변수라 0번이다.
- `if` 가지 안의 `big`은 1번이다. 가지가 끝나면 번호가 1로 되돌아가서, `else` 가지의 `small`도 1번이다. 두 이름은 동시에 살아 있을 수 없으므로 칸 하나를 나눠 쓴다.
- `word`도 1번이다. 대입은 **오른쪽을 먼저** 해석하고 그 뒤에 이름을 묶는다. `if` 전체를 해석하는 동안 `big`과 `small`이 1번을 잠시 쓰고 돌려준 뒤, 그 1번이 `word`에게 간다.

함수가 쓰는 칸의 수는 "동시에 살아 있는 이름의 최대 수"다. 이 함수는 2칸이면 된다. 8장에서 VM이 함수를 부를 때 이 수만큼 칸을 마련한다.

```fung run
fn label(n):
  word = if n > 9:
    big = n * 10
    "big ${big}"
  else:
    small = n + 1
    "small ${small}"
  ;;
  word
;;
print(label(12))
```

"오른쪽을 먼저"에는 다른 효과도 있다. `x = x + 1`에서 오른쪽의 `x`는 대입하기 **전의** `x`다. 같은 스코프에서 같은 이름에 다시 대입하면 같은 칸을 다시 쓴다.

```dump core
x = 1
x = x + 1
print(x)
```

## 파일 최상위: 전역과 끌어올리기 {#globals}

파일 최상위에서 만든 이름은 지역 슬롯이 아니라 **전역 칸**(global)이 된다. 함수 호출의 스택 칸은 함수가 끝나면 사라지지만, 파일의 이름은 그 파일의 함수들이 언제 불려도 거기 있어야 하기 때문이다. 다른 파일이 `import`해서 쓰는 이름도 이 칸들이다(11장).

최상위의 `fn`은 특별하게 다룬다. 이름 해석은 파일의 `fn` 문장을 **먼저** 모아 전역 번호를 붙이고, 코어 트리의 맨 앞으로 옮긴다. 이것을 **끌어올리기**(hoisting)라고 한다. 그래서 함수를 정의하기 전 줄에서 불러도 되고, 두 함수가 서로를 불러도 된다.

```dump core
limit = 10
fn clamp(x) = x > limit then limit else x
print(clamp(42))
```

소스에서는 `limit = 10`이 먼저인데, 코어에서는 `clamp`의 대입이 맨 앞으로 왔다. `clamp`가 0번, `limit`이 1번 칸이다. 그런데 `clamp`는 `limit`보다 먼저 만들어지는데도 안에서 `(global 1)`로 `limit`을 읽는다. 이것은 `limit`이 최상위에서 **딱 한 번만** 대입되는 이름이라서 가능하다. 한 번만 대입되면 값이 바뀌지 않으므로 상수와 같고, 최상위 `fn`이 불릴 때 그 칸을 읽어도 안전하다. 두 번 이상 대입되는 최상위 변수는 최상위 `fn` 안에서 보이지 않는다(`E0204`와 "인자로 넘기세요" 도움말). 이 규칙의 이유는 9장에서 "함수는 만들어질 때 보이는 변수를 복사한다"는 fung의 함수 규칙과 함께 본다.

```fung run
limit = 10
fn clamp(x) = x > limit then limit else x
print(clamp(42))
```

## 찾는 순서 {#order}

이름 해석이 이름 하나를 읽을 때 찾는 순서는 이렇다.

1. 지금 함수의 블록들. 가장 안쪽 블록부터 바깥쪽으로.
2. 지금 함수 자신의 이름(블록 안의 이름 있는 `fn`이면).
3. 바깥 함수들. 거기서 찾으면 "붙잡은 값"이 된다(9장).
4. 파일의 전역.
5. prelude.

어디에도 없으면 에러다. 그런데 바로 `E0204`(undefined name)를 내지 않고, 더 쓸모 있는 설명이 있는지 먼저 본다.

- 이미 끝난 블록에서 만든 이름이면 `E0206`: "블록 안에서 만든 이름이라 여기서 안 보인다." 블록의 값을 대입하라는 도움말이 붙는다.
- 같은 블록의 뒤에서 정의하는 지역 `fn`이면 `E0208`.
- 그 밖이면 `E0204`. 보이는 이름 가운데 비슷한 것이 있으면 "a similar name exists"를 붙인다. 비슷함은 글자를 몇 번 고치면 같아지는가(편집 거리)로 잰다. 이름 길이가 3~4글자면 1번, 5글자 이상이면 2번까지 허용하고, 이웃한 두 글자를 맞바꾼 것(`fiels` → `files`)도 한 번으로 친다.

```fung run exit=2 error=E0204
fn double(x) = x * 2
print(doubel(21))
```

## 스코프 규칙과 에러 모으기 {#rules}

이름 해석은 이름을 번호로 바꾸는 김에 fung의 스코프 규칙도 검사한다. 대표적인 것이 **바깥 변수 재대입 금지**다. 블록 안에서 블록 바깥의 변수에 다시 대입할 수 없다. 쉘 스크립트에 익숙하면 이렇게 쓰고 싶어진다.

```fung run exit=2 error=E0205
lines = ["ok", "error: disk", "ok", "error: net"]
count = 0
for l in lines:
  if starts_with(l, "error"): count = count + 1 ;;
;;
print(count)
```

판정 방법은 간단하다. 대입을 만나면 지금 블록의 표를 본다. 있으면 같은 칸에 다시 대입. 없는데 바깥 스코프 어딘가에 있으면 `E0205`. 어디에도 없으면 새 이름이다.

이름 해석은 **에러를 하나 찾아도 멈추지 않는다**. 파일 끝까지 훑으며 모든 에러를 모아 한꺼번에 보고한다.

```fung run exit=2 error=E0204
print(a)
print(b)
```

파서는 첫 에러에서 멈췄는데(4장) 이름 해석은 왜 다 모을 수 있을까? 파서가 틀리면 그 뒤의 구조를 믿을 수 없지만, 이름 해석은 이미 올바른 트리 위에서 일한다. 이름 하나가 틀려도 트리의 다른 부분은 멀쩡하므로 계속 검사해도 엉뚱한 에러가 따라 나오지 않는다.

이름 해석이 검사하는 것은 그 밖에도 많다. `for` 안의 `return`(`E0213`), 파일 최상위의 `return`(`E0211`), 모듈 이름 가리기, 최상위 `fn` 이름에 대입(`E0209`), 대문자 이름을 변수로(`E0225`)… 그리고 **경고**도 여기서 만든다. 쓰지 않는 지역 변수(`W0102`), 쓰지 않는 import(`W0101`), prelude 이름 가리기(`W0103`). 경고는 `fung check`와 `fung test`에서만 보인다. 끝으로 이름 해석이 끝난 트리를 한 번 더 돌며 "값을 쓰는 자리의 조용한 `nil`"(`else` 없는 `if`는 `E0223`, 대입으로 끝나는 블록은 `E0224`)을 찾는다. 함수 본문의 끝은 늘 값을 쓰는 자리이고, `test` 블록의 본문과 문장 `for`의 본문은 아니다.

:::box mistake 블록 안에서 바깥 변수 바꾸기
`E0205`는 쉘이나 다른 언어에서 넘어온 사람이 가장 자주 만나는 에러다. 값을 바꾸는 대신 값을 **만든다**. 위의 예는 `fold`로 쓴다. `fold(xs, 처음, f)`는 처음 값에서 시작해 원소마다 `f(지금까지, 원소)`를 불러 새 값을 만든다.

```fung run
lines = ["ok", "error: disk", "ok", "error: net"]
count = fold(lines, 0, (n, l) => starts_with(l, "error") then n + 1 else n)
print(count)
```

:::

:::box other 다른 언어는
- **Python**: 함수의 지역 변수는 컴파일 때 번호가 정해져 `LOAD_FAST n`으로 칸을 바로 읽는다. 그러나 전역과 내장 이름은 `LOAD_GLOBAL`이 실행 중에 사전을 찾는다. 그래서 오타가 난 전역 이름은 그 줄이 실행될 때 `NameError`가 된다.
- **Lua**: 지역 변수는 레지스터 번호로, 전역은 실행 중에 표(`_ENV`)에서 찾는다. 선언하지 않은 이름은 에러가 아니라 `nil`이다.
- **JavaScript**: `var`는 함수 전체가 스코프이고 선언이 함수 맨 위로 끌어올려진다. 블록 스코프는 나중에 `let`·`const`로 더해졌다.
- **bash**: 기본은 전역 변수 하나의 공간이고, `local`은 동적 스코프다. 이름은 늘 실행 중에 찾는다.
:::

:::box choice fung의 선택
- **실행 중에는 이름을 찾지 않는다.** 이름 해석이 모든 이름을 다섯 갈래 중 하나로 분류하고, 컴파일러는 이름을 다시 찾지 않는다(설계 문서 09). 마일스톤 노트 M2는 이것을 실행 중에 사전을 찾는 언어(Python 같은)와 컴파일 언어의 중요한 차이로 들었다.
- **블록이 끝나면 슬롯을 재사용한다**(설계 문서 09). 함수가 쓰는 칸 수가 "동시에 살아 있는 이름 수"로 줄어든다.
- **의미 에러는 파일 전체를 검사한 뒤 모두 보고한다**(설계 문서 08). 문법 에러가 첫 번째 하나인 것과 대비된다.
- **블록은 바깥 변수를 바꿀 수 없다.** fung은 반복문과 블록 안 재할당을 채택하지 않았다. 설계 문서 00은 그 이유로 "`for` 안에서 `total = total + x`가 조용히 0이 되는 함정"을 든다. `for`의 본문은 람다(5장)이므로, 바깥 변수를 바꾸는 것을 허용하면 그 변경이 람다 안에서만 일어나고 바깥은 그대로인 버그가 된다. fung은 그것을 조용히 두지 않고 `E0205`로 만든다(결정 원칙 1: 엄격함 우선).
:::

:::exercise 슬롯 번호 맞히기
아래 함수에서 `host`, `port`, `addr`, `msg`는 각각 몇 번 슬롯일까? 예상한 뒤 `fung dump core`로 확인하자.

```fung frag
fn describe(host, port):
  addr = "${host}:${port}"
  msg = if port == 443:
    tls = "https"
    "${tls}://${addr}"
  else:
    "http://${addr}"
  ;;
  msg
;;
```

:::solution
매개변수 `host`가 0번, `port`가 1번, `addr`이 2번이다. `if` 가지의 `tls`가 3번을 잠시 쓰고 돌려준 뒤, 오른쪽을 다 해석한 `msg`가 3번을 받는다.

```dump core

  msg = if port == 443:

  else:
    "http://${addr}"
  ;;
  msg
;;
print(describe("db1", 443))
```

## 정리 {#summary}

- 바인딩은 이름과 값의 연결, 스코프는 이름이 보이는 범위다. fung은 소스만 보고 스코프가 정해지는 렉시컬 스코프다.
- 이름 해석은 모든 이름을 지역 슬롯, 붙잡은 값, 자기 자신, 모듈 전역, prelude 중 하나로 정한다. 실행 중에는 이름을 찾지 않는다.
- 슬롯 번호는 함수마다 차례로 주고, 블록이 끝나면 되돌려 재사용한다. 대입은 오른쪽을 먼저 해석한다.
- 최상위 `fn`은 끌어올려진다. 한 번만 대입되는 최상위 이름은 최상위 `fn`에서도 읽힌다.
- 스코프 위반은 멈추지 않고 모두 모아 보고한다. 비슷한 이름 힌트는 편집 거리로 찾는다.

다음 장에서는 지금까지 본 에러 메시지가 어떻게 만들어지는지, 위치와 카탈로그를 본다. 스코프 규칙 전체는 [언어 레퍼런스의 스코프](../reference/language.html#scope)에, `E0205`는 [에러 목록](../reference/errors.html#E0205)에 있다.
