# 렉서: 글자를 토큰으로

<ol class="stages"><li>소스</li><li class="on">토큰</li><li>트리</li><li>코어</li><li>바이트코드</li><li>실행</li></ol>

:::goals
- 토큰이 무엇이고 무엇을 담는가
- 렉서가 글자를 자르는 규칙: 가장 길게 자르기, 예약어와 이름, 숫자와 기간, 문자열과 보간
- 줄바꿈과 주석을 렉서가 어떻게 다루는가
- 위치(줄과 칸)를 세는 법과, 렉서가 내는 에러
:::

## 토큰이란 {#token}

1장의 번역 비유에서 첫 일은 글자를 **단어**로 나누는 것이었다. 프로그래밍 언어에서 그 단어를 **토큰**(token)이라고 하고, 글자의 줄을 토큰의 줄로 바꾸는 단계를 **렉서**(lexer), 또는 어휘 분석기(lexical analyzer), 스캐너(scanner)라고 한다.

`x * 2`를 생각해 보자. 글자는 다섯 개(`x`, 공백, `*`, 공백, `2`)지만 토큰은 셋이다. "이름 `x`", "곱하기 연산자", "정수 2". 공백은 토큰을 가르는 역할만 하고 사라진다.

토큰 하나는 보통 네 가지를 담는다.

- **종류**(kind): 이름인가, 정수인가, `(`인가. 파서는 주로 이것만 보고 문법을 판단한다.
- **글자**(text): 소스에 쓰인 그대로의 조각. `double`, `21`, `*`.
- **위치**(position): 몇째 줄 몇째 칸에서 시작했나. 에러 메시지가 이것으로 정확한 곳을 가리킨다.
- **값**(value): 리터럴(literal, 소스에 직접 쓴 값)이면 해석한 값. 글자 `1_000`의 값은 정수 1000이고, 글자 `1h30m`의 값은 5,400,000,000,000 나노초다.

렉서는 문법을 모른다. `x * 2`가 올바른 식인지, `* x 2`가 틀렸는지는 렉서의 관심이 아니다. 둘 다 토큰 셋으로 잘 잘린다. 순서가 맞는지는 다음 단계인 파서(4장)가 본다. 렉서가 판단하는 것은 **글자 수준의 규칙**뿐이다. "`@`라는 글자는 fung에 없다", "숫자 바로 뒤에 `abc`가 붙을 수 없다" 같은 것.

## 따라가기: 두 줄의 토큰 {#follow}

`fung dump`에는 토큰 단계가 없다. 아래 표는 fung의 렉서 함수 `lexer::lex`가 이 책의 두 줄에 대해 실제로 돌려준 토큰을 그대로 옮긴 것이다(왼쪽부터 위치, 종류, 글자).

```plain
1:1   KwFn     "fn"
1:4   Name     "double"
1:10  LParen   "("
1:11  Name     "x"
1:12  RParen   ")"
1:14  Assign   "="
1:16  Name     "x"
1:18  Star     "*"
1:20  Int      "2"        값 2
1:21  Newline
2:1   Name     "print"
2:6   LParen   "("
2:7   Name     "double"
2:13  LParen   "("
2:14  Int      "21"       값 21
2:16  RParen   ")"
2:17  RParen   ")"
2:18  Newline
3:1   Eof
```

몇 가지를 눈여겨보자.

- `fn`은 이름이 아니라 **예약어**(keyword) 토큰 `KwFn`이다. `double`과 `x`, `print`는 모두 `Name`이다. 렉서는 `print`가 내장 함수라는 것을 모른다. 그것을 아는 것은 6장의 이름 해석이다.
- 공백은 토큰이 되지 않았지만 줄바꿈은 `Newline`이라는 **토큰이 되었다**. 아래에서 이유를 본다.
- 마지막은 항상 `Eof`(end of file, 파일 끝) 토큰이다. 파서가 "더 읽을 것이 없다"를 다른 토큰과 똑같이 다룰 수 있다.
- 위치는 그 토큰의 첫 글자 자리다. `*`는 1:18, 곧 첫 줄 열여덟째 칸이다. 8장에서 바이트코드의 `MUL` 명령이 바로 이 1:18을 기억하고 있는 것을 보게 된다.

## 렉서가 일하는 방식 {#how}

렉서는 소스의 앞에서부터 글자를 하나씩 들여다보며 "다음 글자가 무엇으로 시작하는가"로 갈래를 탄다. fung 렉서의 큰 갈래는 이렇다.

- 공백·탭: 건너뛴다.
- 줄바꿈: `Newline` 토큰. 윈도식 줄 끝 `\r\n`도 토큰 하나다.
- `#`: 줄 끝까지 주석.
- 숫자: 수 또는 기간.
- `"`: 문자열, `` ` ``: 원시 문자열, `'`: 심볼.
- 글자나 `_`: 이름(또는 예약어, 태그).
- 그 밖: 연산자와 구두점. 모르는 글자면 에러.

이렇게 "지금 글자 하나(또는 몇 개)를 보고 다음에 무엇을 할지 정하는" 구조를 손으로 짠 렉서라고 한다. 규칙을 정규식으로 적어 주면 렉서 코드를 만들어 주는 도구(lex, flex 같은 렉서 생성기)도 있지만, 손으로 짠 렉서가 에러 메시지를 다듬기 쉬워서 많은 언어가 손으로 짠다.

### 가장 길게 자르기 {#maximal-munch}

`==`를 보면 `=` 두 개인가, 같다 연산자 하나인가? `..=`는 `..`과 `=`인가? 렉서는 **가능한 한 길게** 자른다. 이 규칙을 "maximal munch"(최대한 크게 베어 물기)라고 부른다. fung 렉서는 세 글자 연산자 표(`..=` `...`)를 먼저 보고, 없으면 두 글자 표(`==` `!=` `<=` `>=` `=>` `->` `//` `**` `|>` `??` `..` `;;`), 그다음 한 글자 표를 본다.

이 규칙 덕분에 블록 끝 `;;`가 헷갈리지 않는다. `x = 1 ;;; y = 2`는 `;;`(블록 끝) 다음 `;`(문장 구분)으로 잘린다.

```plain
1:1   Name        "x"
1:3   Assign      "="
1:5   Int         "1"
1:7   DoubleSemi  ";;"
1:9   Semi        ";"
1:11  Name        "y"
...
```

### 이름, 예약어, 태그 {#names}

글자나 `_`로 시작하면 이름 규칙을 따라 끝까지 읽는다. 이름에 쓸 수 있는 글자는 유니코드 표준(UAX #31)이 정하므로 한글 이름도 된다. 다 읽은 뒤 세 갈래로 나눈다.

1. 예약어 표에 있으면 예약어. fung의 예약어는 20개다: `fn` `if` `else` `then` `match` `when` `for` `in` `not` `and` `or` `return` `import` `as` `type` `test` `assert` `true` `false` `nil`.
2. 첫 글자가 유니코드 대문자면 **태그**(`Ok`, `Err`, `Red`).
3. 그 밖은 이름. 한글에는 대소문자가 없으므로 한글로 시작하는 이름은 항상 이름이다.

이름은 NFC라는 유니코드 정규형으로 바꿔 둔다. 같은 `é`라도 "한 글자 é"와 "e + 위에 붙는 기호" 두 가지로 쓸 수 있는데, 둘을 같은 이름으로 보기 위해서다. 맥 파일 이름처럼 분해된 글자로 들어온 이름을 위한 것이다(설계 문서 01).

### 숫자와 기간 {#numbers}

숫자로 시작하면 수를 읽는다. 정수(`42`, `1_000_000`, `0xff`, `0o17`, `0b1010`)와 실수(`3.14`, `2.5e-3`)가 있고, 숫자 **바로 뒤에** `ms` `s` `m` `h`가 붙으면 기간(`500ms`, `1h30m`)이다. 렉서가 이 판단을 모두 끝내고, 해석한 값을 토큰에 넣어 둔다.

```fung run
print(1_000, 0x1F, 2.5e-3, 1h30m)
```

숫자 뒤에 엉뚱한 글자가 붙으면 렉서가 바로 멈춘다. 이름 `abc`와 숫자 `30`이 붙어 있는 것인지 오타인지 렉서는 알 수 없으므로 에러로 본다.

```fung run exit=2 error=E0102
price = 30abc
```

복합 기간은 큰 단위부터 써야 한다. `30m1h`는 `E0105`(malformed duration)다.

음수는 토큰이 아니다. `-3`은 `-` 토큰과 `3` 토큰이고, 파서가 이것을 "3에 단항 마이너스"로 묶는다. 8장의 바이트코드에서 `CONST 3` 다음에 `NEG`가 나오는 것이 그 흔적이다. 예외는 가장 작은 정수 `-9223372036854775808` 하나다. 크기 `9223372036854775808`은 64비트 정수에 들어가지 않으므로, 렉서는 이 값만 특별히 표시해 두고 파서가 바로 앞의 `-`와 접어 허용한다.

### 문자열과 보간 {#strings}

`"`를 만나면 닫는 `"`까지 읽으며 이스케이프(`\n`, `\t`, `\"` …)를 해석한다. 모르는 이스케이프는 에러다. `"C:\new"` 같은 함정을 잡으려는 엄격한 규칙이다(설계 문서 01).

보간 `${…}`이 까다롭다. `"got ${m["k"]}"`에서 안쪽의 `"`가 바깥 문자열을 끝내면 안 된다. 렉서는 `${`를 만나면 중괄호 깊이를 세며 코드 부분을 건너뛰고, 그 안에서 `"`를 만나면 안쪽 문자열 하나를 통째로 건너뛴다. 그리고 문자열 토큰 하나에 **조각들**을 담는다. `"host ${name}!"`의 토큰에는 세 조각이 들어 있다.

```plain
2:7   String  "\"host ${name}!\""
              조각: 글자 "host " / 코드 "name" / 글자 "!"
```

코드 조각은 렉서가 읽지 않고 **글자 그대로와 위치만** 보관한다. 파서가 나중에 그 조각을 다시 렉싱하고 파싱하는데, 이때 조각이 파일의 몇째 줄 몇째 칸에서 시작했는지(`lex_at`)를 넘겨주므로 조각 안의 에러도 파일 기준 위치로 나온다.

```plain
error[E0110]: unexpected end of file
  --> example.fung:2:21
  |
2 | print("host ${name +} up")
  |                     ^
  |
```

## 줄바꿈과 주석 {#newline-comment}

많은 언어의 렉서는 줄바꿈을 공백처럼 버린다. fung 렉서는 줄바꿈을 `Newline` 토큰으로 내보낸다. fung에서는 줄바꿈이 문장의 끝이기 때문이다. 그런데 늘 그런 것은 아니다. `+`로 끝나는 줄은 다음 줄로 이어지고, 괄호 안의 줄바꿈은 공백이며, 다음 줄이 `|>`로 시작하면 이어진다. 이 판단은 "지금 괄호 안인가", "앞 토큰이 연산자인가" 같은 문맥이 필요하다. 렉서는 문맥을 모르므로 줄바꿈을 그대로 넘기고, **파서가** 문맥을 보고 버릴지 정한다(4장).

주석은 반대로 토큰 줄에서 뺀다. 실행에는 아무 상관이 없기 때문이다. 다만 버리지 않고 위치와 함께 **별도 목록**(trivia, 자질구레한 것)에 모아 둔다. 실행 경로는 이 목록을 쓰지 않는다. 포맷터(`fung fmt`)가 코드를 다시 쓸 때 주석을 원래 자리에 돌려놓는 데 쓴다(15장).

```fung run
timeout = 1h30m  # wait at most this long
print(timeout)
```

이 프로그램의 토큰에 주석은 없다. 렉서는 `# wait at most this long`을 "1:18에서 시작하는 주석"으로 따로 보관한다.

## 위치 세기 {#positions}

위치는 줄과 칸으로 센다. 칸은 **글자 단위**이지 바이트 단위가 아니다. 한글 한 글자는 UTF-8로 3바이트이지만 칸은 하나다. 에러는 사람에게 보여 주는 것이므로 사람이 세는 방식을 따른다.

```fung run exit=2 error=E0101
ab = 1
참치 = ab @ 2
```

`@`는 둘째 줄 아홉째 글자다. 바이트로 셌다면 13이 되어 밑줄이 엉뚱한 곳을 가리켰을 것이다. 렉서는 그래서 위치를 두 가지로 들고 다닌다. 소스를 잘라 낼 때 쓰는 **바이트 위치**와, 사람에게 보여 줄 **글자 칸**이다. 토큰도 둘 다 담는다(`pos`와 `off`·`end`).

그 밖의 규칙도 위치를 사람의 눈에 맞춘다. 줄 끝이 `\r\n`이어도 위치가 같고, 파일 맨 앞의 BOM(U+FEFF, 일부 편집기가 붙이는 보이지 않는 표시)은 칸으로 세지 않는다.

## 렉서의 에러 {#errors}

렉서의 에러는 모두 `E01xx`이고, **첫 번째 에러에서 멈춘다**. 글자 하나가 잘못되면 그 뒤의 토큰 경계도 믿을 수 없기 때문이다. 문자열의 닫는 `"`를 빠뜨리면 그 뒤 전체가 문자열처럼 읽힐 수 있다.

:::box other 다른 언어는
- **Python**: 들여쓰기가 문법이라, 렉서가 줄 앞의 공백을 세어 `INDENT`·`DEDENT`라는 가짜 토큰을 만든다. 파서는 이것을 중괄호처럼 쓴다. fung은 들여쓰기에 뜻이 없어서 이런 토큰이 없다.
- **C**: 렉서 앞에 전처리기(`#include`, `#define`)가 있어서 글자를 먼저 바꿔 놓는다. 그래서 에러 위치가 실제 파일과 어긋나기 쉽다.
- **JavaScript**: 줄바꿈을 따로 토큰으로 두지 않는 대신 "토큰 앞에 줄바꿈이 있었다"는 표시를 붙이고, 파서가 그것으로 세미콜론을 자동으로 끼울지 정한다. fung과 같은 생각(줄바꿈 판단은 파서)의 다른 모양이다.
- **렉서 생성기**: lex·flex 같은 도구는 정규식 규칙에서 렉서를 만들어 준다. 큰 컴파일러들도 손으로 짠 렉서를 쓰는 경우가 많다.
:::

:::box choice fung의 선택
- **글자 수준 규칙은 전부 렉서에서 끝낸다.** 숫자의 형태와 범위, 기간의 단위 순서, 이스케이프, 보간 조각, 원시 문자열, 심볼. 첫 마일스톤(M1)에서 이것을 한 번에 다 만든 이유는 뒤의 마일스톤에서 문자열과 기간을 쓸 때 렉서를 다시 열지 않기 위해서였다(마일스톤 노트 M1).
- **줄바꿈은 토큰으로, 판단은 파서가.** 줄 이어짐과 `:`의 두 역할(블록 시작인가, 이름 인자의 구분자인가)은 문맥이 있어야 정할 수 있어서 파서가 맡는다(설계 문서 01·09).
- **주석은 따로 보관한다.** 포맷터가 원래 자리에 되돌려 놓기 위해서다(설계 문서 09).
- **칸은 글자 단위.** 칸은 사람에게 보여 줄 때 쓰므로 바이트로 세면 틀린다(이식 노트 R1).
- **외부 라이브러리 없이 손으로 짰다.** 앞단 크레이트(`fung-front`)는 외부 크레이트를 하나도 쓰지 않는다는 저장소의 의존성 정책을 따른다. 유니코드 판정 표(`spec/unicode.txt`)도 직접 생성해 넣었다.
:::

## 코드에서 찾아보기 {#source}

- `crates/fung-front/src/lexer.rs`: 렉서 전체. 입구는 `lex(file, src)`로, 토큰 목록과 주석 목록을 돌려준다. 보간 조각처럼 파일 중간에서 시작하는 글자는 `lex_at`으로 렉싱한다.
  - `Kind`: 토큰 종류(`Name`, `Int`, `KwFn`, `DoubleSemi` …). `Kind::describe`는 에러 메시지에 쓰는 이름.
  - `Token`: `kind`, `text`, `pos`, `off`·`end`(바이트 위치), `int`·`float`·`dur`(해석한 값), `parts`(문자열 조각).
  - `Part`(문자열 조각), `Comment`(보관하는 주석), `KEYWORDS`(예약어 20개).
  - `Lexer::run`: 첫 글자로 갈래를 타는 큰 반복문. `Lexer::punct`와 `punct3`·`punct2`·`punct1`이 가장 길게 자르기, `Lexer::ident`가 이름·예약어·태그 가르기다.
- `crates/fung-front/src/lexer/number.rs`: `Lexer::number`(정수·실수·기간)와 단위 표 `duration_unit`.
- `crates/fung-front/src/lexer/string.rs`: `Lexer::str`, `skip_interpolation`, `skip_quoted`, `raw_str`, `symbol`.
- `crates/fung-front/src/unicode/mod.rs`: `is_name_start`, `is_name_continue`, `is_upper`, 그리고 `nfc`.
- `crates/fung-front/src/source.rs`: 위치 `Pos { file, line, col }`.

:::exercise 렉서가 받아 주는 것
다음 다섯 가운데 렉서가 거절하는 것은 무엇이고, 그 에러 번호는? 렉서는 통과하지만 파서가 거절하는 것도 하나 있다.

`1_000` · `30m1h` · `0x1F` · `.5` · `"tab\t"`

:::solution
- `30m1h`: 렉서가 거절한다. 기간은 큰 단위부터라 `E0105`.
- `.5`: 렉서는 `.`(점)과 `5`(정수) 두 토큰으로 잘 자른다. 그런데 식이 점으로 시작할 수 없으므로 파서가 `E0110 unexpected .`을 낸다. 소수점 앞 숫자를 반드시 쓰게 한 이유는 다음 줄이 `.`으로 시작하면 앞 줄에 이어지는 규칙(`.field` 이어 쓰기)과 겹치지 않게 하려는 것이다(설계 문서 01).
- 나머지 셋은 모두 된다.

```fung run
print(1_000, 0x1F, "tab\t|")
```

:::

## 정리 {#summary}

- 렉서는 글자의 줄을 토큰의 줄로 자른다. 토큰은 종류, 글자, 위치, 값을 담는다.
- 연산자는 가장 길게 자른다. 이름은 다 읽은 뒤 예약어·태그·이름으로 나눈다.
- 숫자·기간·문자열 같은 글자 수준 규칙은 모두 렉서에서 끝나고, 보간의 코드 조각은 위치와 함께 보관했다가 파서가 읽는다.
- 줄바꿈은 토큰으로 내보내고 판단은 파서에게 맡긴다. 주석은 포맷터를 위해 따로 보관한다.
- 위치의 칸은 글자 단위다. 렉서는 첫 에러에서 멈추고, 번호는 `E01xx`다.

다음 장에서는 이 토큰의 줄을 파서가 트리로 만든다. 글자 수준 규칙의 전체 목록은 [언어 레퍼런스의 글자 수준 규칙](../reference/language.html#lexical)에 있다.
